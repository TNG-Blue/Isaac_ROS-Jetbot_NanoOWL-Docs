    Kubernetes Deployment¶

    Deploy Isaac ROS Jetbot NanoOWL on Kubernetes clusters.

    📚 Overview¶

    Kubernetes enables scalable, automated container orchestration for Isaac ROS Jetbot NanoOWL systems, supporting multiple robots and edge deployments.

    Benefits: - ✅ Automated scaling - ✅ Self-healing - ✅ Rolling updates - ✅ Multi-robot coordination - ✅ High availability - ✅ Resource management

    🏗️ Kubernetes Architecture¶

    Cluster Components¶

    YAML
    Kubernetes Cluster:
├── Control Plane
│   ├── API Server
│   ├── Scheduler
│   ├── Controller Manager
│   └── etcd (data store)
├── Worker Nodes
│   ├── Robot 1 (Jetson Orin Nano)
│   ├── Robot 2 (Jetson Orin Nano)
│   └── Robot N
└── Add-ons
    ├── DNS
    ├── Networking (CNI)
    ├── Monitoring (Prometheus)
    └── Logging (ELK)

    🚀 Quick Start¶

    Prerequisites¶

    Bash
    # Install kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl

# Verify installation
kubectl version --client

# Install kubeadm & kubelet
sudo apt-get install -y kubeadm kubelet kubernetes-cni

# Start kubelet service
sudo systemctl start kubelet
sudo systemctl enable kubelet

    Initialize Kubernetes Cluster¶

    Bash
    # Initialize control plane (on master node)
sudo kubeadm init \
  --pod-network-cidr=10.244.0.0/16 \
  --kubernetes-version=stable

# Configure kubectl
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# Install networking addon (Flannel)
kubectl apply -f https://raw.githubusercontent.com/coreos/flannel/master/Documentation/kube-flannel.yml

# Verify cluster
kubectl get nodes
kubectl get pods -A

    📋 Kubernetes Manifests¶

    Namespace¶

    YAML
    # File: Kubernetes/namespace/jetbot-namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: jetbot
  labels:
    name: jetbot

    Apply:

    Bash
    kubectl apply -f Kubernetes/namespace/jetbot-namespace.yaml

    ConfigMap - ROS2 Configuration¶

    YAML
    # File: Kubernetes/configmaps/ros2-config.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: ros2-config
  namespace: jetbot
data:
  ROS_DOMAIN_ID: "0"
  ROS_LOCALHOST_ONLY: "0"
  ROS_DISTRO: "humble"

    Secret - Credentials¶

    YAML
    # File: Kubernetes/secrets/credentials.yaml
apiVersion: v1
kind: Secret
metadata:
  name: jetbot-credentials
  namespace: jetbot
type: Opaque
stringData:
  api_key: "your-api-key-here"
  registry_username: "your-username"
  registry_password: "your-password"

    Deployment - Motor Controller¶

    YAML
    # File: Kubernetes/workloads/motor-controller-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: motor-controller
  namespace: jetbot
spec:
  replicas: 1
  selector:
    matchLabels:
      app: motor-controller
  template:
    metadata:
      labels:
        app: motor-controller
    spec:
      nodeSelector:
        kubernetes.io/hostname: jetbot-1
      containers:
      - name: motor-controller
        image: tngblue/jetbot_nanoowl:latest
        resources:
          requests:
            memory: "1Gi"
            cpu: "500m"
            nvidia.com/gpu: 1
          limits:
            memory: "2Gi"
            cpu: "1000m"
            nvidia.com/gpu: 1
        envFrom:
        - configMapRef:
            name: ros2-config
        volumeMounts:
        - name: data
          mountPath: /home/jetbot/data
        - name: serial
          mountPath: /dev/ttyUSB0
      volumes:
      - name: data
        hostPath:
          path: /data/jetbot-1
          type: Directory
      - name: serial
        hostPath:
          path: /dev/ttyUSB0
          type: CharDevice

    Deployment - Object Detection¶

    YAML
    # File: Kubernetes/workloads/detection-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: object-detection
  namespace: jetbot
spec:
  replicas: 1
  selector:
    matchLabels:
      app: object-detection
  template:
    metadata:
      labels:
        app: object-detection
    spec:
      nodeSelector:
        kubernetes.io/hostname: jetbot-1
      containers:
      - name: detection
        image: tngblue/object_detection_isaac_ros:latest
        resources:
          requests:
            memory: "2Gi"
            cpu: "1000m"
            nvidia.com/gpu: 1
          limits:
            memory: "4Gi"
            cpu: "2000m"
            nvidia.com/gpu: 1
        env:
        - name: ROS_DOMAIN_ID
          valueFrom:
            configMapKeyRef:
              name: ros2-config
              key: ROS_DOMAIN_ID
        volumeMounts:
        - name: models
          mountPath: /home/jetbot/models
      volumes:
      - name: models
        hostPath:
          path: /models
          type: Directory

    Service¶

    YAML
    # File: Kubernetes/network/motor-controller-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: motor-controller-service
  namespace: jetbot
spec:
  type: ClusterIP
  selector:
    app: motor-controller
  ports:
  - name: ros2
    port: 11311
    targetPort: 11311
  - name: rest-api
    port: 8080
    targetPort: 8080

    StatefulSet - Multi-Robot¶

    YAML
    # File: Kubernetes/workloads/jetbot-statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: jetbots
  namespace: jetbot
spec:
  serviceName: jetbot-headless
  replicas: 3
  selector:
    matchLabels:
      app: jetbot
  template:
    metadata:
      labels:
        app: jetbot
    spec:
      containers:
      - name: jetbot
        image: tngblue/jetbot_nanoowl:latest
        env:
        - name: ROBOT_NAME
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: ROBOT_ID
          valueFrom:
            fieldRef:
              fieldPath: metadata.ordinalSubset
        volumeMounts:
        - name: data
          mountPath: /home/jetbot/data
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      storageClassName: fast-ssd
      resources:
        requests:
          storage: 10Gi

    RBAC - Role-Based Access Control¶

    YAML
    # File: Kubernetes/rbac/jetbot-role.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: jetbot-sa
  namespace: jetbot

---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: jetbot-role
  namespace: jetbot
rules:
- apiGroups: [""]
  resources: ["configmaps", "secrets"]
  verbs: ["get", "list", "watch"]
- apiGroups: [""]
  resources: ["services"]
  verbs: ["get", "list"]

---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: jetbot-rolebinding
  namespace: jetbot
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: jetbot-role
subjects:
- kind: ServiceAccount
  name: jetbot-sa
  namespace: jetbot

    🔧 Kustomization¶

    Kustomization Base¶

    YAML
    # File: Kubernetes/kustomization/base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: jetbot

resources:
  - ../namespace/jetbot-namespace.yaml
  - ../configmaps/ros2-config.yaml
  - ../secrets/credentials.yaml
  - ../workloads/motor-controller-deployment.yaml
  - ../workloads/detection-deployment.yaml
  - ../network/services.yaml
  - ../rbac/jetbot-role.yaml
  - ../storage/persistent-volumes.yaml

commonLabels:
  app.kubernetes.io/name: jetbot
  app.kubernetes.io/version: 2.0.0

commonAnnotations:
  managed-by: kustomize
  description: "Isaac ROS Jetbot NanoOWL Kubernetes Deployment"

    Kustomization Overlay - Production¶

    YAML
    # File: Kubernetes/kustomization/overlays/production/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

bases:
  - ../../base

replicas:
  - name: motor-controller
    count: 2
  - name: object-detection
    count: 2

patchesStrategicMerge:
  - deployment-patch.yaml

configMapGenerator:
  - name: ros2-config
    behavior: merge
    literals:
      - LOG_LEVEL=WARN

images:
  - name: tngblue/jetbot_nanoowl
    newTag: v2.0.0-prod

    🚀 Deployment Commands¶

    Deploy with kubectl¶

    Bash
    # Create namespace
kubectl create namespace jetbot

# Apply all manifests
kubectl apply -f Kubernetes/namespace/
kubectl apply -f Kubernetes/configmaps/
kubectl apply -f Kubernetes/secrets/
kubectl apply -f Kubernetes/workloads/
kubectl apply -f Kubernetes/network/
kubectl apply -f Kubernetes/rbac/

# Or use kustomize
kubectl apply -k Kubernetes/kustomization/base/

# Check deployment status
kubectl get deployments -n jetbot
kubectl get pods -n jetbot
kubectl get services -n jetbot

# View logs
kubectl logs -n jetbot -f deployment/motor-controller

# Get pod details
kubectl describe pod <pod-name> -n jetbot

    Rolling Updates¶

    Bash
    # Update image
kubectl set image deployment/motor-controller \
  motor-controller=tngblue/jetbot_nanoowl:v2.0.1 \
  -n jetbot

# Check rollout status
kubectl rollout status deployment/motor-controller -n jetbot

# Rollback if needed
kubectl rollout undo deployment/motor-controller -n jetbot

# View rollout history
kubectl rollout history deployment/motor-controller -n jetbot

    🔍 Monitoring¶

    Check Node Status¶

    Bash
    # List nodes
kubectl get nodes

# Node resource usage
kubectl top nodes

# Detailed node info
kubectl describe node <node-name>

    Pod Management¶

    Bash
    # List pods
kubectl get pods -n jetbot

# Pod details
kubectl describe pod <pod-name> -n jetbot

# Pod logs
kubectl logs <pod-name> -n jetbot
kubectl logs -f <pod-name> -n jetbot

# Execute command in pod
kubectl exec -it <pod-name> -n jetbot -- bash

# Copy files
kubectl cp jetbot/<pod-name>:/home/jetbot/data ./local-data

    🐛 Troubleshooting¶

    Pod Not Starting¶

    Bash
    # Check pod status
kubectl describe pod <pod-name> -n jetbot

# Check logs
kubectl logs <pod-name> -n jetbot
kubectl logs <pod-name> -n jetbot --previous

# Check events
kubectl get events -n jetbot --sort-by='.lastTimestamp'

    GPU Access¶

    Bash
    # Check GPU node labels
kubectl get nodes --show-labels | grep nvidia

# Verify GPU requests
kubectl describe pod <pod-name> -n jetbot | grep -A 5 "Limits"
