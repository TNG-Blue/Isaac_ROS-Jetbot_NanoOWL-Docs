    Deployment¶

    How the software reaches the robot, runs there, stays up to date and talks to operators. Each page below is rendered from, or written against, the files that implement it.

    • Docker

      One image per ROS 2 node from a single template, CPU and GPU bases, the runtime contract and Docker Compose for a single Jetson.

      Docker

    • Kubernetes

      Bootstrap of the two-Jetson k3s cluster: network, install scripts, settings and where their numbers come from.

      Kubernetes

    • Helm

      The ros2-jetson chart: node catalogue, scheduling and resource budget, DDS in Kubernetes, failover.

      Helm Charts

    • OTA Updates

      A/B firmware updates for the STM32N6 microcontrollers from the Go OTA server.

      OTA Updates

    • MAVLink Relay Server

      TLS relay that connects the vehicle and operator consoles across NAT without opening a port on the robot.

      MAVLink Relay

    • OTA Web Interface

      Static preview of the OTA server's firmware dashboard.

      Web Interface

    Deployment targets¶

    Target Use How
    Native build development on the Jetson or a PC ROS/build.sh (Installation)
    Docker Compose, one Jetson bench work with the production images Docker/compose (Docker)
    k3s + Helm, two Jetsons the vehicle Kubernetes/ + Helm/ (tutorial)
    OTA server firmware distribution to the MCUs Server_OTA/ on the cluster, a host or App Engine (Server OTA deployment)
    MAVLink relay operator consoles on another network Server_Relay/ (MAVLink Relay)

    Vehicle network¶

    Address (192.168.10.0/24) Device
    .1 Jetson #1: k3s server, image registry :5000, micro-ROS agent UDP 8888
    .2 JetOwl flight controller (STM32N657)
    .3 JetOwl_Vision camera (STM32N655)
    .4 Jetson #2: k3s agent
    .200 OTA server (MetalLB)

    The MCUs use static addresses (no DHCP). ROS 2 pods use host networking so that DDS multicast discovery crosses the boards on the physical switch; see Helm.

    Release flow¶

    flowchart LR
    C["commit on master"] --> CI["CI: lint, tests,<br/>docs build"]
    CI --> IMG["Docker/scripts/build_all.sh<br/>--push --tag vX.Y.Z"]
    IMG --> H["Helm/scripts/deploy.sh<br/>--set global.imageTag=vX.Y.Z"]
    FW["firmware: make ota-upload"] --> OTA["Server_OTA"]
    OTA --> MCU["MCUs: ota/start → ota/apply"]

    Roll back the ROS 2 side with helm -n jetowl rollback jetowl; the firmware side rolls back on its own when a new image fails its trial boot. See Release Process.
