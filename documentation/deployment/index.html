    🐳 Docker Deployment¶

    Quick Start¶

    Bash
    # Build container
docker build -t jetbot:latest -f Dockerfile .

# Run container
docker run --gpus all \
  --privileged \
  -v /dev:/dev \
  -it jetbot:latest

    Docker Compose¶

    YAML
    version: '3.8'

services:
  ros2:
    image: jetbot:ros2
    environment:
      ROS_DOMAIN_ID: 0
    volumes:
      - /dev:/dev
    devices:
      - /dev/nvidia0:/dev/nvidia0
    privileged: true

  api:
    image: jetbot:api
    ports:
      - "8080:8080"
    depends_on:
      - ros2

    ☸️ Kubernetes Deployment¶

    Namespace & RBAC¶

    YAML
    apiVersion: v1
kind: Namespace
metadata:
  name: jetbot

---

apiVersion: v1
kind: ServiceAccount
metadata:
  name: jetbot-controller
  namespace: jetbot

    Deployment Manifest¶

    YAML
    apiVersion: apps/v1
kind: Deployment
metadata:
  name: jetbot-ros2
  namespace: jetbot
spec:
  replicas: 1
  selector:
    matchLabels:
      app: jetbot
  template:
    metadata:
      labels:
        app: jetbot
    spec:
      containers:
      - name: ros2
        image: jetbot:ros2
        resources:
          limits:
            nvidia.com/gpu: 1
        volumeMounts:
        - name: dev
          mountPath: /dev
      volumes:
      - name: dev
        hostPath:
          path: /dev

    📦 Helm Charts¶

    Chart Structure¶

    Text Only
    jetbot-helm/
├── Chart.yaml
├── values.yaml
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── configmap.yaml
│   └── secret.yaml
└── values/
    ├── development.yaml
    ├── staging.yaml
    └── production.yaml

    Install with Helm¶

    Bash
    # Add chart repository
helm repo add jetbot https://charts.jetbot.ai
helm repo update

# Install release
helm install jetbot jetbot/jetbot \
  -f values/production.yaml \
  --namespace jetbot

    🔄 OTA Updates¶

    Update Architecture¶

    sequenceDiagram
    participant Device as 🤖 Robot
    participant UpdateSvr as 📦 Update Server
    participant Storage as 💾 Storage

    UpdateSvr->>Device: New version available
    Device->>Device: Check available space
    Device->>UpdateSvr: Start download
    UpdateSvr->>Device: Stream update package
    Device->>Storage: Save to staging partition
    Device->>Device: Verify signature
    Device->>Device: Pre-update checks
    Device->>Device: Apply update
    Device->>Device: Reboot & verify
    Device->>UpdateSvr: Confirm success

    Update Configuration¶

    YAML
    update_config:
  server: "https://updates.jetbot.ai"
  check_interval: 3600  # seconds
  auto_update: false

  signing:
    key_file: "/etc/jetbot/update.key"
    verify_signature: true

  staging:
    partition: "/dev/nvme0n1p3"
    max_size: 2GB

  rollback:
    enabled: true
    backup_boot: true
    verify_integrity: true

    🔒 Security Best Practices¶

    Image Security¶

    Bash
    # Scan for vulnerabilities
trivy image jetbot:latest

# Sign image
cosign sign --key cosign.key jetbot:latest

# Verify signature
cosign verify --key cosign.pub jetbot:latest

    Network Security¶

    YAML
    Network Policies:
  - Restrict ingress to API port only
  - Restrict egress to known hosts
  - Enable TLS for all communications
  - Use VPN for remote access

RBAC:
  - Least privilege for services
  - Pod security policies
  - Network policies

    🔧 Common Deployment Scenarios¶

    Scenario 1: Solo Robot Development¶

    Bash
    # Simple Docker setup
docker-compose up -d

# Access robot
ssh jetbot@jetbot.local

# Monitor
docker logs -f jetbot-ros2

    Scenario 2: Multiple Robots (LoRa)¶

    Bash
    # LoRa mesh network
ROS_DOMAIN_ID=1 ros2 launch jetbot_bringup bringup.py network:=lora

# Fleet monitoring dashboard
ros2 launch jetbot_monitoring monitoring.py multi_robot:=true

    Scenario 3: Production Fleet (Kubernetes)¶

    Bash
    # Deploy fleet on Kubernetes
helm install fleet jetbot/jetbot \
  --values fleet-values.yaml

# Monitor fleet health
kubectl get nodes -l jetbot=robot
kubectl top pods -n jetbot

    ✅ Deployment Checklist¶

    Before going to production:

    • All sensors calibrated and tested
    • System stability tested for 24+ hours
    • Security certificates generated and installed
    • Monitoring and logging configured
    • Backup and disaster recovery plan
    • Documentation updated
    • Team trained on operations
    • Performance benchmarks verified
    • Network connectivity tested
    • Power system validated
