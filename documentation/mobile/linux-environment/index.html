    Linux environment — Jetbot NanoOWL (Qt)¶

    Source

    Snapshot of docs/LINUX_ENVIRONMENT.md from TNG-Blue/JetbotNanoOWL at commit d3d7467 (submodule Mobile/Android/JetbotNanoOWL/Qt). Regenerate with Scripts/mkdocs_hooks/snapshot_submodules.py after updating the submodule.

    An Ubuntu 22.04 guest that runs inside the app, without root: a login shell on a real terminal, apt, vendor repositories (ROS 2 Humble, VS Code, Chrome), the apps you install, and their windows on the phone's screen the way WSLg shows Linux windows on Windows.

    This document says how each piece works, why it is built that way, and derives the one estimator the feature uses. Everything described here is in app/src/linux/ and is exercised by tests/tst_linux.cpp.

    1. Architecture¶

      this app (Qt)                                      guest (PRoot)

  LinuxPage.qml ─ Linux (LinuxBackend) ─ install ──▶ Ubuntu 22.04.5 rootfs
                         │               apt ──────▶ package manager
                         │
  TerminalView ◀── PTY (posix_openpt) ─────────────▶ bash -l as jetbot_owl@Blue
                         │
  LinuxAppsPage ◀─────── /usr/share/applications/*.desktop

                                                       │ draws into a mapped file
  LinuxSurfaceView ◀═══ the same pages (mmap) ═════════┘

    Piece File Job
    PRootRuntime prootruntime.cpp fetch PRoot from the Termux repository, verify, unpack, self-test
    LinuxEnvironment linuxenvironment.cpp the rootfs: bootstrap, identity, the PRoot command line, running commands
    archive layer archive.cpp gzip / xz streams, ustar + pax + GNU tar, ar, extraction that cannot escape its root

    The engine (everything but the QML items) is the static library jetbot_linux, so the app and the host tests link the same code.

    2. The runtime, and why the app targets SDK 28¶

    An unrooted Android device gives an app no chroot(2) and no user namespaces. PRoot does the job in user space: it ptraces the guest and rewrites the path argument of every syscall, so /usr/bin/apt is served from <files>/linux/rootfs/usr/bin/apt. -0 reports uid 0, which is what lets a package manager believe it may write to /usr.

    W^X. Since Android 10 a file the app itself wrote can never be executed, unless the app targets SDK 28 or lower. PRoot, its loader and every program in the guest are files the app wrote, so the Qt app sets QT_ANDROID_TARGET_SDK_VERSION 28 — the same trade Termux makes.

    What it buys: a stock APK is complete (no build machine); the APK carries no GPL binaries (PRoot is GPL-2.0, libtalloc LGPL-3.0 — the phone downloads them from their publisher, as a package manager would); ~450 KB is not carried by installs that never open this page.

    What it costs: Google Play will not accept the app (sideloading and GitHub releases only), and the whole app opts out of the Android 10+ behaviour changes. A build that bundles libproot.so into lib/<abi>/ (the one directory Android executes from at any target) is preferred automatically when present, and could raise the target again.

    Installing it. PRootRuntime::install downloads the repository's dists/stable/main/binary-<arch>/Packages index, then proot, libtalloc and libandroid-shmem. Each .deb is checked against the SHA-256 that index publishes before anything is unpacked. A .deb is an ar archive whose data.tar.xz holds the files under the Termux prefix; those are relocated into files/runtime/ and everything else (docs, licences) is skipped. Installation is not complete until proot --version has run: a device that refuses to exec the files fails here, by name (execve: Permission denied is reported through a close-on-exec error pipe rather than as an anonymous exit status 127).

    The invocation:

    proot [--kill-on-exit] -r <rootfs> -0 [--link2symlink]
      -b /dev -b /proc -b /sys
      -b <files>/linux/tmp:/tmp  -b <files>/linux/shm:/dev/shm
      -b <external>/shared:/mnt/android          (when it exists)
      -b /proc/self/fd:/dev/fd
      -w /home/jetbot_owl
      /usr/bin/env -i <guest environment> /bin/sh -lc "<command>"
    • --kill-on-exit and --link2symlink are used when this PRoot advertises them in --help (Termux's build and upstream 5.4 do; Ubuntu's packaged 5.1 does not). --link2symlink is added only where link(2) fails in the guest's directory — Android's app storage — because dpkg relies on hard links.
    • env -i makes the guest's environment exactly the one listed below, instead of Android's ANDROID_ROOT and LD_LIBRARY_PATH.
    • /dev/std* are not bound. PRoot resolves such a binding to the terminal when it starts, after which ttyname(3) in the guest reports /proc/<pid>/fd/0 instead of /dev/pts/N and tmux, screen, ssh and gpg lose their terminal (found by the on-device self-test, see §8). /dev/fd/0..2 are the same descriptors.
    • Each session runs in its own process group (setsid), so stopping it reaches every tracee even without --kill-on-exit.

    3. The guest, and the bootstrap¶

    Ubuntu 22.04.5 LTS, only. It is the userspace of a Jetson on JetPack 6 and the release ROS 2 Humble is built for, so a package name resolves on the phone the way it does on the robot.

    ABI image SHA-256 (Canonical's SHA256SUMS)
    arm64-v8a ubuntu-base-22.04.5-base-arm64.tar.gz 075d4abd2817a5023ab0a82f5cb314c5ec0aa64a9c0b40fd3154ca3bfdae979f
    armeabi-v7a …-armhf.tar.gz fd77cb0659326b75c08ce06b6b8649d2e13ef9a704a8e9212fec32cb97d42add
    x86_64 …-amd64.tar.gz 242cd8898b33ea806ef5f13b1076ed7c76f9f989d18384452f7166692438ff1a

    The sequence: download (streamed to disk, hashed on the way) → verify → extract → configure. A mismatching digest stops before a single entry is written: a base image is code that will run with the app's authority, so checking after extraction would be no check at all.

    Extraction cannot escape the rootfs. An entry is refused when its normalised path climbs out (../x), or when an ancestor already on disk is a symlink resolving outside — the case a lexical check misses (evil -> /, then evil/etc/passwd). Hard-link targets are checked the same way. Symlink targets are written verbatim and never followed on the host: in the guest an absolute /lib/... is right, here it would point at Android. Directory modes are applied last, deepest first, so a read-only directory does not stop its own children being written; device nodes and FIFOs are skipped (PRoot serves Android's /dev). All of this is in tests/tst_linux.cpp (tarSlipIsRefused, tarGzipAndXzRoundTrip).

    Configuration writes what a base image lacks: resolv.conf (PRoot has no resolver of its own), hosts, hostname, the marker file — and then the identity pass below. The apt sources are left alone: the image already enables main, restricted, universe and multiverse on the right archive host.

    3.1 Who the guest says you are¶

    The prompt is jetbot_owl@Blue: an account jetbot_owl (first free uid ≥ 1000, kept stable across runs) whose home is the working directory of every guest process, and the hostname Blue. The pass runs before every guest process, behind a version marker (/.jetbot-identity, now 3), so a guest installed by an older build picks up what a newer one writes.

    • sudo and su are shims in /usr/local/bin. A real sudo is setuid, which PRoot cannot honour (there is no kernel transition to make), and every guest process already holds the authority it would grant. The shim parses sudo's options and runs the command; sudo -i gives a login shell.
    • /usr/sbin/policy-rc.d answers 101 ("action forbidden", invoke-rc.d(8)), as Ubuntu's container images do: there is no init system in the guest, so a package's maintainer script must not try to start its service. Without it, x11-common's postinst fails and leaves every X package unconfigured.
    • Android's supplementary groups get names in /etc/group (inet, everybody, u0_a368_cache, …, from android_filesystem_config.h and the per-user id scheme), or Ubuntu's bash.bashrc prints "cannot find name for group ID" in every shell.
    • ~/.bashrc and ~/.profile start from /etc/skel and are never overwritten.

    3.2 Builds that do not get the app killed¶

    Every guest process is a child of this app, so to Android the guest's memory is the app's. A build that asks for more than the phone has gets the whole app killed. Each shell therefore starts with

    \[\text{jobs} = \operatorname{clamp}\!\left(\left\lfloor \frac{M - R}{J} \right\rfloor,\ 1,\ \text{cpus}\right),\qquad R = J = 1536\ \text{MB},\]

    where \(M\) is MemAvailable when the shell starts. For jobs > 1 this guarantees \(\text{jobs}\cdot J + R \le M\) (asserted over a sweep in buildLimits). The result goes to MAKEFLAGS and CMAKE_BUILD_PARALLEL_LEVEL, and ~/.colcon/defaults.yaml (written only if missing) sets colcon to one package at a time, so the two do not multiply. While anything runs, a foreground service tells Android the app is doing work the user is waiting for.

    4. The terminal¶

    A pipe is not a terminal: behind one, isatty() is 0, so apt prints no progress, sh offers no prompt, nano and htop refuse to start, and Ctrl+C cannot be delivered. The shell gets a real pseudo-terminal:

    posix_openpt → grantpt → unlockpt → ptsname_r → TIOCSWINSZ
fork
  child:  setsid · open(slave) · TIOCSCTTY · dup2 → 0,1,2 · close the rest · execve(proot …)
  parent: master fd → QSocketNotifier on the GUI thread

    The command is if command -v bash …; then exec bash -l; fi; exec sh -l, so the PTY's child is the login shell itself. Resizing sends TIOCSWINSZ (the kernel raises SIGWINCH and curses programs reflow); closing sends SIGHUP to the whole process group, so a package manager caught mid-install does not survive as an orphan holding dpkg's lock.

    Flow control is free here. The master is read only when the GUI event loop gets to it, and each read is bounded (64 KiB). A compiler that writes faster than the emulator parses fills the kernel's PTY buffer and blocks in write(2): the build slows to the speed of the screen, nothing is dropped and nothing queues in this process. (The Kotlin terminal needed an explicit bounded queue because its emulator ran in a separate WebView process.)

    The terminal also exports the shared desktop's DISPLAY and session bus, and starts that desktop in the background, so a graphical program typed at the prompt has a screen; the monitor button opens it.

    5. Windows on the phone — no display protocol¶

    WSLg needs RDP because its guest is a virtual machine sharing no memory with the host. This guest is a process tree whose /tmp is a directory the app owns, so:

    • Xvfb -fbdir /tmp/xfb-N keeps its screen in a memory-mapped XWD file, which LinuxSurfaceView maps directly (XSurfaceSession in the core);
    • its socket /tmp/.X11-unix/XN is a local path here too, and the server is started -nolisten tcp, so there is no port for anything to reach;
    • DAMAGE reports the bounding box of what changed, and the frame thread copies only that box into the image the scene graph uploads;
    • XTEST carries taps and keys. Input uses a second X connection owned by the GUI thread, so each connection has exactly one owner and a tap is sent the moment it happens.

    Frames arrive when the guest draws and never otherwise: there is no rate to choose, so no pacing loop is needed on this path (the M/G/1 pacer in the core, frame_pacer.h, serves request-driven protocols such as RFB).

    One desktop for every app. Each app opens on the shared desktop, and an openbox rule — added to the stock rc.xml, so its keys and menus stay — maximises every type="normal" window, while dialogs keep the size they ask for (Alt+Tab, on the key row, switches between apps). One X server is one server's memory, and there is no limit on how many apps run: the earlier "display per app" mode needed a server each and capped them at eight, which is why it was removed. A LinuxSurfaceView maps frames only while it is visible (ItemVisibleHasChanged), and the app keeps at most one display page in its stack. The session script waits on the X socket by elapsed time, loads the X resources below, starts a session bus at a chosen address and the window manager, then waits on the server; its log (/tmp/xsession-N.log) is one tap away in the viewer.

    Gestures (shared with the VNC viewer, TouchPointer): one finger is the left button, a long press a right click, two fingers scroll, a two-finger tap toggles the keyboard. A key row supplies Esc, Tab, arrows, F-keys and sticky Ctrl, Alt, Shift and Super.

    Geometry: a physical panel. The guest screen is described the way a phone's is — aspect \(a{:}b = 20{:}9\), diagonal \(D\) (default 6.8 in) and density \(\rho\) (default 400 dpi) — not by a resolution. Its sides follow by Pythagoras:

    \[W = \rho\,D\,\frac{a}{\sqrt{a^2+b^2}},\qquad H = \rho\,D\,\frac{b}{\sqrt{a^2+b^2}}\qquad(\text{rounded to even})\]

    so 6.8 in at 400 dpi is 2480 × 1116 (and \(\sqrt{W^2+H^2}/\rho = 6.80\) in back). Xvfb runs at that size with -dpi 400.

    Scaling every app. X toolkits assume 96 dpi and lay out in their own pixels; on a phone each is scaled by

    \[s = \frac{\rho}{160}.\]

    160 dpi is where Android's density-independent pixel is one pixel, and it is the CSS reference pixel — the visual angle of one pixel at 96 dpi from 28 in, 0.0213° (CSS Values and Units §5.2) — for a phone read at 16.8 in: \(96 \cdot 28 / 16.8 = 160\). Apps then lay out on

    \[\frac{W}{s} \times \frac{H}{s} = 160\,D\,\frac{a}{\sqrt{a^2+b^2}} \times 160\,D\,\frac{b}{\sqrt{a^2+b^2}} = 992 \times 446 \text{ (6.8 in)},\]

    which does not depend on \(\rho\): density buys sharpness, the diagonal buys room. \(s\) reaches each toolkit the way it reads it:

    toolkit setting (s = 2.5)
    Xft, Chromium/Electron (VS Code), Pango (openbox), Tk X resource Xft.dpi: 240 (= 96 s), via xrdb -nocpp -merge
    GTK ¾ GDK_SCALE=2 (integer) and GDK_DPI_SCALE=1.25, product = s
    Qt ⅚ QT_SCALE_FACTOR=2.5, QT_FONT_DPI=96 so Xft.dpi does not scale text twice, automatic scaling off
    Java (JetBrains IDEs) JAVA_TOOL_OPTIONS=-Dsun.java2d.uiScale=2.5
    EFL ELM_SCALE=2.5
    cursor XCURSOR_SIZE=60, Xcursor.size: 60 (24 s)

    The Linux page's Display tab picks \(D\) and \(\rho\); a change applies when the desktop next starts (Restart desktop to apply).

    The unix-socket limit. PRoot hands the X server the host path of its socket, which must fit sockaddr_un.sun_path (108 bytes). On a phone it is about 72; a session refuses to start, with a message saying why, when the app's data directory makes it longer.

    5.1 Closing the app closes the guest¶

    Every process the app starts is a process-group leader (setsid), recorded until reaped. Closing the app ends all of them in one pass — SIGTERM to every group, one shared grace period of 0.8 s, then SIGKILL — and PRoot's --kill-on-exit takes the guest processes it traces with it, X servers and apps included, even those that left their group. Three paths lead there:

    How the app goes What runs
    Back out of the last page, or the app quits QCoreApplication::aboutToQuit → linuxenv::shutdownAllGuests()
    Swiped away from Recents LinuxGuestService.onTaskRemoved → the same, through JNI; then the process ends, since the foreground service would otherwise keep it, and the guest, alive (stopWithTask="false" so that callback is delivered)
    Killed by Android outright (no callback) on the next start, killStrays() stops any PRoot of this app's user that is not a child of the new process

    The terminal's shells go the same way: they are groups like any other.

    5.2 The keyboard held sideways¶

    In landscape an IME shows a full-screen "extract" editor (an empty text box and Done) unless the editor sets IME_FLAG_NO_EXTRACT_UI / IME_FLAG_NO_FULLSCREEN, which Qt 6.8 never does. Qt writes its options into its QtEditText on every show, then restarts the input 15 ms later. LinuxPlatform.installImeFix adds the two flags back when focus moves to that editor and after the layout pass every show requests; if the layout pass came after the restart (a 60 Hz frame is 16.7 ms), it restarts the input once more so the IME reads the flags. The keyboard then takes only its own height, for every text field in the app.

    6. Packages, repositories, files¶

    • Packages: apt-get install -y --no-install-recommends with --force-confdef --force-confold, because there is no one to answer a config-file prompt. The index is refreshed once per run before the first install (a base image ships an empty one). Names are shell-quoted. When apt says "unable to locate package", the console adds that the usual cause is a vendor repository not yet added.
    • Bundles: Desktop base (xvfb, openbox, xterm, fonts, dbus-x11), Seamless windows (matchbox), Build tools (build-essential, cmake, git, pip). Anything else is installed by name.
    • Repositories: ROS 2 Humble, VS Code and Chrome as presets, or any deb … line with an HTTPS key URL. The key must be an OpenPGP public key — armoured (.asc) or binary (.gpg, as ROS publishes it; RFC 4880 packet tag 6) — and is written to /etc/apt/keyrings/ with signed-by= naming it. If apt-get update rejects the repository, both files are removed again.
    • Apps are read from the guest's .desktop files every time (XDG search path, the per-user copy shadowing the packaged one), so an app installed from the terminal appears without the app being told. Icons come from the guest's icon themes (PNG, SVG and XPM all render). Chromium-family programs get --no-sandbox; Electron apps read ELECTRON_DISABLE_SANDBOX.
    • Files: one folder is visible to both sides — the app's external files directory, bound at /mnt/android (and ~/android). Import and export go through the system picker, so no storage permission is requested.

    7. The one estimator: transfer progress¶

    A byte counter sampled four times a second gives a difference quotient that swings by tens of percent; an ETA computed from it is unusable. Model the transfer as constant rate disturbed by white acceleration:

    \[x = \begin{bmatrix} b \\ \dot b\end{bmatrix},\quad F = \begin{bmatrix} 1 & T_s \\ 0 & 1\end{bmatrix},\quad H = \begin{bmatrix}1 & 0\end{bmatrix}.\]

    The Kalman gain of this pair converges to a constant; running the filter at that limit is the alpha-beta tracker (core/src/alpha_beta.cpp):

    \[b^- = b + \dot b\,T_s,\quad r = b_\text{meas} - b^-,\quad b \leftarrow b^- + \alpha r,\quad \dot b \leftarrow \dot b + \tfrac{\beta}{T_s} r.\]

    With a constant true rate the error \(e = [e_b,\ T_s e_{\dot b}]^\top\) obeys \(e_k = A e_{k-1}\) with

    \[A = \begin{bmatrix} 1-\alpha & 1-\alpha \\ -\beta & 1-\beta \end{bmatrix},\qquad z^2 - (2-\alpha-\beta)z + (1-\alpha) = 0. \tag{P}\]

    The Jury test gives stability iff \(0 < \alpha < 2\) and \(0 < \beta < 4 - 2\alpha\). With the pairing the constant-velocity Kalman filter converges to (Kalata 1984),

    \[\beta = \frac{\alpha^2}{2-\alpha}, \tag{K}\]

    the discriminant of (P) is \(-4\alpha^2(1-\alpha)/(2-\alpha)^2 \le 0\), so the poles are a complex pair of modulus exactly

    \[|z| = \sqrt{1-\alpha}. \tag{M}\]

    The error decays like \((1-\alpha)^{k/2}\) for every admissible \(\alpha\), independent of \(T_s\). With \(\alpha = 0.3\) that is \(0.837\) per step — a factor of ten in about 13 samples, ~3 s at 4 Hz — and zero steady-state error on a ramp. ProgressMeter drives the tracker at a fixed 250 ms with the measured interval, for the rootfs download (bytes) and its extraction (compressed bytes consumed — the only total known up front). The host suites check (K), (M), the Jury region (jetbot_core_tests) and convergence to within 10 % of the true rate under ±20 % jitter (progressMeterConverges).

    9. Security properties¶

    • The display listens on no network socket (-nolisten tcp); its only endpoint is a unix socket inside the app's private storage.
    • The rootfs and every runtime package are verified against digests published separately from the files, over HTTPS, before anything is unpacked; archive entries cannot escape their root.
    • No new runtime permission. The guest runs as the app's uid with the app's access; -0 makes it believe it is root. It is a convenience boundary, not a security one: anything in it can read and write everything the app can.
    • Package names and repository fields are validated and shell-quoted; a repository key must be an OpenPGP public key fetched over HTTPS.
    • targetSdk 28 is a deliberate reduction in platform hardening (§2).

    10. Known limitations¶

    • PRoot's cost. Every syscall detours through the tracer; builds run slower than natively, and seccomp acceleration depends on the device's kernel.
    • No /dev/stdin|stdout|stderr on Android inside the guest (§2) — use /dev/fd/0..2.
    • Phantom-process limits (Android 12+) can kill large background process trees; on Android 14 it can be relaxed in Developer options ("Disable child process restrictions") or with adb shell settings put global settings_enable_monitor_phantom_procs false.
    • No GPU acceleration in the guest: Xvfb renders in software.
