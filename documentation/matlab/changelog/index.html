    CHANGELOG¶

    Source

    This page is rendered from MATLAB/CHANGELOG.md, the authoritative description kept next to the code in MATLAB/.

    All notable changes to the MATLAB tree will be documented in this file.

    [MATLAB] The four repositories in one Simulink model, October 31, 2026¶

    What's New¶

    simulink/system/ holds jetowl_system, one model of the whole project. Its device subsystems are JetOwl FC, Isaac ROS Jetson, JetOwl Vision, Remote UAV, the JetbotNanoOWL phone and the UAV plant. Its network subsystems are the Ethernet micro-ROS link, LoRa LR1121 and the phone's USB/WebSocket links. It also has a communication interface map and a 15 s scenario that uses every link.

    • jetowl_system_spec.py: the model, drawn as 14 Simulink-style diagrams plus the interface map. It writes jetowl_system_data.m (483 blocks, 670 lines, execution order).
    • jetowl_build_system_model.m: builds jetowl_system.slx (MATLAB Function wrappers with P as Parameter data, fixed-step single-tasking). Its dry run checks the plan in Octave.
    • jetowl_system_sim.m: runs the same graph without Simulink.
    • jetowl_system_params.m: TAKEOFF waits for three GNSS fixes.
    • New blocks in utilities/:
      • comm_net_link, comm_rx_age, comm_lora_time_on_air
      • comm_rflink_uplink_tx/_rx, comm_rflink_tlm_tx/_rx (RC/RCX/TLM frames)
      • guid_mission_stage, guid_mission_fc
      • vis_preview_mode_check, vis_preview_publisher, vis_preview_receiver
    • jetowl_sim_params: P.rflink, P.vis, P.phone, P.net (one-way delay per link from its physics: Ethernet stack + wire time, LoRa time on air), P.traj.t_hold, P.eskf.yaw_sigma.

    • test_system_model_suite (8 groups) checks every link against the number it must produce:

      • message counts;
      • measured delays = P.net;
      • 25 uplink frames lost in the 0.5 s outage;
      • the mission chain to WAYPOINT_FOLLOW;
      • preview accepted at 7.45 Hz, rgb8 rejected (−2);
      • FAILSAFE 88 ms after the outage starts;
      • route NONE 1.4 s after the unplug;
      • vertical tracking 0.048 m.

      test_utilities_blocks_suite gains a "system links" group.

    Known Limitations¶

    • The .slx is built by the script in MATLAB. It is not stored, and it was not built in CI (Octave runs the same graph).
    • The USB, WebSocket and Ethernet stack latencies are placeholders until measured.
    • est_baro_height takes its reference from the first pressure sample, so its noise becomes a constant height bias. The baro NIS mean is 1.9, outside its 99 % band once the LiDAR is in use.

    Issues Addressed¶

    • comm_net_link: between arrivals, the held output returned the packet 63 ticks old instead of the newest one. The Jetson ESKF read stale IMU samples, so the horizontal NEES was 12 for 2 dof. It is now consistent (≥ 95 % of the samples inside 99.7 %).
    • Jetson Control in the system model: the MPC's horizontal acceleration is applied only once the estimate is clear of the ground (ẑ > 3σ_z). On the ground, a tilted setpoint made the FC's ESO wind up against the contact (f̂ ≈ −35), and the torque-priority mixer starved the collective thrust, which delayed lift-off by 1.2 s.

    [MATLAB] Simulink-style block diagrams, October 31, 2026¶

    What's New¶

    The mermaid flowcharts of utilities/README.md are replaced by 13 block diagrams drawn the way Simulink draws a model: MATLAB Function blocks with their argument names as ports, Parameter data listed under each block, the Unit Delay of every block state, Rate Transitions, Mux/Selector, Inport/Outport and sample-time colours.

    • utilities/diagrams/make_block_diagrams.py (with simulink_svg.py): reads the ports from the .m files and refuses a diagram with an input left open or driven twice. It produces the UAV top level and its six subsystems, the inside of ctrl_rate_loop, the camera AE/AWB loops and the inside of vis_ae_awb, the camera-arm gaze loop, the JetBot drive loop and the FOC loop.
    • The wiring is the one simulink/sil runs. Unit Delays mark where a block reads the previous tick's output, which Simulink would otherwise report as an algebraic loop.

    [MATLAB] MATLAB Function blocks of the whole project, October 30, 2026¶

    What's New¶

    MATLAB/utilities is rebuilt as a library of Simulink MATLAB Function blocks ported from the four repositories, with flowcharts that wire them (utilities/README.md) and closed-loop SIL scripts that execute those flowcharts (simulink/sil/).

    • utilities/ — 75 blocks in 12 folders (plus config/), each with its source file, derivation and reference:
      • plant/: quad-X 6-DOF rigid body with rotor drag (RK4), ESC + rotor first order + delay, PMSM dq model, hobby servos, camera exposure with pipeline delays, JetBot diff drive
      • sensors/, filters/: IMU, baro (ICAO), GNSS (HDOP·σ_UERE), MT6835, LiDAR, pinhole bearing, wheel encoders; first-order low-pass in three discretisations, biquad, median, Hampel, guard
      • estimation/: Mahony, dual-IMU Markley mean, ESO (exact ZOH), 15-state ESKF (GNSS, baro, LiDAR, heading, χ² gates), dual GNSS consistency test + covariance intersection, CWNA odometry filter, bearing KF with delayed measurements, diff-drive EKF, α–β
      • control/, allocation/: complete PID, ESO rate loop with achieved-torque feedback, quaternion attitude law, 2-DOF rotor speed (FF inverse + SIMC), FOC with decoupling, condensed MPC (FISTA, DOB, design fitted to the FC inner loop), thrust/attitude map, 2-DOF position, SIMC velocity PI, DLS, quad-X torque-priority mixer
      • guidance/, safety/, comms/, vision/: min-jerk, cmd_guard failsafe, RC ANGLE mode, flight-mode FSM, command arbiter, servo rules R1–R8, UDP channel, link quality, AE/AWB log-domain loop, exposure allocation, ISP gain encoding, preview decimation
      • config/jetowl_sim_params.m: every parameter with the line it comes from, or its design rule
      • Stateful blocks carry their state through a Unit Delay (no hidden persistent), so several instances are independent
    • utilities/ros2_interface/: the 34 ROS 2 monitor helpers, moved from utilities/ros2/ into messages/ state/ geometry/ mapping/ views/ (logic unchanged); jetowl_utilities_path adds every folder. The monitor scripts and Simulink monitor blocks use it.
    • Tests (Octave 8.4): test_utilities_blocks_suite (20 groups), test_sil_closed_loop_suite (7 groups), test_vision_ros_suite rewritten; test_runner_all runs the five suites.

    Performance Improvements¶

    • UAV SIL, 1 m climb + 2 m transit, no noise: overshoot 21 %, final error 0.095 m
    • UAV SIL with sensor noise: vertical error ≤ 0.03 m, horizontal ≤ 1.5 m (1 Hz GNSS, σ 0.76 m), NIS means GNSS 2.62 (3 dof), baro 1.00, LiDAR 1.14
    • Link outage 1.5 s at hover: bounded descent 0.50 m (model 0.49 m), recovery to 1.49 m
    • Camera AE re-converges 10 frames after a ×4 scene step; gaze loop error 3 mrad; FOC i_q τ = 1/ω_ci

    Breaking Changes¶

    • utilities/estimation, utilities/navigation, utilities/visualization removed (Kalman_Calibration, IMU_Encoder_Position_Estimator, filterDetections, WaypointFollower, Orbit_Follower, Obstacle_Avoidance, Position_3D_Visualizer, launchUnrealVisualization, lidar_visualization)
      • Migration: estimation → est_*, navigation → guid_* + ctrl_linear_mpc, 3-D views → utilities/ros2_interface/views
    • utilities/ros2/ → utilities/ros2_interface/<group>/; call jetowl_utilities_path()
    • test_sensor_fusion_suite, test_navigation_suite removed (they tested the removed functions)

    Known Limitations¶

    • The .slx models were not rebuilt; blocks, parameters and wiring are delivered as files, flowcharts and SIL scripts. Tested in GNU Octave, not in MATLAB/Simulink.
    • Rotor, wheel-motor and servo models use the source repositories' placeholder values.
    • Findings of the SIL (details in utilities/README.md §8): the FC rate PID gains realise the designed crossover only when scaled by b₀; the FC ATT_FILTER_WN = 1 rad/s is too high for the Jetson outer loop (ω_n ≤ 0.089 rad/s used); the failsafe weight estimate assumes a balanced last command.

    [MATLAB] Simulink blocks and SLAM view, October 2, 2026¶

    What's New¶

    Simulink models built only from MATLAB Function blocks, plus a SLAM view that updates in real time. See simulink/README.md.

    • simulink/blocks/: 31 .m files, one per MATLAB Function block. Each block's code is a single call. Fixed-size signals come from jetowl_blk_sizes.
      • Sources: clock, and 18 ROS 2 sources (odometry, IMU, GNSS, baro, setpoints, thrust, rpm, range, SLAM pose / debug / map / path, scan, markers, ground truth, mission). They read through coder.extrinsic.
      • Processing (%#codegen): GNSS → ENU on the ESKF datum, barometric height, scan → map points, 95 % ellipse (closed-form 2×2 eigen-decomposition), obstacles → odom, SLAM NIS consistency window, map areas.
      • Sinks: real-time flight view and SLAM view. Commands: command step and an edge-triggered flight/nav_command publisher, which sends on a live source only.
    • simulink/runtime/jetowl_sl_bridge.m: data source for the blocks.
      • Live ROS 2 (JetOwlRos2Session), ros2 bag, demo, or any history state.
      • Reproducible playback that maps model time to data time.
      • Per-topic read pointers and a cached grid fit.
    • simulink/runtime/jetowl_sl_scope.m: ring-buffer history. Redraws at redraw_hz (10 Hz) of model time and reuses the figures of jetowl_ros2_viz.
    • simulink/jetowl_build_monitor_model.m: builds jetowl_ros2_monitor.slx from jetowl_monitor_wiring with 25 MATLAB Function blocks and nothing else.
      • Fixed-step 0.05 s, real-time pacing.
      • InitFcn / StopFcn open and close the source.
      • dry_run returns the generated block code.
    • simulink/jetowl_monitor_sil.m: runs the same block graph in a fixed-step loop without Simulink (MATLAB or Octave), optionally paced to wall time.
    • SLAM view (utilities/ros2/jetowl_slam_view_*, jetowl_slam_data):
      • Map, keyframes, pose with 95 % ellipse and ±2σ yaw, scan, ICP vs prior.
      • NIS per scan with the window mean, exact 95 % χ² bounds and the 0.99 gate; consistency verdict.
      • Innovations ±2√S, ICP quality, eigenvalues / degeneracy, pose σ, processing time, EKF v, ω, b_g, map areas.
    • scripts/ros2/jetowl_ros2_viz.m: views option (dashboard, slam). Live, bag and demo redraw both views from one snapshot.
    • New math, each with its source in the header:
      • jetowl_chi2_quantile: exact, by bisection on gammainc (A&S 26.4.19).
      • jetowl_nis_bounds: Bar-Shalom §5.4.2.
      • jetowl_slam_window_stats, jetowl_grid_fit (max-pool), jetowl_map_stats (Nav2 thresholds).
    • jetowl_viz_update is split into jetowl_viz_data (numbers) and jetowl_viz_draw (graphics). Simulink and ROS feed the same renderer.
    • Catalog: /slam/debug (29 fields) added. /slam/pose rows now carry the yaw variance.
    • Demo: /slam/debug with χ²(3)-distributed NIS (Park–Miller + Box–Muller, deterministic), ICP rejection and degeneracy windows, and a map that grows as it is explored.
    • test/tests/test_simulink_blocks_suite.m: 9 groups. Covers the χ² / NIS references, grid fit, every block against its MATLAB counterpart, the bridge, the wiring, the builder's generated code (executed), the block graph against direct computation, and the headless views. Octave shims for coder.extrinsic / coder.const live in test/shims/ (Octave only).

    Known Limitations¶

    • ROS I/O and graphics run through coder.extrinsic: use the Normal or Accelerator simulation mode. They do not work in Rapid Accelerator or embedded code.
    • The .slx builder needs Simulink. Here it was verified through its dry_run output and jetowl_monitor_sil, not by opening Simulink.

    [MATLAB] October 2, 2026¶

    What's New¶

    ROS 2 toolkit for reading, subscribing to and publishing JetOwl topics, with a 3-D / 2-D dashboard. See the README section "ROS 2 toolkit".

    • scripts/ros2/jetowl_ros2_viz.m: one entry point with three modes.
      • demo: a synthetic flight; needs no ROS.
      • live: joins ROS_DOMAIN_ID and redraws on a 5 Hz timer.
      • bag: replays a ros2 bag at a chosen speed.
    • scripts/ros2/JetOwlRos2Session.m: graph session.
      • list_topics and subscribe, with per-topic QoS (transient-local for /map, /slam/path, /mission/preview).
      • Ring-buffer history and snapshot.
      • publish_nav_command and publish_waypoints (flight/waypoints, PoseArray).
      • Generic publish, which refuses actuator topics unless AllowActuatorTopics is set.
    • scripts/ros2/jetowl_bag_load.m: loads a ros2 bag into the same history state.
    • utilities/ros2/: pure, source-cited functions.
      • Quaternion / Euler / rotation matrix.
      • WGS-84 → ENU, ISA barometric altitude.
      • LaserScan → points, OccupancyGrid geometry.
      • χ² covariance ellipse, marker bounding spheres.
      • Topic catalog and message decoders (REP-103/105/117/145).
      • Dashboard: 3-D, 2-D, altitude, position, attitude, RPM.
    • test/tests/test_ros2_viz_suite.m: 11 test groups, also in test_runner_all. They pass in GNU Octave 8.4, headless dashboard included.

    Bug Fixes¶

    • scripts/ros_interface/Connect_ROS2_Humble.m: joins the ROS 2 graph with ros2node on ROS_DOMAIN_ID (the ROS 1 rosinit / ROS_MASTER_URI had no effect on ROS 2), reads the topics ros2_lidar_slam really publishes (/scan LaserScan, /range Range instead of /ld19_scan, /lpb40b_scan), gates LD19 beams to 0.3–12 m before lidarSLAM, and no longer feeds the single-point LPB40B rangefinder to a 2-D SLAM
