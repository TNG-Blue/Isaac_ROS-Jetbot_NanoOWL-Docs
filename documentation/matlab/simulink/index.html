    JetOwl Simulink blocks (MATLAB Function blocks only)¶

    Source

    This page is rendered from MATLAB/simulink/README.md, the authoritative description kept next to the code in MATLAB/simulink/.

    Every block of the JetOwl ROS 2 monitor is a MATLAB Function block whose code is one call of a .m file in blocks/. To build a model you place MATLAB Function blocks and connect them. No other Simulink library block is needed: no ROS Toolbox Subscribe block, no Scope, no Clock.

                    ┌──────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
 jetowl_blk_    │ clock        │──►│ 15 ROS 2 sources     │──►│ 7 processing blocks  │──► 2 views
 clock ─────────┘ t = k·Ts     │   │ /odometry/filtered … │   │ ENU, baro, scan,     │   flight
                               │   │ /map /slam/* /scan   │   │ ellipse, NIS window, │   SLAM
                               │   └──────────────────────┘   │ obstacles, map area  │
                               │                              └──────────────────────┘

    Quick start¶

    addpath('MATLAB/simulink');  jetowl_sl_setup_path();
jetowl_build_monitor_model();                                    % demo source, no ROS needed
sim('jetowl_ros2_monitor');                                      % two figures update in real time

jetowl_build_monitor_model(struct('source', 'live', 'arg', 0));  % robot, ROS_DOMAIN_ID = 0
jetowl_build_monitor_model(struct('source', 'bag', 'arg', 'rosbag2_2026_10_02'));

    Without Simulink (base MATLAB or GNU Octave), the same block graph runs in a fixed-step loop:

    out = jetowl_monitor_sil(struct('source', 'demo', 'duration', 30));
out = jetowl_monitor_sil(struct('source', 'live', 'arg', 0, 'duration', 600));   % paced

    Assembling a block by hand¶

    1. Add a MATLAB Function block (Simulink › User-Defined Functions).
    2. Replace its code with the call given in the header of the .m file, for example:
    function [odo, n] = fcn(t)
[odo, n] = jetowl_blk_sub_odometry(t);
    1. Connect the ports by name: they are the argument names of the function. Keep the fixed-step discrete solver with every block on an inherited sample time, and run jetowl_sl_setup_path() plus jetowl_sl_bridge('open', …) in the model InitFcn.

    jetowl_monitor_wiring.m is the complete wiring of the reference model. The builder and the Simulink-free runner both read it.

    Block reference¶

    Sizes come from blocks/jetowl_blk_sizes.m: NSCAN = 1024, GMAX = 512, NPATH = 2000, NTRAJ = 128, NOBS = 32, NELL = 65. Variable-length messages are NaN-padded (−1 for the grid) to these sizes and carry their valid count.

    Sources (ROS 2 → signals)¶

    Each source returns the newest sample with time ≤ t (zero-order hold) and n, the number of messages received so far. A change of n means a new sample.

    Block Topic Outputs
    jetowl_blk_clock(Ts) — t = k·Ts
    jetowl_blk_sub_odometry /odometry/filtered odo [1×12] p, v_world, rpy, Pxx Pxy Pyy
    jetowl_blk_sub_ground_truth /hexa/ground_truth/odometry gt [1×12]
    jetowl_blk_sub_imu /imu/data imu [1×9] rpy, ω, a
    jetowl_blk_sub_gnss /gps/fix lla [1×3]

    Processing (pure maths, %#codegen, no ROS)¶

    Block Computes Source of the formula
    jetowl_blk_gnss_enu(lla, n) WGS-84 → ENU about the mean of the first 10 fixes (ESKF datum) NIMA TR8350.2; Groves eq. 2.150
    jetowl_blk_baro_height(p, n, odo) h = 44330.77·(1 − (p/p0)^0.190263) + z_ESKF(first sample) ICAO Doc 7488
    jetowl_blk_scan_points(r, meta, pose) beams gated by REP-117, sensor → base (mount) → map (SLAM pose) REP-117; Siciliano §2.7
    jetowl_blk_cov_ellipse(pose) 95 % ellipse, k² = −2 ln 0.05, closed-form 2×2 eigen-decomposition Bar-Shalom §1.4.17; Strang §6.4
    jetowl_blk_obstacles_world(obs, no, odo) base_link markers → odom: p + R(rpy)·c Siciliano §2.7; same as the MPC
    jetowl_blk_slam_consistency(dbg, n) NIS mean over the last 50 accepted updates, exact 95 % χ² bounds, ICP acceptance, degenerate share, worst time Bar-Shalom §5.4.2
    jetowl_blk_map_stats(G, meta, n) explored / occupied / free area (Nav2 trinary thresholds) Nav2 map_server

    Views (sinks) and commands¶

    Block Shows
    jetowl_blk_view_flight(t, odo, gt, imu, rpy_sp, enu, h_baro, rpm, P_sp, P_pred, W) 3-D trail, axes, GNSS, setpoint, MPC path, obstacles; 2-D SLAM panel; position, altitude (ESKF / baro / GNSS), attitude vs setpoint, rpm
    jetowl_blk_view_slam(t, G, meta, n_map, pose, n_pose, P_path, pts, ell, dbg, n_dbg, cons, ms) map, keyframes, pose with 95 % ellipse and ±2σ yaw, scan, ICP vs prior; NIS with window mean, bounds and gate; innovations ±2√S; ICP quality; eigenvalues and degeneracy; σ; processing time vs 100 ms; EKF v, ω, b_g; statistics panel with the NIS verdict
    jetowl_blk_command_step(t, t_on, cmd_id) 0 before t_on, cmd_id after
    jetowl_blk_pub_nav_command(cmd) publishes flight/nav_command once per change; only on a live source

    The views are the figures of jetowl_ros2_viz (jetowl_viz_draw, jetowl_slam_view_draw), fed with the same data structs. A model, a bag replay and a live MATLAB session therefore show identical plots.

    Real time¶

    • Model time = wall time. The builder turns on simulation pacing (rate 1). The scope redraws every 1/redraw_hz (default 10 Hz) of model time and keeps every sample in ring buffers (12 000 samples = 10 min at 20 Hz).
    • Live data. The bridge reads the newest message of each topic once per step from JetOwlRos2Session. Playback of a bag or the demo maps model time to data time (t_data = t0 + t), so a run is reproducible.
    • Execution modes. ROS I/O and graphics run in MATLAB through coder.extrinsic. Use the Normal or Accelerator simulation mode. Rapid Accelerator and embedded code generation cannot call MATLAB, and the processing blocks are the only part that would generate standalone code.

    Safety¶

    The blocks only read, except jetowl_blk_pub_nav_command. That block sends a navigation command name from JetOwlRos2Session.NAV_COMMANDS to flight_controller_node. The controller checks the command against its state machine and keeps its own closed loop, watchdog and failsafe. No block writes an actuator topic (/control/*, /cmd_vel, /hexa/*). The reference model contains no command block.

    Verification¶

    MATLAB/test/tests/test_simulink_blocks_suite.m (9 groups) checks the following, in MATLAB or GNU Octave without Simulink:

    • the chi-square quantile against its CDF and against the closed form for 2 degrees of freedom;
    • the NIS bounds against the Wilson–Hilferty bounds of lidar_slam_node (< 1 %);
    • the grid fit against a direct max-pool, including that occupied cells stay occupied;
    • every processing block against the MATLAB function it mirrors;
    • the bridge cursor, padding, decimation and publish gate;
    • the wiring (order, ports, nargin / nargout);
    • the code the builder writes into each block, executed and compared with direct calls;
    • a run of the block graph against the dashboard and SLAM data computed from the same history.

    jetowl_build_monitor_model itself needs Simulink. Its dry_run output, meaning every block body and every line, is what the test executes.

    cd MATLAB/test/tests && octave --eval "test_simulink_blocks_suite()"
