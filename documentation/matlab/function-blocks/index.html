    MATLAB/utilities — MATLAB Function blocks of the whole project¶

    Source

    This page is rendered from MATLAB/utilities/README.md, the authoritative description kept next to the code in MATLAB/utilities/.

    Every .m file in these folders is one Simulink MATLAB Function block. Together they model the four repositories as one closed-loop system:

    Repository What is modelled here
    JetOwl_FlightControl (STM32N657 FC) IMU → Mahony → dual-IMU fusion, ESO + rate PID, quad-X mixer, quaternion attitude law, 2-DOF rotor speed control, MT6835 encoders, cmd_guard failsafe, link quality, RC input, dual GNSS + covariance intersection, FOC
    Isaac_ROS-Jetbot_NanoOWL (Jetson, this repo) 15-state ESKF, odometry CWNA filter, condensed MPC with disturbance observer, thrust/attitude map, 2-DOF position controller, min-jerk trajectory, flight-mode FSM, camera-arm gaze loop (bearing KF, SIMC PI, DLS, servo safety)
    JetOwl_Vision (STM32N657 camera) AE/AWB log-domain delayed Kalman loop, exposure/gain allocation, ISP gain encoding, preview decimation
    JetbotNanoOWL (phone/desktop app + JetBot) diff-drive kinematics and EKF, industrial PID, α–β tracker, low-pass/biquad/median filters, command arbiter

    Each block cites the file it ports and the textbook or paper its equations come from (header of the .m file). Every number lives in config/jetowl_sim_params.m with the source line it was copied from, or the design rule it was derived with.

    2. Using a block in Simulink¶

    1. Parameters. Run jetowl_sim_params in Model Properties → Callbacks → InitFcn. It puts P (and prm_<group>) in the base workspace. In each MATLAB Function block declare the argument P as Scope: Parameter, non-tunable (Model Explorer).
    2. Block code is one call:
    function [y, S] = fcn(w_rot, f_ext, S0, P)
[y, S] = plant_multirotor_6dof(w_rot, f_ext, S0, P);
    1. State. Stateful blocks have no hidden persistent variables: the state S is an output that comes back as an input through a Unit Delay with initial condition 0. A state whose first element is 0 means "not initialised"; the block initialises itself on the first sample. Several instances of the same block (two IMUs, two GNSS receivers) are therefore independent, and the model can be reset by resetting the delays.
    2. Rates. Give each block the sample time of the table below and put Rate Transition blocks (ZOH) between rates. The base rate is 1 kHz.
    Rate Blocks
    20 kHz ctrl_foc_current, plant_pmsm_dq (inside each ESC)
    1 kHz plant_* (UAV), sens_imu, sens_mt6835_encoder, est_attitude_mahony, est_imu_dual_fusion, est_encoder_speed, ctrl_rate_loop, ctrl_rotor_speed_2dof, comm_udp_channel, comm_link_quality, guid_cmd_guard
    250 Hz ctrl_attitude_quat
    200 Hz est_eskf_ins (IMU), LiDAR 100 Hz, baro 25 Hz, GNSS 1 Hz (sens_gnss → est_gnss_frontend → est_gnss_dual_ci)
    50 Hz guid_flight_mode, est_odometry_cwna, guid_reference_horizon, ctrl_linear_mpc, ctrl_thrust_attitude_map, camera arm (est_bearing_kf … plant_servo_axes), JetBot
    frame (30 Hz) plant_camera_exposure, vis_ae_awb, vis_preview_decimate

    The scripts in ../simulink/sil/ execute exactly these graphs in a loop (jetowl_sil_uav, jetowl_sil_subsystems), so the wiring below is tested without Simulink.

    8. Design notes found while building the model¶

    These came out of the closed-loop SIL runs and are stated in the parameter file:

    1. Rate PID gains. attitude_ctrl_rate_crossover() of the FC designs the rate loop as L = b₀·C(s)/s (crossover 15.78 rad/s), but after ESO compensation the PID drives a plant 1/s. The PID that realises the designed loop has gains b₀·RATE_PID_K; with the raw RATE_PID_K the loop crosses over at ≈ 0.16 rad/s, below the attitude gain K = 3.16 s⁻¹.
    2. Complementary-filter bandwidth. On a multirotor the accelerometer x/y channels measure rotor drag, not tilt (Martin & Salaün 2010; Leishman et al. 2014). With the FC default ATT_FILTER_WN = 1 rad/s the tilt estimate is pulled during horizontal acceleration right at the outer-loop crossover (1.26 rad/s): 85 % overshoot on a 2 m step in SIL. The bound ω_n ≤ 0.1·ω_c/(2ζ) (≤ 10 % leak) gives 0.089 rad/s and 21 % overshoot (13 % with an ideal attitude estimate).
    3. Delayed bearing measurements. The detection delay must enter the measurement matrix (H = [1, −λ]); plugging ω̂·λ in as a constant makes the filter inconsistent and the gaze loop diverges with 3 px noise.
    4. Failsafe weight estimate. guid_cmd_guard latches W = T cos θ of the last command. If the link drops during an aggressive manoeuvre W is too high and the "descent" climbs; the bound in the FC header (ε·g) assumes a balanced command.

    10. Limits of the model¶

    • The .slx files in simulink/ were not rebuilt; this folder provides the blocks, the parameters and the wiring (flowcharts + SIL scripts).
    • Rotor, wheel-motor and servo models use the identified or placeholder values of the source repositories (marked [placeholder] in jetowl_sim_params); they must be re-identified on the hardware.
    • guid_min_jerk implements the rest-to-rest (stop at every waypoint) case of the Jetson planner, guid_flight_mode the subset of modes used by a waypoint mission, and est_gnss_dual_ci the epoch-paired case (both receivers sampled together).
    • FC nav_dr.c (GNSS-free ESKF with rotor-drag model) is represented by est_eskf_ins with baro + LiDAR updates; the hexacopter (X12) Gazebo controller is not modelled here.
