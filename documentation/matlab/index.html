    Isaac ROS Jetbot NanoOWL¶

    Source

    This page is rendered from MATLAB/README.md, the authoritative description kept next to the code in MATLAB/.

    Simulation and data visualization framework for autonomous robotics using NVIDIA Isaac ROS, Jetbot platform, and NanoOWL vision model.

    Overview¶

    This project provides a comprehensive MATLAB/Simulink environment for simulating, testing, and analyzing autonomous robot behaviors. It integrates NVIDIA Isaac ROS framework with Jetbot hardware platform, utilizing the lightweight NanoOWL model for efficient object detection and navigation algorithms.

    MATLAB is used for:

    • Simulating robot dynamics and control algorithms
    • Rendering and visualizing sensor data (camera, IMU, encoders)
    • Analyzing experimental results and system performance
    • Prototyping computer vision and navigation algorithms
    • Hardware-in-the-loop testing before hardware deployment

    Requirements¶

    MathWorks Products¶

    • MATLAB R2021b or later
    • Simulink
    • Computer Vision Toolbox
    • Robotics System Toolbox
    • ROS Toolbox
    • Image Processing Toolbox (recommended)
    • Navigation Toolbox (recommended)

    3rd Party Products¶

    • Ubuntu 22.04 LTS (for hardware deployment, shipped by JetPack 6.2)
    • ROS 2 Humble
    • NVIDIA Isaac ROS packages
    • Python 3.10
    • CUDA Toolkit 12.6+ (for hardware deployment)

    Hardware Requirements (Optional - for deployment)¶

    • NVIDIA Jetson Orin Nano Super (8GB Developer Kit)
    • Jetbot chassis with differential drive
    • CSI/USB camera module
    • IMU sensor
    • USB-C PD power supply, 5V/5A (25W)

    Getting Started¶

    Installation¶

    1. Clone or download this repository to your local machine
    2. Open MATLAB and navigate to the project folder
    3. Open the project file: Isaac_ROS-Jetbot_NanoOWL.prj
    4. MATLAB will automatically configure paths and dependencies

    Quick Start¶

    Run the main example scripts located in the scripts/ folder or open Simulink models directly from the simulink/ folder.

    Key Features¶

    Robot Trajectory Simulation¶

    Simulate differential drive robot following predefined paths with realistic physics and sensor models.

    Sensor Data Visualization¶

    Load and visualize recorded sensor data including camera frames, IMU readings, and wheel encoder measurements.

    Vision Pipeline Testing¶

    Test object detection pipeline with NanoOWL model integration for real-time performance analysis.

    Simulink Model Execution¶

    Run comprehensive Simulink models for robot dynamics, sensor fusion, and navigation control.

    ROS 2 toolkit: read, subscribe, publish, 3-D / 2-D view¶

    scripts/ros2/ and utilities/ros2/ connect MATLAB to the JetOwl ROS 2 graph (Humble). With them you can list topics, subscribe to them, record into ring buffers, and send navigation commands. The data is drawn on one dashboard with 3-D and 2-D views plus time series.

    addpath('scripts/ros2');
jetowl_ros2_viz();                                   % demo: synthetic flight, no ROS needed
[h, s] = jetowl_ros2_viz('live', 0);                 % ROS_DOMAIN_ID = 0
s.list_topics()                                      % topic list of the graph
s.publish_nav_command('HOVER');                      % flight/nav_command (std_msgs/String)
s.publish_waypoints([0 0 3; 10 0 3; 10 10 3]);       % flight/waypoints (PoseArray, frame odom)
jetowl_ros2_viz('bag', 'rosbag2_2026_10_02', struct('speed', 4));   % replay a ros2 bag
jetowl_ros2_viz('live', 0, struct('views', {{'slam'}}, 'rate_hz', 10));  % SLAM view only

    Two figures update in real time from the same history snapshot: the flight dashboard and the SLAM view (opts.views, default both).

    Panel Content Topics
    3-D (odom, ENU) ESKF trail, body axes, ground truth, GNSS, setpoint, MPC path, mission, obstacles (bounding spheres), map, scan /odometry/filtered, /hexa/ground_truth/odometry, /gps/fix, /flight/setpoint, /control/predicted_path, /mission/preview, /tracked/markers, /map, /scan
    2-D (top view) Occupancy grid, SLAM path, LiDAR points, pose, 95 % position ellipse /map, /slam/path, /slam/pose, /scan
    Altitude ESKF z, barometric height, GNSS height /odometry/filtered, /baro/pressure, /gps/fix
    Position / attitude / RPM x y z, roll pitch yaw vs. attitude setpoint, rotor speeds /odometry/filtered, /imu/data, /control/attitude_setpoint, /jetowl/motor_rpm

    SLAM view (jetowl_slam_view_create / jetowl_slam_data / jetowl_slam_view_draw), from /map, /slam/pose, /slam/path, /slam/debug and /scan:

    Panel Content
    Map occupancy grid (unknown cells not drawn), keyframes, pose with 95 % ellipse and ±2σ yaw wedge, scan in the map frame, newest ICP measurement vs EKF prior
    NIS per scan (accepted / rejected), mean over the last 50 accepted updates, exact 95 % bounds of that mean, gate χ²₃(0.99) = 11.34; verdict CONSISTENT / NOT CONSISTENT
    Innovation ν_x, ν_y, ν_yaw with ±2√S_ii
    ICP inlier ratio, reduced χ², rejected scans; eigenvalues of the scaled information H' (log) with the degeneracy flag
    Health pose σ (x, y, yaw), processing time per scan vs the 100 ms scan period, EKF v, ω, gyro bias
    Statistics the numbers above plus explored / occupied / free area of the map (Nav2 thresholds)

    The topic list, with types and QoS, lives in utilities/ros2/jetowl_topic_catalog.m.

    QoS. Subscriptions are best-effort, which matches any publisher. The exceptions are the latched topics (/map, /slam/path, /mission/preview). These are subscribed reliable + transient-local, so the last sample is delivered on connection.

    Safety gate. JetOwlRos2Session.publish refuses actuator topics (/control/*, /cmd_vel*, /hexa/*, /jetowl/arm*) unless AllowActuatorTopics = true is set explicitly. From MATLAB the normal path is a navigation command or waypoints. These go through ros2_flight_controller, which keeps its own closed loop, watchdog and failsafe.

    Mathematics (each function cites its source in its header):

    Function Formula Source
    jetowl_quat_to_rotm, jetowl_quat_to_euler, jetowl_euler_to_rotm Hamilton quaternion → R; ZYX Euler, R = Rz(ψ)·Ry(θ)·Rx(φ) Kuipers, Quaternions and Rotation Sequences §5.14, §7.8; REP-103
    jetowl_decode_msg (odometry) v_world = R(q)·v_child (twist is in the child frame) REP-105, nav_msgs/Odometry
    jetowl_geodetic_to_enu WGS-84 geodetic → ECEF → ENU NIMA TR8350.2; Groves eq. 2.112, 2.150
    jetowl_baro_altitude h = 44330.77·(1 − (p/p0)^0.190263) ICAO Doc 7488 (ISA), the same constants as the ESKF
    jetowl_scan_to_points θ_i = θ_min + i·Δθ; Inf/NaN or out-of-limit ranges dropped REP-117; planar rigid transform, Siciliano et al. §2.7
    jetowl_grid_geometry Row-major OccupancyGrid, origin rotated by its yaw nav_msgs/OccupancyGrid
    jetowl_cov_ellipse k² = −2·ln(1 − p) (χ² quantile, 2 dof), eigen-decomposition of P Bar-Shalom, Li & Kirubarajan §1.4.17, §3.7
    jetowl_marker_radius Bounding sphere for a box, cylinder or sphere Same as ros2_control_system obstacle_geometry.hpp
    jetowl_chi2_quantile Solves gammainc(x/2, n/2) = p by bisection (exact χ² quantile, no toolbox) Abramowitz & Stegun 26.4.19, 6.5.1
    jetowl_nis_bounds m·NIS_avg ~ χ²(m·k): bounds χ²_{mk}(0.025, 0.975)/m Bar-Shalom, Li & Kirubarajan §5.4.2
    jetowl_slam_window_stats NIS mean over the last 50 accepted EKF updates (the nis_window of the SLAM node), ICP acceptance, degenerate share as above; slam_params.yaml
    jetowl_grid_fit Map into a fixed N×N grid by integer max-pool (an occupied cell stays occupied) nav_msgs/OccupancyGrid
    jetowl_map_stats Explored / occupied (v ≥ 65) / free (v ≤ 25) area Nav2 map_server trinary thresholds

    The dashboard only shows data. It does not filter or estimate anything itself. The state it draws is the one the ESKF and SLAM already estimate on the Jetson, so the view is the robot's own closed loop, not a second copy of it.

    The demo (jetowl_viz_demo_state) is a synthetic coordinated-turn helix. It uses the bank angle φ = −atan(v·ω/g) and a hover RPM scale that is only illustrative. Its /slam/debug draws the innovation as ν = S^½·z, z ~ N(0, I₃), so the NIS is χ²(3) by construction, as for a consistent filter. It uses a deterministic Park–Miller + Box–Muller generator. The map is revealed within 12 m of the visited positions.

    Requirements. live and bag need ROS Toolbox (ROS 2). demo and the tests run in base MATLAB and in GNU Octave ≥ 8:

    cd test/tests && octave --eval "test_ros2_viz_suite()"         # 11 groups
cd test/tests && octave --eval "test_simulink_blocks_suite()"  # 9 groups

    Simulink: MATLAB Function blocks for ROS 2 monitoring¶

    simulink/blocks/ holds one .m file per MATLAB Function block. A model is built only from MATLAB Function blocks whose code is a single call such as [odo, n] = jetowl_blk_sub_odometry(t);. No other Simulink library block is needed.

    • 15 ROS 2 sources: odometry, IMU, GNSS, baro, setpoints, rpm, SLAM pose / debug / map / path, scan, markers, and more.
    • 7 processing blocks: GNSS → ENU, baro height, scan → map points, 95 % ellipse, obstacles → odom, SLAM NIS consistency, map area.
    • 2 real-time views: flight dashboard and SLAM view.
    addpath('simulink');  jetowl_sl_setup_path();
jetowl_build_monitor_model();                                   % builds jetowl_ros2_monitor.slx
sim('jetowl_ros2_monitor');                                     % demo source, real-time pacing
jetowl_build_monitor_model(struct('source', 'live', 'arg', 0)); % robot on ROS_DOMAIN_ID 0
out = jetowl_monitor_sil(struct('duration', 30));               % same graph without Simulink

    Block reference, ports, sizes and the real-time model settings: simulink/README.md.

    Simulink Models¶

    robot_dynamics.slx¶

    Simulates the kinematics and dynamics of a differential drive robot. Includes wheel encoders, motor models, and physics-based motion.

    Inputs:

    • Left wheel velocity command (rad/s)
    • Right wheel velocity command (rad/s)

    Outputs:

    • Robot pose (x, y, theta)
    • Wheel encoder ticks
    • Linear and angular velocities

    sensor_fusion.slx¶

    Fuses data from multiple sensors (camera, IMU, encoders) for robust state estimation.

    Features:

    • Extended Kalman Filter (EKF) for pose estimation
    • Complementary filter for IMU data
    • Outlier rejection and sensor validation

    vision_pipeline.slx¶

    Complete image processing pipeline from raw camera input to object detection.

    Pipeline stages:

    1. Image preprocessing (resize, normalize)
    2. Feature extraction
    3. Object detection (NanoOWL)
    4. Post-processing and tracking

    navigation_controller.slx¶

    Path planning and motion control for autonomous navigation.

    Components:

    • A* path planning algorithm
    • Pure pursuit controller
    • Obstacle avoidance
    • Dynamic replanning

    Data Analysis Utilities¶

    The project includes comprehensive utilities for loading experimental data, analyzing detection performance, calculating metrics (precision, recall, F1 score), plotting confusion matrices, and exporting data to ROS bag format.

    Testing¶

    Run all tests using MATLAB's testing framework. Individual test files are available in the test/ folder for specific components like kinematics, vision pipeline, and navigation.

    Hardware Deployment¶

    While MATLAB is primarily used for simulation, you can deploy algorithms to hardware using:

    1. Simulink Coder to generate C++ code from Simulink models
    2. ROS Toolbox to interface with Isaac ROS nodes
    3. GPU Coder to deploy to NVIDIA Jetson platforms

    The project supports ROS connection to real hardware for testing and validation.

    Configuration¶

    Configuration files are located in resources/config/ and include:

    robot_params.json - Robot physical parameters (wheel radius, track width, max velocity, acceleration limits)

    vision_config.json - Vision system settings (camera resolution, frame rate, detection thresholds)

    Troubleshooting¶

    Problem: Simulink models won't open

    • Ensure all required toolboxes are installed
    • Check MATLAB version compatibility (R2021b+)

    Problem: Cannot load trained models

    • Verify model files exist in resources/models/
    • Check Deep Learning Toolbox installation

    Problem: ROS connection fails

    • Verify ROS master IP address
    • Ensure network connectivity
    • Check firewall settings
