    📡 Communication Protocols¶

    1. ROS2 DDS (Primary)¶

    YAML
    Protocol: DDS (Data Distribution Service)
Implementation: FastDDS / CycloneDDS
Transport: UDP Multicast / TCP
Port Range: 7400-7500
QoS Profiles:
  - RELIABLE: Critical data (commands, state)
  - BEST_EFFORT: Sensor data (high frequency)
  - TRANSIENT_LOCAL: Configuration data

Configuration:
  Domain ID: 0-232 (configurable)
  Discovery: Multicast / Simple Discovery Protocol
  Security: DDS Security (optional)

    ROS2 DDS Configuration¶

    XML
    <!-- fastdds_profile.xml -->
<profiles>
    <transport_descriptors>
        <transport_descriptor>
            <transport_id>UDPv4</transport_id>
            <type>UDPv4</type>
            <maxMessageSize>65500</maxMessageSize>
            <sendBufferSize>1048576</sendBufferSize>
            <receiveBufferSize>1048576</receiveBufferSize>
        </transport_descriptor>
    </transport_descriptors>

    <participant profile_name="jetbot_participant">
        <rtps>
            <name>jetbot_robot</name>
            <builtin>
                <discovery_config>
                    <leaseDuration>
                        <sec>10</sec>
                    </leaseDuration>
                </discovery_config>
            </builtin>
            <userTransports>
                <transport_id>UDPv4</transport_id>
            </userTransports>
        </rtps>
    </participant>
</profiles>

    2. WiFi Network¶

    YAML
    Standard: IEEE 802.11ac (WiFi 5)
Frequency: 2.4GHz & 5GHz dual-band
Security: WPA3-Personal / WPA2-Enterprise
SSID: jetbot_nanoowl
IP Allocation: DHCP with static reservations

Access Point Settings:
  Channel: Auto (or fixed 36/149 for 5GHz)
  Bandwidth: 40MHz (2.4GHz), 80MHz (5GHz)
  Transmit Power: 20dBm
  Range: 50-100m (indoor), 200m+ (outdoor)

Performance:
  Throughput: 150-300 Mbps (actual)
  Latency: 5-15ms (local network)
  Concurrent Devices: 50+ (depends on AP)

    WiFi Configuration¶

    Bash
    # /etc/netplan/01-network.yaml
network:
  version: 2
  wifis:
    wlan0:
      dhcp4: no
      addresses:
        - 192.168.1.101/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]
      access-points:
        "jetbot_nanoowl":
          password: "your_password_here"
          auth:
            key-management: psk

    3. Ethernet¶

    YAML
    Standard: IEEE 802.3 Gigabit Ethernet
Speed: 1000 Mbps
Interface: eth0
IP: Static (192.168.1.101)
Gateway: 192.168.1.1
DNS: 8.8.8.8, 8.8.4.4

Use Cases:
  - High-bandwidth data transfer
  - Firmware updates
  - System configuration
  - Debugging and development
  - Real-time video streaming

    4. LoRa Communication¶

    YAML
    Frequency: 868 MHz (EU) / 915 MHz (US) / 923 MHz (AS)
Modulation: LoRa CSS (Chirp Spread Spectrum)
Bandwidth: 125 kHz / 250 kHz / 500 kHz
Spreading Factor: SF7-SF12 (configurable)
Coding Rate: 4/5, 4/6, 4/7, 4/8
Max Payload: 255 bytes per packet
Data Rate: 0.3 - 50 kbps (varies with SF)
Range: 1-10 km (urban), up to 20km (line of sight)

Use Cases:
  - Long-range telemetry
  - Emergency communications
  - Image transfer (low-res, compressed)
  - GPS coordinates broadcasting
  - Status updates

    LoRa Packet Structure¶

    Text Only
    ┌──────────────────────────────────────────────────┐
│ Preamble │ Header │ Payload │ CRC │
│  8 bytes │ 2 bytes│ 0-255 B │ 2 B │
└──────────────────────────────────────────────────┘

Header Format:
  - Device ID (1 byte)
  - Packet Type (1 byte)
    * 0x01: Telemetry
    * 0x02: Command
    * 0x03: Image Fragment
    * 0x04: ACK/NACK
    * 0x05: Heartbeat

Payload Examples:
  Telemetry:
    - GPS (lat, lon, alt)
    - Battery voltage
    - System status

  Image Transfer:
    - Fragment ID
    - Total fragments
    - Image data (200 bytes)
    - CRC16

    5. Cellular (Optional)¶

    YAML
    Standard: 4G LTE / 5G NR
Module: Quectel EC25 / Simcom SIM7600
Speed: 150 Mbps down, 50 Mbps up (LTE Cat 4)
Fallback: 3G HSPA+, 2G EDGE

Use Cases:
  - Internet access in remote areas
  - Cloud connectivity
  - Remote monitoring
  - OTA updates
  - Emergency communications

    🔒 Network Security¶

    Firewall Configuration¶

    Bash
    # iptables rules

# Allow established connections
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow loopback
iptables -A INPUT -i lo -j ACCEPT

# Allow SSH (from specific IPs only)
iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT

# Allow ROS2 DDS ports
iptables -A INPUT -p udp --dport 7400:7500 -s 192.168.1.0/24 -j ACCEPT

# Allow HTTP/HTTPS for API
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Allow MQTT
iptables -A INPUT -p tcp --dport 1883 -j ACCEPT
iptables -A INPUT -p tcp --dport 8883 -j ACCEPT

# Drop all other traffic
iptables -A INPUT -j DROP

    VPN Configuration¶

    YAML
    VPN Type: WireGuard
Purpose: Secure remote access
Configuration:
  Server: 10.0.0.1
  Client: 10.0.0.2 (Robot)
  Port: 51820
  Encryption: ChaCha20-Poly1305

Setup:
  - Generate keys (wg genkey)
  - Configure peers
  - Enable IP forwarding
  - Start WireGuard interface

  Cipher Suites:
    - TLS_AES_256_GCM_SHA384
    - TLS_CHACHA20_POLY1305_SHA256
  Certificate Validation: Enabled
  HSTS: Enabled (production)

    🔧 Network Optimization¶

    Quality of Service (QoS)¶

    YAML
    ROS2 QoS Profiles:
  Sensor Data:
    Reliability: BEST_EFFORT
    History: KEEP_LAST (depth: 5)
    Durability: VOLATILE
    Lifespan: 100ms

  Control Commands:
    Reliability: RELIABLE
    History: KEEP_LAST (depth: 10)
    Durability: TRANSIENT_LOCAL
    Lifespan: 1s
    Deadline: 100ms

  Configuration:
    Reliability: RELIABLE
    History: KEEP_ALL
    Durability: TRANSIENT_LOCAL
    Lifespan: INFINITE

    Bandwidth Management¶

    Bash
    # Traffic shaping with tc (traffic control)

# Create root qdisc
tc qdisc add dev wlan0 root handle 1: htb default 30

# Add classes with bandwidth limits
tc class add dev wlan0 parent 1: classid 1:1 htb rate 100mbit

# High priority: Control commands (30% bandwidth)
tc class add dev wlan0 parent 1:1 classid 1:10 htb rate 30mbit ceil 50mbit prio 1

# Medium priority: Sensor data (50% bandwidth)
tc class add dev wlan0 parent 1:1 classid 1:20 htb rate 50mbit ceil 80mbit prio 2

# Low priority: Other traffic (20% bandwidth)
tc class add dev wlan0 parent 1:1 classid 1:30 htb rate 20mbit ceil 100mbit prio 3

# Add filters to classify traffic
tc filter add dev wlan0 protocol ip parent 1:0 prio 1 u32 \
  match ip dport 7400 0xffff flowid 1:10  # ROS2 control
tc filter add dev wlan0 protocol ip parent 1:0 prio 2 u32 \
  match ip dport 7420 0xffff flowid 1:20  # ROS2 sensors

    Fleet Management¶

    YAML
    Architecture: Star topology with mesh backup
Primary: WiFi through central router
Backup: LoRa peer-to-peer mesh

Coordination:
  - Shared ROS2 domain (domain_id=42)
  - Distributed parameter server
  - Synchronized time (NTP/PTP)
  - Cooperative SLAM
  - Task allocation protocol

Network Namespace: ros_fleet
Topics:
  - /fleet/robots/status
  - /fleet/tasks/allocation
  - /fleet/map/shared
  - /fleet/coordination/commands

    🛠️ Troubleshooting¶

    Common Issues¶

    Issue Symptoms Solution
    High Latency Delayed responses Check WiFi interference, optimize QoS
    Packet Loss Missing data Improve signal strength, reduce bandwidth
    Connection Drops Intermittent disconnects Check AP capacity, update firmware
    Slow Transfer Low throughput Check channel congestion, use 5GHz
    LoRa Timeout No response Increase timeout, check antenna
