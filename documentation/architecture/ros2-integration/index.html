    ROS2 Integration Strategy¶

    How ROS2 is integrated into the Isaac ROS Jetbot NanoOWL platform.

    🤖 ROS2 Fundamentals¶

    ROS2 Humble Hawksbill¶

    YAML
    Version: Humble Hawksbill
Release: May 2023
Support Duration: May 2028 (5 years)
License: Apache 2.0

    Why ROS2? - ✅ Production-ready middleware - ✅ Better real-time capabilities than ROS1 - ✅ DDS-based communications - ✅ Active community support - ✅ Multiple language support (C++, Python)

    Message Design Pattern¶

    Python
    # Good: Specific, documented messages
msg ObjectDetection
  builtin_interfaces/Time timestamp
  string[] class_names
  float32[] confidences
  BoundingBox[] bboxes
  geometry_msgs/Point[] positions

# Avoid: Generic messages (too flexible)
msg GenericData
  string data
  float64[] values

    📨 Message Flow Examples¶

    Real-time Detection Pipeline¶

    sequenceDiagram
    participant Camera as 📷 Camera
    participant CamNode as Camera Node
    participant DetNode as Detection Node
    participant ControlNode as Control Node
    participant Motor as ⚙️ Motor

    Camera->>CamNode: Raw frame @ 30Hz
    CamNode->>CamNode: encode to ROS msg
    CamNode->>DetNode: publish /camera/image_raw

    DetNode->>DetNode: receive image
    DetNode->>DetNode: GPU inference
    DetNode->>ControlNode: publish /detection/objects

    ControlNode->>ControlNode: process detections
    ControlNode->>Motor: publish /cmd_vel
    Motor->>Motor: apply commands

    Latency Budget:

    Text Only
    Camera capture:     33ms (30 FPS)
Message publish:     1ms
Detection inference:15ms
Message transport:   2ms
Control processing:  3ms
Motor command:       1ms
─────────────────────────
Total:             ~55ms

    ⚙️ Parameter Management¶

    Parameter Server¶

    YAML
    # ROS2 Parameter Tree
jetbot:
  detection:
    confidence_threshold: 0.5
    nms_threshold: 0.4
    model_path: "/models/yolov8.trt"

  control:
    linear_speed_max: 1.0      # m/s
    angular_speed_max: 2.0     # rad/s
    pid:
      kp: 1.0
      ki: 0.1
      kd: 0.05

  hardware:
    camera_resolution: [640, 480]
    camera_fps: 30
    lidar_enabled: true

    Parameter Service Usage¶

    C++
    // C++ Example
auto param_client = std::make_shared<rclcpp::SyncParametersClient>(node);

// Get parameter
auto confidence = param_client->get_parameter("detection.confidence_threshold");

// Set parameter
param_client->set_parameter(
    rclcpp::Parameter("detection.confidence_threshold", 0.6)
);

// List all parameters
auto params = param_client->get_parameters(
    {"detection.model_path", "control.linear_speed_max"}
);

    🏃 Lifecycle Management¶

    Node Lifecycle States¶

    stateDiagram-v2
    [*] --> Unconfigured: Create
    Unconfigured --> Inactive: Configure
    Inactive --> Active: Activate
    Active --> Inactive: Deactivate
    Inactive --> Unconfigured: Cleanup
    Unconfigured --> [*]: Destroy

    Lifecycle Transitions¶

    Transition Purpose Actions
    Configure Initialize resources Load params, allocate memory
    Activate Start processing Begin subscription, timers
    Deactivate Stop processing Stop subscriptions, pause
    Cleanup Release resources Free memory, close files

    Implementation Example¶

    C++
    class DetectionNode : public rclcpp_lifecycle::LifecycleNode {
public:
  DetectionNode() : LifecycleNode("detection_node") {}

private:
  rclcpp_lifecycle::node_interfaces::LifecycleNodeInterface::CallbackReturn
  on_configure(const rclcpp_lifecycle::State & state) {
    // Load model, allocate GPU memory
    RCLCPP_INFO(this->get_logger(), "Configuring...");
    return LifecycleNodeInterface::CallbackReturn::SUCCESS;
  }

  rclcpp_lifecycle::node_interfaces::LifecycleNodeInterface::CallbackReturn
  on_activate(const rclcpp_lifecycle::State & state) {
    // Start subscriptions, create timers
    RCLCPP_INFO(this->get_logger(), "Activating...");
    return LifecycleNodeInterface::CallbackReturn::SUCCESS;
  }
};

    Monitoring Subscription¶

    C++
    // Subscribe to diagnostics
auto diagnostics_sub = create_subscription<diagnostic_msgs::DiagnosticArray>(
    "/diagnostics",
    10,
    [this](const diagnostic_msgs::DiagnosticArray::SharedPtr msg) {
        for (const auto & status : msg->status) {
            RCLCPP_DEBUG(
                this->get_logger(),
                "Diagnostic [%s]: %d", 
                status.name.c_str(),
                status.level
            );
        }
    }
);

    🚀 Best Practices¶

    1. Node Design¶

    C++
    ✅ Single responsibility principle
✅ Clear naming conventions
✅ Parameter-driven configuration
✅ Proper lifecycle management
✅ Error handling & recovery

❌ Monolithic nodes
❌ Hard-coded values
❌ Ignoring lifecycle
❌ Silent failures

    2. Message Design¶

    C++
    ✅ Specific message types
✅ Proper timestamps
✅ Clear field names
✅ Documentation strings
✅ Versioning strategy

❌ Generic/flexible messages
❌ Missing timestamps
❌ Ambiguous names
❌ No documentation

    3. Communication Patterns¶

    C++
    ✅ Use topics for data streams
✅ Use services for request/response
✅ Use actions for long-running tasks
✅ Appropriate QoS settings
✅ Namespace organization

❌ Services for streams
❌ Topics for requests
❌ Wrong QoS profiles
❌ Flat namespace
