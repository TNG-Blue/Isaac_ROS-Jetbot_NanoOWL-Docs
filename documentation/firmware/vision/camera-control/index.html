    MIPI CSI-2 camera on FreeRTOS: STM32N655 + IMX335¶

    Source

    Snapshot of docs/camera/CAMERA_CSI_RTOS.md from TNG-Blue/JetOwl_Vision at commit 09cd68c (submodule Microcontroller/JetOwl_Vision). Regenerate with Scripts/mkdocs_hooks/snapshot_submodules.py after updating the submodule.

    This document describes the Appli/Camera module: it reads a MIPI CSI-2 camera through the CSI host and DCMIPP of the STM32N655, runs on FreeRTOS (CMSIS-RTOS2), and closes auto-exposure (AE) and auto-white-balance (AWB) loops. Every formula has a reference (section 8) and is verified by unit tests (tests/host) and an analysis script (logloop_analysis.py).

    1. Architecture¶

                    +------------------------- feedback loop (every frame) ------------------------+
                |                                                                              |
 IMX335 --CSI-2 2 lane RAW10--> CSI host --> DCMIPP pipe1 ISP:                                 |
  ^  (I2C: exposure, gain)                   black level -> WB gain -> demosaic -> [statistics]|
  |                                          -> downsize 2592x1944→640x480 -> gamma -> RGB565 |
  |                                                  |                         |              |
  |                                                  | AXI                     | frame IRQ    |
  |                                                  v                         v              |
  |                                          frame buffers (AXISRAM3..6)   camera thread      |
  |                                                  ^                     (High priority)    |
  |                                                  |                         |              |
  |                                  CAM_AcquireFrame/ReleaseFrame      measure R̄,Ḡ,B̄ ------+
  |                                          (consumer thread)                 |
  |                                                                            v
  +-------------------- actuator <-- quantisation <-- controller <-- Kalman (estimation)
    File Role
    Camera/Inc/camera_conf.h Board pins, sensor, pipeline, control-loop parameters
    Camera/Src/camera.c DCMIPP/CSI/ISP, IRQ, buffer ring, camera thread, API
    Camera/Src/camera_io.c Sensor I2C, EN/NRST pins, power-up sequence
    Camera/Src/cam_i2c_timing.c Computes the TIMINGR register from the I2C standard (section 6)
    Camera/Src/cam_logloop.c Kalman filter + common control law (section 4)
    Camera/Src/cam_isp_ctrl.c AE, AWB, actuator quantisation (sections 4, 5)
    Drivers/BSP/Components/imx335 ST's IMX335 driver (stm32-imx335 v1.3.2, BSD-3)
    Drivers/STM32N6xx_HAL_Driver/*dcmipp*, *i2c* ST HAL v1.4.0, the same version as the existing HAL

    Application API (camera.h):

    CAM_WaitReady(timeout_ms);                 // wait until the camera is streaming
CAM_AcquireFrame(&frame, timeout_ms);      // take the newest frame, RGB565 640x480
/* ... use frame.data (AI, display) ... */
CAM_ReleaseFrame(&frame);                  // return the buffer
CAM_GetStatus(&st);                        // frame, drop and error counts, exposure, gain

    defaultTask in app_freertos.c is an example consumer thread.

    2. Data path and hardware configuration¶

    • Clocks (PLL1 = 64 MHz / 2 × 25 = 800 MHz, configured by the FSBL): DCMIPP = IC17 = 800/4 = 200 MHz (matches RCC.DCMIPPFreq_Value in the .ioc), CSI D-PHY reference = IC18 = 800/40 = 20 MHz.
    • CSI-2: 2 lanes, no lane swap, D-PHY band DCMIPP_CSI_PHY_BT_1600, VC0, data type RAW10 (0x2B): the same IMX335 configuration as ST's camera middleware.
    • Downsize (RM0486, same formula as CMW_UTILS_get_down_config): \(\text{ratio} = \lfloor 8192 \cdot W_{in}/W_{out} \rfloor = 33177\), \(\text{div} = \lfloor (1024\cdot 8192 - 1)/\text{ratio} \rfloor = 252\). HAL constraints: \(\text{ratio} \le 65535\), \(128 \le \text{div} \le 1023\); a ratio < 8 is checked with #error at compile time.
    • Buffers: CAM_NUM_BUFFERS × 614 400 B at 0x34200000 (AXISRAM3..6, secure alias). These banks are powered down after reset; cam_axisram_enable() enables their clocks and clears SRAMSD. The linker script does not use this region. An #error fires if the buffers exceed 1 792 KiB.
    • RIF: the DCMIPP is a bus master (RIMC CID1, secure, privileged); the DCMIPP, CSI and I2C1 slaves are set secure/privileged (CAM_RIF_Config(), called from SystemIsolation_Config).
    • Cache: the DCMIPP writes to RAM without going through the D-cache, so CAM_AcquireFrame() invalidates the buffer region when the D-cache is enabled.

    3. RTOS synchronisation and buffer protocol¶

    RTOS objects are statically allocated (the project's heap_5 has only 8 KiB):

    • Pipe1 frame ISR → osThreadFlagsSet(camera, FRAME): wakes the AE/AWB loop.
    • ISR → osSemaphoreRelease(frame_sem) (binary): signals a new frame to the consumer thread.
    • The consumer thread changes buffer state inside taskENTER_CRITICAL(). The critical section masks the DCMIPP IRQ because its priority is 6, not higher than configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5, so it is blocked by BASEPRI.

    Invariant: the DCMIPP never writes into a buffer held by the consumer thread.

    Proof. The state consists of capture (the buffer the DCMIPP is writing), ready (the newest complete frame) and held (the set of buffers being held). Only the ISR changes capture, and before changing it, it picks next ∉ held ∪ {capture}. If no such buffer exists, capture is kept and the frame is dropped (dropped++). The consumer thread only adds the element ready to held, and ready ≠ capture because the ISR sets ready = done and capture = next ≠ done in the same run. The two state changes are mutually exclusive thanks to the critical section. Therefore capture ∉ held always holds. The new address is a shadow register latched at the next frame. At 30 fps the IMX335's vertical blanking is (4500 − 1944) lines × 7.4 µs ≈ 18 ms, far longer than the ISR latency. ∎

    With 2 buffers, if the consumer holds a buffer for longer than one frame, new frames are dropped (never torn). Increase CAM_NUM_BUFFERS if memory allows.

    4. Log-domain control loop: filter → estimation → control → actuator → feedback¶

    4.1 Model¶

    A CMOS sensor is linear below saturation. The measured mean brightness is \(y = L\cdot t\cdot g\), where \(L\) is the scene luminance, \(t\) the exposure time and \(g\) the gain. Taking the logarithm turns the product into a sum:

    \[z_k = u_{k-D} + d_k + v_k,\qquad u=\ln(t\,g),\; d=\ln L,\; v_k\sim\mathcal N(0,R)\]

    \(D\) is the number of frames between writing the actuator and the statistics reflecting that value (IMX335: \(D=3\), equal to sensorDelay in ST's tuning; ISP registers: \(D=1\)). The changing scene is modelled as a random walk: \(d_{k+1} = d_k + w_k\), \(w_k\sim\mathcal N(0,Q)\).

    AWB has exactly this form. The green ISP gain is held at 1 and measured after demosaicing: \(\ln(\bar R/\bar G) = \ln g_R + \ln(R_{raw}/G_{raw})\). So \(u=\ln g_R\) and \(d\) is the colour of the illuminant. All three loops (AE, AWB-R, AWB-B) therefore share CAM_LogLoop_t.

    Decoupling. AE measures \(\bar G\), which does not depend on the AWB gains (G gain = 1). The ratio \(\bar R/\bar G\) does not depend on \(t\,g\) in the linear region. The interaction matrix is therefore diagonal, and each loop's stability can be analysed separately.

    4.2 Kalman filter (estimating \(d\))¶

    With \(u_{k-D}\) known (the value actually written, stored in a ring buffer), the measurement is \(\tilde z_k = z_k - u_{k-D} = d_k + v_k\). Scalar Kalman filter:

    \[P^-_k = P_{k-1}+Q,\quad K_k=\frac{P^-_k}{P^-_k+R},\quad \hat d_k=\hat d_{k-1}+K_k(\tilde z_k-\hat d_{k-1}),\quad P_k=(1-K_k)P^-_k\]

    The fixed point of the Riccati equation, \(P^-=(1-K)P^- + Q\), gives \(P^{-2} - QP^- - QR = 0\), hence

    \[P^-_\infty=\frac{Q+\sqrt{Q^2+4QR}}{2},\qquad K_\infty=\frac{P^-_\infty}{P^-_\infty+R}\in(0,1).\]

    The code initialises at \(P_\infty\), so the system is LTI from the first frame and the proofs below apply without considering a transient. AE (\(Q=2.5\cdot10^{-3}\), \(R=10^{-2}\)) gives \(K_\infty = 0.3904\). AWB (\(Q=10^{-3}\), \(R=10^{-2}\)) gives \(K_\infty=0.2702\). The test test_riccati compares this closed-form solution with the Riccati iteration.

    4.3 Control law (certainty equivalence)¶

    The plant has the form \(z=u+d\), so the input that reaches the set-point is \(u_k = z_{ref} - \hat d_k\). The command is then rate-limited \(|u_k-u_{k-1}|\le\Delta\) (AE: \(\Delta=\ln 2\) per frame), saturated to \([u_{min},u_{max}]\) and quantised (4.6).

    No windup. The estimator uses the applied \(u\) (after saturation and quantisation). Hence \(\tilde z_k = d_k+v_k\) holds for every \(u\): no integral of the control error accumulates while the actuator is saturated.

    4.4 Stability and steady-state error¶

    Consider a plant with model errors: a gain \(\alpha\) (pixel saturation, non-linearity) and a true delay \(D_p\) different from the model delay \(D_m\): \(z_k=\alpha u_{k-D_p}+d\). Substituting \(u=z_{ref}-\hat d\) into the steady-state filter, the homogeneous part gives the characteristic polynomial

    \[\chi(\lambda)=\lambda^N-(1-K)\lambda^{N-1}+K\alpha\,\lambda^{N-D_p}-K\,\lambda^{N-D_m},\quad N=\max(D_p,D_m).\]

    When \(D_p=D_m=D\): \(\chi(\lambda)=\lambda^{D}-(1-K)\lambda^{D-1}+K(\alpha-1)\).

    • \(D=1\): \(\lambda=1-K\alpha\), stable if and only if \(0<\alpha<2/K\).
    • \(D=2\): Jury's criterion for \(\lambda^2+a_1\lambda+a_0\) with \(a_1=-(1-K)\), \(a_0=K(\alpha-1)\): \(|a_0|<1\), \(1+a_1+a_0=K\alpha>0\), \(1-a_1+a_0=2-2K+K\alpha>0\). Hence stable if and only if \(0<\alpha<1+1/K\).
    • \(D\ge3\): checked with the Schur–Cohn criterion (script).

    Zero steady-state error for every \(\alpha\) in the stability region. At equilibrium, \(\hat d = d+(\alpha-1)(z_{ref}-\hat d)\), so \(\alpha\hat d = d+(\alpha-1)z_{ref}\) and \(z=\alpha(z_{ref}-\hat d)+d=z_{ref}\). The random walk in the model is equivalent to an integrator, so the system has integral action.

    Results of python3 docs/camera/logloop_analysis.py. The analytical and Schur–Cohn margins agree:

    Loop \(K_\infty\) \(D=1\) \(D=2\) \(D=3\)
    AE 0.3904 \(\alpha<5.12\) (theory 5.123) \(\alpha<3.56\) (theory 3.562) \(\alpha<2.895\)
    AWB 0.2702 \(\alpha<7.40\) \(\alpha<4.70\) \(\alpha<3.585\)

    Delay error for AE (\(D_m=3\)): a true delay of 1…4 frames is still stable for \(\alpha\in(0;\,2.23]\) and beyond. The nominal model is \(\alpha=1\), so the gain margin is more than a factor of 2.

    4.5 Saturated (censored) measurements¶

    When \(\bar G\ge Y_{clip}\) (240), we only know that \(z\ge\ln Y_{clip}\), i.e. \(d\ge \ln Y_{clip}-u_{k-D}\); when \(\bar G\le Y_{floor}\), the opposite. A normal Kalman update would then produce a biased estimate. The code projects \(\hat d\) onto the feasible set:

    \[\hat d \leftarrow \max\bigl(\hat d,\ \ln Y_{clip}-u_{k-D}\bigr)\]

    The covariance only receives the time update, and at the first unsaturated sample \(\hat d\) is re-initialised to \(z-u_{k-D}\).

    No overshoot when the model is exact (\(\alpha=1\), \(D_p=D_m\), constant \(d\)). Assume \(\hat d\le d\) beforehand. This holds right after a step up in brightness, since \(\hat d\) still carries the dark scene's value. The projection bound satisfies \(\ln Y_{clip}-u_{k-D}\le d\), so \(\max(\hat d,\text{bound})\le d\) and the inequality is preserved. Then \(u=z_{ref}-\hat d\ge z_{ref}-d\); the rate limit only makes \(u\) decrease more slowly, so \(z=u+d\ge z_{ref}\). Throughout the saturated phase the image approaches the set-point from the bright side and is never driven too dark. The residual deviation in simulation (≈ 8 %) comes from measurement noise and quantisation. Simulation (dark → very bright scene, \(D=3\)): the ±20 % settling time drops from 19 to 13 frames. Trade-off: when \(\alpha>1\) or the true delay exceeds the model delay, the lower bound is no longer tight, so the temporary darkening can be larger (up to −50 % at \(\alpha=1.5\)). The stability region is unchanged because the projection acts only during saturation.

    4.6 AE actuator allocation and quantisation¶

    \(E=e^u\) [µs × gain]. Exposure time is preferred (less noisy than gain): \(t=\mathrm{clamp}(E, 7, t_{max})\), line count \(n=\lfloor t/7\rfloor\), \(t_q=7n\). The remainder \(E/t_q\ge1\) goes into the gain, rounded to the IMX335's 0.3 dB step (72 dB maximum). The value of \(u\) written to the estimator is \(\ln(t_q\,g_q)\).

    \(t_{max} = (4500-9)\cdot 7 = 31\,437\) µs. ST's driver computes SHR0 = VMAX − t/7 and requires SHR0 ≥ 9. A larger \(t\) makes the unsigned subtraction wrap around (the driver's own 33 266 µs exceeds this limit). The line constant is 7 µs, not 7.407 µs, because the driver uses (uint32_t)IMX335_1H_PERIOD_USEC. This fixed multiplicative error only adds a constant to \(d\), so the filter absorbs it.

    4.7 AWB (gray world)¶

    Set-point \(z_{ref}=0\), i.e. \(\bar R=\bar G=\bar B\) after the gains. Updates happen only when \(10\le\bar G\le200\) (linear region, no dark noise, no clipping). Outside that range the loop only performs the time update (gains held). Gains are bounded to \([1;\,3.5]\), the envelope of ST's IMX335 calibration points from 2800 K to 6650 K (R 1.24…2.44; B 1.43…2.82) plus a margin. This constraint keeps gray world from drifting on monochromatic scenes. The ISP gain is encoded as \(g = \text{MULT}/128\cdot 2^{\text{SHF}}\), with an error ≤ ½ LSB (≤ 0.39 % for \(g\ge1\)).

    5. Why this estimator + controller instead of PID¶

    In the log domain the plant is a unit gain plus a pure delay. With Gaussian noise and a random-walk scene, the Kalman filter is the optimal linear (MMSE) estimator. The certainty-equivalence law separates from the estimator (separation principle), and because the delay \(D\) is compensated explicitly through the history of \(u\) (equivalent to a Smith predictor), the loop gain is not limited by the delay when the model is exact. A PI on the image error would have to reduce its gain with \(D\) to stay stable and would need an additional anti-windup mechanism. Here the absence of windup follows from the structure (section 4.3).

    6. I2C timing (CAM_IO_I2C_ComputeTiming)¶

    The TIMINGR register is computed from the actual I2C kernel clock (HAL_RCCEx_GetPeriphCLKFreq) instead of a "magic" constant. For PRESC = 0…15 the first value satisfying every constraint is selected (UM10204 table 10, RM0486 formulas, analog filter on, \(t_{AF}\in[50,260]\) ns):

    • \((SCLDEL+1)t_{PRESC}\ge t_r+t_{SU;DAT}\)
    • \(t_f+t_{HD;DAT,min}-t_{AF,min}-3t_{I2CCLK}\le SDADEL\cdot t_{PRESC}\le t_{VD;DAT}-t_r-t_{AF,max}-4t_{I2CCLK}\)
    • \((SCLL+1)t_{PRESC}\ge t_{LOW}\), \((SCLH+1)t_{PRESC}\ge t_{HIGH}\), \((SCLL+SCLH+2)t_{PRESC}+2(t_{AF,min}+2t_{I2CCLK})\ge 1/f_{SCL}\), so \(f_{SCL}\) never exceeds the target.

    The test decodes TIMINGR at 16…200 MHz × 100/400 kHz and checks each inequality. It also confirms that 400 MHz at 100 kHz has no solution, because \(t_{PRESC}\le40\) ns while \(t_{SCLDEL}\) needs ≥ 78 ns per step.
