    RF / GNSS link security: measurements, detection, response¶

    Source

    Snapshot of docs/SECURITY.md from TNG-Blue/JetOwl_FlightControl at commit 64287b2 (submodule Microcontroller/JetOwl_FlightControl). Regenerate with Scripts/mkdocs_hooks/snapshot_submodules.py after updating the submodule.

    FC: Application/Control/Src/sec_feed.c (pure C, host test tests/host/test_sec_feed.c), Application/Interface/Src/sec_app.c (guard glue), the security window in rflink_app.c, the GSV / C/N0 statistics in gnss_nmea.c and gnss_app.c, the topics in uros_app.c. Jetson (Isaac_ROS-Jetbot_NanoOWL): Source/ROS2_RF_Spectrum/ros2_rf_spectrum/link_security/ (detector: rules + network), Source/ROS2_Flight_Controller/src/security_response.cpp (flight response), Source/ROS2_Control_System/src/cpp/uav/security_advice.cpp (GNSS trust + advice).

    1. Who does what¶

    FC  LR1121 ×2: packet RSSI/SNR, CRC, CMAC, replay, GetRssiInst ──┐   /jetowl/security/rf_link
    GSV C/N0, GGA/RMC, gnss_frontend/gnss_dual verdicts ──────────┤   /jetowl/security/gnss
    nav_dr (GNSS-free dead reckoning) ────────────────────────────┤   /jetowl/dr/pose
                                                                   ▼
Jetson  link_security (ros2_rf_spectrum)  — DETECTS only: rules R-RF1..4, R-G1..6 + network
        └─▶ /jetowl/security/threat (Float32MultiArray, 19 values)
              ├─▶ ros2_flight_controller  — FLIGHT response (Stateflow: HOLD / RTH / LAND)
              │     └─▶ /jetowl/security/response (UInt8MultiArray [ver, seq, action, acted])
              └─▶ ros2_control_system uav_state_estimator — GNSS TRUST of the ESKF
                    + response ─▶ /jetowl/security/advice (8 B, CRC-8) ─▶ FC
FC  sec_guard (sec_feed.h): distrusted receiver → verdict GNSS_DISTRUSTED (7)
    → /gps/fix NO_FIX, LoRa GNSS pages "distrusted" on the remote

    Each decision is taken by the node that owns that loop: the flight controller owns the flight modes, the estimator owns GNSS fusion, the FC owns /gps/fix and the radio. The detector never commands anything, and the FC never takes a flight action from the advice (§5).

    2. What the FC measures¶

    2.1 Radio (/jetowl/security/rf_link, 10 Hz, 35 floats, layout SEC_RF_*)¶

    Per band (2.4 GHz commands, sub-GHz commands in the P format) over the 100 ms window: commands expected (time the band was planned to carry commands / T), received, CRC/header errors, CMAC failures (BAD_TAG, BAD_HDR, BAD_LEN), replays (STALE, REKEY), energy means of packet RSSI and noise, mean SNR, and GetRssiInst samples.

    • Noise of a frame: P_rssi = S + N = N (1 + 10^(SNR/10)) ⇒ N = RSSI − 10 log10(1 + 10^(SNR/10)) (Semtech AN1200.22 §4). Powers are averaged in mW (energy detector, Urkowitz 1967), SNR in dB.
    • GetRssiInst (0x0205, RSSI = −RssiInst/2 dBm) is read (a) right after every missed command, on the channel where the frame was expected, and (b) at most every 100 ms on the idle channel after a received frame — so the clean level is learned with the same estimator the post-miss samples are compared with. (b) is taken only when the next frame cannot be on air: time to the deadline > T/2 + guard ⇒ ≥ T/2 − ToA > 0 before it starts, and ≥ 1 ms after the receiver started (12 symbols at SF6/BW812).
    • The sub-GHz band is measured only while the FC listens there (P format); in the N format the FC only transmits on it.

    2.2 GNSS (/jetowl/security/gnss, per epoch of either receiver, 42 doubles, SEC_G_*)¶

    Per receiver: epoch count, UTC, verdict (with the distrust applied), quality, satellites, HDOP, position, RMC ground speed (A), and the C/N0 statistics of the GSV cycle: satellites in view, tracked, mean, population std, min, max and the Pearson correlation of C/N0 with elevation. GSV (NMEA 0183 v4.11): each (talker, PRN, signal ID) is one measurement, the cycle since the previous GGA is reduced when the next GGA closes the epoch (one epoch, ≤ 1 s, late). Receiver A's GSV reaches a second gnss_nmea parser through the driver's raw-line callback.

    3. Detection (link_security)¶

    All rules are hypothesis tests at α = 10⁻³ (one-sided, z_α = 3.090) unless stated.

    Rule Threat Test Source
    R-RF1 jam P(X ≤ K | Bin(E, p₀)) < α with p₀ = exp(−10^(−M/10)) (Rayleigh) and (energy z >_α or P(X ≥ C | Bin(E, 1−p₀)) < α) Xu et al., MobiHoc 2005 (PDR vs signal strength); Goldsmith 2005
    R-RF2 jam noise rise z_N > z_α with margin < 9.8 dB (Rayleigh outage > 10 %) rflink_band.h
    R-RF3 inject CMAC failures ≥ k_T, Poisson(max(C,1)·2⁻¹⁶) tail < 10⁻⁶ CRC-16 undetected error 2⁻¹⁶
    R-RF4 replay stale frames among fresh ones, no rekey in the window rflink_proto.h
    R-G1 GNSS jam mean and max C/N0 down (z < −z_α) without a spread increase (χ² upper test), or sudden loss of tracking Betz, ION NTM 2001
    R-G2 spoof n s²/ŝ² < χ²_α(n−1): uniform C/N0 Psiaki & Humphreys 2016
    R-G3 spoof Fisher z of the C/N0–elevation correlation < −z_α, spread not up Fisher 1921
    R-G4 spoof C/N0_max > 59 dB-Hz (−150 dBW + 5 dBic + 204 dBW/Hz) ICDs
    R-G5 spoof (|Δp_GNSS| − |Δp_DR|)² / (2σ_g² + σ_DR²) > 10.83 χ²(1) 99.9 %
    R-G6 spoof |Δt_UTC − Δt_FC| > 0.38 s (370 ms detection delay + 10 ms resolution) gnss_app.h

    Baselines (EWMA, n_eff 300 RF windows / 60 epochs) learn only from windows no rule or network flagged and, for RF, without significant loss. Energy means of different sizes are compared after removing the log-normal bias c σ² (1 − 1/n), c = ln10/20 (delta method).

    Network: 40 features (the same statistics, clipped/scaled) → 64 → 32 → 6 sigmoid outputs, binary cross-entropy, Adam, trained on the GPU with CuPy (cuBLAS), NumPy fallback, on physics-model synthetic data (synth.py). Thresholds per label = (1 − 10⁻³) quantile of benign validation scores (Neyman–Pearson); a network detection is confirmed after 3 consecutive evaluations (10⁻⁹). A confirmed threat is held 10 s.

    Held-out synthetic test (models/link_security_metrics.md, all attack strengths incl. J/N 1 dB):

    threat rules TPR network TPR rules OR network benign FPR (OR)
    rf_jam_24 0.746 0.940 0.940 0.0020
    rf_jam_sub 0.757 0.947 0.948 0.0009
    rf_inject 0.945 0.979 0.979 0
    rf_replay 1.000 1.000 1.000 0.0003
    gnss_jam 0.984 0.997 0.998 0.0013
    gnss_spoof 0.815 0.864 0.867 0.0033

    These are synthetic numbers: retrain with recorded flights (log_features: true, train_link_security.py --extra) before relying on the network on an airframe.

    4. Response on the Jetson¶

    ros2_flight_controller (security_response.h): GNSS spoof / jam → LAND in place (RTH would fly to a forged home; the node already lands on a lost fix). Command link jammed and lost (rc_fresh false) → RTH (LAND if GNSS is attacked too); jammed but still up (other band) → warning. Injection / replay → no action (CMAC and the sequence check reject them on the FC). Escalate-only per episode, arming refused during a GNSS or RF-jam threat, stale input (> 1 s) → no action.

    ros2_control_system uav_state_estimator (security_advice.hpp): a receiver is distrusted while a fresh GNSS threat marks it (no mask → both), or both when the ESKF's χ² gate also rejected 3 consecutive fixes (10⁻⁹); held 10 s. While distrusted, no GNSS position / velocity is fused and the divergence reset (which would jump to a forged position) is not applied. The advice (threats, flight action in force, distrust mask, confidence, sources) goes to the FC at 2 Hz and on every change.

    Pilot authority: the flight controller reads rc_authority of /jetowl/status. With PILOT (switch ANGLE) the FC ignores the Jetson, so no flight-mode event is issued: a jammed and lost command link is reported as the FC's own bounded descent (action LAND, flown by cmd_guard, rc_input.h §3), other threats as no action (the pilot flies), and the response is applied if the pilot switches to AUTO while the threat lasts (ARCHITECTURE.md §9.3).

    5. The FC guard (sec_feed.h)¶

    Advice refused on wrong length, version, CRC-8/SMBUS, reserved bits or unknown action. Fresh for 4 periods (2 s). A distrust bit holds SEC_GNSS_HOLD_MS = 10 s after its last assertion: if a live attack is detected with P_d ≥ 0.5 per 1 Hz epoch, the latch reopens on it with probability ≤ 0.5¹⁰ < 10⁻³. The advice arrives unauthenticated over the vehicle Ethernet, so it can only lower trust (receiver → GNSS_DISTRUSTED, /gps/fix NO_FIX, remote map stops), never command a flight action: a forged advice can at worst stop the use of GNSS, which the FC's own loop does not use. The action field is reported (sec_action in /jetowl/status).

    6. Not verified on hardware¶

    GetRssiInst settling after SetRx, the actual offset between GetRssiInst and the packet noise estimate (cancelled by design, not measured), LG290P / L76K GSV output with signal IDs, the network on real attacks, and the false-alarm rates in flight. Bench order (control-systems.md §4): signal-generator jammer on the 2.4 GHz / 921 MHz channels with the link at a known margin, then a GNSS simulator for jamming / spoofing in a shielded box.
