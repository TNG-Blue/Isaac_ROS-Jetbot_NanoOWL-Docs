    micro-ROS over UDP/Ethernet: JetOwl ↔ Jetson (Isaac_ROS-Jetbot_NanoOWL)¶

    Source

    Snapshot of docs/MICROROS_ETHERNET.md from TNG-Blue/JetOwl_FlightControl at commit 23b5ac3 (submodule Microcontroller/JetOwl_FlightControl). Regenerate with Scripts/mkdocs_hooks/snapshot_submodules.py after updating the submodule.

    This document describes what has been built and verified in the repository (compiled, linked, host-tested), and separates out what is not yet verified on hardware. Read section 9 before flashing a board.

    1. Architecture¶

     Jetson Orin (ROS 2 Humble)                              STM32N657 — AppliNonSecure (FreeRTOS)
 ┌──────────────────────────────┐                       ┌───────────────────────────────────────┐
 │ uav_trajectory_controller    │ /control/attitude_    │ "uros" task (uros_app.c, 200 Hz)        │
 │  (MPC, 50 Hz, ENU/FLU)       │  setpoint, /control/  │   ENU/FLU → NED/FRD (frame_conv.c)      │
 │                              │  thrust ────────────▶ │   FlightControl_SubmitAttitudeCommand   │
 │ uav_state_estimator (ESKF)   │ ◀──── /imu/data ───── │ ┌─ TIM interrupt 1 kHz (flight_control.c)┐│
 │ flight_controller (modes)    │ ◀─ /jetowl/status ─── │ │ cmd_guard → attitude_ctrl (250 Hz)    ││
 │ jetowl_bridge ─ /jetowl/arm ▶│                       │ │ → rate_loop PID+ESO (1 kHz) → mixer   ││
 └──────────┬───────────────────┘                       │ │ → DShot → ESC → RPM (bidirectional)   ││
            │ micro_ros_agent udp4 :8888                │ └──────────── IMU feedback ────────────┘│
            └──────── UDP/IPv4, 100BASE-TX RMII ────────│ lwIP 2.2.1 ← ethernetif.c ← ETH1+LAN8742│
                                                        └───────────────────────────────────────┘

    Two design principles:

    1. The attitude and rate loops are always closed on the firmware's IMU. Commands from the Jetson are only set-points. A slow network or lost packets never open a loop; they only make the set-point stale → handled by cmd_guard (section 4).
    2. No intermediate node on the command path. The firmware subscribes to exactly the topics that ros2_control_system publishes and publishes exactly the topics the ESKF listens to — the Jetson stack runs unchanged.

    2. Topic contract¶

    Direction Name Type QoS Rate
    FC→J /imu/data sensor_msgs/Imu (ENU/FLU, frame imu_link) best effort 200 Hz
    FC→J /jetowl/status diagnostic_msgs/DiagnosticStatus reliable 2 Hz
    FC→J /jetowl/motor_rpm std_msgs/Float32MultiArray (NaN = unknown) best effort 50 Hz
    FC→J /baro/pressure sensor_msgs/FluidPressure [Pa], BMP280, variance 1.44 Pa² (BST-BMP280-DS001 table 8; airframe_config.h section 6.4) → ESKF on the Jetson best effort 25 Hz
    J→FC /control/attitude_setpoint geometry_msgs/QuaternionStamped best effort 50 Hz
    J→FC /control/thrust std_msgs/Float64 [N] best effort 50 Hz
    J→FC /jetowl/arm std_srvs/SetBool (service) — on request
    J→FC /jetowl/ota/start, /jetowl/ota/apply std_srvs/Trigger (service) — on request, docs/OTA.md

    QoS compatibility: a reliable publisher (MPC) → best-effort subscriber (FC) is valid; a best-effort publisher (FC /imu/data) → SensorDataQoS subscriber (ESKF) is valid. A serialised Imu is ≈ 330 B and fits the custom transport's 512 B MTU (best effort does not fragment).

    3. Frame conversion (frame_conv.c)¶

    Firmware: NED (world) / FRD (body). ROS (REP-103): ENU / FLU. With q_ab the rotation taking a vector from frame b to frame a, q_ac = q_ab ⊗ q_bc (Diebel 2006 §6):

    ENU→NED:  M = [[0,1,0],[1,0,0],[0,0,-1]], det M = +1  →  q_NE = (0, 1/√2, 1/√2, 0)   (π about (1,1,0)/√2)
FRD→FLU:  diag(1,-1,-1)                                →  q_LB = (0, 1, 0, 0)        (π about x)

q_ned_frd = q_NE ⊗ q_enu_flu ⊗ q_LB
q_enu_flu = q_NE⁻¹ ⊗ q_ned_frd ⊗ q_LB⁻¹
ω_flu = diag(1,-1,-1) ω_frd,   a_flu = diag(1,-1,-1) a_frd

    tests/host/test_frame_conv.c checks the geometric definition: for every q and v, R(q_enu) v_flu = M_EN R(q_ned) v_frd (error < 1e-5), and a level FC heading north ⇒ ROS yaw = +90°.

    4. Command gate cmd_guard (Application/Control)¶

    Command validation: NaN/Inf → rejected; | |q|−1 | > 0.1 → rejected (a corrupted packet or wrong type, not a rounding error); commanded tilt limited to 35° (more than the Jetson MPC's 30°, so valid commands are never clipped); thrust clamped to [0, 4 k_f ω_max²] (actuator saturation).

    Pairing the two topics: /control/attitude_setpoint and /control/thrust are published back to back every MPC cycle; a command is submitted only when both are fresh (≤ 0.1 s). If one topic stops ⇒ nothing is submitted ⇒ failsafe.

    Link loss (timeout = 0.1 s = 5 MPC cycles; losing 1–2 UDP packets does not trigger it):

    Axis Action Loop
    roll/pitch return to level closed (IMU)
    yaw hold the heading (twist) of the last valid command closed (IMU)
    vertical landing profile, see below open — the FC has no altitude sensor in its loop

    The open vertical loop is a permitted exception (control-systems §1: no feedback sensor exists in the FC's loop). Model m z̈ = T cos θ − m g; at equilibrium T cos θ = m g, so the weight estimate is W = T_last cos θ_last:

    phase 1, 0 ≤ t < t1 = v_d/a_d :  T = W (1 − a_d/g)   ⇒  z̈ = −a_d
phase 2, t ≥ t1               :  T = W              ⇒  ż = −v_d
t_fs = v_d/a_d + max(0, h_max − v_d²/(2a_d)) / v_d     (= 31 s with a_d = 0.5, v_d = 1, h_max = 30 m)

    If the link has not returned after 1.2 t_fs ⇒ disarm (a defined safe state). Error bound: a relative error ε in W ⇒ z̈ off by ε g (ε = 5 % ⇒ 0.49 m/s²) — which is why the time limit is required. The profile (0.5 m/s², 1 m/s) matches the "stale odometry" failsafe of ros2_control_system.

    Arming conditions: fresh command, valid IMU (sample < 20 ms old), commanded thrust ≤ 20 % of maximum thrust, measured tilt < 20°, TIM loop running. Disarm is always accepted. Automatic disarm: t_fs elapsed, IMU lost in flight, tilt > 75° for 0.25 s (flipped).

    tests/host/test_cmd_guard.c: 36 checks (rejection/clamping, ACTIVE→FAILSAFE→ACTIVE, the exact values W(1−a/g) then W, heading hold, disarm after 37.2 s, 32-bit tick-counter wrap-around, every arming refusal reason).

    5. Attitude loop attitude_ctrl (Application/Control)¶

    q_e = q̂⁻¹ ⊗ q_sp,   s = sgn(q_e.w),   Ω_i = sat_i(2 s K_i q_e.v_i)

    Source: Wie, Weiss & Arapostathis, JGCD 12(3), 1989 — the same law as the simulated attitude loop in Gazebo/ROS2_Hexacopter_Control on the Jetson side.

    Proof (assuming an ideal rate loop ω = Ω, valid with a bandwidth separation ≥ 5, Khalil ch. 11): q̇_e = −½ [0,ω] ⊗ q_e ⇒ q̇_e.w = ½ ω·q_e.v. With V = 1 − s q_e.w ≥ 0: V̇ = −½ s Σ Ω_i q_e.v_i. Saturation preserves the sign, so each term s Ω_i q_e.v_i ≥ 0 ⇒ V̇ ≤ 0, zero only when q_e.v = 0 (LaSalle ⇒ convergence; s selects the short arc ⇒ no unwinding). Without saturation: V̇ = −Σ K_i q_e.v_i².

    Choice of K: at small angles q_e.v ≈ θ/2 ⇒ Ω = Kθ, L_att = K/s · T_rate(s). K_i = ω_c,rate,i / 5; ω_c,rate is computed exactly from the configured PID + b0 (L_r(jω) = C_pid(jω) b0/(jω), bisection on a log scale) rather than approximated by b0 Kp. With the current sample values: ω_c = 15.78 rad/s ⇒ K = 3.16 s⁻¹ (roll/pitch). With T_rate ≈ ω_c/(s+ω_c): PM = 90° − atan(⅕) = 78.7°.

    tests/host/test_attitude_ctrl.c: Ω = Kθ at small angles; q and −q give the same command; saturation preserves the sign; V never increases along a trajectory starting from a 170° error, and converges; with a first-order rate loop (ω_c = 15) overshoot < 1 %; the tilt limit preserves direction and axis; ω_c matches an independent double-precision complex computation (error 1e-4).

    6. Network: ETH1 + LAN8742 + lwIP¶

    Item Value Source
    PHY, interface LAN8742, RMII STM32CubeN6 Projects/NUCLEO-N657X0-Q/Applications/NetXDuo/Nx_UDP_Echo_Client
    Pins PF4 MDIO, PF5 CLK, PF7 REF_CLK, PF10 CRS_DV, PF11 TX_EN, PF12/13 TXD0/1, PF14/15 RXD0/1, PG11 MDC — AF11 as above (HAL_ETH_MspInit)
    ETH1 clock source HCLK as above
    PHY driver Drivers/BSP/Components/lan8742 github.com/STMicroelectronics/stm32-lan8742 (BSD-3)
    Stack lwIP STABLE-2_2_1, FreeRTOS sys_arch, socket API github.com/lwip-tcpip/lwip (BSD)
    Addresses FC 192.168.10.2/24, agent 192.168.10.1:8888, static IP Application/Network/Inc/net_config.h

    TrustZone/RIF (AppliSecure/Core/Src/main.c, JetOwl_EthernetToNonSecure, inside USER CODE): ETH1 clock, RISC ETH1 = NSEC, RIMC master ETH1 = NSEC (DMA issues NS transactions), the 10 RMII pins = NSEC, NVIC_SetTargetState(ETH1_IRQn). Without this step a non-secure access to ETH1 raises an IAC/fault.

    Cache: the NS D-cache is enabled and the HAL ETH driver does not maintain the descriptor cache. The RX/TX descriptors + 12 RX buffers live in one static block aligned to 32 B, sized to a multiple of 32 and declared non-cacheable through MPU_NS region 0 (ARMv8-M allows 32 B regions). TX buffers are lwIP pbufs ⇒ SCB_CleanDCache_by_Addr before DMA.

    Interrupts: ETH1 priority 7 ≥ configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY (5) — required for the ISR to call xSemaphoreGiveFromISR.

    Transport: net_if.c replaces the original udp_transport.c (which fixed port 8888 at both ends and called recv(MSG_WAITALL) on a datagram socket). Framing is disabled (UDP is packet-oriented).

    7. Timestamps¶

    header.stamp = t0 + t_sample: t_sample is the instant the chip sampled (INT pin + SH-2 time field, CONTROL_DESIGN.md §1.5) on the control loop's µs clock; t0 comes from rmw_uros_sync_session (agent clock = Jetson clock) and is re-synchronised every 10 s. Intervals between stamps are exact to the µs; the absolute origin is off by at most ~1 ms (the micro-ROS clock follows the FreeRTOS tick) — a constant offset between two synchronisations. Latency budget of the set-point path: MPC period 20 ms + UDP/agent < 1 ms (direct 100 Mbit/s link) + 250 Hz sampling ≤ 4 ms; the MPC already budgets 40 ms for the attitude loop.

    8. Build¶

    make microros              # first time: builds libmicroros.a in docker (micro_ros_static_library_builder:humble)
make                       # AppliSecure → AppliNonSecure (mandatory order)
make -C Makefile nonsecure MICROROS=0   # network-less build
make agent                 # runs the micro-ROS agent (docker) on the Jetson/host
    • The repository root contains a CubeMX-generated directory Makefile/, so the entry point is GNUmakefile (GNU make reads it first).
    • The builder runs make print_cflags at the repository root; print_cflags prints exactly the firmware's ABI flags (-mcpu=cortex-m55 -mthumb -mfpu=fpv5-d16 -mfloat-abi=hard …) — the library and the firmware must share the ABI.
    • Makefile/AppliSecure writes the import library to Makefile/AppliSecure/build/secure_nsclib.o and Makefile/AppliNonSecure links that exact file. It deliberately does not write Secure_nsclib/secure_nsclib.o (used by the CMake build): sharing one file between the two builds could make the NS image link against the veneers of a secure image other than the one flashed.
    • Measured results: AppliSecure ROM 14.0 KB / RAM 13.1 KB; AppliNonSecure (micro-ROS) ROM 181.6 KB / 511 KB, RAM 224.2 KB / 512 KB (two 64 KB heaps: FreeRTOS + micro-ROS).

    9. Not yet verified / open items¶

    • Not yet run on hardware. In order: ping 192.168.10.2 → the agent sees the session → ros2 topic list → bench without propellers → HIL (control-systems §4).
    • The IMU read path exists (imu_acq.c, CONTROL_DESIGN.md §1.4–1.5) but runs only once CubeMX has enabled I2C1 + EXTI PE0 and BOARD_CUBEMX_PERIPHERALS_READY = 1. Until then the firmware refuses to arm and does not publish /imu/data. The mounting frame q_SB is an assumption — the static check of §1.4 must be performed.
    • BOARD_CUBEMX_PERIPHERALS_READY = 0: the TIM6 tick is not running ⇒ arming is refused (control loop timer not running).
    • Pre-existing conflict: CubeMX currently uses TIM1 as the NS HAL timebase, while board_config.h reserves TIM1 for DShot. The timebase must move to another timer before DShot is enabled.
    • The Jetson MPC's thrust_min_n estimate (5 N, X12 airframe) must be below 20 % of the JetOwl airframe's maximum thrust, otherwise arming is refused (thrust command too high).
    • The Imu covariances are 0 ("unknown") until an Allan-variance log of the IMU is available.
