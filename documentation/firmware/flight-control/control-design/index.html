    Flight control loop design — derivations and references¶

    Source

    Snapshot of docs/CONTROL_DESIGN.md from TNG-Blue/JetOwl_FlightControl at commit 23b5ac3 (submodule Microcontroller/JetOwl_FlightControl). Regenerate with Scripts/mkdocs_hooks/snapshot_submodules.py after updating the submodule.

    Project principle: every formula in Application/Control/ must be traceable to a verifiable source (peer-reviewed paper, textbook or datasheet). No invented coefficients. This document is the "proof"; the code is only its implementation.

    0. Signal diagram¶

      IMU / GNSS / Baro
        |
        v
  [Calibration + bias removal]     calib.c
        |
        v
  [State filter]                   attitude_filter.c   (Mahony on SO(3))
        |  q, omega
        v
  [Disturbance estimator]          eso.c               (Extended State Observer)
        |  f_hat  (total disturbance + model error)
        v
  [Controller]                     pid.c / rate_ctrl   (cascade, compensates f_hat)
        |  [T, tau_x, tau_y, tau_z]
        v
  [Control allocation / mixer]     mixer.c
        |  u_i (per rotor)
        v
  [ESC / servo]                    Application/Interface
        |
        +--------- physical feedback: the IMU measures again -----------> back to the filter

    The loop is closed at the IMU/GNSS. The only open segment is ESC command → actual rotor speed (see §6).

    1. Sensor calibration¶

    1.1 Gyro error model¶

    omega_meas(t) = omega_true(t) + b(t) + n_g(t)
b_dot(t)      = n_b(t)

    b = slowly varying bias (random walk), n_g ~ white noise. This is the standard model used throughout the attitude-estimation literature; the parameters sigma_g, sigma_b are measured with the Allan variance.

    Source: IEEE Std 952-1997, IEEE Standard Specification Format Guide and Test Procedure for Single-Axis Interferometric Fiber Optic Gyros, Annex C (Allan variance) — the standard definition of angle random walk and rate random walk.

    1.2 Accelerometer / magnetometer calibration¶

    Affine model: y = M (x - b), estimated by ellipsoid fitting (a constrained least-squares problem with a closed-form solution through an eigen-decomposition).

    Source: Gebre-Egziabher, Elkaim, Powell, Parkinson, "Calibration of Strapdown Magnetometers in Magnetic Field Domain", Journal of Aerospace Engineering 19(2), 2006.

    1.3 Conversion from the Adafruit IMU (SH-2)¶

    The Adafruit_IMU driver returns fixed-point Q-point values. The conversion factors to SI are taken directly from the "SH-2 Reference Manual" (CEVA/Hillcrest) — cited at Drivers/JetOwl/Inc/Adafruit_IMU.h:9-14. No further derivation is involved.

    1.4 IMU read path: mounting frame and calibration gate¶

    Code: Application/Control/Src/imu_frontend.c (maths, host test test_imu_frontend.c) and Application/Interface/Src/imu_acq.c (FreeRTOS task reading I2C — not read inside the 1 kHz interrupt).

    q_NB = q_NW ⊗ q_WS ⊗ q_SB            v_B = R(q_SB)⁻¹ v_S        (Diebel 2006 §6)
q_WS : chip → the chip's world frame (ENU, Android convention — SH-2; BNO055 ORI = Android)
q_NW : ENU → NED = (0, 1/√2, 1/√2, 0)
q_SB : FRD body → chip (mounting). Default: chip level, top side up, chip x towards the nose ⇒ (0, 1, 0, 0)

    Calibration gate: both chips self-calibrate dynamically (gyro/accel/mag); a sample is accepted only when the accuracy status is > 0 (SH-2 accuracy; BNO055 CALIB_STAT.SYS). Outliers: NaN, | |q|−1 | > 0.1, or any axis ≥ 98 % of the datasheet full scale (saturation) ⇒ the sample is rejected.

    Mandatory static check before flight (the default q_SB is an ASSUMPTION, not yet confirmed on the airframe):

    Attitude /imu/data must show Firmware state
    Level, nose pointing (magnetic) north ENU yaw = +90°, roll = pitch = 0, linear_acceleration.z ≈ +9.81 imu_fusion = 3 (BOTH)
    Right wing down 30° ENU/FLU roll = +30° (right down about the forward x axis) —
    Nose up 30° FLU pitch = −30° —

    If one chip is mounted differently from the assumption, imu_fusion reports a disagreement (> 15°, imu_fusion = 4) and the firmware refuses to arm — a second line of defence, not a substitute for the check above.

    1.5 Sampling instant and latency¶

    • BNO08x: t = t_INT + 100 µs·(−BaseDelta + Rebase + delay) (SH-2 Reference Manual 1000-3625: reports 0xFB/0xFA, 14-bit delay field = status[7:2]:byte3). t_INT is captured by EXTI on the INT pin with the control loop's µs clock (FlightControl_NowUs = TIM6 tick × 1000 + TIM6 counter).
    • BNO055: no timestamp; the fusion registers update at 100 Hz with an unknown phase ⇒ data age ~ U(0, 10 ms): unbiased estimate t = t_read − 5 ms, standard deviation 10/√12 = 2.9 ms. Fusing a sample B that is up to Δt older than sample A adds an error ≤ w_B·|ω|·Δt = 0.5·3.5·0.01 rad = 1°.
    • Rate loop: the 200 Hz gyro is held (ZOH) at 1 kHz. Delay = T/2 + I2C ≈ 2.5 + 0.6 ms + chip delay ⇒ Δφ = −ω_c·τ ≈ −2.8° at ω_c = 15.78 rad/s (plus the chip delay; the firmware reports sh2_delay_max_ms).

    2. Attitude filter — Mahony on SO(3)¶

    2.1 Why this filter¶

    The filter must (a) have a stability proof, (b) have no singularity at large angles and © be light enough for 1 kHz. Mahony's nonlinear complementary filter meets all three: it operates directly on the group SO(3), so it has no Euler gimbal-lock singularity, and it comes with a Lyapunov proof of almost-global asymptotic stability.

    2.2 Formulas (quaternion form, passive complementary filter)¶

    Let q be the attitude estimate (body → inertial) and b_hat the gyro-bias estimate.

    The orientation error measured from the reference vectors (gravity v_a, magnetic field v_m):

    e = sum_i  k_i * ( v_i_meas  x  v_i_pred )                    (1)

    where v_i_pred = R(q)^T * v_i_ref is the reference vector rotated into the body frame and x is the cross product.

    Update law:

    b_hat_dot = -k_I * e                                          (2)
omega_corr = omega_meas - b_hat + k_P * e                     (3)
q_dot      = 0.5 * q ⊗ [0, omega_corr]                        (4)

    2.3 Stability proof (summary)¶

    With the Lyapunov function V = tr(I - R_err) on SO(3) (R_err = R_hat^T R), Mahony et al. prove V_dot <= 0 and that the largest invariant set consists of the desired equilibrium plus three unstable equilibria (the 180° rotations). Convergence is therefore almost global — the region of attraction is all of SO(3) except a set of measure zero.

    Source: Mahony R., Hamel T., Pflimlin J.-M., "Nonlinear Complementary Filters on the Special Orthogonal Group", IEEE Transactions on Automatic Control, 53(5), 2008, pp. 1203–1218. Theorem 5.1 and its proof.

    2.4 Choosing k_P, k_I¶

    Linearised around a small error, the system becomes second order:

    e_dot_dot + k_P * e_dot + k_I * e = 0

    Compared with the standard form s^2 + 2*zeta*wn*s + wn^2:

    wn   = sqrt(k_I)
zeta = k_P / (2*sqrt(k_I))

    Hence no trial-and-error tuning: choose wn (desired bandwidth, rad/s) and zeta (recommended 1/sqrt(2)), then solve:

    k_I = wn^2
k_P = 2 * zeta * wn                                            (5)

    The bandwidth wn must lie in between: high enough to track the gyro bias, low enough not to be disturbed by linear acceleration during manoeuvres. In practice 0.5–2 rad/s is a reasonable range for a drone.

    2.5 Selected configuration: two IMUs in parallel, this filter NOT used¶

    The project runs both a BNO08x (Adafruit) and a BNO055 (DFRobot). Both perform fusion inside the chip and output a quaternion, so attitude_filter (Mahony) is not used on the main flight path — stacking two filters only adds delay and breaks the statistical assumptions.

    The module is kept, fully tested, for cases that require fusion from raw data (for example to control the latency completely, or after switching to an IMU without internal fusion).

    Fusing the two quaternions is described in §2.7.

    2.6 Accuracy benefit of two sensors¶

    If two sensors have independent errors with the same variance σ², the equally weighted mean has variance σ²/2, i.e. the standard deviation is reduced by √2 (~29 %).

    This has been measured numerically in tests/host/test_imu_fusion.c::test_noise_reduction: injecting independent noise into both inputs around the same true value gives a single/fused RMS-error ratio in the range 1.2–1.7.

    The "independent" condition really matters. Two IMUs placed side by side on the same board share the same vibration and the same thermal drift; that common part of the error is not removed. The √2 benefit applies only to the truly independent part. Placing the two IMUs far apart and with different orientations increases the independent part.

    The optimal weights are inversely proportional to the variance of each sensor. The current default uses equal weights because the real variance of each unit has not been measured yet.

    2.7 Fusing two quaternions — why not average component-wise¶

    Unit quaternions live on the sphere S³, not in a flat vector space. Averaging component-wise and normalising is an unfounded approximation, increasingly wrong as the two rotations differ, and it is even ill-defined because q and −q represent the same rotation — flipping the sign of one input gives a completely different result, and two nearly identical estimates can even cancel each other out.

    Markley et al. define the mean as the solution of the optimisation problem:

    q_mean = argmax  Σ w_i (qᵀ q_i)²      subject to |q| = 1

    The solution is the eigenvector of the largest eigenvalue of M = Σ w_i q_i q_iᵀ. The squared form (qᵀq_i)² is precisely what removes the sign ambiguity.

    Closed form for two quaternions (the eigenvector lies in the plane spanned by {q₁, q₂}, which reduces the problem to the eigenvalues of a 2×2 matrix):

    c = q₁ · q₂                                (after aligning signs so that c ≥ 0)
z = √( (w₁ − w₂)² + 4 w₁ w₂ c² )
a = (w₁ − w₂ + z) / 2
b = w₂ c
q_mean = normalize(a q₁ + b q₂)

    Check with w₁ = w₂ = ½: z = c, a = b = c/2 → the equally weighted mean, as expected.

    Source: Markley F. L., Cheng Y., Crassidis J. L., Oshman Y., "Averaging Quaternions", Journal of Guidance, Control, and Dynamics, 30(4), 2007, pp. 1193–1197.

    Implementation: Application/Control/Src/imu_fusion.c.

    2.8 Disagreement detection¶

    Angle between the two estimates: θ = 2·arccos(|q₁·q₂|). Above the threshold (default 15°) the estimates are not fused: the result would be a value in between that matches neither. Nor does this layer pick one of the two on its own — that needs external information (magnetometer, dynamic model) it does not have. It keeps the previous cycle's value and reports upwards.

    imu_fusion_disagreement() is well worth logging: it rises before a sensor fails completely and can serve as an early warning.

    The 15° threshold is a starting value, not yet measured on a real airframe. The correct way to set it: log imu_fusion_disagreement() over a few minutes of test flight, take the 99th percentile and double it.

    2.9 Heavier alternative: MEKF¶

    If higher accuracy is needed and the computational budget allows it, use a Multiplicative EKF (estimating the error in the 3-dimensional tangent space, which avoids the quaternion normalisation constraint).

    Sources: Markley F. L., "Attitude Error Representations for Kalman Filtering", Journal of Guidance, Control, and Dynamics, 26(2), 2003. Survey: Crassidis, Markley, Cheng, "Survey of Nonlinear Attitude Estimation Methods", JGCD 30(1), 2007.

    The matrix implementation uses CMSIS-DSP's arm_mat_* (Drivers/CMSIS/DSP/Source/MatrixFunctions/).

    3. Disturbance estimator — Extended State Observer (ESO)¶

    3.1 Why it is needed¶

    The filter of §2 estimates the state. It does not estimate the disturbance: gusts, a centre-of-gravity offset, thrust-model error, a sagging battery that reduces thrust. With PID alone these must be "chased" by the integral term — slowly and with overshoot. The ESO estimates them directly and compensates them in the control law.

    3.2 Formulas¶

    Consider one axis (for example the roll rate) of the form:

    y_dot = b0 * u + f(t)                                          (6)

    f(t) = total disturbance (everything not modelled), b0 = known nominal gain.

    Extend f as a state: x1 = y, x2 = f. Second-order observer:

    x1_hat_dot = x2_hat + b0*u + l1*(y - x1_hat)                   (7)
x2_hat_dot =                 l2*(y - x1_hat)                   (8)

    3.3 Choosing l1, l2 — closed form, no trial-and-error¶

    Characteristic polynomial of the observer error: s^2 + l1*s + l2. Place all poles at -wo (Gao's bandwidth parameterisation):

    s^2 + l1*s + l2 = (s + wo)^2
=>  l1 = 2*wo
    l2 = wo^2                                                  (9)

    Only one tuning parameter remains: wo (observer bandwidth, rad/s). Rule of thumb: set wo ≈ 3..10 times the control-loop bandwidth, and keep wo well below the sampling frequency (wo << 2*pi*fs) so that the discretisation remains valid.

    Sources:

    • Han J., "From PID to Active Disturbance Rejection Control", IEEE Transactions on Industrial Electronics, 56(3), 2009, pp. 900–906 — the ESO and total-disturbance concepts.
    • Gao Z., "Scaling and Bandwidth-Parameterization Based Controller Tuning", Proceedings of the American Control Conference, 2003, pp. 4989–4996 — formula (9).
    • Guo B.-Z., Zhao Z.-L., "On the convergence of an extended state observer for nonlinear systems with uncertainty", Systems & Control Letters, 60(6), 2011, pp. 420–430 — convergence proof.

    3.4 Compensation law¶

    u = ( u0 - x2_hat ) / b0                                       (10)

    u0 is the output of the controller of §4. Substituting (10) into (6):

    y_dot = b0 * (u0 - f_hat)/b0 + f  =  u0 + (f - f_hat)  ≈  u0

    After compensation the plant becomes a pure integrator — the controller of §4 only needs to be designed for that simple nominal system. That is why the ESO is worth using.

    3.5 Discretisation¶

    Application/Control/Src/eso.c uses an exact ZOH, with coefficients precomputed at configuration time. The full derivation is in that file's header comment; the key point is that A has the double eigenvalue -wo, so A + wo*I is nilpotent (its square is zero), which truncates the exponential series after the first-order term:

    Ad = exp(-wo*Ts) * [[1 - wo*Ts,  Ts       ],
                    [-wo^2*Ts,   1 + wo*Ts]]
Bd = [ b0*E*Ts ;  b0*(E*(1 + wo*Ts) - 1) ]           E = exp(-wo*Ts)
Ld = [ 1 - E*(1 - wo*Ts) ;  wo^2*Ts*E ]

    Expanding to first order in Ts gives back exactly the forward-Euler formulas — checked in tests/host/test_eso.c.

    3.6 The wo*Ts constraint — stable does NOT mean accurate¶

    This is the most common pitfall with an ESO, and it has been measured numerically in tests/host/test_eso.c::test_accuracy_requires_small_wo_ts:

    wo*Ts f_hat (true disturbance = 1.0) Error
    5.00 0.17 83 %
    0.50 0.98 2 %
    0.05 1.0001 0.01 %

    Why: the eigenvalue of Ad is exp(-wo*Ts) < 1 for every Ts > 0, so the observer never diverges — the advantage of ZOH over forward Euler (which goes unstable for wo*Ts > 2). But the ZOH discretisation treats y as an input held constant over each period, while the real y varies continuously. When wo*Ts is large the observer converges within a single period and never "sees" the intra-period variation, so the disturbance estimate is systematically low.

    Practical consequence: an ESO that "runs stably, with no NaN and no divergence" can still be 80 % wrong. wo*Ts must be checked numerically, not by looking at a plot. Rule: keep wo*Ts <= 0.1. At 1 kHz (Ts = 1 ms) this limits wo <= 100 rad/s.

    Application/Interface/Inc/airframe_config.h sets ESO_WO_RATE = 100.0f, i.e. wo*Ts = 0.1 at 1 kHz — exactly at the limit. A higher wo requires a correspondingly faster rate loop.

    4. Controller¶

    4.1 Three-tier architecture: primary MPC — reflex PID — motor FOC¶

       [MPC]  primary, 50 Hz          planning, explicit constraint handling
     │    Application/Control/mpc.c
     │    produces the desired acceleration → converted to tilt + thrust
     ▼
 ┌─────────────────────────────────────────────┐
 │  [SUPERVISOR]  arbiter                      │  supervisor.c
 │  MPC fresh & nominal → follow the MPC       │
 │  surprise → DISCARD the plan, PID handles it│
 │  MPC stale → PID runs alone                 │
 └─────────────────────────────────────────────┘
     │
     ▼
   [PID]  secondary = REFLEX, 1 kHz    always running, never plans
     │    attitude_filter → eso → rate_loop (pid.c)
     ▼
   [mixer] → [ESC, bidirectional DShot300]
                    │
                    └─ [FOC]  inside the ESC, with an encoder
                              foc.c is a reference implementation, not run on the MCU

    Time-scale separation principle: an inner loop must be at least 3–5 times faster than the outer loop before it can be treated as "ideal" when designing the outer loop. The ratios 1000/250/50 Hz all satisfy this.

    Tier Rate Role In Out
    MPC 50 Hz primary — look-ahead, constraints p, v, reference trajectory desired acceleration
    Attitude 250 Hz intermediate q_sp, q_hat omega_sp
    PID + ESO 1000 Hz secondary — reflex omega_sp, omega_meas torque tau
    FOC ~20 kHz inside the ESC iq_ref, encoder 3 duty cycles

    Attitude loop (250 Hz) — attitude_ctrl.c: a P law on the error quaternion Ω = sat(2 sgn(q_e.w) K ⊙ q_e.v), q_e = q̂⁻¹ ⊗ q_sp (Wie, Weiss & Arapostathis 1989), Lyapunov function V = 1 − |q_e.w|, K_i = ω_c,rate,i / 5 with ω_c,rate computed exactly from the PID + b0. The set-point comes from the MPC on the Jetson through micro-ROS and passes through cmd_guard.c (validation, 0.1 s timeout, bounded failsafe). Full derivation and proof: docs/MICROROS_ETHERNET.md §4–5.

    4.1b Why the PID is a "reflex" and not merely the inner loop¶

    The MPC looks ahead and respects constraints, but it is slow and can miss its deadline. The PID does not look ahead but is always present and reacts instantly.

    supervisor.c decides whom to follow. Three modes:

    Mode When Set-point given to the PID
    MPC_ACTIVE the plan is fresh and the situation is nominal the MPC's
    REFLEX the error jumps, or the estimated disturbance jumps, or a measurement fails a safe value
    PID_ONLY MPC stale / no plan yet the last good value

    The easiest thing to get wrong — why the plan must be DISCARDED in a reflex:

    When something unexpected happens (a strong gust, a collision, a lost rotor), the current MPC plan was computed for a world that no longer exists. Continuing to execute it is not just useless but harmful: it pulls the aircraft towards a trajectory that is no longer feasible.

    So REFLEX is not "blending MPC and PID" — it drops the MPC output entirely, lets the PID handle the situation, and forces the MPC to re-plan from scratch (supervisor_should_reset_plan() signals this for exactly one cycle).

    Hysteresis and dwell time: entering the reflex mode uses a high threshold; leaving it uses a lower one, which must be held continuously for dwell_cycles cycles. These two mechanisms prevent toggling when the error oscillates around a threshold — chattering at the arbiter level is more dangerous than choosing the wrong mode, because it makes the output jump continuously. supervisor_init() rejects a configuration with an exit threshold ≥ the entry threshold for exactly this reason.

    The estimated disturbance is also a reflex input, not only the tracking error: a jump in the ESO disturbance signals that the world has just changed even before the tracking error has had time to grow. Catching it one cycle earlier is worth it.

    4.1c MPC — condensed form and time budget¶

    Implementation: Application/Control/Src/mpc.c + qp_solver.c.

    Model: a double integrator per axis, with acceleration as the input. The three axes decouple at small tilt angles — true in normal flight. During aggressive manoeuvres the decoupling assumption no longer holds, and that is precisely one of the moments when the reflex tier must take over.

    Condensed form: the state variables are eliminated, leaving only the input sequence as the decision variable:

    X = Ψ x₀ + Φ U
J = (X − X_ref)ᵀ Q̄ (X − X_ref) + Uᵀ R̄ U  =  ½ Uᵀ H U + gᵀ U + const

H = 2(ΦᵀQ̄Φ + R̄)          ← depends only on parameters, COMPUTED ONCE at initialisation
g = 2ΦᵀQ̄(Ψx₀ − X_ref)     ← rebuilt every cycle, O(N²)

    For a double integrator, Ψ and Φ have a closed form; no matrix powers are needed:

    Ψ:  p_k = p₀ + k·Ts·v₀ ,  v_k = v₀
Φ:  effect of u_j on state k (k > j), with m = k−j−1:
    on position = Ts²(m + 0.5)
    on velocity = Ts

    The reference trajectory must be consistent over the whole horizon: p_ref_k = p_ref + k·Ts·v_ref. Holding p_ref fixed while v_ref ≠ 0 is a self-contradictory request (one cannot both stay at p_ref and move at v_ref) and causes a constant tracking lag that can never be removed — not because an integral term is missing but because the problem is posed wrongly. Locked in by test_mpc.c::test_tracks_moving_reference.

    Constraints: box constraints on the input (|u| ≤ a_max, derived from the maximum tilt: a_max = g·tan(θ_max)) are handled exactly. Constraints on the state (for example |v| ≤ v_max) are not boxes in U and cannot be included — the velocity is penalised in the cost through q_vel instead. This is a real limitation of the approach, not an oversight: adding state constraints would break the iteration bound and with it the real-time guarantee.

    4.1d QP solution with a bounded iteration count¶

    An interior-point or active-set solver is fast in most cases, but nobody can bound its worst case. In a flight control loop what matters is not the average but the ceiling: one overrun cycle is one cycle without a control command.

    Nesterov's fast gradient method with a constant step has a provable linear convergence rate:

    f(z_k) − f* ≤ (1 − √(μ/L))ᵏ · (f(z₀) − f*)

    From this the number of iterations needed for a given accuracy can be derived (qp_required_iterations()) and — more importantly — a fixed iteration count can be set directly with the maximum error known in advance. That trades bounded accuracy for a deterministic run time.

    Eigenvalue bounds by Gershgorin instead of computing the true eigenvalues (too expensive every cycle):

    λ_max ≤ max_i ( H_ii + Σ_{j≠i} |H_ij| )
λ_min ≥ min_i ( H_ii − Σ_{j≠i} |H_ij| )

    Using the upper bound as L is safe: a step smaller than the optimal step converges more slowly but still converges. Conversely, a step larger than 1/λ_max makes the method diverge.

    The most important safety property: the fast gradient method projects every iterate onto the box, so the returned solution is always feasible even when the iterations run out — it may only be sub-optimal. In flight control, a feasible, slightly sub-optimal command is far better than no command at all.

    Sources:

    • Nesterov Y., "A method of solving a convex programming problem with convergence rate O(1/k²)", Soviet Math. Doklady, 27(2), 1983.
    • Nesterov Y., Introductory Lectures on Convex Optimization, Kluwer, 2004, §2.2.
    • Richter S., Jones C. N., Morari M., "Computational Complexity Certification for Real-Time MPC With Input Constraints Based on the Fast Gradient Method", IEEE TAC, 57(6), 2012.
    • Gershgorin S. A., "Über die Abgrenzung der Eigenwerte einer Matrix", Izv. Akad. Nauk SSSR, 1931.
    • Maciejowski J. M., Predictive Control with Constraints, Prentice Hall, 2002, Ch. 3.

    4.2 Discrete PID — implementation form¶

    Parallel form with a filtered derivative (a pure derivative amplifies high-frequency noise without bound):

    P(k) = Kp * e(k)
I(k) = I(k-1) + Ki * Ts * e(k)                     (rectangular integration)
D(k) = (Td/(Td + N*Ts)) * D(k-1)
       - (Kp*Td*N/(Td + N*Ts)) * (y(k) - y(k-1))   (derivative on the MEASUREMENT, not on the ERROR)

    with Td = Kd/Kp (derivative time). The high-frequency gain of the D term is bounded at Kp*N.

    Two mandatory details:

    1. The derivative acts on the measured signal y, not on the error e. On e, every set-point change would produce an unbounded derivative spike ("derivative kick").
    2. The filter coefficient N (typically 8–20) bounds the high-frequency gain of the D term at Kp*Kd*N. Without N, gyro noise is amplified straight into the motors.

    4.3 Integrator anti-windup — back-calculation¶

    When the output saturates, the integral keeps accumulating and the system loses control when it leaves saturation. Back-calculation is used:

    u_unsat = P + I + D
u       = sat(u_unsat, u_min, u_max)
I       = I + (Ts/Tt) * (u - u_unsat)                          (11)

    Tt = tracking time constant, recommended Tt = sqrt(Ti * Td) (geometric mean).

    Source: Åström K. J., Hägglund T., Advanced PID Control, ISA, 2006 — Chapter 3 (implementation form, derivative filtering, coefficient N) and Section 3.5 (back-calculation anti-windup, formula (11) and the choice of Tt).

    4.4 Tustin discretisation of the filter stages¶

    Every linear filter in the chain uses the bilinear transform:

    s  ->  (2/Ts) * (z-1)/(z+1)

    Tustin preserves stability (it maps the left half-plane into the unit circle) — the decisive advantage over forward Euler, which can turn a stable continuous system into an unstable discrete one when Ts is large. When the cut-off frequency must match exactly, pre-warping is used: w_d = (2/Ts)*tan(w_a*Ts/2).

    Source: Franklin, Powell, Workman, Digital Control of Dynamic Systems, 3rd ed., Chapter 4.

    4.5 Other controller options¶

    The project is not limited to PID. Choose according to the requirements and the computational budget:

    Controller When to use it Source
    Cascade PID Default, lightweight, good enough for stable flight Åström & Hägglund, Advanced PID Control, 2006
    LQR Optimal error/energy trade-off around hover; the DARE is solved offline and the online part is just the matrix product u = -K x Anderson B.D.O., Moore J.B., Optimal Control: Linear Quadratic Methods, Prentice-Hall, 1990
    Geometric control on SE(3) Large angles, aerobatics, aggressive trajectory tracking — avoids Euler singularities entirely, with an exponential stability proof Lee T., Leok M., McClamroch N.H., "Geometric Tracking Control of a Quadrotor UAV on SE(3)", IEEE CDC, 2010

    4.6 FOC — control tier of an encoder-equipped BLDC motor¶

    Implementation: Application/Control/Src/foc.c, verified in tests/host/test_foc.c.

    Why FOC rather than six-step control: six-step (trapezoidal) control energises only 2 of the 3 phases at any time, so the current vector jumps in 60° steps → noticeable torque ripple and acoustic noise. FOC keeps the current vector always perpendicular to the rotor flux, giving smooth torque and maximum torque per ampere.

    Why an encoder is mandatory: the Park transform needs the electrical angle of the rotor. Sensorless estimation (based on the back-EMF) does not work at very low speed and at start-up, because the back-EMF is proportional to speed and tends to zero. An encoder gives the absolute angle at every speed, standstill included.

    Transform chain¶

    ia, ib (ADC) → [Clarke] → α,β → [Park θ] → d,q
                                             ↓
                              [d-axis PI: id_ref = 0]
                              [q-axis PI: iq_ref ∝ torque]
                                             ↓
                           [limit |v| ≤ Vdc/√3] → [Park⁻¹] → [SVPWM] → 3 duty cycles
                                             ↓
                        inverter bridge → motor → encoder → back to Park

    Clarke convention: amplitude-invariant¶

    iα = ia
iβ = (ia + 2·ib) / √3          (using ia + ib + ic = 0)

    Only two phases need to be measured — which is why the circuit needs only two shunt resistors.

    There are two Clarke conventions. The project uses the amplitude-invariant one: the magnitude of the α-β vector equals the phase-current amplitude, readable directly in real amperes. The power-invariant convention (an extra factor √(2/3)) gives an orthogonal matrix but scales the torque differently. Mixing the two conventions is a classic bug that makes the torque constant wrong by a factor of √(3/2).

    SVPWM by zero-sequence injection (min–max)¶

    Instead of determining the sector and computing dwell times as in classical SVPWM, compute the three phase voltages and subtract the midpoint of their maximum and minimum:

    vcom = (max(va,vb,vc) + min(va,vb,vc)) / 2
duty_x = 0.5 + (v_x − vcom) / Vdc

    The result is identical to classical SVPWM, with no sector determination and no trigonometric tables.

    The subtraction shifts all three phase voltages by the same amount, so the line-to-line voltages are unchanged — and the motor only sees line-to-line voltages — while the required amplitude decreases. The maximum phase amplitude therefore reaches Vdc/√3 instead of Vdc/2 for sinusoidal PWM, i.e. a bus utilisation 2/√3 = 1.1547 times better (+15.47 %).

    This figure is measured numerically in test_foc.c::test_svpwm_bus_utilisation: the amplitude is increased until the modulation index reaches its limit at an arbitrary angle, and the result lands exactly on Vdc/√3.

    Voltage limiting by vector magnitude¶

    Beyond Vdc/√3 the inverter enters over-modulation: distorted waveforms, high-order harmonics, torque no longer proportional to iq. When the vector must be shrunk, it is scaled by its magnitude rather than clamping each component separately — separate clamping changes the angle of the voltage vector, i.e. the direction of the torque. Locked in by a test.

    Encoder angle-offset calibration¶

    The encoder's zero does not coincide with the rotor's d axis. Procedure (run once, motor unloaded):

    1. Force a voltage vector along a fixed d direction (vd > 0, vq = 0, θ = 0).
    2. The rotor aligns itself with the d axis and comes to rest.
    3. Read the encoder count at that position → that is the offset.

    With a wrong value the torque falls as cos(error) and reverses beyond 90° electrical. The value obtained should be stored in FRAM (already on the board) so that calibration is not repeated at every start-up.

    Known limitation¶

    At high speed the d and q axes are coupled through the ω·L·i terms (cross-coupling). Feed-forward decoupling of those terms is the next upgrade; for now the two PI loops have to reject them as a disturbance. This is acceptable over a drone's normal operating speed range.

    Sources¶

    • Park R. H., "Two-reaction theory of synchronous machines", AIEE Transactions, 48, 1929 — the original d-q transform.
    • Clarke E., "Circuit Analysis of A-C Power Systems", Vol. I, Wiley, 1943 — the α-β transform.
    • van der Broeck, Skudelny, Stanke, "Analysis and Realization of a Pulsewidth Modulator Based on Voltage Space Vectors", IEEE Trans. Industry Applications, 24(1), 1988 — SVPWM.
    • Bose B. K., Modern Power Electronics and AC Drives, Prentice-Hall, 2002, Chapter 8.

    5. Control allocation (mixer)¶

    5.1 Rotor model¶

    For each rotor i spinning at angular speed w_i:

    thrust        T_i  = k_f * w_i^2
drag torque   Q_i  = k_m * w_i^2

    This quadratic relation comes from propeller momentum theory: thrust is proportional to rho * A * (w*R)^2 with a thrust coefficient C_T that is nearly constant in normal operation.

    Source: Leishman J. G., Principles of Helicopter Aerodynamics, 2nd ed., Cambridge University Press, 2006, Chapter 2 (momentum theory, definitions of C_T, C_Q).

    k_f and k_m must be MEASURED; guessed values are not acceptable. See §5.4.

    5.2 Allocation matrix for a quad-X¶

    Standard rotor numbering: 1 = front-right (CCW), 2 = rear-left (CCW), 3 = front-left (CW), 4 = rear-right (CW). Arm length l (centre → rotor), projected half-diagonal d = l/sqrt(2).

    With x_i = w_i^2:

    [ T     ]   [  k_f      k_f      k_f      k_f   ] [ x1 ]
[ tau_x ] = [ -d*k_f    d*k_f    d*k_f   -d*k_f ] [ x2 ]        (12)
[ tau_y ]   [  d*k_f   -d*k_f    d*k_f   -d*k_f ] [ x3 ]
[ tau_z ]   [ -k_m     -k_m      k_m      k_m   ] [ x4 ]

    (The signs of the tau_z row follow the direction of rotation: a CCW rotor produces a reaction torque in the negative z direction, a CW rotor in the positive direction.)

    For a quad-X this matrix M is invertible (det M != 0 when k_f, k_m, d != 0), so:

    x = M^(-1) * [T, tau_x, tau_y, tau_z]^T                        (13)
w_i = sqrt( max(x_i, 0) )                                       (14)

    M^(-1) is computed once at initialisation, never inside the loop.

    5.3 General case and saturation¶

    With more than 4 rotors (hexa, octo), M is 4 x n and the problem is under-determined. The Moore–Penrose pseudo-inverse M^+ = M^T (M M^T)^(-1) gives the minimum 2-norm solution, equivalent to minimising the sum of w_i^2 (an approximation of the energy).

    When the solution violates the bounds [x_min, x_max], the elements must not be clipped independently — that breaks the ratios between the torques and can reverse a torque. An allocation algorithm with saturation handling is required (giving priority to tau over T, because losing torque flips the aircraft whereas losing thrust only costs altitude).

    Source: Johansen T. A., Fossen T. I., "Control allocation — A survey", Automatica, 49(5), 2013, pp. 1087–1103.

    5.4 Measuring k_f, k_m — mandatory before flight¶

    A thrust stand with load cells for force and torque is required, plus a rotor-speed sensor (or an ESC with telemetry).

    1. Run the rotor at a series of steady speeds w_j (for example 10 points covering the whole range).
    2. Record (w_j, T_j, Q_j) in steady state.

    3. Fit a linear least-squares line through the origin in the variable u = w^2: 

      k_f = sum(u_j * T_j) / sum(u_j^2)
k_m = sum(u_j * Q_j) / sum(u_j^2)

    4. Check R^2 > 0.98. If lower, the quadratic assumption does not hold over that range (usually because of ground effect or the rotor entering the vortex-ring state) — narrow the range or use a higher-order model.

    Record the results in Application/Interface/Inc/airframe_config.h. Never commit sample values as if they were measured values.

    6. Closed loop — the open segment closed by bidirectional DShot¶

    Design update. The first version of this document stated that ESC command → rotor speed was the only open segment of the system, because with PWM/OneShot the firmware cannot know whether a rotor reached the requested speed. The project has adopted bidirectional DShot, so that open segment no longer exists.

    6.1 How the loop is closed¶

    Bidirectional DShot makes the ESC return the actual electrical period after every frame. From it:

    period [µs] = mantissa << exponent          (12 bits: eee mmmmmmmmm)
eRPM        = 60e6 / period
mech. RPM   = eRPM / (pole count / 2)

    Implementation: Application/Control/Src/dshot.c, verified in tests/host/test_dshot.c against reference values computed independently from the specification.

    The chain thereby becomes fully closed at every tier:

    throttle command → ESC → rotor → measured actual RPM → back to the controller

    6.2 Consequence for the speed → throttle map¶

    A linear w ↔ throttle map is still only an approximation (ESCs are linear in throttle, not in rotor speed, and the characteristic depends on load, battery voltage and temperature). But its error no longer matters: the actual RPM is read back every cycle, so the map serves only as a feed-forward — a starting point for the feedback loop to correct, not an assumption that has to be right. That feedback loop is designed in §6.6.

    6.3 Three states that must be distinguished, never merged¶

    This is the easiest place to make a mistake, and it is pinned down by a test:

    State Meaning Required behaviour
    valid && !stopped actual RPM read used by the feedback loop
    valid && stopped the ESC reports the rotor has stopped RPM = 0, treated as a genuinely stopped rotor
    !valid wrong CRC / corrupted GCR quintet — nothing is known must not be treated as RPM = 0

    Treating a corrupted frame as RPM = 0 would make the controller believe the rotor had stopped and drive the command to full scale — exactly when nothing is known about that rotor. test_dshot.c::test_stopped_vs_invalid locks this behaviour in.

    6.4 Additional feedback sources¶

    • INA260 (Drivers/JetOwl/Inc/Adafruit_INA260.h): current is a proxy for torque (Q ≈ k_t · I for a BLDC). It cannot replace the RPM measurement but detects a jammed or lost rotor.
    • The outer loop through the IMU remains independently closed: a rotor that does not reach its speed shows up as an angular-rate error that the rate loop compensates. This is the second line of protection and keeps working even if the telemetry fails completely.

    6.5 Conditions for the telemetry to work¶

    The ESC must run firmware with bidirectional DShot enabled (BLHeli_32, Bluejay). Otherwise:

    • the ESC never answers, and
    • the inverted CRC of bidirectional mode makes the ESC drop every frame → the motor does not turn at all.

    That is the typical symptom of a wrong BOARD_ESC_BIDIRECTIONAL flag, easily mistaken for a wiring fault.

    6.6 Rotor-speed loop from RPM telemetry¶

    Implementation: Application/Control/Src/rotor_speed.c (pure maths, host test tests/host/test_rotor_speed.c), called from the 1 kHz tick interrupt in flight_control.c::rotor_step right after rate_loop_update. One instance per rotor.

    w_ref (mixer) ─► reference model r_m ─► FF = model inverse ────────┐
                     │                                               ▼
                     └► delay D, LPF ─► r_cmp ─(+)─► PI (SIMC) ─(+)─► clamp ─► DShot ─► ESC ─► rotor
                                          ▲(−)                                                 │
                                          └── LPF 150 Hz ◄── RPM telemetry (previous frame) ◄──┘

    Plant model¶

    Torque balance on the rotor shaft [35]: J ẇ = a_u (u − u0) − b w − k_m w² (b = K_t K_e / R, k_m the propeller drag-torque coefficient). Linearised around w0:

    G(s) = K e^(−θs) / (τ s + 1),   τ = J / (b + 2 k_m w0),   K = a_u / (b + 2 k_m w0)

    An important consequence: K/τ = a_u/J does not depend on the operating point. At the crossover frequency (ω ≫ 1/τ) L(jω) ≈ Kc K / (τ jω) depends only on K/τ, so one set of gains serves the whole speed range — the operating point only changes the low-frequency part, which the integrator takes care of. A non-linear simulation at 200, 500 and 1100 rad/s (τ varying 20–58 ms, K varying 0.37–1.07) confirms this.

    Delay θ = Ts/2 (command ZOH) + Ts (the RPM used in cycle k is the response to frame k−1) + T_e/2 (the ESC averages over one electrical period, ~0.43 ms at 10 000 RPM with 14 poles) ≈ 1.9 ms → 2 ms is used.

    Measurement filter¶

    The RPM is quantised (1 µs electrical period, 9-bit mantissa) → white noise of a few rad/s, multiplied by Kc ≈ 8 count/(rad/s). First-order filter f_c = 150 Hz, ZOH discretisation [8]: y[k] = y[k−1] + a (x[k] − y[k−1]), a = 1 − e^(−Ts/τ_f). Criteria: f_c ≥ 5·f_crossover,rotor (24.7 Hz) → phase lag at crossover atan(1/5) ≤ 11.3° (9.4° in practice), and f_c < f_s/2. τ_f is the smallest neglected time constant, so by Skogestad's half rule [33]: τ_eff = τ + τ_f/2, θ_eff = θ + τ_f/2 — and SIMC uses (τ_eff, θ_eff).

    Controller — two degrees of freedom¶

    The first version used u = u_ff(w_ref) + PI(w_ref − w_meas). Simulation showed 17–20 % overshoot even with a correct feed-forward: the FF already supplied the throttle needed for the step, and the P term added Kc·Δw on top for the same step. The standard solution is a two-degree-of-freedom structure [36], [7]:

    (a) reference model:   r_m[k+1] = r_m[k] + a_m (w_ref[k] − r_m[k]),   a_m = 1 − e^(−Ts/τ_c)
(b) FF = exact inverse of the ZOH model  w[k+1] = p w[k] + (1−p) K u[k],  p = e^(−Ts/τ):
        u_ff[k] = S(r_m[k+1]) + g_d (r_m[k+1] − r_m[k]),     g_d = p / ((1−p) K)
(c) r_cmp = LPF( r_m delayed by D = θ/Ts + ½ sample, linear interpolation )   — the EXPECTED measurement
(d) PI on e = r_cmp − w_filtered:
        u = u_ff + Kc e + I,   u_sat = clamp(u, 48, 2047)
        I ← I + (Kc/Ti) Ts e + (Ts/Tt)(u_sat − u)                 (back-calculation [7], Tt = Ti/2)

    S is the static inverse of the model: in steady state a_u (u − u0) = b w + k_m w², so S(w) = c0 + c1 w + c2 w² with c0 = u0, c1 = b/a_u, c2 = k_m/a_u. It must be monotonically increasing on [w_min, w_max] (rotor_speed_init checks both end points). g_d ≈ τ/(K Ts) = J/(a_u Ts) — also independent of the operating point. With a correct model, r_cmp matches the measurement and the feedback barely acts (test: |e| ≤ 0.05 rad/s after a 50 rad/s step); (a)–© are outside the loop and do not change the stability margins.

    SIMC gains [33], [34]:

    Kc = τ_eff / (K (τ_c + θ_eff)),     Ti = min(τ_eff, 4 (τ_c + θ_eff))

    τ_c is squeezed between two constraints:

    Constraint Reason Value
    τ_c ≥ θ_eff SIMC recommendation for a fast/robust compromise [33] θ_eff = 2.53 ms
    τ_c + θ_eff ≤ 1/(5 ω_c,rate) the rate loop treats the actuator as ideal (5× separation, [27]) 1/(5·15.78) = 12.7 ms

    τ_c = 4 ms is chosen → Kc = 8.50 count/(rad/s), Ti = 26.1 ms.

    Stability margins — computed on the actual DISCRETE loop¶

    test_rotor_speed.c::test_margins evaluates L(e^{jωTs}) = C(z)·F(z)·G(z)·e^{−jω·0.43 ms} with a forward-Euler PI, a ZOH LPF, the exact ZOH plant and the z⁻¹ of previous-frame telemetry — using the very macros in airframe_config.h:

    Case ω_c [rad/s] PM GM
    Nominal 152 65.6° 13.8 dB
    Worst of the 4 corners ±20 % K, τ — 58.0° 10.4 dB
    Worst ±20 %, 1 telemetry frame lost (+1 Ts delay) — 45.2° 6.6 dB
    Worst ±20 %, 2 frames lost (+2 Ts delay) — 32.4° ✗ 4.1 dB ✗

    Requirement of control-systems §4: GM ≥ 6 dB, PM ≥ 45° — met by the first three rows.

    The sample-age limit ROTOR_MEAS_TIMEOUT_S = 2.5 ms follows directly from the last two rows: the normal age is 1 Ts and each lost frame adds 1 Ts of delay; one lost frame still meets the requirement, two do not → only ages ≤ 2 Ts are accepted. The limit sits between 2 Ts and 3 Ts so that it does not depend on floating-point rounding; beyond it → FF_ONLY.

    Time response (non-linear plant, test_nonlinear_steps)¶

    Identified FF, plant a_u off by ±10 % (battery sag):

    Step Overshoot 2 % settling Steady-state error
    200 → 400 rad/s ≤ 0.3 % 18 ms < 0.03 rad/s
    500 → 800 rad/s 0 % 39–44 ms (dynamic FF saturates — a physical limit) < 0.03 rad/s
    1100 → 900 rad/s 0 % 19–22 ms < 0.03 rad/s

    Default linear FF (not identified, c2 = 0): overshoot ≤ 3.8 %, settling ≤ 49 ms — the integrator absorbs the mismatch. Quantisation noise ±3 rad/s: peak-to-peak throttle ripple 41 counts (< Kc·6 = 51 without filtering). Saturation for 0.5 s at w_ref = W_MAX, then back to 600 rad/s: I is bounded (back-calculation) and recovers in 69 ms.

    When no usable feedback exists¶

    Condition Mode Behaviour
    RPM valid, age ≤ timeout, not stopped CLOSED (a)–(d)
    No RPM / stale (wrong CRC, ESC not answering, plain DShot) FF_ONLY u = u_ff + I, I frozen; the filter re-initialises from the first sample when telemetry returns
    ESC reports stopped (below the measurable range, during sensorless start-up) STARTUP as FF_ONLY — the model G(s) does not hold in this region
    stopped continuously for > ROTOR_STALL_TIME_S while armed STALLED S(w_ref) only, no PI — no throttle pushed into a jammed motor; cleared only on disarm; /jetowl/status reports ERROR rotor stalled

    FF_ONLY with BOARD_ESC_BIDIRECTIONAL = 0 is a justified open loop: no rotor-speed sensor exists. The rate loop on the IMU remains closed around it (§6.4). Monitoring: rotor_closed_mask, rotor_stall_mask in /jetowl/status; fc_telemetry_t carries rotor_mode, rotor_w_ref, rotor_err, rotor_u for logging.

    Identification procedure — mandatory before flight¶

    On a thrust stand, propeller fitted, battery full, reading the RPM through /jetowl/motor_rpm (50 Hz) or a 1 kHz log:

    1. Static map S: ≥ 10 throttle levels u_j evenly spread over 10–90 %, each held ≥ 5τ (≥ 0.3 s), averaging w_j over the last 0.2 s. Least squares u_j ≈ c0 + c1 w_j + c2 w_j² (linear in the parameters). Check R² > 0.99 and monotonicity → ROTOR_FF_C0/C1/C2.
    2. K, τ, θ: ±5 % throttle steps around mid-range; fit w(t) = w0 + K Δu (1 − e^{−(t−θ)/τ}) (tfest/procest or non-linear least squares); report the fit (%). Repeat at 3 operating points and check that K/τ is nearly constant (the assumption of §6.6) → ROTOR_K_PLANT, ROTOR_TAU, ROTOR_THETA.
    3. ROTOR_STALL_TIME_S: measure the time from arming until rotor_mode leaves STARTUP over 20 arming cycles; set it to ≥ 2× the largest value.
    4. Re-run ctest — test_rotor_speed recomputes the margins with the new constants and must still PASS.

    7. Timing and discretisation¶

    Every discrete formula above assumes a fixed Ts. That assumption breaks if HAL_Delay() or a free-running loop is used.

    Mandatory requirements:

    • The tick comes from a TIM interrupt, not from a while(1) loop.
    • Never call HAL_Delay() in any function that runs in the control loop.
    • Measure the actual jitter (record max|Ts(k) - Ts_nominal|). If the jitter exceeds ~1 % of Ts, it must be fixed before trusting the control results.
    • Blocking I2C/UART/SPI transfers must not be placed in the control-loop ISR — use DMA and read the result in the next cycle.

    Group Rate Work
    A 1000 Hz gyro read, ESO, rate loop, mixer, ESC write
    B 250 Hz accel/mag read, attitude filter, attitude loop

    9. Limitations of this design¶

    An honest account of what has not been done yet:

    • k_f, k_m, l and the inertia matrix J have no real values yet — they must be measured on the specific airframe (§5.4). Every constant in airframe_config.h is currently a sample value for testing, not for flight.
    • The PID/LQR gains are not tuned — an identified model or bench experiments are required.
    • The rotor-speed loop (§6.6) uses sample K, τ, θ, S — the stability margins are computed correctly for those numbers, but they must be re-identified on the real motor + propeller with the procedure of §6.6.
    • There is no detailed aerodynamic model yet (body drag, ground effect, rotor interaction).
    • Safety logic is not implemented yet: signal-loss failsafe, low-battery detection, geofence.
    • The mathematics is tested on the host (tests/host/); the parts running on hardware are not yet verified.
