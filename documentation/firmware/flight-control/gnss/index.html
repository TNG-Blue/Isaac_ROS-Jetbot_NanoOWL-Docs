    GNSS: two receivers, front end, /gps/fix and the LoRa position pages¶

    Source

    Snapshot of docs/GNSS.md from TNG-Blue/JetOwl_FlightControl at commit ffcc11c (submodule Microcontroller/JetOwl_FlightControl). Regenerate with Scripts/mkdocs_hooks/snapshot_submodules.py after updating the submodule.

    Application/Control/Src/gnss_frontend.c, gnss_nmea.c, gnss_dual.c (pure C, host tests tests/host/test_gnss_frontend.c, test_gnss_nmea.c, test_gnss_dual.c), Application/Interface/Src/gnss_app.c (HAL glue, task gnss), sensor_bus.c (I2C1 mutex), the GNSS pages of Application/RfLink/ (RFLINK.md §6.2) and /gps/fix in uros_app.c.     1. Where the fix goes — and where it does not¶

    A  LG290P ──USART3 DMA idle-line──▶ WaveShare_GNSS.c (NMEA checksum, GGA/RMC/GSA)
           ──▶ gnss_frontend (cfg A: fault modes, σ_h = HDOP·σ_UERE) ────────────┐
B  L76K   ──I2C1 0x20 raw NMEA snapshot──▶ DFRobot_GNSS.c ──▶ gnss_nmea (GGA/GSA)  │
           ──▶ gnss_frontend (cfg B) ─────────────────────────────────────────────┤
                                                                                 ▼
           gnss_dual (pairing by UTC tag, χ² consistency, covariance intersection)
              ├──▶ /gps/fix (NavSatFix) ──▶ Jetson uav_state_estimator (ESKF, χ² gate)
              │        ──▶ odometry/filtered ──▶ MPC ──▶ /control/attitude_setpoint ──▶ FC
              └──▶ LoRa GNSS / GNSS_AUX pages ──▶ Remote_UAV ──▶ phone (map, Kalman filter)

    The FC has no position loop; GNSS never enters its own control law. The loop that uses the position is closed on the Jetson (ESKF → MPC → attitude set-point → FC attitude/rate loops → rotors → IMU/GNSS). The FC's job is the sensor interface of the control-systems rule (§2.1): the measurement model, its noise, its sample rate and its fault modes.

    2. Measurement model and fault modes¶

    y = [φ, λ, h] (WGS-84 latitude, longitude, ellipsoidal height) + v, v ~ N(0, R), with R from the dilution of precision (Kaplan & Hegarty, Understanding GPS/GNSS, 3rd ed., §11.2.1):

    cov(position) = σ_UERE² (GᵀG)⁻¹   ⇒   σ_h (DRMS) = HDOP·σ_UERE,   σ_v = VDOP·σ_UERE

    /gps/fix carries R as COVARIANCE_TYPE_APPROXIMATED, ENU-ordered (REP-145), with the horizontal variance split equally over east and north (σ_E² = σ_N² = σ_h²/2). Without VDOP (or PDOP, from PDOP² = HDOP² + VDOP²) the type is UNKNOWN and the ESKF uses its configured σ.

    Verdict Condition Why
    NO_FIX GGA quality 0 or no valid position no measurement
    NOT_MEASURED quality 6 (dead reckoning), 7 (manual), 8 (simulation) the receiver reports a number it did not measure
    FEW_SATS < 4 satellites x, y, z and the clock bias are 4 unknowns
    STALE older than 2.5 × the output period one lost sentence passes, two do not
    BAD_VALUE non-finite, |φ| > 90°, |λ| > 180°, HDOP ≤ 0 corrupted sentence that passed the checksum
    DISAGREE (6) the two receivers fail the χ² consistency test (§6) two sources cannot tell which one is wrong

    A refused epoch is still published, as STATUS_NO_FIX with NaN coordinates, so no consumer can mistake it for a measurement; on the LoRa page the position is INT32_MIN and the verdict code is in GNSS_AUX v2.

    3. σ_UERE — derivation of the defaults and how to identify it¶

    For a circular normal horizontal error with per-axis σ, the radius is Rayleigh-distributed: the median (CEP) is σ√(2 ln 2) = 1.1774 σ and DRMS = √2 σ, so DRMS = 1.2011 · CEP (checked by a 200 000-sample Monte Carlo in test_gnss_frontend.c). A datasheet CEP measured under open sky at HDOP ≈ 1 therefore gives σ_UERE ≈ 1.2011 · CEP (airframe_config.h §12).

    The defaults (1.0 m CEP code solution, 0.02 m CEP RTK fixed) are placeholders. Identify the real value before trusting the covariance:

    1. Put the antenna on a surveyed point (or average ≥ 24 h of RTK-fixed output as the truth).
    2. Log /gps/fix (or the raw NMEA) for ≥ 1 h, same fix class throughout.
    3. σ̂_UERE = RMS(horizontal error) / mean(HDOP); repeat per fix class.
    4. Write the values into GNSS_UERE_*_M and check the ESKF's GNSS NIS (estimator/diagnostics) stays inside its χ²(3) bounds on a flight log.

    4. Timing¶

    • LG290P NMEA output 1 Hz by default (GNSS_FIX_PERIOD_MS), 460 800 baud, DMA idle-line reception; the task polls every 20 ms (GNSS_APP_PERIOD_MS).
    • The fix is time-stamped at the instant its GGA sentence was parsed. The receiver's own output latency (fix epoch → first byte) is not published for the LG290P: it is a known bias, to be measured with the PPS pin against the UART (the ESKF tolerates a bias well below its gate: at 5 m/s, 50 ms is 0.25 m).
    • On the LoRa downlink the GNSS page is sent 3 times per second; the phone's display therefore shows a position at most 0.4 s + fix age old, and its Kalman filter predicts across the gap.

    6. Two receivers (gnss_dual.h)¶

    A: Waveshare LG290P B: DFRobot TEL0157
    Chip Quectel LG290P03, quad-band, RTK Quectel L76K, GPS + BeiDou + GLONASS L1
    Link USART3 460 800 Bd, DMA idle-line I2C1 0x20, raw NMEA snapshot every 200 ms
    σ_UERE per fix class, §3 2.0 m CEP × 1.2011 (DFRobot wiki), all classes

    Pairing. Both receivers compute their fix at the same GNSS-time epochs, so two fixes with the same GGA UTC tag measure the same instant. A new epoch waits for the other receiver's epoch with the same tag only while that receiver is alive (last epoch OK and younger than GNSS_MAX_AGE_MS) and behind, and at most B_POLL + RAW_PREP + B_XFER + APP_PERIOD = 200 + 100 + 50 + 20 = 370 ms — B's worst detection delay. Otherwise it is published alone. Output epochs are strictly monotone (an epoch not newer than the last published is dropped).

    Consistency test. d = x_B − x_A in the local NED frame of A (WGS-84 radii, Groves eqs. 2.105–2.106). Common-mode errors (atmosphere, ephemeris) correlate the two receivers positively, so cov(d) ≤ P_A + P_B and NIS = dᵀ(P_A + P_B)⁻¹d > χ²_k(0.999) has a false-alarm rate ≤ 10⁻³ (measured 0.00100 over 200 000 Monte Carlo pairs in test_gnss_dual.c). k = 3 when both give σ_v and the geoid separation (ellipsoidal heights then compare whatever geoid model each receiver uses), else k = 2. The antennas are up to GNSS_ANTENNA_SEP_M apart in an unknown direction: the most favourable admissible offset is taken, |d| → max(0, |d| − L). A failed pair is GNSS_DISAGREE: no fix for that epoch (the same rule as the two IMUs).

    Fusion: covariance intersection (Julier & Uhlmann, ACC 1997). P⁻¹ = w P_A⁻¹ + (1 − w) P_B⁻¹ is consistent for every unknown cross-correlation; w minimises tr P (closed form in gnss_dual.h, checked against a brute-force search). Treating the receivers as independent (information-form average) would publish a σ smaller than the real error when their errors are correlated — the Monte Carlo with ρ = 0.8 in test_gnss_dual.c shows the CI σ covers the error. Horizontal-only pairs have isotropic P_h, so w is 0 or 1: the receiver with the smaller σ_h is used.

    Driver corrections (DFRobot_GNSS.c) against the official library (DFRobot/DFRobot_GNSS getLat, getAlt, getGnssLen, getAllGnss):

    Quantity Before Official library (now) Error removed
    lat / lon DD + (MM·10⁵ + MMMMM)/10⁷ DD + MM/60 + MMMMM/10⁵/60 (MM = minutes) up to 0.4° ≈ 44 km
    alt / SOG / COG (H·256 + L) + X/10 ((H & 0x7F)·256 + L) + X/100 up to 8.91 m (X = 99), and 32 768 m when bit 7 of H is set
    raw NMEA start value 1, 20 ms wait, one read ≤ 256 B 0x55, 100 ms, chunks of 32 B read before the module is ready, truncated

    I2C1 is shared by the imu task (BNO08x, BNO055, BMP280) and the gnss task (TEL0157) through a priority-inheritance mutex (sensor_bus.h). The GNSS task holds it for one transaction at a time (≤ 0.79 ms, 5 ms HAL timeout), so the IMU's extra latency is bounded and its sample time (INT edge) is unaffected.

    7. CubeMX and status¶

    • USART3 on D0/D1 (board_config.h §2.2), 460 800 baud, RX DMA + IDLE interrupt (the driver uses HAL_UARTEx_ReceiveToIdle_DMA), RST on PD12. gnss_app.c owns HAL_UARTEx_RxEventCallback / HAL_UART_ErrorCallback.
    • TEL0157 on I2C1 (address 0x20, no conflict with 0x4A / 0x28 / 0x76 / 0x40 / 0x70), switch on the module set to I2C. It is initialised inside the gnss task (begin, enablePower, GPS + BeiDou + GLONASS); if it does not answer, receiver A runs alone.
    • GnssApp_Start() is called from app_freertos.c; it returns false while BOARD_CUBEMX_PERIPHERALS_READY = 0, and nothing is published.
    • Not verified on hardware: the LG290P sentence set at the configured rate, the output latency, σ_UERE of both receivers (§3), the L76K's output rate (1 Hz assumed, same as A — check that the GGA tags of A and B coincide in a log), the TEL0157 raw-NMEA content and GNSS_ANTENNA_SEP_M (measure on the airframe).
