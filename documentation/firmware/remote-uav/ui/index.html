    Display user interface (Remote_UAV)¶

    Source

    This page is rendered from Microcontroller/Remote_UAV/docs/UI.md, the authoritative description kept next to the code in Microcontroller/Remote_UAV/docs/.

    Code: src/ui/ (LVGL 9.2.2), src/net/connectivity.{h,cpp} (Wi-Fi / Bluetooth LE). Hardware-independent logic: src/ui/ui_logic.{h,c} (tested by tests/host/test_ui_logic.c). Full user-interface simulation on the host: tests/sim/ (section 9).

    GIGA Display Shield 800 × 480, GT911 capacitive touch, landscape by default: Arduino_H7_Video(800, 480, GigaDisplayShield) on the native 480 × 800 panel with LV_DISPLAY_ROTATION_270; LVGL rotates the touch coordinates by the same transform, so no manual coordinate mapping is needed.

    The on-screen text is in Vietnamese (section 10). This document gives the labels in English.

    1. Layout¶

    ┌──────────── status bar (swipe down from here) ─────── Wi-Fi BT Battery ┐
│ SAFE/ARMED │ ANGLE ▶ PILOT/JETSON │ UL FAIR │ DL GOOD                   │
├──────────────────────────┬─────────────────────────────────────────────┤
│ artificial horizon       │ telemetry: heading, thrust, TLM age,        │
│ (roll / pitch from FC)   │ UL/DL LQ RSSI SNR, margin, battery, RPM     │
├──────────────────────────┴─────────────────────────────────────────────┤
│ R ▭  P ▭  Y ▭  T ▭                    [Calibrate] [Next] [Cancel]      │
└────────────────────────────────────────────────────────────────────────┘

    Everything the screen says about the aircraft comes from measured telemetry (the closed-loop feedback to the pilot), never from the commands the remote has sent.

    LVGL layer Content File
    lv_screen_active() dashboard ui_dashboard.cpp
    lv_layer_top() Wi-Fi page, password page, Bluetooth page ui_wifi.cpp, ui_bt.cpp
    dimming layer + quick-settings drawer + top-edge strip ui_quick.cpp
    toast ui_common.cpp

    2. Quick-settings drawer (swipe down)¶

    Gesture Result
    Swipe down from the top edge (28 px) the drawer follows the finger; released past half way or flung down ⇒ opens
    Tap the Wi-Fi / Bluetooth tile on/off
    Long-press the Wi-Fi tile (400 ms) turn on if off, scan, open the network list
    Long-press the Bluetooth tile turn on if off, scan for 6 s, open the device list
    Swipe up on the drawer, or tap the dimmed area close

    2.1 Gesture constants¶

    Taken from Android ViewConfiguration (AOSP frameworks/base/core/java/android/view/ViewConfiguration.java), converted from dp to the pixels of this display:

    density:  √(800² + 480²) / 5.0 in = 186.6 ppi      1 dp = 1/160 in = 1.166 px
TOUCH_SLOP               8 dp   →  9.3 px    minimum movement that becomes a drag
MINIMUM_FLING_VELOCITY  50 dp/s → 58 px/s    release velocity that counts as a fling
status bar              24 dp   → 28 px      edge area that starts a drawer drag
DEFAULT_LONG_PRESS_TIMEOUT 400 ms            = LVGL's default long_press_time

    2.2 Drawer model¶

    Visible height h ∈ [0, H], H = 300 px.

    • Closed: press inside the edge area, h = clamp(y − y₀, 0, H).
    • Open: drag starting on the drawer, h = clamp(H + (y − y₀), 0, H).

    The release velocity v is a first-order low-pass filter of the difference Δy/Δt. Time constant τ = 50 ms, backward-Euler discretisation: a = Δt / (τ + Δt).

    Touch is read every Δt = 10 ms (UI_TOUCH_READ_MS, matching the GT911's ~100 Hz report rate), so a = 1/6:

    • A 1 px jitter on one sample (100 px/s in the difference) is reduced to ≤ 17 px/s, below the 58 px/s fling threshold.
    • A real fling (≥ 300 px/s) crosses the threshold after τ·ln(300/242) = 11 ms.

    Decision on release, as on Android:

    |v| ≥ v_fling  →  open = (v > 0)        (the fling direction wins)
otherwise       →  open = (h ≥ H/2)

    After release the drawer animates to its final position in 200 ms (Android config_shortAnimTime, ease-out).

    3. Wi-Fi¶

    1. Long-press the Wi-Fi tile to open the list of scanned networks, sorted by RSSI. The connected network is listed first. Each row shows signal bars, SSID, WPA/Open and dBm.
    2. Tap a WPA network to open the password page with a phone-style on-screen keyboard (lv_keyboard):
      • abc, ABC and 1# layouts with letters, digits and symbols.
      • 👁 shows/hides the password.
      • ✓ or "Connect" connects.
    3. A WPA2-PSK passphrase must be 8–63 characters (IEEE 802.11i-2004, Annex H.4); a passphrase of the wrong length is not sent.
    4. Tap the connected network to open the Disconnect / Forget / Close dialog.
    5. After a successful connection the SSID and password are stored in KVStore (/kv/wifi_saved, CRC-32). At the next power-on the remote reconnects to this network.

    The signal bars use the mapping of Android WifiManager.calculateSignalLevel (API ≤ 29): rssi ≤ −100 → 0, rssi ≥ −55 → L−1, otherwise ⌊(rssi + 100)(L − 1)/45⌋.

    Security: the password is stored unencrypted in the GIGA's QSPI flash. Anyone with the board and a USB cable can read it. Do not use networks whose password matters; use "Forget" before handing the device over.

    4. Bluetooth¶

    The GIGA R1 supports Bluetooth Low Energy only (ArduinoBLE, central role). Bluetooth Classic (audio, SPP, pairing from a phone's Bluetooth menu) is not available on this board.

    • Long-press the Bluetooth tile to scan for BT_SCAN_MS = 6 s. Per Bluetooth Core v5.3 Vol 6 Part B §4.4.2.2 the advertising interval lies within 20 ms … 10.24 s, and connectable devices typically use ≤ 1.28 s, so 6 s sees each device ≥ 4 times.
    • The list shows the name (or "Unnamed"), address, signal bars and dBm.
    • Tap a device to connect; tap the connected device to disconnect.

    5. Coexistence with the 2.4 GHz control link¶

    Wi-Fi/BLE share the 2.4 GHz band with the LoRa uplink (FHSS 2402–2478 MHz, 20 channels, 4 MHz step).

    • One 20 MHz Wi-Fi channel overlaps 5 of the 20 hopping channels (25 %).
    • Wi-Fi scanning and handshakes transmit in bursts and can destroy RC frames that happen to hop onto those channels.
    • The FC tolerates 4 consecutive lost frames before entering failsafe (cmd_guard, 0.1 s).

    Therefore, with NET_BLOCK_WHEN_ARMED = 1, while the aircraft is ARMED:

    • Switching on, scanning and connecting are refused, with a toast explaining why. "ARMED" here means the last ARMED state reported by telemetry (even when that telemetry is stale, since losing telemetry in flight is exactly when the uplink must not be disturbed), or a pending ARM request from the remote (arm_desired).
    • An existing connection is kept.

    6. Threads and thread safety¶

    Thread Priority Job
    ui BelowNormal lv_timer_handler() every 5 ms, data refresh every 100 ms (telemetry is 10 Hz)
    net Low every blocking Wi-Fi/BLE call (scanNetworks, begin, BLE.scan, connect)
    • LVGL is not thread-safe: only ui_begin() (before the threads start) and ui_task() call LVGL.
    • The UI sends requests to net through rtos::Mail<NetCmd, 8> and reads its state with net_snapshot() (mutex-protected), so the interface never freezes while scanning.
    • net is not among the threads supervised by the watchdog: WiFi.begin() may block for up to WIFI_CONNECT_TIMEOUT_MS = 15 s.

    7. LVGL memory¶

    Measured with lv_mem_monitor in the simulation (real LVGL + real UI code):

    State Used Peak
    dashboard + pages + drawer + keyboard, no list rows 47 KiB 48 KiB
    + 24 Wi-Fi networks (NET_MAX_AP) 80 KiB 84 KiB
    + 20 BLE devices (NET_MAX_BT), Wi-Fi page closed 88 KiB 91 KiB
    • The default 64 KiB heap (LV_MEM_SIZE in the core's Arduino_H7_Video/src/lv_conf_9.h) overflows as soon as the first scan result arrives; LVGL then halts in LV_ASSERT_MALLOC. The simulation reproduces this failure exactly.
    • TLSF accepts pools of at most block_size_max = 2^⌈log₂ LV_MEM_SIZE⌉ = 64 KiB, so a single 96 KiB pool is silently rejected by lv_tlsf_add_pool.
    • ui_begin() therefore adds UI_LVGL_POOL_COUNT = 2 pools of 48 KiB each. Total usable memory is 152 KiB, 40 % above the 91 KiB peak.
    • A closed page frees its rows, so the two lists never coexist.
    • Transparent lists drop the theme's clip_corner, which forces LVGL to draw rounded corners through two 768 px-wide ARGB8888 layers occupying ~30 KiB each.
    • Signal bars are one custom-drawn object (LV_EVENT_DRAW_MAIN) instead of 4 child objects.
    • Every 10 s, Serial prints [UI] lvgl heap used … / … B, max … for checking on real hardware.

    8. Artificial horizon¶

    The aircraft symbol is fixed at the centre of the box. The world rotates by −roll, and pitch shifts the horizon by k = 120 px / 45° along the rotated vertical axis.

    With c = cos(−φ), s = sin(−φ) and C the centre of the box:

    body point (x, y) → screen  P = C + (x·c − y·s,  x·s + y·c)
horizon: y = off = θ·k ;  pitch ladder ±10/20/30°: y = off − δ·k
    • Lines (horizon, pitch ladder) are clipped to the box with Liang–Barsky (ACM TOG 3(1), 1984), because the points of an lv_line must lie inside the widget.
    • Ground is the half-plane n·P ≥ off + n·C with n = (−s, c). It is filled with one very thick line (ui_ground_band):
      • Every point of the box lies within R/2 of C, with R = √(w² + h²). Their signed distance to the horizon therefore lies in [s_c − R/2, s_c + R/2], with s_c = n·C − d.
      • The band [max(0, s_c − R/2), s_c + R/2] covers exactly the ground. Its lower edge is the horizon whenever the horizon crosses the box.
      • A host test checks 25 roll/pitch combinations on a 5 px grid: no point is misclassified.
    • Triangles are not used because LVGL 9.2's software triangle rasteriser fills triangles with a vertical edge incorrectly, and every polygon clipped to the box has such edges (the defect was observed in the simulation).

    9. Host simulation¶

    cmake -S tests/sim -B build-sim && cmake --build build-sim -j
ctest --test-dir build-sim --output-on-failure        # ui_scenario, ui_scenario_worst_case_heap
build-sim/ui_sim --shots /tmp/shots                   # 800×480 PPM screenshot of each step
cmake -S tests/sim -B build-sim -DUI_SIM_SANITIZE=ON  # ASan + UBSan (slower)

    The simulation uses the same LVGL library and lv_conf_9.h as the GIGA core (with only Arm-2D disabled) and the real src/ui/ code. Taps and swipes are injected through a fake input device at the firmware's own timing. The scenario checks the effect of each step:

    1. Swipe the drawer open, then tap the Wi-Fi tile: wifi_on.
    2. Long-press the Wi-Fi tile: the network list is scanned.
    3. Tap a WPA network: the keyboard appears.
    4. Type matkhau123 (switching to the 1# layout) and press ✓: net_wifi_connect("TNG-Blue_Lab", "matkhau123").
    5. Long-press the Bluetooth tile: switched on and scanning. Tap a device: connects to the correct address.
    6. Swipe up to close the drawer, tap "Calibrate": the EVT_CAL_START flag is set.
    7. LVGL heap peak ≤ 80 % of the total pool (--worst: full lists of 24 + 20).

    Requires the lvgl 9.2.2 library in ~/Arduino/libraries and the arduino:mbed_giga core (found automatically, or pass -DLVGL_DIR=… -DGIGA_VIDEO_DIR=…).

    10. Vietnamese font¶

    LVGL ships only Latin Montserrat. src/ui/fonts/font_vn_{16,20,28}.c are 4 bpp bitmaps containing:

    • Basic Latin and Latin-1.
    • Vietnamese: Ă Đ Ĩ Ũ Ơ Ư and the U+1EA0–U+1EF9 block.
    • – — • … →.
    • The LV_SYMBOL_* set (Font Awesome 5).

    Regenerate with:

    tools/gen_fonts.sh ~/Arduino/libraries/lvgl     # needs lv_font_conv 1.5.2 (npx or LV_FONT_CONV=…)

    Licences: Montserrat and Font Awesome 5 Free are under SIL OFL-1.1. The copyright notices are at the top of each file and in NOTICE.md §8. When a user-interface string gains a new character, its code range must be added to the script's TEXT_RANGE; a missing glyph is drawn as a box.

    11. Not yet verified on hardware¶

    The code compiles for the GIGA (arduino-cli compile --fqbn arduino:mbed_giga:giga) and runs correctly in the simulation, but has not run on a real board. Still to be checked:

    • Wi-Fi/BT firmware of the Murata 1DX module, stored in QSPI. The first time, run the example STM32H747_System → QSPIFormat, then WiFiFirmwareUpdater.
    • Real Wi-Fi scan and connection times; Wi-Fi and BLE active at the same time on the same chip.
    • Actual GT911 report rate on the shield (read register 0x8056); smoothness of the drawer drag.
    • The [UI] lvgl heap line on Serial with full lists, compared with the simulated figures of section 7.
    • RC frame loss while Wi-Fi is active in the DISARMED state (pre-flight preparation).
