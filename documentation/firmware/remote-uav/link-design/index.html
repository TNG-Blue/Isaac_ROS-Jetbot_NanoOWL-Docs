    Full-duplex LoRa control link (Remote_UAV ↔ JetOwl_FlightControl)¶

    Source

    This page is rendered from Microcontroller/Remote_UAV/docs/LINK_DESIGN.md, the authoritative description kept next to the code in Microcontroller/Remote_UAV/docs/.

    Design document for Application/RfLink/ (a pure-C library, shared verbatim with Isaac_ROS-Jetbot_NanoOWL/Microcontroller/Remote_UAV/src/rflink/), Application/Control/Src/rc_input.c and Application/Interface/Src/rflink_app.c. Every figure below is either checked by a host test (tests/host/test_rflink.c, test_rc_input.c) or cited.

    1. Hardware¶

    Remote_UAV (ground) JetOwl_FlightControl (UAV)
    MCU Arduino GIGA R1 WiFi (STM32H747) + GIGA Display Shield STM32N657 (NUCLEO-N657X0-Q)
    UL module (uplink, commands) Core1121-XF #1 — transmit only, SPI1 (D11–D13) Core1121-XF #1 — receive only, SPI5
    DL module (downlink, telemetry) Core1121-XF #2 — receive only, SPI (header D89–D91) Core1121-XF #2 — transmit only, SPI5

    Chip: Semtech LR1121, 32 MHz TCXO at 3.0 V, RF switch on DIO5/DIO6 (table from the Waveshare BSP). Frequency ranges supported by the chip (Semtech lr1121_common.h): 150–960 MHz, 2000–2100 MHz (S-band), 2400–2500 MHz. The LR1121 has no 1.2 GHz band.

    FC pins: Application/Interface/Inc/board_config.h sections 2.4 and 2.8. Remote pins: Remote_UAV/src/app/app_config.h and Remote_UAV/docs/WIRING.md.

    2. Why full duplex needs TWO modules at EACH end¶

    A LoRa transceiver is half-duplex: it cannot transmit and receive at the same time. Full duplex here is FDD (frequency-division duplex): each end has two modules, each module handles one direction only, and the two directions use two different bands and run simultaneously:

    flowchart LR
    subgraph GND[Remote_UAV – GIGA R1]
        S[Sticks + buttons] --> F[Filtering + calibration] --> TXu[LR1121 UL<br/>TRANSMIT only]
        RXd[LR1121 DL<br/>RECEIVE only] --> UI[Display<br/>MEASURED state]
    end
    subgraph AIR[UAV – STM32N657]
        RXu[LR1121 UL<br/>RECEIVE only] --> RC[rc_input] --> CG[cmd_guard] --> AT[attitude_ctrl → rate_loop → ESC]
        IMU[IMU + ESC RPM] --> AT
        AT --> TLM[telemetry] --> TXd[LR1121 DL<br/>TRANSMIT only]
    end
    TXu -- "2.4 GHz FHSS, 50 Hz" --> RXu
    TXd -- "sub-GHz 921.4 MHz, 10 Hz" --> RXd

    Consequences: there is no TX/RX turnaround time, telemetry never blocks commands, and command latency does not depend on traffic in the opposite direction.

    2.1 Band choice: why commands use 2.4 GHz and telemetry sub-GHz (default)¶

    Criterion Commands (UL) 2.4 GHz Telemetry (DL) sub-GHz
    Worldwide regulation ISM 2400–2483.5 MHz; FHSS with ≥ 15 channels is compliant under ETSI EN 300 328 §4.3.1.4 and FCC 15.247(a)(1)(iii) Region-dependent (AS923 / EU868 / US915)
    Bandwidth → ToA BW 812 kHz ⇒ ToA 5.2 ms ⇒ 50 Hz feasible BW 250 kHz ⇒ ToA 41 ms ⇒ 10 Hz
    Link budget sufficient for line of sight (section 5) large margin

    TX→RX isolation on the same airframe. With a 13 dBm transmit antenna and a receive antenna d ≈ 10 cm apart: FSPL = 20 log₁₀(4πd/λ) ≈ 20 dB at 2.44 GHz ⇒ a blocker of ≈ −7 dBm at the receiver, while the wanted packet arrives near the sensitivity limit (≈ −105 dBm) ⇒ ≈ 98 dB of selectivity is needed. Placing the two directions in two bands ~1.5 GHz apart lets each module's matching network and antenna provide most of that; putting both at 2.4 GHz (RFLINK_PLAN_2G4_DUAL) is usable only with widely separated antennas.

    Harmonics. rflink_check_config() rejects a configuration in which the 2nd or 3rd harmonic of the DL falls inside the UL range (a non-linear PA radiates its strongest harmonics at orders 2–3). 921.4 MHz → 1842.8 / 2764.2 MHz: outside 2402–2478 MHz.

    S-band 2000–2010 MHz (RFLINK_PLAN_2G4_SBAND) is a mobile-satellite-service (MSS) band and requires a licence.

    2.2 Three band plans (rflink_config.h)¶

    RFLINK_PLAN UL DL DL ToA / period
    2G4_SUBGHZ (default) 2402–2478 MHz, 20 channels, 4 MHz step 921.4 MHz (AS923, Vietnam) 41.1 ms / 100 ms
    — RFLINK_REGION_EU868 as above 869.525 MHz (g3, duty ≤ 10 %) 41.1 ms / 500 ms = 8 %
    — RFLINK_REGION_US915 as above 915 MHz, BW 500 kHz (DTS) 20.5 ms / 100 ms
    2G4_SBAND as above 2005 MHz — licence required 25.3 ms / 100 ms
    2G4_DUAL 2402–2447 MHz, 16 channels 2478 MHz 25.3 ms / 100 ms

    To change the plan or region, add -DRFLINK_PLAN=... / -DRFLINK_REGION=... to both firmwares.

    3. Physical layer and timing¶

    Time on air from the Semtech formula (AN1200.13; lr11xx_radio_get_lora_time_on_air_numerator, tested against an independent implementation of the formula):

    n_payload = 8 + max(ceil((8PL − 4SF + 28 + 16CRC − 20IH − 8FS) / (4(SF − 2DE))) · (CR + 4), 0)
T = (n_pre + 4.25 + 2FS + n_payload) · 2^SF / BW          FS = 1 when SF ≤ 6 (fine synch)
    UL (RC) DL (TLM)
    SF / BW / CR 6 / 812 kHz / ⅘ 7 / 250 kHz / ⅘
    Preamble 12 (SF6 requires ≥ 12) 8
    Frame 21 B (9 header + 8 payload + 4 tag) 37 B (9 + 24 + 4)
    ToA 5.22 ms 41.08 ms
    Period 20 ms (50 Hz) 100 ms (10 Hz)
    Output power 13 dBm (HF PA maximum) 14 dBm

    Command latency (stick → set-point in cmd_guard), mean: stick filter ≈ 28 ms (group delay of the 2nd-order Butterworth, f_c = 7.93 Hz, see Remote_UAV/src/input/stick_dsp.h) + frame wait T/2 = 10 ms + ToA 5.2 ms + processing < 1 ms + attitude-loop tick ≤ 4 ms ⇒ ≈ 46 ms.

    4. Frequency hopping and synchronisation (rflink_fhss.h)¶

    • The channel sequence is a permutation π of {0..19} (Fisher–Yates + xorshift32, seed derived from the master key). Frame number seq is transmitted on channel π[seq mod 20].
    • Lock: frame k received at r_k ⇒ listen immediately on π[k+1] with deadline D = r_k + T + g. Past the deadline ⇒ hop to π[k+2] before frame k+2 starts, with margin T − ToA − g = 20 − 5.22 − 3 = 11.8 ms > 0.
    • Clock drift: 100 ppm in total ⇒ still inside the g = 3 ms window after at most g/(εT) = 1500 consecutive lost frames; the "blind hopping" limit is set to 50 frames (1 s), after which the receiver enters SEARCH.
    • SEARCH: park on π[0]; since π is a permutation the transmitter visits that channel at least once every 20 frames ⇒ re-acquisition ≤ 20 × 20 ms = 0.4 s (no packet loss).

    5. Link budget (theoretical, free space)¶

    Sensitivity S = −174 + 10 log₁₀ BW + NF + SNR_min. From the Waveshare figure (−111 dBm at SF7/BW800) ⇒ NF ≈ 11.4 dB ⇒ SF6/BW812: S ≈ −108.5 dBm.

    UL: PL_max = 13 + 2 + 2 − (−108.5) = 125.5 dB. Subtracting a 10 dB fading margin (Rayleigh P_out 10 %, section 7) ⇒ FSPL 115.5 dB ⇒ d = 10^((115.5 − 100.2)/20) km ≈ 5.8 km in free space at 2.44 GHz. The sub-GHz DL has far more margin (≈ 100 km in theory) ⇒ the UL limits the range — sufficient for visual-line-of-sight flight. The real range is lower (Fresnel zone, shadowing by the airframe, antennas).

    6. Framing, authentication, replay protection (rflink_proto.h)¶

    off size  field
0   1     hdr = (version << 4) | type        type 1 = RC, 2 = TLM
1   4     nonce_tx (current nonce of the transmitter)
5   4     seq      (frame counter of the transmitter)
9   N     payload
9+N 4     tag = AES-CMAC_Kdir(nonce_rx || frame[0..9+N))[0..3]
    • AES-128 (FIPS-197) + CMAC (NIST SP 800-38B), tested against the FIPS-197 C.1 and RFC 4493 vectors.
    • Per-direction keys K_UL, K_DL and the hopping seed are derived with a counter-mode KDF (NIST SP 800-108r1, PRF = CMAC) from a 128-bit master key (rflink_key.h).
    • Replay protection without non-volatile memory: the tag covers the receiver's random nonce (LR1121 GetRandomNumber, generated at boot) ⇒ a frame recorded before that boot carries a wrong tag. Within a session, seq must increase strictly. If the transmitter reboots (seq back to 0) ⇒ 3 frames with a valid tag but stale sequence ⇒ the receiver changes its nonce (rekey) ⇒ the transmitter learns the new nonce over the other direction ⇒ recovery (≈ 0.5 s).
    • 32-bit tag: forgery probability per frame 2⁻³²; at 50 frames/s this takes on average ~1.4 years of continuous attempts on the correct hopping channel.
    • The default key is public ⇒ warnings at compile time, on the remote's screen and on the LED. Generate a private key with python3 tools/rflink_keygen.py (writes rflink_key_local.h into both repositories, already in .gitignore).

    7. Link-quality estimation (rflink_quality.h)¶

    • LQ = fraction of frames received in a 64-frame window indexed by seq (an unbiased binomial estimator, σ ≤ 6.25 %).
    • RSSI/SNR are low-pass filtered (first order, τ = 0.5 s, backward Euler: a = T/(τ + T)).
    • Margin M = SNR_filtered − SNR_min(SF) (SX1276 table 13, SX1261/2 §6.1.1).
    • Grading by Rayleigh outage probability P_out = 1 − exp(−10^(−M/10)): GOOD when P_out ≤ 1 % (M ≥ 20.0 dB), FAIR when ≤ 10 % (M ≥ 9.8 dB), POOR otherwise (Goldsmith, Wireless Communications, §3.2.1). No hand-picked thresholds.

    8. From stick to propeller (rc_input.h) — the loop stays closed¶

    stick → median 3 → Butterworth 2 (Tustin, pre-warped) → calibration → 3σ deadband → expo   [remote]
   → LoRa UL → authentication → rc_input → cmd_guard → attitude_ctrl (250 Hz) → rate_loop (1 kHz)
   → rotor_speed → DShot → ESC;   feedback: IMU (attitude, angular rate) + ESC RPM           [FC]
   → telemetry DL → remote display (MEASURED state) → pilot                                  [outer loop]
    • ANGLE mode: φ = r·θ_max, θ = −p·θ_max (FRD), ψ_sp integrates the yaw-rate command with the measured dt (limited by RC_DT_MAX_S), q_sp = q_z(ψ) ⊗ q_y(θ) ⊗ q_x(φ), T = t·T_max.
    • θ_max = ATT_CMD_TILT_MAX (full stick = exactly the cmd_guard limit), r_max = ½ of the attitude loop's yaw-rate limit (half the range is reserved for the correction term), T_max = maximum physical thrust.
    • Bumpless switching: while disarmed, or right after authority passes to the pilot ⇒ ψ_sp := ψ_measured.
    • Command authority: ANGLE ⇒ only RC feeds cmd_guard and Jetson commands are dropped (uros_app.c try_submit, on_arm); AUTO ⇒ only the Jetson. RC lost while the pilot holds authority ⇒ nobody feeds cmd_guard ⇒ the cmd_guard failsafe performs a bounded landing after CMD_TIMEOUT_S = 0.1 s = 5 frames. False-failsafe probability with independent packet loss p: p⁵ = 10⁻⁵ at p = 10 %.
    • Arm/disarm act on an EDGE between two consecutive fresh frames; arming must still pass cmd_guard_arm_check. KILL disarms on every frame while held and is latched until KILL is released and arm is switched off.
    • Stick failure (the remote sees an ADC stuck at a rail for ≥ 100 ms) ⇒ flag RFLINK_RC_STICK_FAULT ⇒ the FC feeds no set-point (entering the same proven failsafe path); ARM/KILL keep working.
    • RTH: the FC has no position loop yet ⇒ the request is only forwarded to the Jetson through the rc_rth_request key of /jetowl/status.

    9. Firmware integration¶

    1. CubeMX: enable SPI5 (mode 0, prescaler 16 = 12.5 MHz), GPIO per board_config.h section 2.8, rising-edge EXTI on PE10 and PF3. Set BOARD_CUBEMX_PERIPHERALS_READY = 1.
    2. app_freertos.c already calls RfLinkApp_Start() (returns false while the peripherals are missing).
    3. Every other SPI5 user (FRAM) must take RfLinkApp_SpiLock().
    4. Key: python3 tools/rflink_keygen.py, then rebuild both firmwares.
    5. Host check: ctest --test-dir build-host (test_rflink, test_rc_input).

    New status keys in /jetowl/status: rc_authority (0 none, 1 pilot, 2 Jetson), rc_fresh, rc_link_lq_pct, rc_rssi_dbm, rc_snr_db, rc_rth_request.

    10. Still to be measured on hardware (no data yet — not to be guessed)¶

    • Actual RxDone timing offset (d) and the remote's transmit jitter ⇒ confirm g = 3 ms.
    • Real antenna isolation between the two modules on the airframe (measure the DL leakage RSSI at the UL module).
    • Real SF6/BW812 sensitivity of the Core1121 (section 5 uses the vendor figure plus a noise model).
    • Packet error rate versus distance, to validate the Rayleigh model of section 7.
