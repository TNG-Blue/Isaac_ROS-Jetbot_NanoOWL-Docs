    ROS2_Flight_Controller — mission, guidance and outer position loop¶

    Source

    This page is rendered from Source/ROS2_Flight_Controller/README.md, the authoritative description kept next to the code in Source/ROS2_Flight_Controller/.

    ros2_flight_controller 0.6.0 runs the flight-mode state machine (arm, takeoff, hover, waypoint mission, orbit, path, obstacle avoidance, RTH, landing, joystick), the safety monitor and the outer position/yaw loop. It outputs

    • flight/setpoint + flight/active — the reference trajectory for the MPC of ros2_control_system, which then closes the loop down to thrust and attitude (the JetOwl path), and
    • flight/cmd_vel — the same command as a world-frame (odom, ENU) velocity and yaw rate, for an external velocity-mode autopilot. It is deliberately not called cmd_vel: by REP-103 that name carries a body/heading-frame command, which this node consumes (below).

    Manual flight (MANUAL_JOYSTICK, entered with the nav command MANUAL, left with MANUAL_RELEASE) flies a heading-frame velocity (x forward, y left, z up) from joy (sensor_msgs/Joy, default) or, with manual.source: cmd_vel, from cmd_vel (geometry_msgs/Twist, e.g. isaac_ros_target_follower_node). The command is rotated by the estimated heading, v_world = R_z(ψ̂) v_heading, and goes through the same position loop, limits, geofence and battery failsafes as any other mode. A source silent for joystick.signal_timeout_s (1 s) raises HEARTBEAT_LOST → return to home; the timeout is checked on the control-loop clock, so a source that stops publishing is detected too.

    Missions (YAML files, survey/orbit patterns, pre-flight feasibility, sequencing) are handled by ros2_mission_planner, which drives this node through flight/waypoints and flight/nav_command. The whole stack is launched with ros2 launch ros2_mission_planner autonomous_mission.launch.py.

    odom ─▶ OdometryFilter (CWNA KF, χ² gate) ─▶ Stateflow + guidance ─▶ reference p, v, a, ψ
                                               │  min-jerk trajectory (HOVER, RTH, missions)
                                               │  guidance modules (takeoff, landing, orbit…)
                                               ▼
                         2-DOF position/yaw controller ─▶ saturation ─▶ flight/cmd_vel
                                               └────────▶ flight/setpoint, flight/active

    Control design (control-systems.md §5)¶

    CONTROL DESIGN — outer position / yaw loop
  Plant        : autopilot velocity loop 1/(τ_v s + 1): P(s) = 1/(s(τ_v s + 1)),
                 τ_xy = 0.4 s, τ_z = 0.3 s, τ_ψ = 0.2 s (to be identified by a velocity step)
  Sensor       : nav_msgs/Odometry (ESKF of ros2_control_system at 100 Hz, or any source)
  Filter/Est.  : per-axis CWNA Kalman filter (Bar-Shalom §6.2.2), q = a_max² T, R floor for
                 upstream-KF corrections, χ²₂ gate 13.82; NIS mean 1.994 (expected 2) in test
  Reference    : minimum-jerk quintics through waypoints (Richter, Bry & Roy 2013), C²,
                 limits by rest-to-rest bounds + exact time scaling; speed limited to
                 0.8 (v_sat − τ_v a_max) to keep feedforward/feedback headroom; distance to the
                 waypoint polyline ≤ max_path_deviation_m (stops added at the worst knots)
  Controller   : 2-DOF v_cmd = v_ref + τ_v a_ref + K_p (p_ref − p̂), feedforward read τ_d ahead,
                 K_p = 1/(4ζ²τ_v), ζ = 1 (pole placement)
  Actuator     : |v_xy| ≤ 5 m/s, v_z ∈ [−1.5, 3] m/s, |ω| ≤ 1 rad/s, altitude ceiling
  Loop         : closed on the filtered odometry, 50 Hz
  Margins      : xy K 0.625/s PM 75.0° GM 32.2 dB; z K 0.833/s PM 74.5° GM 29.7 dB;
                 yaw K 1.25/s PM 73.6° GM 26.3 dB (τ_d = 40 ms)
  Time domain  : 2 m step: 0 % overshoot, 4.4 s 2 % settling; ±20 % τ_v: ≤ 0.3 % overshoot;
                 min-jerk tracking error 1 mm (8 mm without delay compensation)
  Failsafe     : stale odometry → land (v = (0, 0, −v_land)); battery low → RTH, critical →
                 land; GNSS lost → land; geofence → RTH; inverted → emergency stop;
                 takeoff abort → emergency stop on the ground, land when airborne
  Reference    : Åström & Murray §12.4; Franklin, Powell & Emami-Naeini ch. 4/6;
                 Bar-Shalom, Li & Kirubarajan §6.2; Richter, Bry & Roy 2013; Flash & Hogan 1985

    Derivations: include/ros2_flight_controller/{position_controller,trajectory,estimation}/*.h.

    New and changed parameters (0.5.0)¶

    trajectory.max_path_deviation_m (1.0 m): bound on the distance of the planned trajectory to the waypoint polyline (min_jerk_trajectory.h, Deviation). rth_altitude_m is now above home. Both, like the speed and time limits, are read at run time by ros2_mission_planner.

    New and changed parameters (0.4.0)¶

    See config/flight_params.yaml; every entry carries its source. Highlights: waypoint_guidance (min_jerk | l1), position_controller.*, trajectory.*, setpoint.*, odometry_filter.*, odom_timeout_s, prearm.max_position_sigma_m, safety.require_gps, geofence.vertices_x/y.

    Build and test¶

    colcon build --packages-select ros2_flight_controller --cmake-args -DBUILD_TESTING=ON
colcon test --packages-select ros2_flight_controller && colcon test-result --verbose

    Tests run with -UNDEBUG, so their asserts are active in the default Release build (they were compiled out before 0.4.0). Full-stack SIL: see ../ROS2_Control_System/README.md.

    Known limitations¶

    • τ_v values are assumptions until identified on the vehicle; the margins scale with them.
    • NavSatFix carries no satellite count; a valid fix is mapped to the pre-arm minimum.
    • The GPU trajectory optimiser (kernels/) is built only with CUDA and is not used by the node; it is compile-checked for sm_87 but not yet executed on a GPU.
    • HIL and bench evidence are still to be produced.
