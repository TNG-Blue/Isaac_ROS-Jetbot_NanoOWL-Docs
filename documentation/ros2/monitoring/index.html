    System Monitoring¶

    Real-time system diagnostics, logging, and performance monitoring.

    🎯 Overview¶

    The Monitoring module provides comprehensive system diagnostics, real-time performance tracking, and fault detection for the Isaac ROS Jetbot NanoOWL platform.

    Key Features: - Real-time system metrics (CPU, memory, disk) - Temperature monitoring and thermal management - Battery health tracking - Network diagnostics - ROS2 node health monitoring - Performance profiling - Automated fault detection - Historical data logging

    🚀 Quick Start¶

    Installation¶

    Bash
    # Install dependencies
sudo apt install -y \
    ros-humble-diagnostic-aggregator \
    ros-humble-self-test \
    lm-sensors \
    thermald

# Build
cd ~/ros2_ws
colcon build --packages-select jetbot_monitoring
source install/setup.bash

    Running Monitoring¶

    Bash
    # Launch monitoring system
ros2 launch jetbot_monitoring monitoring.launch.py

# View system status
ros2 topic echo /diagnostics

# Query specific metric
ros2 service call /monitoring/get_system_status jetbot_interfaces/GetSystemStatus

# View performance graph
ros2 run rqt_graph rqt_graph

    🔧 Configuration¶

    Monitoring Parameters¶

    YAML
    # config/monitoring_config.yaml
monitoring_node:
  ros__parameters:
    # Update frequency
    system_update_rate: 5  # Hz
    battery_update_rate: 1  # Hz
    thermal_update_rate: 10  # Hz
    network_update_rate: 2  # Hz

    # Sensor configuration
    enable_cpu_monitoring: true
    enable_memory_monitoring: true
    enable_disk_monitoring: true
    enable_temperature_monitoring: true
    enable_battery_monitoring: true
    enable_network_monitoring: true
    enable_ros2_monitoring: true

    # Thermal sensors
    thermal_zone: "/sys/class/thermal/thermal_zone0"
    thermal_sensors:
      - name: "cpu"
        path: "/sys/class/hwmon/hwmon0/temp1_input"
      - name: "gpu"
        path: "/sys/class/hwmon/hwmon0/temp2_input"
      - name: "ambient"
        path: "/sys/class/hwmon/hwmon0/temp3_input"

    # Battery configuration
    battery_path: "/sys/class/power_supply/battery"
    battery_type: "Li-Po"  # Li-Po, Li-Ion, NiMH
    battery_cells: 2
    battery_nominal_voltage: 7.4  # Volts
    battery_capacity: 5000  # mAh

    # Network interfaces
    network_interfaces:
      - "eth0"
      - "wlan0"

    # Performance profiling
    enable_profiling: true
    profile_update_rate: 1  # Hz

    # Logging
    enable_logging: true
    log_directory: "/var/log/jetbot"
    log_max_size: 100  # MB
    log_retention_days: 30

    # Publishing
    diagnostics_topic: "/diagnostics"
    metrics_topic: "/monitoring/metrics"

    Alert Thresholds¶

    YAML
    # config/alert_thresholds.yaml
alert_thresholds:
  ros__parameters:
    # CPU
    cpu:
      warning: 80    # percent
      critical: 95   # percent

    # Memory
    memory:
      warning: 85    # percent
      critical: 95   # percent

    # Disk
    disk:
      warning: 80    # percent
      critical: 90   # percent

    # Temperature
    temperature:
      warning: 70    # Celsius
      critical: 85   # Celsius
      shutdown: 95   # Celsius

    # Battery
    battery:
      warning: 30    # percent
      critical: 15   # percent
      low_voltage: 6.5  # Volts

    # Network
    network:
      packet_loss_warning: 5   # percent
      packet_loss_critical: 10 # percent
      latency_warning: 100     # ms
      latency_critical: 500    # ms

    # ROS2
    ros2:
      node_heartbeat_timeout: 5  # seconds
      topic_frequency_tolerance: 20  # percent

    📊 System Metrics¶

    CPU Performance¶

    YAML
    Metrics:
  - Usage percentage: 0-100%
  - Per-core load: Individual core activity
  - Average load (1/5/15 min): System load average
  - Context switches: Per second
  - Interrupts: Hardware + software

Calculation:
  CPU Usage = (total_time - idle_time) / total_time * 100
  Load Average = (sum of running tasks) / cpu_count

    Memory Usage¶

    YAML
    Metrics:
  - Total memory: Fixed at 8GB
  - Used memory: Currently allocated
  - Available memory: Free + reclaimable
  - Buffers: Disk cache
  - Swap usage: Virtual memory

Breakdown:
  - System: Linux kernel, drivers
  - ROS2: Node processes, middleware
  - Applications: User programs
  - Cache: Recoverable memory

    Disk I/O¶

    YAML
    Metrics:
  - Read/write throughput: MB/s
  - IOPS: Operations per second
  - Queue depth: Pending requests
  - Latency: Operation time

Thresholds:
  - Warning: > 500 MB/s sustained
  - Critical: > 800 MB/s sustained
  - Latency warning: > 50ms average

    Network Statistics¶

    YAML
    Per-Interface:
  - RX bytes: Data received
  - TX bytes: Data transmitted
  - RX packets: Packet count
  - TX packets: Packet count
  - Errors: Transmission errors
  - Dropped: Lost packets

Calculations:
  - Bandwidth: (bytes * 8) / time
  - Packet loss rate: dropped / total * 100
  - Error rate: errors / total * 100

    🔋 Battery Monitoring¶

    Battery State Estimation¶

    C++
    // Calculate state of charge (SOC)
float voltage = get_battery_voltage();  // e.g., 7.2V
float soc = (voltage - min_voltage) / (max_voltage - min_voltage) * 100;

// For 2S Li-Po: min=6.0V, max=8.4V
// SOC = (7.2 - 6.0) / (8.4 - 6.0) * 100 = 50%

    Battery Health Analysis¶

    YAML
    Health Indicators:
  - Internal resistance: Measured from voltage drop under load
  - Cycle count: Number of charge/discharge cycles
  - Capacity fade: Actual vs nominal capacity
  - Age: Days in service
  - Temperature history: Thermal stress

Estimation:
  Health% = (Cycles / Max_Cycles) * 100
         + (Temp_Peak / Max_Temp) * 100
         - (Age_Days / Life_Days) * 50

    Discharge Profile¶

    YAML
    Typical Li-Po 2S (7.4V nominal):

Discharge Curve:
  100%: 8.40V (fully charged)
   75%: 7.80V
   50%: 7.30V
   25%: 6.80V
    0%: 6.00V (fully discharged)

Safe Operating Range:
  Min Voltage: 6.0V (stop use)
  Recommended Min: 6.5V (extend life)
  Max Voltage: 8.4V (fully charged)
  Continuous Current: 10A max

    🌡️ Thermal Management¶

    Temperature Sensors¶

    YAML
    Jetson Orin Nano Thermal Zones:

CPU Package:
  - Path: /sys/class/thermal/thermal_zone0
  - Normal: 40-60°C
  - Warning: 70°C
  - Throttle: 80°C
  - Shutdown: 95°C

GPU:
  - Normal: 35-60°C
  - Same thresholds as CPU

Memory/SoC:
  - Normal: 30-50°C
  - Warning: 70°C

Ambient:
  - Typical: 20-35°C
  - Consideration: ΔT = (Die - Ambient)

    Cooling Strategies¶

    YAML
    Strategy 1: Passive (No Fan)
  - Heatsink only
  - Air circulation
  - Performance: Limited at high load
  - Power: 0W (none needed)

Strategy 2: Active (Fan)
  - Variable speed fan
  - Thermostat control
  - Temperature setpoint: 65°C
  - Fan speed: PWM-controlled
  - Power: ~1W

Strategy 3: Throttling
  - Reduce CPU frequency
  - Reduce GPU frequency
  - Maintain thermal limit
  - Performance: Reduced by 20-40%

Strategy 4: Shutdown (Safety)
  - Graceful shutdown if > 95°C
  - Prevents hardware damage
  - Alert user
  - Automatic recovery when cooled

    📈 Performance Profiling¶

    ROS2 Node Profiling¶

    YAML
    Metrics per Node:
  - CPU usage: Percentage
  - Memory usage: MB
  - Message processing time: Latency
  - Topic subscription/publication rate
  - Service call frequency
  - Parameter count

Collection:
  - Automatic via ros2_tracing
  - Manual with rclcpp profiling hooks
  - Aggregated in diagnostics

    Real-time Latency Analysis¶

    YAML
    Latency Measurements:
  - Node processing time: Execution of callback
  - Topic publish latency: Message timestamped
  - DDS transport latency: Network delay
  - Total end-to-end latency: Camera to output

Histogram:
  Percentile  | Latency
  -------     | -------
  Min         | 2ms
  P50 (median)| 8ms
  P95         | 12ms
  P99         | 15ms
  Max         | 25ms

    🎮 ROS2 Topics and Services¶

    Published Topics¶

    YAML
    /diagnostics:
  type: diagnostic_msgs/DiagnosticArray
  description: All system diagnostics

/monitoring/cpu:
  type: jetbot_interfaces/SystemMetrics
  description: CPU usage and statistics

/monitoring/memory:
  type: jetbot_interfaces/MemoryStats
  description: Memory usage breakdown

/monitoring/temperature:
  type: sensor_msgs/Temperature
  description: CPU/GPU temperature

/monitoring/battery:
  type: sensor_msgs/BatteryState
  description: Battery voltage, current, health

/monitoring/network:
  type: jetbot_interfaces/NetworkStats
  description: Network interface statistics

/monitoring/performance:
  type: jetbot_interfaces/PerformanceMetrics
  description: Real-time performance data

    Services¶

    YAML
    /monitoring/get_system_status:
  type: jetbot_interfaces/GetSystemStatus
  description: Query complete system status

/monitoring/get_diagnostics:
  type: diagnostic_msgs/GetDiagnostics
  description: Request diagnostic data

/monitoring/restart_monitoring:
  type: std_srvs/Empty
  description: Restart monitoring system

/monitoring/export_logs:
  type: jetbot_interfaces/ExportLogs
  description: Export historical logs
