    RF Spectrum Analysis¶

    Wireless signal analysis and spectrum monitoring.

    🎯 Overview¶

    The RF Spectrum Analysis module provides real-time wireless spectrum monitoring, signal analysis, and interference detection for optimizing wireless performance.

    Key Features: - Real-time spectrum analyzer (300MHz - 6GHz) - Signal strength (RSSI) monitoring - Interference detection - Channel quality assessment - WiFi/LoRa coexistence analysis - Frequency hopping verification - Signal-to-noise ratio (SNR) calculation - Spectrum occupancy mapping

    🚀 Quick Start¶

    Installation¶

    Bash
    # Install dependencies
sudo apt install -y \
    libuhd-dev \
    gnuradio \
    gnuradio-dev \
    python3-pyqtgraph

# Build
cd ~/ros2_ws
colcon build --packages-select jetbot_spectrum_analysis
source install/setup.bash

    Running Spectrum Analysis¶

    Bash
    # Launch spectrum analyzer
ros2 launch jetbot_spectrum_analysis spectrum_analysis.launch.py

# View real-time spectrum
ros2 topic echo /spectrum/power_spectrum

# Check interference levels
ros2 service call /spectrum/check_interference jetbot_interfaces/CheckInterference

# Export spectrum data
ros2 service call /spectrum/export_data jetbot_interfaces/ExportSpectrumData

    🔧 Configuration¶

    Spectrum Configuration¶

    YAML
    # config/spectrum_config.yaml
spectrum_analyzer:
  ros__parameters:
    # Hardware
    hardware_type: "usrp"  # usrp, hackrf, rtlsdr, limesdr
    device_id: 0

    # Frequency range
    frequency_start: 300e6    # 300 MHz
    frequency_stop: 6e9       # 6 GHz
    frequency_step: 1e6       # 1 MHz resolution

    # Sampling
    sample_rate: 10e6         # 10 MHz
    samples_per_spectrum: 1024
    num_averages: 10

    # Detection sensitivity
    detection_threshold: -100  # dBm
    min_signal_strength: -120  # dBm

    # Sub-bands of interest
    sub_bands:
      - name: "2.4GHz WiFi"
        start: 2.4e9
        stop: 2.5e9
        channels: 13
        channel_width: 20e6

      - name: "5GHz WiFi"
        start: 5.1e9
        stop: 5.9e9
        channels: 25
        channel_width: 20e6

      - name: "LoRa 915MHz"
        start: 902e6
        stop: 928e6
        channels: 64
        channel_width: 125e3

    # Update rate
    update_frequency: 1  # Hz

    # Logging
    enable_spectrum_logging: true
    log_directory: "/var/log/jetbot/spectrum"

    📡 Spectrum Bands¶

    2.4 GHz WiFi Band (ISM)¶

    YAML
    Band: 2.4 - 2.5 GHz
Technology: 802.11b/g/n/ax
Channel Bandwidth: 20/40/80/160 MHz

Channels (FCC - North America):
  1:  2412 MHz (default)
  2:  2417 MHz
  3:  2422 MHz
  4:  2427 MHz
  5:  2432 MHz
  6:  2437 MHz
  7:  2442 MHz
  8:  2447 MHz
  9:  2452 MHz
  10: 2457 MHz
  11: 2462 MHz
  12: 2467 MHz (non-overlapping)
  13: 2472 MHz (non-overlapping)

Non-overlapping Channels: 1, 6, 11 (recommended)
Typical Bandwidth: 20 MHz per channel
Overlap Penalty: 25 dB adjacent, 5 dB overlapping

Common Interference:
  - Bluetooth: 2.402 - 2.480 GHz
  - Microwaves: 2.45 GHz
  - Cordless phones: 2.4 GHz

    5 GHz WiFi Band (UNII)¶

    YAML
    Band: 5.15 - 5.85 GHz
Technology: 802.11a/n/ac/ax
Channel Bandwidth: 20/40/80/160 MHz

Bands:
  UNII-1 (5.15-5.25 GHz):
    Channels: 36, 40, 44, 48
    Power Limit: 17 dBm
    Use Case: Indoor/Outdoor

  UNII-2 (5.25-5.35 GHz):
    Channels: 52, 56, 60, 64
    Power Limit: 24 dBm
    Use Case: Outdoor, radar sensing

  UNII-3 (5.65-5.85 GHz):
    Channels: 149, 153, 157, 161, 165
    Power Limit: 30 dBm
    Use Case: Outdoor

Advantages over 2.4 GHz:
  - More channels available
  - Less interference (unlicensed)
  - Higher data rates (20/40/80/160 MHz)
  - Lower latency

Disadvantages:
  - Shorter range (higher frequency = more attenuation)
  - Lower wall penetration
  - Higher power consumption

    915 MHz LoRa Band (ISM)¶

    YAML
    Band: 902 - 928 MHz (North America)
Band: 863 - 870 MHz (Europe)
Technology: LoRaWAN, LoRa point-to-point
Bandwidth: 125 kHz (standard), 250 kHz, 500 kHz

Channels (US):
  Uplink: 902.3 - 914.9 MHz (64 channels @ 200 kHz spacing)
  Downlink: 923.3 - 927.5 MHz (8 channels @ 600 kHz spacing)

Configuration:
  Spreading Factor: 7-12
  Coding Rate: 4/5, 4/6, 4/7, 4/8
  Bandwidth: 125/250/500 kHz

Lower interference than 2.4 GHz:
  - 15 MHz band is large
  - Fewer devices typically
  - Better long-range performance

    📊 Spectral Analysis Techniques¶

    FFT-based Analysis¶

    YAML
    Process:
  1. Apply windowing function (Hann, Hamming)
  2. Compute FFT (Fast Fourier Transform)
  3. Calculate magnitude spectrum
  4. Accumulate multiple spectra (averaging)
  5. Convert to dBm

Advantages:
  - Fast computation
  - Good frequency resolution
  - Well-established technique

Disadvantages:
  - Spectral leakage (side lobes)
  - Picket fence effect
  - Limited dynamic range

    Welch Method (Averaging)¶

    YAML
    Process:
  1. Divide signal into overlapping segments
  2. Apply window to each segment
  3. Compute FFT for each segment
  4. Average the power spectra
  5. Result: Smoother, less noisy spectrum

Parameters:
  - Segment length: 256-1024 samples
  - Overlap: 50%
  - Window: Hann or Hamming

Benefits:
  - Reduced variance in spectrum estimate
  - Better for noise reduction
  - More stable measurements

    Spectrogram (Time-Frequency)¶

    YAML
    Matrix of:
  - Time (x-axis): seconds
  - Frequency (y-axis): MHz/GHz
  - Color intensity: Signal power (dBm)

Use Cases:
  - Transient signal detection
  - Frequency hopping visualization
  - Chirp signal analysis
  - Interference pattern recognition

    🎯 Interference Detection¶

    Automatic Detection Algorithm¶

    C++
    // Detect interference above threshold
for (int freq_idx = 0; freq_idx < spectrum.size(); freq_idx++) {
    float power = spectrum[freq_idx];
    float noise_floor = estimate_noise_floor(spectrum, freq_idx);
    float snr = power - noise_floor;

    if (snr > SNR_THRESHOLD && power > INTERFERENCE_THRESHOLD) {
        // Potential interference detected
        interferenceList.push_back({
            frequency: freq_start + (freq_idx * freq_step),
            power: power,
            snr: snr,
            bandwidth: estimate_bandwidth(spectrum, freq_idx)
        });
    }
}

    Noise Floor Estimation¶

    C++
    // Calculate 10th percentile (noise floor estimate)
std::vector<float> sorted_spectrum(spectrum.begin(), spectrum.end());
std::sort(sorted_spectrum.begin(), sorted_spectrum.end());

float noise_floor = sorted_spectrum[spectrum.size() / 10];

    📈 Channel Quality Metrics¶

    Signal Quality Assessment¶

    YAML
    WiFi Channel Quality:
  RSSI (Received Signal Strength Indicator):
    Excellent: -30 to -50 dBm
    Good:      -50 to -60 dBm
    Fair:      -60 to -70 dBm
    Poor:      -70 to -80 dBm
    Very Poor: < -80 dBm

  SNR (Signal-to-Noise Ratio):
    Excellent: > 40 dB
    Good:      30-40 dB
    Fair:      20-30 dB
    Poor:      10-20 dB
    Very Poor: < 10 dB

  Throughput Estimate (20MHz channel):
    -30 dBm + 40dB SNR: ~150 Mbps (802.11ac)
    -50 dBm + 30dB SNR: ~100 Mbps
    -70 dBm + 20dB SNR: ~50 Mbps
    -80 dBm + 10dB SNR: ~11 Mbps (802.11g)

    Channel Recommendations¶

    YAML
    Algorithm: Select least congested channel

For 2.4GHz:
  1. Measure RSSI on channels 1, 6, 11
  2. Calculate interference (count signals > -70dBm)
  3. Select channel with lowest interference
  4. Example:
     Ch1: 4 interferers → Avoid
     Ch6: 1 interferer  → Recommended
     Ch11: 2 interferers → Moderate

For 5GHz:
  1. Measure all available channels
  2. Prefer UNII-3 (149-165) for best throughput
  3. Check for radar interference (DFS)
  4. Recommend channel with > 30 dB SNR

    🔍 Troubleshooting¶

    High Interference on WiFi¶

    Check: - 2.4GHz band occupancy using spectrum analyzer - Nearby networks using WiFi scanner - Non-WiFi interference (Bluetooth, microwave)

    Solutions: - Switch to 5GHz WiFi (less congested) - Use non-overlapping channels (1, 6, or 11 for 2.4GHz) - Increase WiFi TX power if within regulations - Add antenna with directional gain

    LoRa Performance Degradation¶

    Check: - LoRa band occupancy around 915 MHz - SNR of received signals - Spreading factor efficiency

    Solutions: - Scan for interference with spectrum analyzer - Increase TX power (if allowed by regulations) - Reduce spreading factor if SNR allows - Use frequency hopping to avoid persistent interference

    False Interference Alerts¶

    Check: - Threshold settings in configuration - Noise floor estimation accuracy

    Solutions: - Increase interference threshold - Reduce spike detection sensitivity - Verify interference is persistent before alerting
