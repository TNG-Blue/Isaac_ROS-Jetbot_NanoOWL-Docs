    Stereo Vision¶

    3D perception and depth estimation using stereo cameras.

    🎯 Overview¶

    The Stereo Vision module provides 3D perception capabilities through stereo image pairs, enabling depth estimation, 3D object detection, and 3D scene reconstruction.

    Key Features: - Dual camera stereo setup (baseline: 120mm) - Real-time stereo matching (30+ FPS) - Depth estimation and 3D reconstruction - Disparity-to-depth conversion - 3D point cloud generation - Stereo rectification and undistortion - Object detection in 3D space - Obstacle detection for navigation

    🚀 Quick Start¶

    Installation¶

    # Install dependencies
sudo apt install -y \
    ros-humble-image-geometry \
    ros-humble-stereo-image-proc \
    ros-humble-pointcloud-to-laserscan \
    libopencv-calib3d-dev \
    libopencv-stitching-dev

# Build
cd ~/ros2_ws
colcon build --packages-select jetbot_stereo_vision
source install/setup.bash

    Running Stereo Vision¶

    # Launch stereo processing
ros2 launch jetbot_stereo_vision stereo_vision.launch.py

# View point cloud
ros2 run rviz2 rviz2 -f map

# Check depth map
ros2 run image_view image_view image:=/stereo/depth

    🔧 Configuration¶

    Stereo Camera Setup¶

    # config/stereo_params.yaml
stereo_processor:
  ros__parameters:
    # Camera configuration
    left_camera_topic: "/camera_left/image_raw"
    right_camera_topic: "/camera_right/image_raw"
    left_camera_info_topic: "/camera_left/camera_info"
    right_camera_info_topic: "/camera_right/camera_info"

    # Calibration
    calibration_file: "config/stereo_calibration.yaml"
    rectify_images: true

    # Stereo matching algorithm
    matcher_type: "semi_global"  # bm, sgbm, semi_global

    # Block matching parameters
    block_size: 11              # Odd number (5-31)
    num_disparities: 192        # Multiple of 16
    min_disparity: 0
    max_disparity: 192

    # Matching cost
    cost_function: "census"     # sad, ssd, census
    p1: 100                     # Penalty for disparity change
    p2: 400                     # Penalty for larger changes

    # Uniqueness check
    uniqueness_ratio: 15        # percent
    texture_threshold: 10
    speckle_size: 100           # pixels
    speckle_range: 16           # disparity units

    # Sub-pixel refinement
    enable_subpixel: true

    # Processing
    median_filter_size: 3
    bilateral_filter: true

    # Output
    publish_depth: true
    publish_point_cloud: true
    publish_disparity: true
    depth_scale: 1000           # mm per unit

    🏗️ Architecture¶

    Stereo Processing Pipeline¶

    graph TB
    A["Left Image"]
    B["Right Image"]

    A --> Rect1["Rectification"]
    B --> Rect1

    Rect1 --> Undist["Undistortion"]

    Undist --> Match["Stereo<br/>Matching"]

    Match --> Disp["Disparity<br/>Map"]

    Disp --> DepthEst["Depth<br/>Estimation"]

    DepthEst --> PointCloud["Point Cloud<br/>Generation"]

    PointCloud --> Output["3D Scene<br/>Output"]

    Stereo Matching Algorithm¶

    graph TB
    A["Rectified Images"]

    A --> Feature["Feature<br/>Extraction"]

    Feature --> Cost["Cost Volume<br/>Computation"]

    Cost --> Aggr["Cost<br/>Aggregation"]

    Aggr --> Winner["Winner-Take-All<br/>Labeling"]

    Winner --> LR["Left-Right<br/>Consistency"]

    LR --> Refine["Sub-pixel<br/>Refinement"]

    Refine --> Disp["Final Disparity<br/>Map"]

    📐 Stereo Geometry¶

    Epipolar Geometry Basics¶

    Fundamental Equation:
  q' · F · p = 0

  Where:
    p = point in left image
    q = corresponding point in right image
    F = Fundamental matrix (3×3)

Interpretation:
  - For point p in left image
  - Its epipolar line in right image is: l' = F·p
  - Matching point q must lie on this line
  - Reduces search space from 2D to 1D

    Disparity to Depth Conversion¶

    Process:
  1. Extract disparity from stereo matching
  2. Convert to depth using camera calibration
  3. Format as depth image or point cloud

Formula:
  depth = (baseline × focal_length) / disparity

  Where:
    baseline = distance between cameras (120mm)
    focal_length = camera focal length (919.8 pixels)
    disparity = left_x - right_x (pixels)

Example:
  If disparity = 60 pixels:
    depth = (120mm × 919.8) / 60 = 1840mm = 1.84m

    Depth Accuracy¶

    Depth Resolution:
  Close range (2m):   ±50-100mm
  Mid range (5m):     ±100-200mm
  Far range (10m):    ±200-500mm

  Typical formula:
    depth_error = (baseline² / focal_length) / disparity²

Factors affecting accuracy:
  - Baseline length (wider = better accuracy)
  - Camera resolution
  - Texture richness (more texture = better matching)
  - Lighting conditions
  - Occlusions

    🎯 3D Point Cloud¶

    Point Cloud Generation¶

    // Generate 3D point cloud from disparity
pcl::PointCloud<pcl::PointXYZ>::Ptr cloud(
    new pcl::PointCloud<pcl::PointXYZ>
);

for (int y = 0; y < height; y++) {
    for (int x = 0; x < width; x++) {
        float disparity = disparity_map.at<float>(y, x);

        if (disparity <= 0) continue;  // Invalid

        // Reproject to 3D
        float z = (baseline * focal_length) / disparity;
        float x_3d = (x - cx) * z / focal_length;
        float y_3d = (y - cy) * z / focal_length;

        cloud->push_back(pcl::PointXYZ(x_3d, y_3d, z));
    }
}

    Point Cloud Processing¶

    Operations:
  - Filtering: Remove outliers (radius outlier, statistical)
  - Downsampling: Reduce point density for speed
  - Segmentation: Cluster nearby points into objects
  - Normal estimation: Surface normal calculation
  - Feature detection: Keypoint extraction

Applications:
  - Obstacle detection
  - 3D object recognition
  - Scene reconstruction
  - Navigation planning

    🚨 Obstacle Detection¶

    Real-time Obstacle Detection¶

    // Simple height-based obstacle detection
for (auto& point : cloud->points) {
    // Check if point is at robot height (0.1 - 0.5m)
    if (point.z > 0.1 && point.z < 5.0) {  // In front
        if (point.y > -0.2 && point.y < 0.2) {  // Near centerline
            if (point.x < 0.3 && point.x > 0.0) {  // Close distance
                obstacles.push_back(point);
            }
        }
    }
}

    Ground Plane Segmentation¶

    Algorithm: RANSAC (Random Sample Consensus)

Process:
  1. Randomly select 3 points
  2. Estimate plane parameters
  3. Count inliers (points close to plane)
  4. Repeat N iterations
  5. Keep plane with most inliers

Ground Plane Characteristics:
  - Normal vector: Approximately [0, 0, 1]
  - Distance from sensor: Varies with robot height
  - Points below: Obstacles
  - Points above: Free space

    🔍 Troubleshooting¶

    Poor Depth Quality¶

    Causes: - Uncalibrated cameras - Low texture regions (blank walls) - Insufficient baseline - Incorrect disparity range

    Solutions: - Recalibrate stereo cameras - Increase lighting on scene - Use wider baseline if possible - Adjust num_disparities parameter

    Noisy Disparity Map¶

    Causes: - Reflective surfaces (mirrors, glass) - Occlusions - Poor matching parameters

    Solutions: - Enable median filtering - Increase speckle filter parameters - Adjust cost aggregation parameters - Apply bilateral filter

    Slow Processing¶

    Causes: - High resolution input - Complex matching algorithm - Insufficient GPU acceleration

    Solutions: - Reduce image resolution (e.g., 640×480) - Use faster matching (BM instead of SGBM) - Reduce number of disparities - Enable GPU processing if available
