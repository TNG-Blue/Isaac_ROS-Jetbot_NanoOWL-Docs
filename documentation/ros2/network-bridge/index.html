    ROS2_Network_Bridge — MAVLink ground-station link¶

    Source

    This page is rendered from Source/ROS2_Network_Bridge/README.md, the authoritative description kept next to the code in Source/ROS2_Network_Bridge/.

    ros2_network_bridge 0.4.0 connects the UAV stack to a ground control station (QGroundControl or any MAVLink v2 GCS) over UDP, TCP, a serial telemetry radio, or a TLS relay for consoles on another network. It does three things:

    • Downlink: sends telemetry from the stack to the GCS, within a bandwidth budget.
    • Uplink: turns GCS commands into discrete commands for ros2_flight_controller and ros2_mission_planner. A command is acknowledged only once the flight controller's measured mode confirms it.
    • Datalink loss: runs the failsafe when the GCS link is lost.
    • Observers: the JetbotNanoOWL Android console reads the same downlink. It fuses ODOMETRY (pose and twist with their covariances) in its EKF and only sends a MAV_TYPE_LOG heartbeat, so it is never taken for the GCS (Jetbot console).

    Like the other nodes, it has a ROS-free core (network_bridge_core: codec, conversions, link supervision, transports) behind a thin ROS 2 node. The core is tested with gtest and with the full-stack SIL.

     odometry/filtered ─┐                          ┌─▶ HEARTBEAT 1 Hz, SYS_STATUS 1 Hz,
 gps/fix ───────────┤   telemetry.h            │   ATTITUDE 10 Hz, LOCAL_POSITION_NED 10 Hz,
 battery/state ─────┼─▶ ENU/FLU → NED/FRD, ────┤   GLOBAL_POSITION_INT 5 Hz, ODOMETRY 5 Hz, STATUSTEXT

    Design (control-systems.md §5)¶

    LINK DESIGN
  Sensor      : GCS frames over the transport; MAVLink v2 CRC-16/MCRF4XX + CRC_EXTRA (false
                accept 2⁻¹⁶ per candidate start byte), id/length checked from the header
  Filter      : parser resynchronises byte-wise; uplink loss from sequence gaps
                g = (seq − seq_prev − 1) mod 256, exponential forgetting λ = 0.99:
                p̂ = L/(L + R), L ← λL + g, R ← λR + 1
  Estimator   : link state from GCS heartbeats (MAV_TYPE_GCS): connected / lost after T = 5 s;
                false-loss rate λ_ft = 3600 f_hb (1 − p) p^⌈T f_hb⌉ per hour
                (T = 5 s, 1 Hz: p = 0.1 → 0.032 /h, p = 0.3 → 6.1 /h; Monte-Carlo checked)
  Supervisor  : discrete commands only (no set-points over a lossy link); ACK closed on the
                flight controller's measured mode within 3 s; DISARM refused while flying;
                termination disabled unless allowed; RTL during a mission → mission/abort
                (the planner's return respects keep-out zones)
  Actuation   : flight/nav_command, mission/start, mission/abort
  Failsafe    : link lost + flying + not returning / landing / manual + mission planner not in
                control → RTH (or LAND / HOVER), re-sent every 2 s until the mode confirms it
                (3 retries); a validated mission continues by default
  Odometry    : ODOMETRY #331, LOCAL_NED / BODY_FRD; Σ_mav = J Σ_ros Jᵀ with
                J_pose = blockdiag(T, E⁻¹T) (ROS fixed-axis rotation error → ZYX Euler error,
                E = [Rz Ry e_x, Rz e_y, e_z], det E = cos θ), J_twist = blockdiag(B, B);
                unknown (all-zero / non-finite) or gimbal-locked covariance → NaN, never 0
  Budget      : B = Σ f_i (12 + len_i) = 2301 B/s at the default rates; C = baud/10 (serial 8N1)
                or bps/8; if B > u_max C, periodic rates × s = (u_max C − B_hb)/(B − B_hb)
  Frames      : p_ned = T p_enu, R_ned←frd = T R_enu←flu B, T = [[0,1,0],[1,0,0],[0,0,−1]],
                B = diag(1, −1, −1); ZYX Euler of R_ned←frd
  Scan        : LaserScan → OBSTACLE_DISTANCE #330, BODY_FRD, 360 one-degree sectors in 5
                messages (offsets −180, −108, −36, 36, 108°); ray → body by the mount (ψ_m, t_m),
                de-skewed to the stamp with the body twist held over the revolution,
                p_ref = Rz(ω dt) p_b + v dt (neglected chord |v||ω|dt²/2 = 5 mm at 1 m/s,
                1 rad/s, 0.1 s); sector = nearest echo within ±0.5°, max+1 = free, UINT16_MAX =
                no data; one scan in n = ⌈B_scan / (u_max C − B_streams)⌉ (Wi-Fi 1, 57.6 kBd 16)
  Relay       : TLS 1.2+, CA + host name or SPKI pin; backoff min(T_min·2^(k−1), T_max)
  Verification: 42 gtest cases, 7 of them relay transport against an in-process TLS server
                (pymavlink golden frames byte for byte incl. ODOMETRY and OBSTACLE_DISTANCE,
                scan sectors / mount / de-skew / decimation,
                J_pose against central differences at 200 random attitudes,
                relay: pin, wrong pin sends no token, untrusted cert, refusal back-off, 200 kB noise without a
                false frame, rotation reconstruction on 1000 random attitudes, link-loss
                policies, UDP loopback); SIL with a pymavlink GCS: 14/14 checks
  Reference   : MAVLink serialisation / CRC / command protocol (mavlink.io); REP-103, REP-105;
                PX4 datalink-loss failsafe (NAV_DLL_ACT) for the policy structure

    Commands¶

    MAV_CMD Action Acknowledged ACCEPTED when
    400 COMPONENT_ARM_DISARM (p1 = 1 / 0) ARM / DISARM (DISARM refused while flying) mode ARMED_IDLE / DISARMED
    22 NAV_TAKEOFF TAKEOFF mode TAKEOFF or HOVER
    21 NAV_LAND LAND mode LANDING, LANDED or DISARMED
    20 NAV_RETURN_TO_LAUNCH mission/abort while the planner flies, else RTH service success / mode RETURN_TO_HOME or LANDING
    17 NAV_LOITER_UNLIM HOVER mode HOVER
    300 MISSION_START mission/start service success (reason as STATUSTEXT when denied)
    185 DO_FLIGHTTERMINATION EMERGENCY_STOP only with commands.allow_termination mode EMERGENCY_STOP
    others — UNSUPPORTED

    Every accepted command is first answered with IN_PROGRESS. The final result follows: ACCEPTED, or FAILED after ack_timeout_s. A GCS retry of the pending command gets IN_PROGRESS again and is not re-sent to the flight controller.

    Telemetry¶

    Message Source Notes
    HEARTBEAT flight/status MAV_TYPE_HEXAROTOR; custom_mode = index in the FC mode table below; SAFETY_ARMED, AUTO (autonomous modes), MANUAL_INPUT (joystick); state STANDBY / ACTIVE / CRITICAL (link-loss failsafe) / EMERGENCY
    SYS_STATUS battery/state, link voltage, current (positive discharging), remaining; drop_rate_comm = uplink loss
    ATTITUDE odometry/filtered NED/FRD Euler angles and body rates
    LOCAL_POSITION_NED odometry/filtered odometry origin; twist rotated from the child frame (REP-105)
    GLOBAL_POSITION_INT gps/fix + odometry relative_alt above the arming altitude, heading from the attitude
    ODOMETRY odometry/filtered pose in LOCAL_NED, twist in BODY_FRD, both 6×6 covariances mapped as in the design block; rates.odometry_hz (0 = off)
    OBSTACLE_DISTANCE scan (LaserScan) obstacle.enabled; 5 messages per scan, BODY_FRD, 1° sectors, mount and de-skew as in the design block; decimated to fit the link budget
    STATUSTEXT mission/status events, bridge rate-limited (5/s), split into 50-character chunks

    The custom_mode table is: 0 DISARMED, 1 PRE_ARM_CHECK, 2 ARMED_IDLE, 3 TAKEOFF, 4 HOVER, 5 WAYPOINT_FOLLOW, 6 ORBIT, 7 PATH_MANAGE, 8 OBSTACLE_AVOID, 9 RETURN_TO_HOME, 10 LANDING, 11 LANDED, 12 MANUAL_JOYSTICK, 13 EMERGENCY_STOP.

    Launch¶

    # Bridge only (stack already running); QGroundControl on this machine
ros2 launch ros2_network_bridge network_bridge.launch.py

# Whole stack + GCS link, GCS on another host
ros2 launch ros2_network_bridge uav_with_gcs.launch.py gcs_host:=192.168.2.10

# Telemetry radio
ros2 launch ros2_network_bridge network_bridge.launch.py transport:=serial

# Jetbot graph → JetbotNanoOWL console on the phone
ros2 launch ros2_network_bridge jetbot_console.launch.py phone_host:=192.168.1.50

    Jetbot console¶

    jetbot_console.launch.py points the bridge at the phone, reads the Jetbot's /odometry, raises ODOMETRY to 10 Hz and sets link_loss.action: none (a ground robot has no flight mode to fall back to). The console's EKF uses ODOMETRY as its feedback stream, so the rate sets its watchdog margin: with T_wd = 0.6 s the false-trip rate is 3600 f (1 − p) p^⌈T_wd f⌉ per hour — 0.03 /h at 10 Hz and 10 % loss, 16 /h at the 5 Hz yaml default. 10 Hz costs 2450 B/s, 2 % of a 1 Mbit/s IP budget. The console sends one HEARTBEAT per second as system 254, MAV_COMP_ID_LOG, MAV_TYPE_LOG: it brings learn_remote to the phone's address, but GcsLink only counts MAV_TYPE_GCS, so the console never connects or trips the failsafe.

    The launch also enables obstacle.*: each LD19 scan (scan_topic:=/scan, mount yaw scan_mount_yaw_deg) goes out as OBSTACLE_DISTANCE, and the console places every fan with the 6-DoF pose at the fan's own timestamp. Slices taken at different heights and attitudes therefore stack into a 3-D voxel map (the console's docs/UAV_3D.md). At 10 Hz this costs 8950 B/s. That is every scan on Wi-Fi; on a 57.6 kBd radio the bridge sends one scan in 16.

    On a UAV with ros2_flight_controller, use odom_topic:=/odometry/filtered. Set link_loss_action:=rth if a real GCS (QGroundControl) flies it beside the console. The console is never counted as a GCS, so the setting only acts on that GCS.

    The UDP transport answers one remote. With learn_remote, the console and a QGroundControl on another host would take the downlink in turns; run a MAVLink router (e.g. mavlink-routerd) to serve both.

    Console on another network (transport: relay)¶

    When the phone and the Jetson do not share a network, both are behind NAT, the phone usually behind its carrier's (CGNAT), and neither can reach the other. With transport: relay the bridge dials out over TLS to Server_Relay, and the console does the same; outbound TCP crosses every NAT, so no port is opened on the robot.

    ros2 launch ros2_network_bridge jetbot_console.launch.py transport:=relay \
    relay_host:=relay.example.org relay_robot:=jetbot-01 \
    relay_token_file:=/etc/jetbot/relay.token [relay_pin:=<sha256 of the relay key>]
    • Trust. By default the bridge trusts the system CA store (or relay.ca_file) and checks the relay's host name. With relay.pin_sha256, the relay's public key (SHA-256 of the DER SPKI) is the anchor instead, so a self-signed relay works and a different key is refused before the token is sent.
    • Token. The token is read from relay.token_file, never from a parameter value, so it does not show in ros2 param or in process lists.
    • I/O. A dedicated thread connects, reads and writes. read() and write() only touch its queues, so the 10 ms I/O step never blocks on the network.
    • Reconnection. Back-off is min(T_min·2^(k−1), T_max) after k failures (1 s to 30 s). SIGPIPE is blocked on that thread only.
    • Safety. The relay forwards nothing from an observer to the vehicle except a verified HEARTBEAT. An observer can never send a command through it; GcsLink's safety rules still apply behind that.

    Build and test¶

    colcon build --packages-up-to ros2_network_bridge
colcon test --packages-select ros2_network_bridge && colcon test-result --verbose

    The full-stack SIL (../ROS2_Control_System/tests/sil/uav_stack_sil.py … --mission-planner … --network-bridge <network_bridge_node>) runs a pymavlink GCS against the real nodes and checks the following:

    • MISSION_START over MAVLink is acknowledged ACCEPTED.
    • LOCAL_POSITION_NED is within 0.18 m RMS of the truth, converted to NED.
    • The heartbeat custom_mode follows the flight modes.
    • 15 mission events arrive as STATUSTEXT.
    • After an 8 s GCS silence mid-mission, the bridge reports "mission planner in control — mission continues". The mission completes with only the planner's own RTH.

    Known limitations¶

    • OBSTACLE_DISTANCE is planar and carries no mount height, so the console places a fan at the body origin's height. The mount yaw and the horizontal offset are applied on the bridge.

    • MAVLink message signing is not implemented, so signed frames are rejected. Use a trusted network, udp.allowed_hosts and mavlink.gcs_system_id.

    • Only the command subset above is supported. There is no MAVLink mission protocol (MISSION_ITEM_INT) and no parameter protocol. Missions are uploaded through ros2_mission_planner (mission/upload, mission/upload_waypoints).
    • The loss estimator assumes fewer than 256 consecutive lost frames per GCS stream (sequence wrap). Longer outages already trip the link-loss detection.
    • The flight-controller custom_mode table must follow ros2_flight_controller::FlightMode.
    • ros2_flight_controller/include/.../mavlink_bridge.h is an older, unimplemented sketch. This package supersedes it, as it superseded ros2_communication_bridge, which was removed. The parameter migration table is in the CHANGELOG.
    • HIL with a real radio link is still to be done.
