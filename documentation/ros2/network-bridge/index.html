    Network Bridge¶

    Wireless communication, remote control, and distributed computing.

    🎯 Overview¶

    The Network Bridge module enables wireless communication, remote teleoperation, and distributed computing for the Isaac ROS Jetbot NanoOWL platform.

    Key Features: - 5GHz WiFi connectivity (802.11ac) - LoRa long-range communication (10km range) - 4G/LTE cellular backup (optional) - ROS2 bridge for remote nodes - Video streaming (H.264, H.265) - Command and telemetry UDP/TCP - Multi-robot mesh networking - Network load balancing

    🚀 Quick Start¶

    Installation¶

    # Install dependencies
sudo apt install -y \
    ros-humble-rmw-cyclonedds-cpp \
    gstreamer1.0-tools \
    libgstreamer1.0-dev \
    lora-gateway

# Build
cd ~/ros2_ws
colcon build --packages-select jetbot_network_bridge
source install/setup.bash

    Running Network Bridge¶

    # Launch WiFi bridge
ros2 launch jetbot_network_bridge network_bridge.launch.py network:=wifi

# Launch LoRa bridge
ros2 launch jetbot_network_bridge network_bridge.launch.py network:=lora

# Check network status
ros2 service call /network_bridge/status jetbot_interfaces/GetNetworkStatus

    🔧 Configuration¶

    Network Configuration¶

    # config/network_config.yaml
network_bridge:
  ros__parameters:
    # Primary network
    primary_network: "wifi"  # wifi, lora, cellular

    # WiFi configuration
    wifi:
      enabled: true
      ssid: "jetbot-network"
      password: "secure_password"
      frequency: 5000  # 5GHz
      channel: 149
      tx_power: 30  # dBm
      bandwidth: 80  # MHz

    # LoRa configuration
    lora:
      enabled: true
      frequency: 915.0  # MHz (US ISM band)
      bandwidth: 125  # kHz
      spreading_factor: 7
      coding_rate: 4/5
      tx_power: 20  # dBm
      range_estimate: 10000  # meters

    # Cellular (optional)
    cellular:
      enabled: false
      provider: "verizon"
      apn: "verizon.com"

    # ROS2 bridge
    ros2_bridge:
      enabled: true
      middleware: "CycloneDDS"
      domain_id: 0
      dds_config: "config/dds_config.xml"

    # Network failover
    failover:
      enabled: true
      fallback_network: "lora"
      timeout: 5  # seconds
      retry_count: 3

    # Monitoring
    monitoring_interval: 1  # seconds
    log_network_stats: true

    Video Streaming Configuration¶

    # config/stream_config.yaml
video_streamer:

    max_latency: 200  # milliseconds

    # Adaptive bitrate
    adaptive_bitrate: true
    min_bitrate: 500   # kbps
    max_bitrate: 4000  # kbps

    📡 Communication Protocols¶

    WiFi (802.11ac) - Primary¶

    Specifications:
  Bandwidth: 80/160 MHz
  Max Data Rate: 433 Mbps (1 stream)
  Frequency: 5GHz (less interference)
  Range: 50-100m line-of-sight
  Latency: 5-20ms typical
  Power: ~1.5W at full power

Configuration:
  Channel: 149 (UNII-3)
  Bandwidth: 80MHz
  TX Power: 30dBm (1W)

Use Case: Primary connectivity, high bandwidth

    LoRa - Long Range¶

    Specifications:
  Bandwidth: 125 kHz
  Spreading Factor: 7-12
  Max Data Rate: 50 kbps (SF7)
  Frequency: 915 MHz ISM (US)
  Range: 5-10km line-of-sight
  Latency: 100-500ms typical
  Power: ~0.3W TX, 50mW RX

Configuration:
  Frequency: 915.0 MHz
  SF: 7 (balance between range/speed)
  Coding Rate: 4/5
  CRC Enabled: Yes

Use Case: Long-range fallback, low power

    Cellular (4G/LTE) - Backup¶

    Optional Third Layer:
  Technology: LTE Cat-M1 / NB-IoT
  Data Rate: 1-10 Mbps
  Latency: 50-100ms
  Power: ~2W at full power
  Cost: Monthly plan required

Use Case: Remote deployment, assured connectivity

    🎥 Video Streaming¶

    RTSP Protocol¶

    # Stream to remote viewer
ffplay rtsp://jetbot.local:8554/stream

# Record stream
ffmpeg -i rtsp://jetbot.local:8554/stream -c:v copy output.mp4

# Stream with low latency
gst-launch-1.0 rtspsrc location=rtsp://jetbot.local:8554/stream latency=0 ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! autovideosink

    Bitrate Adaptation¶

    Adaptive Bitrate Scheme:
  Measurement: Packet loss rate, RTT (round trip time)

  Excellent (>95% delivery): 4000 kbps
  Good (90-95% delivery):    2500 kbps
  Fair (80-90% delivery):    1500 kbps
  Poor (<80% delivery):      800 kbps

  Update Frequency: Every 3 seconds
  Hysteresis: ±10% to prevent oscillation

    🎮 Remote Control¶

    Command Packet Format¶

    UDP Command Packet:
  Header: 0xDEADBEEF (4 bytes)
  Sequence: uint16 (2 bytes)
  Command Type: uint8 (1 byte)

  Data:
    - Linear velocity: float (4 bytes)
    - Angular velocity: float (4 bytes)
    - Aux command: uint32 (4 bytes)

  Checksum: CRC32 (4 bytes)
  Total: 23 bytes

Latency: <20ms typical

    Telemetry Packet Format¶

    UDP Telemetry Packet:
  Header: 0xBEEFDEAD (4 bytes)
  Sequence: uint16 (2 bytes)
  Timestamp: uint64 (8 bytes)

  Data:
    - Position: float[3] (12 bytes)
    - Orientation: float[4] quaternion (16 bytes)
    - Velocity: float[3] (12 bytes)
    - Battery: float (4 bytes)
    - Status flags: uint32 (4 bytes)

  Checksum: CRC32 (4 bytes)
  Total: 66 bytes

Rate: 10-30 Hz typical

    🛡️ Security Features¶

    Encryption¶

    AES-256-GCM Encryption:
  Key Exchange: Diffie-Hellman
  Key Size: 256 bits
  Authentication: 16-byte GCM tag
  Nonce: 12 bytes, random

Applied to:
  - ROS2 messages
  - Video stream metadata
  - Control commands
  - Telemetry packets

    Authentication¶

    Certificate-based:
  Type: X.509 v3
  Algorithm: ECDSA P-256
  Validity: 1 year

Device Identity:
  Serial Number: Unique per robot
  MAC Address: Burned in firmware
  IMEI: If cellular equipped

    🔍 Troubleshooting¶

    WiFi Connection Drops¶

    Check: - Signal strength: iwconfig wlan0 - Channel interference: Use WiFi analyzer app - Thermal interference: Check temperature

    Solutions: - Reduce TX power to 20dBm - Switch to less congested channel - Enable 5GHz (less interference)

    High Video Latency¶

    Check: - Network ping: ping -c 10 gateway.local - Packet loss: iperf3 -c server -u -b 2M

    Solutions: - Reduce video resolution - Enable low-latency mode (shorter buffers) - Increase keyframe interval

    LoRa Not Connecting¶

    Check: - Frequency match: 915 MHz (US), 868 MHz (EU) - Antenna connection: SMA connector secure - Power supply: LoRa module needs stable 3.3V

    Solutions: - Verify antenna placement - Check cable integrity - Perform frequency calibration
