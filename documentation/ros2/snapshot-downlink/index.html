    isaac_ros_snapshot_downlink¶

    Source

    This page is rendered from Source/Isaac_ROS-Snapshot_Downlink/README.md, the authoritative description kept next to the code in Source/Isaac_ROS-Snapshot_Downlink/.

    Still photo for the Remote_UAV ground station. The pilot presses Capture on the remote's LCD; the request travels over LoRa 2.4 GHz to the JetOwl flight controller, which relays it to this node over micro-ROS. The node takes the newest frame of the camera layer (/camera/color/image_raw, published by ros2_panorama from the master's IMX477 Dual), compresses it to baseline JPEG on the GPU (CUDA) at the highest quality that fits the radio preset's byte budget, and streams it back to the FC. The FC sends it to the remote on the 2.4 GHz image slot, and the remote decodes it and shows it on the LCD.

    flowchart LR
    R[Remote_UAV<br/>Capture] -- "aux IMG_REQ<br/>2.4 GHz UL" --> F[FC STM32N657]
    F -- "/jetowl/camera/request" --> N[snapshot_node]
    C["camera layer<br/>/camera/color/image_raw (ros2_panorama)"] --> N
    N -- "CUDA: area resample → YCbCr 4:2:0 → FDCT → quantise<br/>CPU: Huffman, rate control" --> N
    N -- "/jetowl/camera/jpeg (reliable, 384 B chunks)" --> F
    F -- "/jetowl/camera/fc_status (bitmap)" --> N
    F -- "image slot SF5, 47 B/frame, 2115 B/s" --> R
    R -- "aux IMG_ACK" --> F

    1. Radio budget: what size, how far, how long¶

    The link is the Waveshare Core1121-XF (Semtech LR1121): 2.4 GHz HF PA ≤ 13 dBm, sensitivity −111 dBm at SF7/BW800 (vendor). The design and the proofs are in Microcontroller/Remote_UAV/docs/LINK_DESIGN.md §6.4 (= JetOwl_FlightControl/docs/RFLINK.md).

    Quantity Value
    Image frame 63 B, SF5 / BW 812 kHz / CR ⅘, ToA 6.157 ms, one after each 50 Hz command frame
    ETSI EN 300 328 medium utilisation of the FC transmitter 9.74 % ≤ 10 % (the limit that fixes the frame length)
    Payload throughput 47 B × 50/s × 0.9 = 2115 B/s
    Free-space range (10 dB fade margin) ≈ 4.4 km (S = −106 dBm at SF5); commands keep SF6 and 5.8 km
    Preset Size Budget Transfer, p = 0 p = 20 %
    0 160 × 120 3 KiB 1.5 s 1.9 s
    1 320 × 240 8 KiB 3.9 s 4.9 s
    2 480 × 360 14 KiB 6.8 s 8.5 s
    3 640 × 480 24 KiB 11.6 s 14.6 s

    E[T] = N / (45 (1 − p)) for N chunks of 47 B under selective repeat. The FC host test measures 4.80 s for 8 KiB at 20 % loss in both directions, against 4.81 s from the formula.

    2. Encoder (include/isaac_ros_snapshot_downlink/jpeg_math.hpp, jpeg_encoder.hpp)¶

    Every per-pixel and per-block function is written once as __host__ __device__. The CUDA kernels (src/jpeg_cuda.cu) and the CPU reference (src/jpeg_cpu.cpp) call the same code, so the host tests check exactly what the GPU runs.

    Stage Definition Reference
    Crop centre crop to the output aspect (16:9 → 4:3 for a 1080p topic) —
    Area resample output pixel = mean of the source over its exact footprint (fractional weights): box prefilter, |H(f)| = |sinc(f s)|, null at the new sampling rate, 2/π at the new Nyquist Wolberg, Digital Image Warping, ch. 5
    Colour Y = 0.299 R + 0.587 G + 0.114 B; Cb, Cr full range ITU-T T.871 §7
    Chroma 4:2:0 by 2 × 2 mean (centred siting) T.871
    FDCT F(v,u) = ¼ C(u) C(v) ΣΣ f cos((2x+1)uπ/16) cos((2y+1)vπ/16), separable ITU-T T.81 A.3.3
    Quantise round(F / Q), Q = K.1 / K.2 scaled by quality T.81 A.3.4, Annex K; IJG jpeg_quality_scaling
    Entropy baseline Huffman, tables K.3–K.6, codes built per Annex C T.81 F.1.2
    Rate control bisection for the largest q with size(q) ≤ budget (8 trials), result verified against the budget jpeg_encoder.hpp

    The rate control is the encoder's closed loop: the measured file size is fed back to the quality. Q is non-increasing in q element by element, so size(q) is non-decreasing in practice. The budget guarantee does not depend on that, because the returned file is checked.

    3. Use¶

    ros2 launch ros2_jetowl_bridge jetowl_bridge.launch.py              # micro-ROS agent for the FC
ros2 launch ros2_panorama panorama.launch.py                        # the camera layer
ros2 launch isaac_ros_snapshot_downlink snapshot_downlink.launch.py
ros2 run isaac_ros_snapshot_downlink snapshot_encode in.ppm out.jpg 320 240 8192   # offline

    This package configures no camera. The IMX477 Dual of the master Jetson (sensors, modes, exposure, stitching into one frame) is configured once in the camera layer, ros2_panorama, whose /camera/color/image_raw every image consumer reads — detection, the arm gaze loop and this node. The radio presets are 4:3: an 8:3 panorama is centre-cropped to 4:3 (§2, Crop).

    Parameters: config/snapshot_downlink.yaml. Every photo sent is also published as ~/snapshot/compressed (sensor_msgs/CompressedImage) and, with save_dir, written to disk.

    4. Tests¶

    cmake -S . -B build -DBUILD_TESTING=ON && cmake --build build -j && ctest --test-dir build   # no ROS
colcon test --packages-select isaac_ros_snapshot_downlink
    Test Checks
    test_jpeg_encoder FDCT against its definition (≤ 2·10⁻³) and Parseval; IJG scaling (q 50 = Annex K, q 100 = 1, monotone); colour points; area resample (checkerboard → mean, fractional weights, constant stays constant); Annex K Huffman codes bit-exact; SOF size; every preset fits and q + 1 would not; CPU = CUDA (≤ 0.05) on a GPU
    test_cam_link FC layouts against the golden vectors of JetOwl_FlightControl/tests/host/test_cam_relay.c; CRC-32; resend from the status bitmap at 30 % loss
    test_jpeg_pil.py Pillow/libjpeg decodes all four presets (baseline, right size, within budget); against an independent numpy area resample, PSNR within 0.5 dB of libjpeg at the same quality, luma > 30 dB

    Results on this repository's CI host (CPU backend): presets at q 80 / 76 / 59 / 67 for a 1920 × 1080 test scene, PSNR equal to libjpeg's to 0.01 dB, files within 5 % of libjpeg in size.
