    ROS2_Control_System — UAV estimation and trajectory control¶

    Source

    This page is rendered from Source/ROS2_Control_System/README.md, the authoritative description kept next to the code in Source/ROS2_Control_System/.

    ros2_control_system 0.6.0 closes the translational loop of the UAV. Its uav_state_estimator is the stack's only state estimator (the former ros2_sensor_fusion EKF is merged into it):

    IMU 200 Hz ─┐  guard + anti-alias LPF   ┌──────────────┐  odometry/filtered  ┌──────────────────────────┐
GNSS 10 Hz ─┼─────────────────────────▶ │ 15-state ESKF │ ──────────────────▶ │ offset-free linear MPC   │
Baro 50 Hz ─┤  χ² gating, recovery      └──────────────┘                     │  (MPPI on CUDA near       │
AHRS yaw  ──┘                                                                │   obstacles)             │
                     flight/setpoint (ros2_flight_controller) ─────────────▶ │ jerk limit → thrust/att. │
                                                                             └────────────┬─────────────┘
                                   control/attitude_setpoint, control/thrust ◀────────────┘
                                   → attitude/rate loops (ROS2_Hexacopter_Control) → vehicle
    Executable Role
    uav_state_estimator IMU/GNSS/baro/heading → error-state Kalman filter → nav_msgs/Odometry (REP-105)
    uav_trajectory_controller odometry + reference trajectory + obstacles → MPC / MPPI → thrust and attitude set-point

    Launch: ros2 launch ros2_control_system control_system.launch.py (parameters: config/uav_control.yaml).

    Control design (control-systems.md §5)¶

    CONTROL DESIGN — translational loop
  Plant        : per axis ṗ = v, v̇ = u + d (u commanded acceleration, d wind / mass error);
                 attitude loop (ROS2_Hexacopter_Control) ≥ 5× faster, booked as 40 ms delay
  Sensors      : BMI088 IMU (N_a 1.72e-3 m/s/√s, N_g 2.44e-4 rad/√s), u-blox GNSS 10 Hz,
                 MS5611 baro 50 Hz, AHRS heading σ 0.05 rad
  Filter       : sample guard (NaN / full scale / order / gap), 1st-order LPF f_c = 50 Hz,
                 α = ω_cT/(1+ω_cT), lag 1.6° at the 1.4 Hz loop crossover
  Estimator    : ESKF [δp δv δθ δb_a δb_g] (Solà 2017), Q from Allan densities, Joseph update,
                 χ² gates 16.27 / 10.83 (99.9 %), PWCS observability 15/15 with manoeuvre
                 (13/15 in hover: horizontal b_a ↔ tilt), NIS 3.10 ∈ [2.85, 3.15] (95 %)
  Controller   : condensed MPC, T_s = 20 ms, N = 25, Bryson Q/R (e_p 1.0/0.5 m, e_v 1.0/0.5 m/s,
                 u_max 4 m/s²), DARE terminal cost ⇒ unconstrained law = LQR (verified),
                 box constraints by FISTA with restart; disturbance observer f_d = 0.3 Hz with
                 target shift u_ss = a_ref − d̂ (offset-free, Pannocchia & Rawlings 2003)
  Obstacles    : MPPI K = 2048, N = 75 on CUDA (sm_87), adaptive temperature (ESS ≥ 10 %),
                 best-sample fallback for bimodal averages, braking failsafe
  Actuator     : jerk limit 20 m/s³, geometric thrust/attitude map (Lee 2010) with 30° tilt,
                 T ∈ [5, 103] N, vertical priority; achieved acceleration feeds d̂ (no windup)
  Loop         : closed on the ESKF estimate; flight/active gates engagement (IDLE on ground)
  Margins      : xy GM 16.2 dB / PM 66.7° @ 4.77 rad/s, z GM 11.3 dB / PM 60.1° @ 8.31 rad/s,
                 closed-loop |z| ≤ 0.98, all with 40 ms delay
  Failsafe     : stale reference → closed-loop position hold; stale odometry → level attitude,
                 bounded open-loop descent (a_z −0.5 m/s² to −1 m/s); ESKF divergence (10
                 consecutive GNSS rejections) → position/velocity reset
  Verification : unit tests (tests/cpp), SIL of the full stack (tests/sil/uav_stack_sil.py)
  Reference    : Solà 2017; Groves 2013; Rawlings, Mayne & Diehl 2017; Beck & Teboulle 2009;
                 Williams et al. 2017; Jasra et al. 2011; Lee, Leok & McClamroch 2010

    The derivations are written next to the code: include/ros2_control_system/uav/*.hpp.

    Topics¶

    Direction Topic Type
    in imu, gnss/fix, gnss/velocity, baro sensor_msgs/Imu, NavSatFix, geometry_msgs/TwistWithCovarianceStamped, sensor_msgs/FluidPressure
    out odometry/filtered, estimator/diagnostics nav_msgs/Odometry, diagnostic_msgs/DiagnosticArray
    in flight/setpoint, flight/active, obstacles trajectory_msgs/MultiDOFJointTrajectory, std_msgs/Bool, visualization_msgs/MarkerArray (SPHERE / CYLINDER / CUBE in any frame with a transform to world_frame; launch: /tracked/markers)
    out control/attitude_setpoint, control/thrust, control/accel_cmd geometry_msgs/QuaternionStamped, std_msgs/Float64 [N], geometry_msgs/AccelStamped
    out control/predicted_path, control/diagnostics nav_msgs/Path, diagnostic_msgs/DiagnosticArray (set-point, estimate, error, u pre/post limit, d̂, iterations, ESS, compute time)
    out control/disturbance geometry_msgs/Vector3Stamped — disturbance-observer estimate d̂ [m/s²], world frame, while engaged (wind estimate of ros2_mission_planner)

    CUDA¶

    The MPPI rollouts (one thread per sample, Philox RNG, coalesced weighted update) are built when CMake finds a CUDA compiler (CMAKE_CUDA_ARCHITECTURES defaults to 87 for Orin Nano Super). Without CUDA, or if a GPU call fails at run time, the bit-comparable CPU backend in mppi.cpp is used with mppi.cpu_samples samples. The linear MPC and the ESKF are small dense problems (≤ 25×25, 15×15) and run on the CPU.

    Build and test¶

    colcon build --packages-select ros2_control_system
colcon test --packages-select ros2_control_system && colcon test-result --verbose

# Software-in-the-loop of the whole stack (needs ros2_flight_controller built too)
python3 tests/sil/uav_stack_sil.py \
  --estimator install/ros2_control_system/lib/ros2_control_system/uav_state_estimator \
  --controller install/ros2_control_system/lib/ros2_control_system/uav_trajectory_controller \
  --flight install/ros2_flight_controller/lib/ros2_flight_controller/flight_controller_node \
  --control-params install/ros2_control_system/share/ros2_control_system/config/uav_control.yaml

    SIL scenario: +10 % mass, a constant 3.4 m/s wind acting through airframe drag and rotor H-force (hexacopter_physical.yaml, unknown to every node), IMU biases, GNSS σ 0.5/0.8 m; ARM → takeoff 5 m → 4-waypoint minimum-jerk mission → RTH → land. Result: control error RMS 6.0 cm in hover and 4.4 cm on the mission, estimation error RMS 0.17–0.18 m, every waypoint passed within 0.19 m, touchdown 6 cm from home. (Previous model — 2 N force, 0.3 N·s/m drag — three runs: 3.4–5.8 cm, 0.17–0.19 m, 0.19 m, 6 cm.)

    With --mission-planner … --mission-params … --mission-file … [--update-file …] (see ../ROS2_Mission_Planner/README.md), ros2_mission_planner flies the mission file instead: it calls mission/start and checks the state sequence, waypoint passes, keep-out clearance of the truth path, the planner's wind estimate (from control/disturbance) and measured-power ratio against the truth, and an in-flight mission change. With --network-bridge <network_bridge_node> (needs pymavlink), a MAVLink ground station starts the mission through ros2_network_bridge and checks its telemetry (position within 0.18 m RMS of the truth) and the datalink-loss policy. All checks pass for the plain, keep-out and re-task scenarios; the wind estimate is within 0.03 m/s of the truth.

    Known limitations¶

    • HIL and bench results are still to be produced (control-systems.md §4 verification order).
    • Accelerometer / gyro bias random-walk densities are conservative placeholders until the unit's Allan-variance log is recorded.
    • MPPI has no finite-sample stability certificate; it is engaged only near obstacles.
    • CUDA sources are compile-checked for sm_87 (clang CUDA front end + CUDA 12.9 headers, 0 errors / 0 warnings); they have not yet been executed on a GPU.
