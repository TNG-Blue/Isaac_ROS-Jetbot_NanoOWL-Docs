    ros2_lidar_slam — 2-D LiDAR SLAM for the Jetbot (LD19 + LPB40B + IMU)¶

    Source

    This page is rendered from Source/ROS2_Lidar_SLAM/README.md, the authoritative description kept next to the code in Source/ROS2_Lidar_SLAM/.

    Drivers for the two range sensors on the robot and a complete 2-D SLAM pipeline, written from their datasheets and protocol documents and verified in software-in-the-loop.

    Part Language Content
    lidar_slam_core C++17, Eigen, no ROS sensor protocols, filters, de-skew, PL-ICP, EKF, pose graph, occupancy grid
    ld19_node C++17, rclcpp LDROBOT LD19 360° DToF scanner → sensor_msgs/LaserScan
    lpb40b_node C++17, rclcpp DFRobot LPB40B single-point DToF range finder → sensor_msgs/Range
    lidar_slam_node C++17, rclcpp SLAM → map, slam/pose, slam/path, TF map → odom, /diagnostics 
     LD19 ──UART 230400──▶ ld19_node ── /scan ─────┐
   CRC-8 0x4D, sensor clock → host time          │     lidar_slam_node (SlamCore)
   gate · mixed-pixel filter                      ├──▶ gate · Hampel · project(Σ) · de-skew(gyro)
 LPB40B ─UART 115200─▶ lpb40b_node ─ /range ──────┤       │
   CRC-8 0x31, status → REP-117, Hampel           │       ▼
 IMU (jetowl_bridge) ── /imu/data ────────────────┤   EKF predict (gyro = input) ──▶ PL-ICP vs submap
 wheel odometry (optional) ── /odom ──────────────┘       ▲   pose update, χ² gate      │ pose, Σ, degeneracy
                                                          └──────────────────────────────┘
                                keyframe ─▶ pose graph ─▶ loop closure (correlative + ICP) ─▶ Gauss–Newton
                                         └▶ log-odds occupancy grid (LD19 rays + LPB40B wide beam) ─▶ /map

    1. The sensors — what they are and how they are used¶

    LDROBOT LD19 (360° scanning DToF)¶

    Source: LD19 Development Manual V2.3, LD19 Datasheet V1.0 (LDROBOT).

    Item Value Used for
    Interface UART 230400 8N1, one-way, streams on power-up baudrate (the old driver used 115200)
    Packet 47 B: 0x54 0x2C, speed, start angle, 12 × {mm, intensity}, end angle, timestamp, CRC-8 ld19_protocol.cpp
    CRC table-driven CRC-8, polynomial 0x4D checked on every packet
    Sampling / rotation 4500 Hz / 10 ± 0.1 Hz (in-device closed loop) 450 rays, Δθ = 0.8°
    Range 0.02–12 m; accuracy ±45 mm for 0.3–12 m, none below 0.3 m gate; SLAM uses 0.3–12 m
    Angle convention 0° = sensor front, clockwise (left-handed) mirrored to REP-103: θ_ros = −θ_ld19
    Timestamp u16 ms, wraps at 30 000 mapped to host time (below)

    Time. USB-serial bridges deliver in 1–16 ms bursts, far more than the 0.22 ms point spacing. Arrival t_rx = s + o + d with d ≥ 0, so the lower envelope of t_rx − s tracks the offset: ô_k = min(ô_{k−1} + ε·Δs, t_rx,k − s_k). In the unit test raw jitter is 5.7 ms RMS and the mapped stamp 0.3 ms RMS.

    LaserScan convention. angle_min = −π, increasing angle; since the sensor turns clockwise, time_increment < 0 and header.stamp is the time of ray 0 (the last one taken). The seam of a revolution is placed at 180° (behind the sensor, cable side).

    DFRobot LPB40B (single-point DToF) — not a scanning LiDAR¶

    Source: DFRobot SEN0586 product page; LP series communication protocol (DFRobot).

    Item Value Used for
    Measurement one distance along a fixed beam sensor_msgs/Range (the old driver published its raw bytes as a LaserScan)
    Range / accuracy / resolution 0.05–40 m (90 % refl.), 0.05–12 m (10 %) / ±5 cm / 1.5 cm σ = 0.05/√3 = 0.029 m
    Beam receive FOV 2.2°, emitter 0.17°, 905 nm wide-beam map model
    Rate 1–2000 Hz, default 100 Hz configured on start-up
    Frame 0x55 key value[4] CRC-8(0x31) 0xAA; data MSB first lpb40b_protocol.cpp
    Status 0 ok · 1 weak · 2 strong · 3 out of range · 4 system error REP-117: ok → r, 3 → +inf, else NaN

    It extends the map forward beyond the LD19's 12 m and gives a second, independent range along the direction of travel. In the grid it is a wide beam: its end cell is marked occupied only while the 2.2° arc is ≤ 2 cells wide (r ≤ 2.6 m); farther away only the free space up to r − 3σ is used, because the echo cannot be localised inside the arc.

    IMU and wheel odometry¶

    The yaw rate comes from /imu/data (BMI088 through Source/ROS2_JetOwl_Bridge sensor_link, already in base_link), used as a process input of the EKF. Wheel odometry is optional (use_odom); do not enable it if that odometry already fused the same IMU.

    2. Quick start¶

    colcon build --packages-select ros2_lidar_slam && source install/setup.bash
ros2 launch ros2_lidar_slam dual_lidar_slam.launch.py ld19_port:=/dev/ld19 lpb40b_port:=/dev/lpb40b
ros2 launch ros2_lidar_slam dual_lidar_slam.launch.py odom_frame:="''"   # no odom → base_link TF
ros2 launch ros2_lidar_slam dual_lidar_slam.launch.py backend:=slam_toolbox
ros2 launch ros2_lidar_slam lidar_visualization.launch.py                 # RViz on a laptop
ros2 service call /lidar_slam_node/save_map std_srvs/srv/Trigger         # ~/maps/slam_<time>.{pgm,yaml,g2o}

    Without ROS: cmake -S . -B build -DBUILD_TESTING=ON && cmake --build build -j && (cd build && ctest).

    Stable device names (/etc/udev/rules.d/99-lidar.rules; check udevadm info -a /dev/ttyUSBx for the vendor/product/serial of your adapters):

    SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", ATTRS{serial}=="<ld19>",   SYMLINK+="ld19"
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", ATTRS{serial}=="<lpb40b>", SYMLINK+="lpb40b"

    The sensor mounts are static transforms from launch arguments ld19_{x,y,z,yaw} and lpb40b_{x,y,z,yaw} (set publish_mounts:=false if the URDF provides them).

    Node Topic / service Type Notes

    all /diagnostics DiagnosticArray rates, CRC errors, rotation, status codes, NIS, loop closures, processing time

    4. Signal chain and design¶

    No actuator is commanded by this package: it is the sensor, filter and estimator part of the chain of control-systems.md. Its output (pose, map) feeds the planners and controllers. The loop inside it is an estimation loop: the fused pose and velocity feed back into the next scan's de-skew, correspondence gate and ICP initial guess, and the map built from the estimates is the next reference.

    CONTROL DESIGN (estimation loop)
  Sensor       : LD19 f_s = 4500 Hz / 10 Hz rev, σ_r = 0.028 m; LPB40B 100 Hz, σ = 0.029 m;
                 BMI088 gyro N_g = 2.443e-4 rad/s/√Hz at 1 kHz
  Filter       : gate (datasheet ranges) · mixed-pixel β < 10° · Hampel K = 2, 3σ (registration
                 only) · voxel 0.05 m · gyro-integrated de-skew
  Estimator    : EKF [x y θ v ω b_g], gyro as input, ICP pose measurement, χ²(0.99) gate,
                 Joseph update; observability rank 5 (ω algebraic), b_g observable
  Measurement  : point-to-line ICP, Gauss–Newton + Huber, Σ = H⁻¹·max(1, χ²_ν), degeneracy
                 via eigenvalues of the scaled information vs. normal-noise floor
  Back end     : keyframe pose graph, Huber, sparse LDLᵀ; loop closure: rasterised correlative
                 search + ICP + geometric verification
  Map          : log-odds grid 0.05 m, P_D = 0.6, P_FA = 0.05, clamp ±4
  Loop         : closed: estimate → de-skew / gate / guess → measurement → estimate
  Verification : 36 unit tests + SIL (tests/test_slam_simulation.cpp), ROS end-to-end with an
                 emulated LD19 on a pseudo-terminal
  References   : Censi ICRA 2008/2007; Zhang, Kaess, Singh ICRA 2016; Olson ICRA 2009;
                 Grisetti et al. 2010; Thrun, Burgard, Fox 2005; Bar-Shalom, Li, Kirubarajan 2001

    4.1 Sensor models (every default is derived)¶

    Quantity Value Derivation
    LD19 range σ_r 0.028 m √(σ_bias² + σ_rand²): σ_bias = 0.045/√3 (±45 mm bound as uniform, [D]), σ_rand = 0.01 m [A]
    LD19 angle σ_φ 0.23° ray spacing Δ/√12 (uniform quantisation of the resampled scan)
    point covariance Σ_p = J diag(σ_r², σ_φ²) Jᵀ J = ∂(r cos φ, r sin φ)/∂(r, φ); checked against 200 000-sample Monte Carlo
    LPB40B σ 0.029 m 0.05/√3
    gyro sample variance N_g²·f_s = 5.97e-5 (rad/s)² IEEE Std 952 Annex C
    gyro mean over T N_g²/T variance of the mean of white noise

    4.2 Filters¶

    • Gate: LD19 0.02–12 m (driver), 0.3–12 m for SLAM (no accuracy below 0.3 m).
    • Mixed pixels: for rays i, j at angular distance Δ, tan β = r_j sin Δ / (r_i − r_j cos Δ); the farther point is removed if β < 10° or β > 170°. At 0.8° spacing this rejects range steps ≥ 0.08·r per ray (≥ 2.8 σ_r already at 1 m).
    • Hampel (registration only): reject if |x − med| > 3·max(1.4826·MAD, σ_r) over 5 rays. Not applied to the published /scan, because it would also delete objects ≤ 2 rays wide (a table leg at 2 m).
    • De-skew: within a 0.1 s revolution the robot moves (0.5 m error at 5 m for ω = 1 rad/s). Each ray is moved to the pose at the scan end with the gyro-integrated motion φ(t) = −∫ₜ^{t_ref}(g − b_g), p(t) = −∫ₜ^{t_ref} v[cos φ, sin φ]. A constant-twist model fails when the yaw rate changes inside the revolution (entering a turn: 5–10σ heading innovations in SIL); the gyro integral removes them (unit test: residual < 5 mm vs. > 5 cm).

    4.3 Scan matching (measurement)¶

    Point-to-line ICP (Censi 2008), e = nᵀ(R p + t − q), weights 1/σ² with σ² = nᵀRΣ_pRᵀn + σ_line², Huber k = 1.345, Gauss–Newton with re-association. The reference line passes through the PCA centroid of its neighbourhood (standard error λ_min/(n−2)).

    • Covariance Σ = H⁻¹·max(1, χ²_ν). Monte Carlo NEES over 60 runs: 2.90, inside the 95 % bounds [2.41, 3.65] of the expected 3 → consistent, not optimistic.
    • Degeneracy (Zhang, Kaess, Singh 2016): eigenvalues of H' = S H S, S = diag(1, 1, 1/L). The PCA normal error σ_δ² = λ_min/(n λ_max) gives a spurious information λ_noise = Σ w σ_δ²/σ² even along an unobservable axis (≈ 2000 m⁻² in a 3 m corridor, which would pass a bare 1/σ_max² = 400 test and claim σ = 2 cm). The threshold is therefore λ_thr = 1/σ_max² + λ_noise(1 + 3√(2/N)); the update is projected on the constrained subspace and the degenerate direction gets σ = 10 m (finite, so it cannot leak into the constrained axes). Corridor test: along-corridor held at the prior, σ_x = 10 m, σ_y = 1.3 mm.

    4.4 Estimator (EKF)¶

    State [x, y, θ, v, ω, b_g]. Process: unicycle with midpoint integration, continuous white-noise acceleration discretised exactly, q̃ = a_max²·T_s (Bar-Shalom §6.2.2): q̃_v = 0.1 m²/s³ (a_max = 1 m/s²). With an IMU the mean gyro rate is the input: θ⁺ = θ + (ḡ − b_g)T, input noise N_g²/T. As a measurement of a random-walk ω, the process noise on θ (≈ 1° per scan) would hide the bias (0.03° per scan); as an input the bias converges (SIL: 0.0050 estimated for 0.0050 true).

    • Observability (rank of [H; HF; …; HF⁵], unit-tested): scans + gyro: ⅚ — everything but ω, which is then the algebraic output ḡ − b_g; scans only: ⅚ (b_g not in the model); gyro + wheels only: 3/6 (pose unobservable, dead reckoning).
    • Gating: pose NIS vs χ²₃(0.99) = 11.34. A 1 m jump is rejected (test). Gyro/odometry are only gated against 5σ faults.
    • Lock-out recovery: 3 consecutive rejections of a healthy registration (converged, ≥ 60 % inliers, non-degenerate) re-initialise the pose from ICP; false-alarm probability 0.01³. Found in SIL: a robot already moving when the node starts (v = 0 prior) diverged. The prior is now σ_v = v_max/√3.
    • Initial uncertainty: v uniform on ±0.5 m/s → σ = 0.29 m/s; ω on ±1 rad/s → 0.58 rad/s; b_g: BMI088 zero-rate offset ±1°/s → 0.02 rad/s.

    4.5 Pose graph and loop closure¶

    Keyframes every 0.2 m or 30°. Edge covariance J(Σ_i + Σ_j)Jᵀ (two independent registrations). Error and Jacobians from Grisetti et al. 2010 (verified against finite differences), Huber k² = χ²₃(0.95), node 0 fixed, sparse LDLᵀ.

    Loop candidates: nearest keyframe ≥ 30 keyframes older within 3 m. Verification: rasterised correlative search ±1 m, ±10° (0.1 m, 1° steps; Olson 2009), then ICP; accepted only if converged, not degenerate and ≥ 60 % inliers. After optimisation the EKF is moved rigidly with the current keyframe and the grid and submap are rebuilt.

    Robustness limit (measured, not assumed): Huber limits a moderately confident wrong loop (σ = 0.3 m wrong edge between nodes 4.4 m apart: least squares pulls them to 2.2 m, Huber keeps 3.5 m) but cannot neutralise a very confident one. The geometric verification is the primary defence.

    4.6 Occupancy grid¶

    Log-odds (Thrun et al. §9.2). Inverse sensor model from detection probabilities with a 0.5 prior: P(occ|hit) = P_D/(P_D + P_FA), P(occ|pass) = (1−P_D)/((1−P_D) + (1−P_FA)); with P_D = 0.6, P_FA = 0.05: l_hit = +2.48, l_pass = −0.87. Clamp ±4 (OctoMap) keeps the map able to change. Resolution 0.05 m ≥ 2σ_r and equal to the beam spacing at 3.6 m.

    5. Verification evidence¶

    colcon test: 0 failures — 37 gtest cases (36 unit + 1 SIL) in 8 executables plus test_serial_utils (colcon reports these as 46 results: cases + CTest entries). All also run without ROS.

    Test Checks

    test_lpb40b_protocol all 9 quick-reference frames of the protocol document; measurement example (1453 mm); 8/44-byte frames in a noisy stream
    test_scan_filters gate; Hampel removes spikes, keeps step edges, < 1 % false rejections; mixed pixel; Σ_p vs Monte Carlo; de-skew exact; gyro de-skew with a yaw-rate step
    test_scan_matcher convergence from 20 cm/3°; NEES consistency; corridor degeneracy; correlative search from 0.9 m/7°
    test_pose_ekf F vs finite differences; observability ranks; bias estimation, NIS consistency; gate
    test_pose_graph Jacobians vs finite differences; loop closure removes drift; Huber limit; g2o
    test_occupancy_grid inverse-model numbers; free/occupied/unknown; growth; wide-beam rule; PGM/YAML
    test_slam_simulation complete pipeline, below
    test_serial_utils baud mapping, errors on missing devices

    SIL (test_slam_simulation): 52 m corridor loop at 0.4 m/s, simulated LD19 with per-ray timing (real motion distortion), σ_r = 0.02 m, BMI088 gyro with 0.005 rad/s bias, LPB40B:

    Metric Result
    ICP accepted / EKF updates 99.9 % / 99.4 % of 1307 scans
    Keyframe ATE (after 8 loop closures) 0.030 m
    Final pose error 0.015 m / 0.18°
    Gyro bias 0.0050 estimated (0.0050 true)
    Map precision 99.5 % of occupied cells within 2 cells of a real wall
    NIS per axis (expect 1) across 1.13, yaw 0.56, along 0.16
    Processing (x86 Xeon 2.8 GHz, 1 core) mean 1.4 ms/scan, keyframe 4 ms, loop-closure worst 66 ms

    NIS, stated plainly. The mean NIS is 1.87 against a 95 % band of [2.87, 3.13] for the mean, so the filter is conservative, never optimistic. Across-track and yaw are consistent. The along-track component (0.16) is low because q̃_v is sized for a_max = 1 m/s² while the SIL robot drives at constant speed. On the vehicle, check nis_mean in /diagnostics: above the upper bound means inconsistent, far below means q̃ can be reduced for that robot's actual accelerations.

    ROS end-to-end (Jazzy, pseudo-terminal emulating an LD19): /scan published at the emulator rate with the correct CW→CCW mirroring (an object at sensor 100–102° appears at ROS −101°), 2 % injected CRC errors detected (0.020) and reported as WARN, /map, /slam/pose, /slam/path, TF and slam/debug published, and a rotationally symmetric room was correctly flagged as degenerate in yaw.

    Still required before driving (verification order of control-systems.md §4): HIL with the real sensors and a recorded bag (NIS inside bounds, bench σ_r), then the vehicle.

    6. Calibration on the bench¶

    1. σ_rand of the LD19: park facing a matte wall at 1, 3 and 6 m, record 100 scans (ros2 bag record /scan), take the standard deviation of the ray normal to the wall; sensor.sigma_range = √((0.045/√3)² + σ_rand²).
    2. LD19 yaw mount: place a single post in front of the robot on its x axis; the post must appear at 0° in /scan viewed in base_link; correct ld19_yaw.
    3. LPB40B: compare range with a tape measure at 1, 5, 10 m; the mean error must be within ±5 cm, else set latency_s/mount.
    4. Consistency: record /slam/debug on a representative run; the mean NIS must lie within nis_bound_low … nis_bound_high of /diagnostics.

    7. Why no CUDA¶

    A revolution has 450 rays. Measured on one x86 core (-O2): the driver's filter chain (gate + mixed-pixel) takes 22 µs per revolution, the SLAM chain (gate, Hampel, projection with covariance, de-skew, voxel) 113 µs, ICP ≈ 1 ms. A kernel launch plus synchronisation alone costs tens of µs (typical figure, not measured on the Orin), so the GPU cannot win at this size; it stays free for NanoOWL. The old kernels also corrupted the data (§1). Their sources remain in cuda/ but are no longer built.

    8. Known limitations¶

    • 2-D only: roll/pitch of the base are assumed small (flat floor). Tilted sensors see the floor.
    • The ICP covariance ignores map-registration correlation; edges use Σ_i + Σ_j.
    • Loop closure, correlative search and grid rebuild run in the scan callback. Worst case 66 ms on x86; on the Orin's Cortex-A78AE expect roughly 2–3× more [A]. Watch processing_ms in /diagnostics; moving loop closure to a worker thread is the next step if it approaches 100 ms.
    • Localisation-only mode on a saved map is not implemented (use backend:=slam_toolbox or Nav2 AMCL with the saved PGM/YAML).
