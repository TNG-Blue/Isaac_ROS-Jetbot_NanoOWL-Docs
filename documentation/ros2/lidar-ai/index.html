    ROS2 Lidar AI Solution¶

    Source

    This page is rendered from Source/ROS2_Lidar_AI_Solution/README.md, the authoritative description kept next to the code in Source/ROS2_Lidar_AI_Solution/.

    ROS2 package providing CUDA-accelerated lidar perception nodes for CenterPoint and PointPillars, with optional BEVFusion multi-sensor fusion and cuPCL utilities. The NVIDIA inference libraries come from the upstream repositories as git submodules (see NVIDIA libraries).

    Overview¶

    This package wraps high-performance CUDA/TensorRT lidar AI components into ROS2 nodes:

    • centerpoint_node for 3D object detection on PointCloud2.
    • pointpillars_node for PointPillars inference on PointCloud2.
    • bevfusion_node for camera + lidar fusion (optional).
    • cuPCL utilities for filtering, segmentation, clustering, ICP, NDT, and octree search (optional).
    • An Isaac ROS integration layer that fuses NanoOWL open-vocabulary 2D detections with the lidar tracks, publishes the result on vision_msgs, and closes a control loop onto the drive base.

    Features¶

    • ROS2 nodes with configurable topics, thresholds, and model paths.
    • Optional BEVFusion fusion pipeline with calibration tensor loading.
    • Optional cuPCL GPU utilities as ROS2 nodes.
    • Launch files for CenterPoint and PointPillars.
    • Model assets installed into the package share folder.
    • Isaac ROS integration: camera/lidar semantic fusion, a vision_msgs bridge, and a closed-loop target follower with a control barrier safety filter.

    Package Layout¶

    ROS2_Lidar_AI_Solution/
├── CMakeLists.txt
├── package.xml
├── launch/
├── src/
│   ├── centerpoint/
│   ├── pointpillars/
│   ├── bevfusion/
│   ├── cupcl/
│   └── isaac_ros/
├── CUDA-Utilities/        own CUDA kernels shared by the nodes (cuda_utilities)
├── CUDA-LidarAI/          CMake project that builds NVIDIA's libraries (lidar_ai::*)
└── Lidar_AI_Solution/     git submodule NVIDIA-AI-IOT/Lidar_AI_Solution (MIT), never modified:
                           CenterPoint, BEVFusion, 3DSparseConvolution, cuOSD, and the nested
                           submodules cuPCL and CUDA-PointPillars (Apache-2.0)

    NVIDIA libraries¶

    The NVIDIA code is not copied into this repository. It is consumed as the git submodule Lidar_AI_Solution/, pinned to an upstream commit, and compiled by CUDA-LidarAI/ into shared libraries with exported CMake targets. The ROS 2 nodes in src/ link those targets only.

    PointPillars is the one exception to the pin: Lidar_AI_Solution pins its nested CUDA-PointPillars at an old revision (092affc, PointPillar::doinfer API), while pointpillars_node uses the current API (pointpillar::lidar::create_core). The nested submodule is therefore moved to its upstream tip with submodule update --remote (below); CMake checks the layout and skips PointPillars with that command if it finds the old one. The submodule is marked ignore = dirty, so this does not show up in git status.

    Target Upstream source Used by
    lidar_ai::centerpoint Lidar_AI_Solution/CUDA-CenterPoint centerpoint_node
    lidar_ai::bevfusion, lidar_ai::custom_layernorm Lidar_AI_Solution/CUDA-BEVFusion + libraries/3DSparseConvolution bevfusion_node
    lidar_ai::pointpillars Lidar_AI_Solution/CUDA-PointPillars (upstream tip) pointpillars_node
    lidar_ai::cuosd Lidar_AI_Solution/libraries/cuOSD isaac_ros_semantic_overlay_node
    lidar_ai::cupcl_<module> Lidar_AI_Solution/libraries/cuPCL (prebuilt, aarch64) cupcl_*_node, ground_plane_node

    What the upstream sources support (checked at configure time, a component that cannot work is skipped with the reason instead of failing at run time):

    Component TensorRT CUDA Notes
    BEVFusion 8 / 10 11–13 libspconv per CUDA major; aarch64 12.8/13.0 are in git, the x86_64 and CUDA 11.4 builds need git lfs pull
    CenterPoint 8 only 11 bundled libspconv needs libcudart.so.11 and libprotobuf.so.17
    PointPillars 8 only any TensorRT 8 binding API
    cuOSD – any
    cuPCL – any prebuilt for aarch64 only

    JetPack 6.x (TensorRT 10, CUDA 12) therefore builds bevfusion_node, the cuPCL nodes and the cuOSD overlay; centerpoint_node and pointpillars_node need JetPack 5.x (TensorRT 8.5, CUDA 11.4) until upstream supports TensorRT 10.

    Fetching the sources¶

    git submodule update --init Source/ROS2_Lidar_AI_Solution/Lidar_AI_Solution
cd Source/ROS2_Lidar_AI_Solution/Lidar_AI_Solution
git submodule update --init libraries/cuPCL
git submodule update --init --remote CUDA-PointPillars   # current API, see above
# x86_64 or CUDA 11 only: the libspconv builds kept in Git LFS
git lfs pull

    --recursive would also fetch mit-han-lab/bevfusion, OpenPCDet, pybind11 and dlpack, which the build does not need, and would leave CUDA-PointPillars at the old pinned revision.

    Building the libraries separately¶

    CUDA-LidarAI is an ordinary CMake project; build and install it once, then build the ROS 2 package against the installed result:

    cmake -S Source/ROS2_Lidar_AI_Solution/CUDA-LidarAI -B build/lidar_ai \
      -DCMAKE_CUDA_ARCHITECTURES=87 -DCMAKE_INSTALL_PREFIX=/opt/lidar_ai
cmake --build build/lidar_ai -j"$(nproc)" && cmake --install build/lidar_ai

colcon build --packages-select ros2_lidar_ai_solution --cmake-args \
    -DUSE_INSTALLED_LIDAR_AI_CORE=ON \
    -Dlidar_ai_core_DIR=/opt/lidar_ai/lib/cmake/lidar_ai_core

    Without USE_INSTALLED_LIDAR_AI_CORE the package builds CUDA-LidarAI as a subdirectory in the same colcon build and installs the libraries into its own prefix (lib/liblidar_ai_*.so, private libspconv builds under lib/lidar_ai/).

    Prerequisites¶

    • ROS 2 Humble or Jazzy
    • CMake 3.18+, C++17 compiler
    • CUDA Toolkit (nvcc available)
    • TensorRT (libnvinfer and libnvinfer_plugin), see the support table above
    • Protobuf and protoc (BEVFusion; its ONNX protobuf sources are regenerated with the installed protoc at build time)
    • Eigen3 (cuPCL nodes)
    • The Lidar_AI_Solution/ submodule (see Fetching the sources)

    Build¶

    Build options:

    • BUILD_CENTERPOINT (default ON)
    • BUILD_POINTPILLARS (default ON)
    • BUILD_BEVFUSION (default OFF)
    • BUILD_CUPCL (default OFF)
    • BUILD_ISAAC_ROS (default ON, needs vision_msgs)
    • BUILD_CUOSD_OVERLAY (default ON, needs CUDA — builds the GPU overlay node)
    • USE_INSTALLED_LIDAR_AI_CORE (default OFF — link against a separately installed lidar_ai_core, with -Dlidar_ai_core_DIR=...)
    • AUTO_CLONE_SUBMODULES (default OFF — clones missing Lidar_AI_Solution/ sources at configure time, at the upstream tip rather than the pinned commit; prefer git submodule update)
    • CUDA-LidarAI options: LIDAR_AI_BUILD_{CENTERPOINT,BEVFUSION,POINTPILLARS,CUOSD,CUPCL}, LIDAR_AI_SPCONV_CUDA_VERSION, LIDAR_AI_{CENTERPOINT,BEVFUSION}_SPCONV_LIBRARY
    • CUDA-V2XFusion (training/export tooling, Python only) is available in Lidar_AI_Solution/CUDA-V2XFusion; there is no node for it.

    Example build: 

    export CUDACXX=/usr/local/cuda/bin/nvcc
export TENSORRT_ROOT=/usr/lib/x86_64-linux-gnu

colcon build --packages-select ros2_lidar_ai_solution \
  --symlink-install --event-handlers console_direct+ \
  --cmake-args \
    -DBUILD_CENTERPOINT=ON \
    -DBUILD_POINTPILLARS=ON \
    -DBUILD_BEVFUSION=OFF \
    -DBUILD_CUPCL=OFF \
    -DCMAKE_CUDA_COMPILER=$CUDACXX \
    -DTENSORRT_ROOT=$TENSORRT_ROOT

    If CUDA or TensorRT are missing, the CUDA-based nodes will be skipped and no executables will be installed.

    Models and Calibration¶

    CenterPoint and PointPillars require TensorRT engine plan files.

    • CenterPoint default: share/ros2_lidar_ai_solution/models/centerpoint/model/rpn_centerhead_sim.plan
    • PointPillars default: share/ros2_lidar_ai_solution/models/pointpillars/model/pointpillar.plan

    BEVFusion expects a model root and calibration tensors: 

    <model_root>/<model_name>/
  build/
    camera.backbone.plan
    camera.vtransform.plan
    fuser.plan
    head.bbox.plan
  lidar.backbone.xyz.onnx

<calibration_root>/
  camera2lidar.tensor
  camera_intrinsics.tensor
  lidar2image.tensor
  img_aug_matrix.tensor

    Running¶

    Source the workspace: 

    source install/setup.bash

    CenterPoint: 

    ros2 launch ros2_lidar_ai_solution centerpoint.launch.py

    PointPillars: 

    ros2 launch ros2_lidar_ai_solution pointpillars.launch.py

    BEVFusion (example): 

    ros2 run ros2_lidar_ai_solution bevfusion_node --ros-args \
  -p input_topic:=/points \
  -p model_root:=/path/to/models/bevfusion \
  -p model_name:=resnet50int8 \
  -p calibration_root:=/path/to/calibration

    Isaac ROS integration (after the lidar pipeline and the Isaac ROS detector are up): 

    ros2 launch ros2_lidar_ai_solution isaac_ros_perception.launch.py

# with closed-loop following
ros2 launch ros2_lidar_ai_solution isaac_ros_perception.launch.py \
  enable_follower:=true target_label:="a person"

    Nodes¶

    CenterPoint Node¶

    • Executable: centerpoint_node
    • Subscribes: sensor_msgs/msg/PointCloud2 (default /points)
    • Publishes: visualization_msgs/msg/MarkerArray (default /centerpoint/markers)

    Key parameters:

    • model_file (string)
    • score_threshold (double)
    • max_points (int)
    • output_frame (string)
    • verbose (bool)

    PointPillars Node¶

    • Executable: pointpillars_node
    • Subscribes: sensor_msgs/msg/PointCloud2 (default /points)
    • Publishes: visualization_msgs/msg/MarkerArray (default /pointpillars/markers)

    Key parameters:

    • model_file (string)
    • score_threshold (double)
    • max_points (int)
    • output_frame (string)
    • enable_timing (bool)

    BEVFusion Node (Optional)¶

    • Executable: bevfusion_node
    • Subscribes: sensor_msgs/msg/PointCloud2 and multiple sensor_msgs/msg/Image
    • Publishes: visualization_msgs/msg/MarkerArray

    Key parameters:

    • model_root, model_name, precision
    • calibration_root
    • score_threshold, max_points
    • num_cameras, camera_topics
    • sync_tolerance_ms

    Images must be rgb8, bgr8, rgba8, or bgra8.

    cuPCL Nodes (Optional)¶

    Executables:

    • cupcl_filter_node
    • cupcl_segmentation_node
    • cupcl_cluster_node
    • cupcl_icp_node
    • cupcl_ndt_node
    • cupcl_octree_node

    These nodes require the cuPCL submodule (Lidar_AI_Solution/libraries/cuPCL, prebuilt aarch64 libraries); they are skipped on x86_64.

    Isaac ROS Integration Nodes¶

    Require vision_msgs; see docs/isaac_ros_integration.md for the models, the derivations and the tuning order.

    isaac_ros_semantic_fusion_node¶

    Projects lidar 3D tracks into the camera, associates them with the Isaac ROS 2D detections, and maintains a recursive Bayesian posterior over the prompt vocabulary for each track.

    • Subscribes: ros2_lidar_ai_msgs/msg/TrackedObjectArray (/tracked/objects), vision_msgs/msg/Detection2DArray (/object_detections), sensor_msgs/msg/CameraInfo (/camera_info), tf2
    • Publishes: ros2_lidar_ai_msgs/msg/SemanticObjectArray (/isaac_ros/semantic_objects), vision_msgs/msg/Detection3DArray, visualization_msgs/msg/MarkerArray

    Key parameters:

    • vocabulary (string[]) — must match the NanoOWL prompt, in the same order
    • association_metric (iom or iou), min_association_score
    • sync_tolerance_ms, forgetting_factor, max_log_odds
    • use_tf, camera_frame, static_camera_translation, static_camera_rotation_rpy

    isaac_ros_detection_bridge_node¶

    Converts between the internal messages and vision_msgs, in either or both directions, so Isaac ROS and nav2 consumers see standard interfaces.

    • Subscribes: TrackedObjectArray, SemanticObjectArray, DetectionResult, vision_msgs/msg/Detection3DArray
    • Publishes: vision_msgs/msg/Detection3DArray (/isaac_ros/detections_3d), vision_msgs/msg/VisionInfo (latched), ros2_lidar_ai_msgs/msg/DetectionResult

    Key parameters:

    • direction (lidar_to_vision | vision_to_lidar | bidirectional)
    • class_labels, max_hypotheses, min_score, publish_vision_info

    isaac_ros_semantic_overlay_node¶

    Draws the fusion result onto the camera image on the GPU with cuOSD (lidar_ai::cuosd). It consumes SemanticObject.projected_bbox, which the fusion node already computes, so it needs no camera model of its own.

    • Subscribes: sensor_msgs/msg/Image (rgb8, bgr8, rgba8 or bgra8), ros2_lidar_ai_msgs/msg/SemanticObjectArray
    • Publishes: sensor_msgs/msg/Image (/isaac_ros/semantic_overlay)

    Key parameters:

    • font_path — leave empty to auto-detect a system TrueType font
    • font_size, box_thickness, label_background_alpha
    • draw_labels, draw_unmatched, min_probability
    • sync_tolerance_ms

    Unsupported encodings are republished unchanged rather than mangled. The drawing runs on the GPU; the image transport is still a host round-trip, which only NITROS removes.

    isaac_ros_target_follower_node¶

    Closed-loop follower: Kalman range/bearing estimation, PD heading with line-of-sight feedforward, PI range control gated by heading, a control barrier safety filter and actuator slew limits, with wheel odometry closing the loop.

    • Subscribes: SemanticObjectArray (/isaac_ros/semantic_objects), nav_msgs/msg/Odometry (/odom), std_msgs/msg/Bool (/safety/emergency_stop)
    • Publishes: geometry_msgs/msg/Twist (/cmd_vel), diagnostic_msgs/msg/DiagnosticArray, visualization_msgs/msg/MarkerArray

    Key parameters:

    • target_label, min_label_probability, desired_distance, safe_distance
    • linear_kp/ki/kd, angular_kp/ki/kd, derivative_tau
    • cbf_alpha, max_linear_velocity, max_linear_acceleration
    • range_process_psd, range_measurement_variance, nis_gate
    • target_timeout_s — past this the node ramps to a stop open loop

    isaac_ros_target_follower_node — control cycle¶

    flowchart TD
    T(["OnControlCycle, fixed rate"]) --> DT["dt = measured period<br/>(reject jumps > 5·T)"]
    DT --> E{"/safety/emergency_stop?"}
    E -- yes --> STOP1["EmitStop(hard): ramp to 0,<br/>reset estimators and integrators"]
    E -- no --> SEL["select target: target_label,<br/>min_label_probability, hysteresis"]
    SEL --> H{"target found?"}
    H -- no --> H1{"silent longer than<br/>target_timeout_s?"}
    H1 -- yes --> STOP2["EmitStop(hard) — open-loop ramp<br/>(no measurement to close the loop)"]
    H1 -- no --> STOP3["EmitStop(soft): keep estimator state"]
    H -- yes --> NEW{"new track id?"}
    NEW -- yes --> RST["restart range / bearing filters"] --> MEAS
    NEW -- no --> MEAS["range d and bearing ψ in the body frame"]
    MEAS --> KF["2-state Kalman filters (range, bearing)<br/>NIS gate"]
    KF --> EGO["remove ego-motion with wheel odometry"]
    EGO --> ERR["e_d = d − d_des, e_ψ with deadbands"]
    ERR --> ANG["ω = LOS-rate feed-forward + Kp·ψ + Kd·ψ̇"]
    ERR --> LIN["v = (Kp·e_d + Ki·∫e_d)·max(cos ψ, 0)"]
    ANG --> CBF["control barrier filter: d ≥ safe_distance"]
    LIN --> CBF
    CBF --> AW["unwind integrator by the clipped amount"]
    AW --> SL["slew limits (max_linear_acceleration, …)"]
    SL --> PUB["publish /cmd_vel, /diagnostics, markers"]

    object_tracker_node and safety_zone_node¶

    flowchart TD
    D(["OnDetections: /fused/markers"]) --> P["predict every track (Kalman CV, dt)"]
    P --> C["cost matrix = distance(prediction, detection)"]
    C --> A["assignment within max_association_distance"]
    A --> M["matched: Kalman update, hits++,<br/>confirm after confirmation_hits"]
    A --> U["unmatched track: missed++,<br/>drop after max_missed_frames"]
    A --> N["unmatched detection: new tentative track"]
    M --> PUB["publish /tracked/objects, /tracked/markers"]
    U --> PUB
    N --> PUB

    S(["safety_zone timer"]) --> S1["for each tracked object: distance to robot"]
    S1 --> S2["zone levels CAUTION / WARNING / CRITICAL<br/>by caution / warning / critical radius"]
    S2 --> S3{"use_velocity_prediction?"}
    S3 -- yes --> S4["closing speed → time to collision,<br/>predicted position inside critical radius → CRITICAL"]
    S3 -- no --> S5
    S4 --> S5["overall level = max of zones<br/>emergency_stop = level ≥ CRITICAL"]
    S5 --> S6["publish /safety/status, /safety/emergency_stop,<br/>/safety/markers, /diagnostics"]

    Other nodes¶

    Node Input → processing → output
    bevfusion_node /points + 6 camera Image topics (camera_topics, time-synchronised within sync_tolerance_ms) → camera + lidar backbones, BEV fuser (TensorRT) → /bevfusion/markers
    cupcl_segmentation_node /points → cuPCL RANSAC plane → /cupcl/segmentation/inliers, …/outliers, …/coefficients
    cupcl_cluster_node /points → cuPCL Euclidean clustering → /cupcl/cluster/points, /cupcl/cluster/markers
    cupcl_icp_node, cupcl_ndt_node /points_source + /points_target → cuPCL ICP / NDT registration → /cupcl/icp/transform, /cupcl/ndt/transform
    cupcl_octree_node /points + /cupcl/octree/query (PointStamped) → GPU octree search → /cupcl/octree/points
    pointcloud_relay_node /points → copy → /relay/points
    pointcloud_stats_node /points → rate and point count → <input>/stats/fps, <input>/stats/point_count, /diagnostics
    pipeline_coordinator_node /diagnostics → node health → /pipeline/status; services ~/get_pipeline_status, ~/enable_node, ~/set_node_param (forwarded to <node>/set_parameters)

    Troubleshooting¶

    • libexec directory does not exist: CUDA/TensorRT not found, nodes were skipped.
    • CUDA available: FALSE: nvcc not detected. Ensure /usr/local/cuda/bin/nvcc is present.
    • lidar_ai_core: TensorRT not found: libnvinfer.so not found. Set TENSORRT_ROOT.
    • lidar_ai_core: <component> skipped, ... is empty: the Lidar_AI_Solution/ submodule was never populated; see Fetching the sources. The configure log lists every submodule and whether it is populated.
    • lidar_ai_core: <component> skipped, ... is a Git LFS pointer: run git -C Lidar_AI_Solution lfs pull (x86_64 and CUDA 11 libspconv builds).
    • lidar_ai_core: PointPillars skipped, ... the revision pinned by Lidar_AI_Solution: run git -C Lidar_AI_Solution submodule update --init --remote CUDA-PointPillars.
    • lidar_ai_core: CenterPoint/PointPillars skipped, ... TensorRT 8 binding API: expected on JetPack 6; see the support table in NVIDIA libraries.
    • Missing plan files: generate TensorRT engines before running nodes.
    • Overlay draws boxes but no text: no usable TrueType font was found. Install one (apt install fonts-dejavu-core) or set font_path.
    • Isaac ROS nodes missing after a build: vision_msgs was not found. Install it with sudo apt install ros-$ROS_DISTRO-vision-msgs and rebuild.
    • matched_count stuck at 0 in /isaac_ros/semantic_objects: the camera-lidar extrinsics or the frame convention are wrong. See docs/isaac_ros_integration.md section 8.
