    DNN Jetbot NanoOWL¶

    Source

    This page is rendered from DeepLearning/README.md, the authoritative description kept next to the code in DeepLearning/.

    CUDA-native object detection and tracking for Isaac ROS Jetbot — with a training-free path: mark an object once, detect only that object.

    Overview¶

    A complete object-detection perception pipeline built on the NVIDIA stack, with no OpenCV dependency anywhere in the image path. Camera capture, colour conversion, denoising, resizing, inference, decoding and suppression all run on the GPU; the frame never leaves device memory between the sensor and the detection result.

    It is a pipeline, not a detection script. The chain is

    camera → conditioning filter → detector → state estimator → tracks

    and every stage is a documented closed-form result, derived in docs/MATH.md and asserted by the unit tests.

    The chain stops at the estimate. This module produces perception output — stable ids, smoothed boxes, velocities, covariances — and does not command actuators. Any control law built on top lives outside it.

    There are two ways to get detections into that chain:

    Path Needs Recognises Setup
    Trained detector an ONNX/TensorRT model the categories it was trained on train or download a model
    Exemplar matching nothing the specific instance you marked draw one box

    They compose: run a class-agnostic detector for proposals, then keep only what you marked.

    Why the stages are what they are¶

    A detector is a noisy, intermittent sensor: boxes jitter frame to frame, objects are missed, and identities are not preserved. Wiring one straight to a motor controller feeds that noise into the actuators. So this module puts the classical chain in between:

    Stage Role Method Guarantee
    Colour conversion Sensor decoding ITU-R BT.601/709 inverse matrix Exact inverse of the standard
    Temporal filter Noise conditioning Steady-state scalar Kalman Gain solves the scalar Riccati equation
    Letterbox + normalise Geometric conditioning Similarity transform + bilinear Aspect-preserving; interpolant is a convex combination
    Detector Measurement CNN + DFL decode + NMS Mask sweep provably equals greedy NMS
    Tracker State estimation Kalman (constant velocity), Joseph form Minimum-variance; covariance stays SPD for any gain
    Association Identity Hungarian algorithm Globally minimum-cost assignment

    Nothing here is a heuristic with a tuned constant where a derivation was available. The temporal filter's gain comes from the sensor's noise variances, and the association gate is a calibrated χ² test with a stated false-rejection rate rather than a tuned pixel threshold.

    Quick start¶

    cd DeepLearning
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure

# Runs with no camera and no model: synthetic GPU frames + analytic ground truth
./build/04_detect_and_track 120

    #include <dnn_jetbot_nanoowl.h>
using namespace cjn::dnn;

auto camera = create_camera_source(CameraConfig{});   // Argus → V4L2 → synthetic
camera->open();

Detector detector(DetectorConfig{});
detector.load_engine("model.engine");

MultiObjectTracker tracker;

GpuFrame frame;
std::vector<Detection> detections;
while (camera->acquire(&frame)) {
    detector.detect(frame, &detections);          // CUDA pre/post + TensorRT
    const auto& tracks = tracker.update(detections, dt);   // Kalman + Hungarian
    // tracks: stable id, smoothed box, velocity, covariance
    camera->release(frame);
}

    Learn by example — no training¶

    Mark a region once. From then on, that object is detected and nothing else is.

    ExemplarMatcher matcher;

// Once: the box comes from a mouse drag, a tap, or wherever you like.
matcher.learn(rgb, w, h, pitch, drawn_box, "my mug", stream);

// From then on, either filter a detector's proposals...
matcher.filter(rgb, w, h, pitch, &detections, stream);
// ...or search the frame with no model at all:
matcher.search(rgb, w, h, pitch, &found, stream);

matcher.memory().save("objects.dnnx");   // remembers across runs

    No dataset, no labels, no gradient step, no weights. The region is reduced to a descriptor by closed-form transforms of the pixels, and stored as a prototype.

    What it is built from¶

    Half Captures Invariant to Fooled by
    Hue-saturation histogram colour distribution rotation, deformation, exposure same-coloured distractors
    HOG (oriented gradients) local shape and texture illumination, contrast same-shaped distractors

    Their blind spots are different, so the default is both, concatenated with weights \(\sqrt{w}\) and \(\sqrt{1-w}\) — which keeps the result on the unit sphere and makes the similarity decompose exactly as w·s_colour + (1−w)·s_hog. The tests demonstrate the complementarity directly: each half alone is fooled by one distractor, and neither is fooled by both.

    Every decision is an inequality, not a tuned constant¶

    • The prototype is optimal. For exemplars on the unit sphere, the normalised mean is the direction maximising total similarity to all of them (Cauchy-Schwarz — Theorem 10.2). The test verifies it against 500 random competing directions.
    • The gate carries an error bound. On learning, background regions of the same frame are sampled and the threshold set to μ_bg + z·σ_bg. By Cantelli's inequality the false-accept rate is at most 1/(1+z²) — 5.9% at the default z = 4 — and that bound holds whatever the similarity distribution turns out to be, which matters because it is nowhere near Gaussian.
    • Ambiguity is rejected, not guessed. The winner must beat the runner-up by a margin; two objects that explain a region equally well make the choice a coin flip.
    • Showing a second view refines the prototype by an exact incremental mean, with no stored history. In practice two or three views matter far more than any threshold tuning.

    What it does not do¶

    It recognises the instance you marked, not its category. Marking one red mug teaches it that mug — not mugs. Category generalisation is what training buys; this is deliberately the other trade: instant, on the spot, for one object.

    Camera input, in CUDA¶

    Backend Transport Copies to GPU Availability
    Argus libargus → EGLStream → CUDA zero Jetson CSI, JetPack
    V4L2 ioctl + mmap → pinned → DMA one any Linux, USB/UVC
    Synthetic generated by a CUDA kernel none always

    The Argus path is the native Jetson route: the hardware ISP publishes into an EGLStream and CUDA consumes device pointers to NVMM memory. The V4L2 path has one unavoidable copy — a UVC device DMAs into kernel buffers CUDA cannot import — staged through page-locked memory so it overlaps with compute. The synthetic backend renders frames on the GPU with an analytically known object trajectory, which is what lets the whole pipeline be validated against ground truth with no hardware attached.

    Formats handled by CUDA kernels: NV12, YUV420, YUYV, RGBA8, RGB8, GRAY8 — BT.601 and BT.709, limited and full range.

    Neural network: three backends, one interface¶

    Backend What it optimises Speed Use it when
    TensorRT the whole network, ahead of time fastest the graph is fixed — deployment
    cuDNN each layer, at runtime fast the graph must stay malleable
    Native CUDA nothing — it is the reference slowest neither library is available

    All three sit behind the same Detector, and all three are checked against the deliberately naive CPU implementations in src/reference_ops.cpp.

    TensorRT — compile the network¶

    TrtBuildConfig config;
config.precision = TrtPrecision::FP16;        // Ampere tensor cores
config.timing_cache_path = "timing.cache";    // minutes -> seconds on a rebuild

TrtEngine engine;
engine.build_from_onnx("yolov8n.onnx", config);
engine.save_engine("yolov8n.engine");         // skip the build next time

    TensorRT benchmarks candidate tactics on the actual GPU and fuses across layer boundaries — something neither of the other backends can do. build_from_onnx also takes an optimisation profile for dynamic input shapes, and reports what it actually enabled through build_log() (a requested precision the device cannot run fast is reported, not silently dropped). INT8 needs Q/DQ nodes in the ONNX: this module ships no calibrator, and says so rather than pretending.

    cuDNN — accelerate the layers¶

    network->set_backend(ComputeBackend::CUDNN);  // or AUTO, the default
detector.set_network(std::move(network));
std::cout << network->backend_summary();      // per-layer: backend, algorithm, workspace

    cuDNN carries hand-tuned kernels for every NVIDIA architecture, including the Ampere tensor-core paths a portable hand-written GEMM cannot reach. The layer asks cuDNN for the fastest algorithm whose scratch fits a budget (64 MiB by default — on a Jetson that memory is the host's too), and falls back to the native kernels when cuDNN cannot serve the geometry rather than failing. ReLU and sigmoid are fused into the convolution call; SiLU, hard-swish and leaky ReLU have no cuDNN mode, so those run as one extra element-wise pass.

    ComputeBackend::AUTO picks cuDNN when the build and the device provide it, and the native path otherwise — so the same binary runs on a Jetson, a desktop without cuDNN, and in CI.

    Native CUDA — the fallback that is also the specification¶

    Convolution lowered to im2col plus a tiled shared-memory GEMM with bias and activation fused into the epilogue; depthwise convolution runs direct; plus max-pool, nearest upsample, channel concat and residual add.

    Batch norm is folded into the preceding convolution by an exact algebraic identity (§6.5), so the folded network computes the same values one kernel cheaper. Weights load from a flat .dnnw archive; tools/export_weights.py converts a PyTorch state_dict.

    A note on TF32¶

    cuDNN uses Ampere's TF32 tensor cores for FP32 convolutions by default. TF32 keeps FP32's exponent but truncates the mantissa to 10 bits, so agreement with the CPU reference is ~1e-3 relative rather than ~1e-6 — far below the 8-bit quantisation of the sensor upstream, and several times faster. Set CudnnConvOptions::allow_tf32 = false when bit-comparing against the reference; 05_backend_benchmark --strict does exactly that.

    Testing¶

    Four suites, 8,306 assertions, all runnable without a GPU:

    test_math_core   5,891 checks   colour round-trips, HSV illumination invariance,
                                bilinear exactness, Riccati solution,
                                DFL shift-invariance, Kalman consistency over
                                400 cycles, pinhole projection round trip,
                                prototype optimality, Cantelli's bound
test_tracking    2,151 checks   Hungarian vs brute force (200 matrices),
                                NMS sweep vs greedy (300 cases), ID stability
                                through crossings, coasting through gaps
test_layers        158 checks   hand-computed convolutions, dilation, depthwise,
                                batch-norm folding equivalence, pooling,
                                backend selection and fallback, TensorRT config
test_exemplar      106 checks   descriptor invariance to exposure and position,
                                colour/shape discrimination and complementarity,
                                prototype refinement, memory persistence,
                                end-to-end learn-once-then-recognise

    The tests assert analytic properties — identities, invariants, conservation laws, closed-form values — not recorded outputs. Because the CUDA kernels call the same math_core.h functions on the device that the tests call on the host, passing them validates the code that actually runs on the GPU.

    Scope and limitations¶

    Stated plainly, so nothing here is mistaken for more than it is:

    • The Argus backend is not exercised by CI. This repository's CI has no Jetson, so the zero-copy CSI path is compiled but not run there. Validate it on the device with 01_camera_cuda_capture argus.
    • No model weights are shipped. Bring a TensorRT engine or a .dnnw archive; the examples fall back to synthetic data so the pipeline still runs.
    • The native CUDA backend is not competitive with TensorRT or cuDNN on real backbones, by design. It exists for inspectability and portability.
    • The cuDNN and TensorRT paths compile against real headers but are not run in CI, which has no GPU. Both compile warning-free against cuDNN 9.26 and TensorRT 10.7; validate throughput on the device with 05_backend_benchmark.
    • No INT8 calibrator is provided. INT8 requires an ONNX carrying Q/DQ nodes.
    • The Orin Nano Super has no DLA cores, so there is no DLA offload option here; that is a property of the hardware, not an omission.
    • No motor control or control feedback. The pipeline ends at the state estimate by design; there is no controller and no actuator interface. A previous revision carried an image-based visual-servo stage — it was removed as out of scope and remains recoverable from git history (commit 91406bf).
    • Range is a monocular estimate (§9.2) from apparent box height, so it needs the physical height of the object class and degrades as the box shrinks. It is reported as data; nothing in the module acts on it.
    • Exemplar matching is instance-level, not category-level. See above; this is the trade the method makes, not a defect to be fixed by tuning.
    • Dark and desaturated objects discriminate less well by colour, because pixels with no usable hue all pool into one achromatic bin. Measured, not assumed — see docs/MATH.md §10.6. Lower color_weight for such objects.
    • Sliding-window search is exhaustive, so its cost grows with the frame area and the number of scales. Filtering a detector's proposals is far cheaper when a detector is available.
    • Tracking runs on the CPU deliberately: for tens of tracks a kernel launch costs more than the whole update. See docs/ARCHITECTURE.md.
    • Resize is aspect-preserving only. An anisotropic stretch is not a similarity transform and would break the inverse box mapping.

    Integration¶

    Module Relationship
    CUDA/ Sibling GPU library (PID/MPC control kernels, VPI). A possible consumer of these tracks, not a dependency
    Source/Isaac_ROS-Object_Detection/ ROS 2 packaging of detection
    Train_Pytorch/ Produces the checkpoints tools/export_weights.py converts

    To publish into ROS 2, wrap Detector and MultiObjectTracker in a node and emit vision_msgs/Detection2DArray, carrying the track id in Detection2D::id and the filter's covariance alongside each box.
