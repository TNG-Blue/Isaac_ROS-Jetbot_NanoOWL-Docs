    OpenMV RT1062 — API Audit & Fix Report¶

    Files audited: Microcontroller/OpenMV/OpenMV_RT1062.py (§2–6) and Source/ROS2_Microcontroller/ (§7) Reference: OpenMV firmware v5.0.0 API docs (MicroPython v1.28) — https://docs.openmv.io/v5.0.0/ Verdict of the original file: ❌ it does not run. It aborts during the import block, before a single frame is captured, and it never brings the Ethernet interface up.

    1. Verdict summary¶

    Question Answer
    Đúng API OpenMV chưa? Chưa. The script targets the tf module and the legacy net.detect() signature, both removed in firmware v4.5.6.
    Nạp code chạy được không? Không. import _thread and import urequests both raise ImportError at load time; tf.load() no longer exists either.
    Có dùng shell ETH không? Không. network is imported but network.LAN() is never constructed, so the PHY is never brought up and no socket can ever connect. It also opened a TCP client, while the ROS2 node is also a client — nobody was listening.

    2. Blocking defects (script cannot start)¶

    # Line (original) Defect Evidence
    B1 30 import _thread — threading is disabled in the OpenMV fork of MicroPython. _thread is not in the v5.0.0 module index. Module-level _thread.allocate_lock() therefore kills the script at import. OpenMV forum, maintainer: "Threading is disabled in our fork."
    B2 31 import urequests — the module is named requests; there is no urequests. requests — HTTP client
    B3 32–33 uhashlib / ubinascii — the u-prefixed aliases are gone; use hashlib / binascii. Python Module Index
    B4 25, 165 import tf + tf.load(path, load_to_fb=True) — the tf C module was replaced by the ml package in v4.5.6; tf.load, detect(), segment() and classification() were removed. load_to_fb was then removed from ml.Model in v5.0.0. v4.5.6 changelog, v5.0.0 changelog

    Any one of B1–B4 is fatal on its own.

    3. Runtime defects (would fail even after the imports were fixed)¶

    # Line Defect Correct API
    R1 — Ethernet is never initialised. network is imported and never used. lan = network.LAN(); lan.active(True); while not lan.isconnected(): ... — DHCP starts automatically once the link is up. (RT1062 quick reference)
    R2 173–187 The cam opens a TCP client to 192.168.1.100:8080, but ros2_microcontroller/openmv_communication.py is also a client (it dials openmv_ip = 192.168.1.104:8080). Two clients, zero servers → the link can never come up. The cam must bind() / listen() / accept().
    R3 671–675 net.detect(img, threshold=…, nms=…) — no such method, and that was never the tf.detect signature either. model.predict([img]) with a post-processor from ml.postprocessing. (ml)
    R4 681–684 obj.classid(), obj.value(), obj.rect() — not part of any OpenMV detection API. Post-processors return per-class lists of ((x, y, w, h), score); the list index is the class id.
    R5 42 ssd_mobilenet_v1.tflite — OpenMV ships decoders for darknet (YOLOv2), ultralytics (YOLOv5/v8), mediapipe and edgeimpulse (FOMO) only. SSD's TFLite_Detection_PostProcess is a custom op that TFLM does not implement. Use FOMO / YOLOv5 / YOLOv8, or write your own postprocess callable. (Post-processors)
    R6 731 except socket.timeout: — MicroPython has no socket.timeout; it raises plain OSError. Evaluating the except clause raises AttributeError, which the outer handler treated as a dead socket → the loop closed and reopened the socket on every single frame. except OSError as e: if e.args[0] in (errno.EAGAIN, errno.ETIMEDOUT): ... (socket.settimeout)
    R7 252, 339 urequests.get(url, timeout=…) — requests.request() has no timeout parameter. Use socket-level timeouts.
    R8 346 response.raw.read(chunk_size) — Response exposes status_code, reason, headers, content, json(). There is no .raw, and stream= is "accepted for API compatibility; not used". content is a decoded str, so it corrupts binary payloads. Stream the body over a raw socket (implemented in the fix).
    R9 246 OTA queries /api/v1/firmware/latest?device_type=… — Server_OTA exposes /api/firmware/list, /api/firmware/info?file=, /download?file=, /api/health, /api/stats. The old URL returns 404 on your own server. See Server_OTA/src/handlers/handlers.go:81.
    R10 386, 409, 440 apply_update() / rollback() call self._dir_exists(...) on files, and download writes {filename} while apply reads a hard-coded firmware.py — the names never match, so an update could never be applied. Fixed: staged name is carried through, .part → atomic rename, previous file kept as .bak.
    R11 57–58, 144–158 sensor is deprecated since v4.5 and every example moved to csi in v5.0.0. Still functional, but alloc_extra_fb/dealloc_extra_fb now raise OSError. csi.CSI() with pixformat() / framesize() / snapshot(time=…).
    R12 87–88 pyb.LED(2) — the RT1062 is an NXP i.MXRT (mimxrt) part; the portable API is machine.LED("LED_GREEN"), shipped as a frozen module on every board. machine.LED
    R13 76 UPDATE_DIR = "/flash/updates" — the RT1062 flash root is /, the SD card is /sdcard. Relative path under the flash root.
    R14 769 Run as OpenMV_RT1062.py, the script only executes from the IDE. OpenMV auto-runs main.py at boot. Copy the script to the cam as main.py.

    4. Design / algorithm defects¶

    # Defect Fix
    D1 ObjectTracker mutated self.tracks while iterating it, and re-keyed tracks so ids were not stable. Rewritten.
    D2 Association was greedy "first track with IoU > 0.3" — order dependent, no optimality guarantee, and it drops the identity of crossing targets. Minimum-cost assignment (Jonker–Volgenant/Hungarian) on 1 − IoU, with gating. Provably optimal for the linear assignment problem.
    D3 No filtering at all: raw detector boxes were published straight to the controller, so the ROS2 side would have to differentiate a noisy signal to get velocity. Per-track α–β estimator on a constant-velocity model, gains from Kalata's tracking index (see below). Position and velocity are published.
    D4 avg_fps = 0.9*avg + 0.1*fps — a magic weight whose bandwidth depends on the (variable) frame rate. First-order IIR with g = 1 − exp(−T/τ), the exact ZOH discretisation of τ·ẏ + y = u, so τ is a real time constant in seconds.
    D5 send_detection_data compared whole dicts to decide "changed", including the confidence float, so essentially every frame was transmitted. Unchanged behaviour, but payload now comes from filtered tracks, which are stable while a target is tracked.

    Estimator design (D3)¶

    State per axis: x = [p, v], constant-velocity model.

    predict:  p⁻ = p + T·v            v⁻ = v
update:   p  = p⁻ + α·r           v  = v⁻ + (β/T)·r ,   r = z − p⁻

    Gains are not hand-tuned. With σ_a the manoeuvre (acceleration) noise std [px/s²] and σ_m the detector position noise std [px], Kalata's tracking index and the steady-state solution of the associated Riccati equation give

    λ = σ_a·T² / σ_m
r = (4 + λ − √(8λ + λ²)) / 4
α = 1 − r²          β = 2(1 − r)²  ≡  2(2 − α) − 4√(1 − α)

    P. R. Kalata, The Tracking Index: A Generalized Parameter for α-β and α-β-γ Target Trackers, IEEE Trans. AES-20(2), 1984.

    Limits check out: λ → 0 ⇒ (α, β) → (0, 0) (pure coasting, ignore the measurement); λ → ∞ ⇒ (α, β) → (1, 2) (full trust in the measurement). Because the frame period jitters, the gains are recomputed from the measured T on every update instead of being frozen at design time.

    Gating uses the normalised squared residual d² = (Δx² + Δy²)/σ_g² against χ²(2 dof, p=0.99) = 9.21, under the stated assumption that the residual is zero-mean Gaussian with std σ_g.

    Box size (w, h) is smoothed by the same first-order lag as D4, with τ = SIZE_TAU_S.

    5. What the rewritten file does¶

    CSI frame → ml.Model.predict() → confidence gate → gated Hungarian association
          → α–β estimator (position + velocity) → line-framed JSON over TCP
          → ROS2 controller node (closes the loop; this script never actuates)
    • csi.CSI with an automatic fallback to sensor on firmware < v5.
    • ml.Model + a selectable post-processor (fomo / yolov5 / yolov8 / yolov2 / none), labels from the model's sidecar .txt or labels.txt.
    • network.LAN() brought up explicitly, DHCP by default, optional static ipconfig(addr4=…, gw4=…), link loss detected and re-established in-loop.
    • TCP server by default (TCP_MODE), non-blocking accept/recv/send, proper errno.EAGAIN handling, \n-framed JSON reassembled across TCP segments.
    • Single-threaded cooperative loop — no _thread, no locks.
    • OTA rewritten against the real Server_OTA API, binary-safe raw-socket download, size check, SHA-256 logged, .part staging, atomic swap with .bak, and it refuses to "apply" a DFU-only image from MicroPython.

    Verification performed¶

    Algorithm and protocol layers were exercised on the host (the camera, ml and network.LAN layers need the board):

    • α–β gains: limit behaviour, the β identity, monotonicity in T, range.
    • Assignment solver: 300 random matrices vs. brute-force optimum — exact match on every case, including non-square ones.
    • Tracker: constant-velocity target with σ=3 px measurement noise → mean position error 1.2 px, velocity estimate 124.6 vs 120.0 px/s true; crossing targets keep distinct ids; stale tracks are deleted.
    • TCP channel over real sockets: framing across segment boundaries, split commands, disconnect detection, reconnect.
    • OTA against a mock of the Go API: device-type filtering, byte-identical 10 kB binary download, SHA-256 match, atomic apply + rollback, size-mismatch rejection with no partial file left behind.

    6. Still to do before the board will run it¶

    1. Check the firmware version on the cam (import omv; print(omv.version_string())) and flash ≥ v4.5.6 — ideally v5.0.0 — from OpenMV IDE.
    2. Provide a real model. Config.MODEL_FILE defaults to trained.tflite; copy your FOMO/YOLO model and its labels to the cam and set Config.POSTPROCESSOR to the matching decoder. ssd_mobilenet_v1.tflite will not work (§R5).
    3. Copy the script as main.py if it should run standalone at boot.
    4. Wire Ethernet through magnetics — the MDI pads must not be wired straight to an RJ45; use the PoE shield or a magjack.
    5. Set Config.STATIC_ADDR4 to 192.168.1.104/24 if you want to keep the IP hard-coded in the ROS2 node, or switch that node to DHCP + mDNS.
    6. Server_OTA only serves .bin/.hex/.elf/.img/.fw (services.isAllowedFileType). To ship .py or .tflite payloads, extend that allow-list server-side first.

    7. ROS2 side (ros2_microcontroller) — also fixed¶

    The bridge node had its own blocking defects and is rewritten in the same change.

    File Defect Fix
    openmv_communication.py @rclpy.callback — no such decorator in rclpy; the module raised AttributeError at import, so the node could never start. Removed; plain callbacks on ROS timers.
    openmv_communication.py rclpy.lifecycle.Node with on_configure, but main() never triggered any transition and there is no lifecycle manager in the repo → the socket was never opened. Plain rclpy.node.Node with an explicit connection state machine. Switching back to LifecycleNode is easy once a manager exists.
    openmv_communication.py main() looped spin_once() (blocking, no timeout) plus read_from_openmv() — a busy loop that starves either the callbacks or the socket. rclpy.spin() + a poll timer (poll_rate_hz) and a diagnostics timer.
    openmv_communication.py reconnect() was a @staticmethod using self (NameError), and nothing ever called it. Exponential backoff t←min(2t, t_max) inside the poll timer, reset on success.
    openmv_communication.py recv() output published as-is: a payload split across TCP segments became a truncated message. Byte buffer split on \n, remainder retained, oversized unframed buffers dropped.
    openmv_communication.py Diagnostics tested if self.socket: — a socket object is always truthy, so a dead link still reported "Operational". OK / WARN (connected but silent > rx_timeout_s) / ERROR (disconnected), plus rx/tx counters and the last error.
    openmv_communication.py analyze_data() called on every received line, but it parses comma-separated numbers while the camera sends JSON → it failed on every message and pulled pandas/numpy (undeclared) into the hot path. Off by default (analyze_numeric_lines), imported lazily, only for non-JSON lines.
    openmv_communication.py Held the I/O lock across a blocking recv(); settimeout(0.1) re-applied per read. Non-blocking sockets; the lock covers only the I/O call, dispatch happens outside it.
    openmv_communication.py CSV log opened in the cwd and never flushed or closed. Optional (log_file, empty disables), header written once, flushed periodically, closed on shutdown.
    openmv_communication.py USB default /dev/ttyUSB0; the OpenMV cam enumerates as /dev/ttyACM*. Default /dev/ttyACM0, transport selected by the transport parameter.
    dynamic_reconfigure.py rclpy.parameter.ParameterCallbackResult does not exist (it is rcl_interfaces.msg.SetParametersResult), and Parameter.Type.FLOAT is DOUBLE. Both corrected; validation extended to the new parameters. This is what the existing tests/test_dynamic_reconfigure.py already expected.
    health_monitor.py Used rclpy.ok() without importing rclpy → NameError on the first iteration, and a non-daemon thread. rclpy imported, daemon thread with a stop event, reports the real link state via node.link_healthy().
    logging_utils.py from rclpy.logger import Logger — the module is rclpy.logging, and the import was unused. Removed.
    openmv_rt1062.launch.py Node imported from launch.actions (it lives in launch_ros.actions); condition=LaunchConfiguration(...) == 'usb' is a Python bool, not a launch condition; package='your_package' placeholders. Rewritten with launch_ros.actions.Node and IfCondition(PythonExpression(...)), real package/executable, and launch arguments.
    setup.py console_scripts for microcontroller_node and diagnostics_node, neither of which exists. Removed.
    package.xml pyserial, rcl_interfaces, launch, launch_ros used but not declared. Declared.

    New published interfaces¶

    openmv_out_topic (raw JSON String) is unchanged. Added:

    • target — geometry_msgs/PointStamped, the highest-confidence target in normalised image coordinates x = 2cx/W − 1, y = 2cy/H − 1, z = √(wh/WH). z is a range proxy: for a pinhole camera s = f·S/Z, so Z = f·S/s and range is inversely proportional to z.
    • target_velocity — geometry_msgs/Vector3Stamped, the same target's image-plane velocity in normalised units per second. The camera already filters it (α–β), so the controller should use it as a feed-forward term rather than differentiating target.

    image_width / image_height must match the camera's framesize (QVGA 320×240 by default).

    Verification performed¶

    Firmware TcpChannel and the ROS2 bridge were run against each other over a loopback socket with the ROS layer stubbed (no ROS2 in this environment): connect both ways, two payloads in one TCP segment plus a split third reassembled, correct normalised target (x=+0.200 y=+0.200 z=0.200, v=(+0.188, −0.100)/s), command round trip answered by the real firmware command handler, diagnostics OK → ERROR on disconnect → WARN when silent, backoff 0.02 → 0.04 → 0.08 → capped, automatic reconnect with backoff reset, and parameter validation accepting/rejecting the right values. tests/test_openmv_communication.py was added for the framing and normalisation paths; it needs a real rclpy, so it was not executed here.
