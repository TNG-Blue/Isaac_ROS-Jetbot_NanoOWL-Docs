    Ground Station MAVLink Tutorial

    Connect a Ground Control Station¶

    Link QGroundControl (or any MAVLink v2 ground station) to the UAV stack through ros2_network_bridge, check the telemetry against the estimator, command the vehicle with acknowledged commands, and configure what happens when the link is lost.

    Before you start

    • Time: about 45 minutes
    • You need: a built workspace (Fly Your First Mission), QGroundControl on the same machine or network, pip install pymavlink for the SIL check
    • You learn: the MAVLink downlink budget, the command/acknowledge protocol, datalink-loss failsafe design, the relay for consoles behind NAT

    What the bridge does¶

    Direction Content
    Downlink HEARTBEAT 1 Hz, SYS_STATUS 1 Hz, ATTITUDE 10 Hz, LOCAL_POSITION_NED 10 Hz, GLOBAL_POSITION_INT 5 Hz, ODOMETRY 5 Hz (with covariances), STATUSTEXT; converted from ENU/FLU to NED/FRD
    Uplink discrete commands only (arm, take-off, land, RTL, loiter, mission start); no set-points cross the lossy link
    Supervision GCS heartbeat watchdog and the datalink-loss failsafe

    A command is acknowledged ACCEPTED only when the flight controller's measured mode confirms it, not when the message was delivered.

    1. Verify the link in SIL first¶

    The full-stack SIL can run a pymavlink ground station against the real nodes:

    ROS/build.sh -u ros2_mission_planner -u ros2_network_bridge
source install/setup.bash
python3 Source/ROS2_Control_System/tests/sil/uav_stack_sil.py \
  --estimator  install/ros2_control_system/lib/ros2_control_system/uav_state_estimator \
  --controller install/ros2_control_system/lib/ros2_control_system/uav_trajectory_controller \
  --flight     install/ros2_flight_controller/lib/ros2_flight_controller/flight_controller_node \
  --control-params install/ros2_control_system/share/ros2_control_system/config/uav_control.yaml \
  --mission-planner install/ros2_mission_planner/lib/ros2_mission_planner/mission_planner_node \
  --mission-params  install/ros2_mission_planner/share/ros2_mission_planner/config/mission_planner_params.yaml \
  --mission-file    install/ros2_mission_planner/share/ros2_mission_planner/config/waypoint_mission.yaml \
  --network-bridge  install/ros2_network_bridge/lib/ros2_network_bridge/network_bridge_node

    The test starts the mission with MAV_CMD_MISSION_START, compares the downlinked position with the truth, and silences the GCS heartbeat for 8 s mid-mission. Expected: MISSION_START acknowledged ACCEPTED, LOCAL_POSITION_NED within 0.18 m RMS of the truth, 15 mission events as STATUSTEXT, and the mission continuing under the planner through the link loss (14/14 checks).

    2. Connect QGroundControl¶

    QGroundControl listens on UDP 14550 by default; the bridge binds 14555 and sends to 14550.

    # GCS on this machine, stack already running
ros2 launch ros2_network_bridge network_bridge.launch.py

# Whole stack + bridge, GCS on another host
ros2 launch ros2_network_bridge uav_with_gcs.launch.py gcs_host:=192.168.2.10

# SiK telemetry radio (57 600 Bd)
ros2 launch ros2_network_bridge network_bridge.launch.py transport:=serial

    With udp.learn_remote: true the bridge answers whichever host sends it MAVLink. Restrict it in config/network_bridge_params.yaml:

        udp:
      allowed_hosts: ["192.168.2.10"]
    mavlink:
      gcs_system_id: 255          # QGroundControl

    No message signing

    MAVLink signing is not implemented; signed frames are rejected. Use a trusted network with allowed_hosts and gcs_system_id set.

    3. Check the telemetry¶

    ros2 topic echo /network/gcs_connected          # true once GCS heartbeats arrive
ros2 topic echo /network/diagnostics            # loss, false-trip rate, rx/tx B/s, CRC errors

    In QGroundControl the vehicle appears as a hexarotor. The flight mode is the heartbeat custom_mode, an index into the flight-controller mode table (0 DISARMED, 2 ARMED_IDLE, 3 TAKEOFF, 4 HOVER, 5 WAYPOINT_FOLLOW, 9 RETURN_TO_HOME, 10 LANDING, 13 EMERGENCY_STOP, …).

    Fit the link budget¶

    The downlink load at the default rates is

    B = Σ f_i · (12 + len_i) = 2301 B/s

    which is 1.8 % of a 1 Mbit/s IP link and 40 % of a 57 600 Bd radio (5760 B/s). The bridge keeps the load under link.max_utilization (50 %); above it, every periodic rate is scaled by s = (u_max·C − B_hb) / (B − B_hb), heartbeats excepted. If you raise a rate, recompute B for your radio.

    4. Command the vehicle¶

    QGroundControl action MAV_CMD ACCEPTED when the FC mode is
    Arm / Disarm 400 COMPONENT_ARM_DISARM ARMED_IDLE / DISARMED (disarm refused while flying)
    Take off 22 NAV_TAKEOFF TAKEOFF or HOVER
    Land 21 NAV_LAND LANDING, LANDED or DISARMED
    Return 20 NAV_RETURN_TO_LAUNCH RETURN_TO_HOME or LANDING (aborts the planner's mission, whose return respects keep-out zones)
    Pause 17 NAV_LOITER_UNLIM HOVER
    Start mission 300 MISSION_START mission/start succeeded

    Every accepted command is first answered IN_PROGRESS, then ACCEPTED, or FAILED after commands.ack_timeout_s (3 s). Flight termination (185) maps to EMERGENCY_STOP only with commands.allow_termination: true.

    Missions are not uploaded through the MAVLink mission protocol. Upload them to the planner (mission/upload) and start them from the GCS.

    5. Configure the datalink-loss failsafe¶

    The link is declared lost after link_loss.timeout_s without a GCS heartbeat. For heartbeat rate f_hb and independent frame loss probability p, the false-loss rate is

    λ_ft = 3600 · f_hb · (1 − p) · p^⌈T·f_hb⌉   per hour

    At T = 5 s, 1 Hz: 0.032/h for p = 0.1, 6.1/h for p = 0.3. /network/diagnostics reports the live value from the measured loss. Increase T if it is too high for your radio.

    Parameter Default Effect
    link_loss.action rth none, hover, rth or land when the link is lost while flying
    link_loss.continue_mission true a mission already validated by the planner continues
    link_loss.retry_s, retries 2 s, 3 the action is re-sent until the flight mode confirms it

    The failsafe does not act while the vehicle is already returning, landing or under manual control.

    6. Consoles on another network¶

    When the console and the vehicle are both behind NAT (a phone on a mobile network), use the TLS relay: both sides dial out to Server_Relay, so no port is opened on the robot.

    ros2 launch ros2_network_bridge jetbot_console.launch.py transport:=relay \
    relay_host:=<relay host> relay_robot:=jetbot-01 \
    relay_token_file:=/etc/jetbot/relay.token relay_pin:=<sha256 of the relay key>

    The token is read from a file (never a parameter, so it does not show in ros2 param), and relay_pin pins the relay's public key so a self-signed relay works and an impostor is refused before the token is sent. The relay forwards nothing from an observer to the vehicle except a verified heartbeat.
