    First Mission¶

    Your first autonomous mission with Isaac ROS Jetbot NanoOWL.

    🎯 Learning Objectives¶

    By the end of this tutorial, you will be able to: - ✅ Power on and connect to your Jetbot - ✅ Verify ROS2 communication - ✅ Send movement commands - ✅ Monitor sensor data in real-time - ✅ Complete a simple autonomous patrol mission

    Estimated Time: 20 minutes
    Difficulty Level: Beginner
    Prerequisites: None

    📋 Prerequisites¶

    Hardware¶

    • Isaac ROS Jetbot NanoOWL with fully charged battery (minimum 7.2V)
    • Power supply cable
    • Ethernet cable or WiFi connection
    • Host computer for SSH connection (optional)

    Software¶

    • ROS2 Humble installed and sourced
    • Basic understanding of Linux terminal
    • SSH client (if using remote access)

    Environment¶

    • Open space for robot movement (at least 2m × 2m)
    • Clear line of sight for camera
    • WiFi connectivity

    🚀 Step 1: Power On Your Jetbot¶

    1.1 Physical Power-Up¶

    Bash
    # Step 1: Check battery level
# - Look at battery indicator LED on Jetbot
# - Green = Good (> 70%)
# - Yellow = Low (30-70%)
# - Red = Critical (< 30%)

# Step 2: Connect power supply
# - Locate power jack (bottom of robot)
# - Insert 7.2V-12V power supply
# - Green LED indicates charging

# Step 3: Press power button
# - Located on top rear of Jetbot
# - Hold for 2 seconds
# - Wait for startup (30-45 seconds)

    1.2 Verify Jetbot Startup¶

    Bash
    # Check indicators
1. Power LED: Solid green ✓
2. Jetson LED: Blinking/solid green ✓
3. Network LED: Solid green ✓

# Listen for audio cues
- Single beep: Startup success ✓
- Three beeps: Startup failed ✗

    🌐 Step 2: Connect to Network¶

    2.1 SSH Connection (Recommended)¶

    Bash
    # From your host computer
ssh jetbot@jetbot.local

# Or using IP address (find with network scanner)
ssh jetbot@192.168.x.x

# Default credentials
Username: jetbot
Password: jetbot

    2.2 Verify Network Connectivity¶

    Bash
    # Check IP address
hostname -I
# Output: 192.168.x.x

# Test internet connection
ping 8.8.8.8
# Should see: bytes from 8.8.8.8: icmp_seq=1

# Check ROS2 domain
echo $ROS_DOMAIN_ID
# Should output: 0 (or your configured domain)

    2.3 Setup ROS2 Environment (if not auto-sourced)¶

    Bash
    # Source ROS2 setup
source /opt/ros/humble/setup.bash

# Source workspace
source ~/ros2_ws/install/setup.bash

# Verify ROS2
ros2 --version
# Output: ROS 2 Humble Hawksbill

    🎮 Step 3: Verify ROS2 Communication¶

    3.1 List Active Nodes¶

    Bash
    # Check running nodes
ros2 node list

# Expected output:
# /camera_driver
# /imu_driver
# /motor_controller
# /detection_node
# /slam_node

    3.2 Check Topics¶

    Bash
    # List all active topics
ros2 topic list

# Key topics to verify:
# /camera/image_raw          ✓ Camera stream
# /imu/data                  ✓ IMU data
# /motor/state               ✓ Motor feedback
# /odom                      ✓ Odometry

# Check topic frequency
ros2 topic hz /camera/image_raw
# Expected: ~30 Hz

    3.3 List Services¶

    Bash
    # View available services
ros2 service list

# Key services:
# /motor/reset              ✓ Reset motors
# /motor/emergency_stop     ✓ Emergency stop
# /camera/calibration       ✓ Camera calibration

    ⚙️ Step 4: Send First Movement Command¶

    4.1 Simple Velocity Command¶

    Bash
    # In your SSH terminal, publish velocity command
ros2 topic pub /cmd_vel geometry_msgs/Twist "linear: {x: 0.2, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}"

# What this does:
# - linear.x: 0.2 m/s = move forward at 0.2 m/s
# - angular.z: 0.0 = no rotation

    4.2 Expected Behavior¶

    ✅ Success: - Motors start spinning - Jetbot moves forward smoothly - No error messages in console - Motor feedback appears in /motor/state

    ❌ Failed: - Motors don't spin - Check error messages: ros2 topic echo /diagnostics - Verify battery voltage: ros2 service call /battery/status jetbot_interfaces/GetBatteryStatus

    4.3 Stop the Robot¶

    Bash
    # Method 1: Zero velocity
ros2 topic pub /cmd_vel geometry_msgs/Twist "linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}"

# Method 2: Emergency stop (if needed)
ros2 service call /motor/emergency_stop std_srvs/Empty

# Method 3: Press power button (if stuck)
# Hold for 2 seconds

    📊 Step 5: Monitor Sensor Data¶

    5.1 View Camera Stream¶

    Bash
    # Option 1: RViz visualization
rviz2

# In RViz:
# 1. Add Image Display
# 2. Select topic: /camera/image_raw
# 3. Observe live camera feed

# Option 2: Command line preview
ros2 run image_view image_view image:=/camera/image_raw

    5.2 Monitor IMU Data¶

    Bash
    # Display IMU stream
ros2 topic echo /imu/data

# Output format:
# header:
#   seq: 1000
#   stamp:
#     sec: 1234567890
#     nsec: 123456789
#   frame_id: imu_link
# orientation:
#   x: 0.0
#   y: 0.0
#   z: 0.0
#   w: 1.0
# linear_acceleration:
#   x: 0.0
#   y: 0.0
#   z: 9.81

    5.3 Check Odometry¶

    Bash
    # Display odometry data
ros2 topic echo /odom --once

# Key fields:
# - position: robot's (x, y, z) coordinates
# - orientation: robot's yaw angle
# - velocity: current linear and angular speed

    5.4 Motor State¶

    Bash
    # Display motor feedback
ros2 topic echo /motor/state

# Expected output:
# left_velocity: 0.25 m/s
# right_velocity: 0.25 m/s
# left_current: 0.5 A
# right_current: 0.5 A

    🤖 Step 6: Complete First Autonomous Mission¶

    6.1 Mission: Patrol Rectangle¶

    Objective: Robot moves in a 1m × 0.5m rectangle pattern

    Bash
    # Create mission file
cat > first_mission.py << 'EOF'
#!/usr/bin/env python3
import rclpy
from geometry_msgs.msg import Twist
import time

def main():
    rclpy.init()
    node = rclpy.create_node('first_mission')

    # Create publisher for velocity commands
    pub = node.create_publisher(Twist, '/cmd_vel', 10)

    # Initialize twist message
    twist = Twist()

    print("Starting patrol mission...")

    # Forward (1 meter)
    print("Moving forward...")
    twist.linear.x = 0.2  # 0.2 m/s
    twist.angular.z = 0.0
    for _ in range(50):  # 5 seconds at 0.2 m/s = 1 meter
        pub.publish(twist)
        time.sleep(0.1)

    # Turn right (90 degrees)
    print("Turning right...")
    twist.linear.x = 0.0
    twist.angular.z = -0.5  # -0.5 rad/s (clockwise)
    for _ in range(32):  # ~3 seconds for 90 degree turn
        pub.publish(twist)
        time.sleep(0.1)

    # Forward (0.5 meters)
    print("Moving forward...")
    twist.linear.x = 0.2
    twist.angular.z = 0.0
    for _ in range(25):  # 2.5 seconds at 0.2 m/s = 0.5 meters
        pub.publish(twist)
        time.sleep(0.1)

    # Turn right (90 degrees)
    print("Turning right...")
    twist.linear.x = 0.0
    twist.angular.z = -0.5
    for _ in range(32):
        pub.publish(twist)
        time.sleep(0.1)

    # Forward (1 meter back to start)
    print("Moving forward...")
    twist.linear.x = 0.2
    twist.angular.z = 0.0
    for _ in range(50):
        pub.publish(twist)
        time.sleep(0.1)

    # Turn right (90 degrees)
    print("Turning right...")
    twist.linear.x = 0.0
    twist.angular.z = -0.5
    for _ in range(32):
        pub.publish(twist)
        time.sleep(0.1)

    # Forward (0.5 meters)
    print("Moving forward...")
    twist.linear.x = 0.2
    twist.angular.z = 0.0
    for _ in range(25):
        pub.publish(twist)
        time.sleep(0.1)

    # Stop
    print("Mission complete! Stopping...")
    twist.linear.x = 0.0
    twist.angular.z = 0.0
    pub.publish(twist)

    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
EOF

# Make executable
chmod +x first_mission.py

# Run mission
python3 first_mission.py

    6.2 Monitor Mission Execution¶

    Bash
    # In another terminal, monitor robot movement
ros2 topic echo /odom

# Observe:
# - X coordinate increases (moving forward)
# - Y coordinate changes (turning)
# - Z orientation (yaw) changes

    ✅ Step 7: Verification Checklist¶

    Use this checklist to confirm successful completion:

    • Jetbot powers on with green LED
    • Can SSH into Jetbot
    • ROS2 topics are publishing
    • Motor commands are received
    • Robot moves forward smoothly
    • Robot can turn
    • Camera stream is visible
    • Odometry data is published
    • Completed patrol rectangle mission
    • Robot returns to starting position

    🎯 Success Criteria¶

    ✅ Mission Successful if: 1. Robot moves forward at 0.2 m/s consistently 2. Turns approximately 90 degrees per command 3. Returns to approximate starting position 4. No warning/error messages 5. Motor current stays below 2A

    ❌ Mission Failed if: 1. Motors don't respond 2. Jerky/unsmooth movement 3. Large odometry drift 4. Excessive motor current (> 2A)

    🐛 Troubleshooting¶

    Issue: Motors Don't Respond¶

    Symptoms: Send cmd_vel but robot doesn't move

    Solutions:

    Bash
    # Check motor controller
ros2 node info /motor_controller

# Check battery voltage
ros2 service call /battery/status jetbot_interfaces/GetBatteryStatus

# Reset motor controller
ros2 service call /motor/reset std_srvs/Empty

# Check motor current
ros2 topic echo /motor/state | grep current

    Issue: Jerky Movement¶

    Symptoms: Robot movement is not smooth

    Solutions:

    Bash
    # Increase command frequency
# Reduce acceleration:
# linear.x = 0.1 (slower)
# angular.z = 0.2 (reduce rotation)

# Check wheel friction
# Manually spin wheels - should be smooth

# Verify surface is flat

    Issue: Odometry Drift¶

    Symptoms: Robot thinks it moved more/less than actual

    Solutions:

    Bash
    # Recalibrate encoders
ros2 service call /odometry/calibrate std_srvs/Empty

# Check wheel diameter in config
# vim ~/ros2_ws/src/jetbot_control/config/control_params.yaml

# Verify encoder connections
# Physical inspection of encoder wires

    Issue: No Camera Feed¶

    Symptoms: Camera image_raw topic not publishing

    Solutions:

    Bash
    # Check camera node
ros2 node info /camera_driver

# Restart camera driver
ros2 service call /camera/reset std_srvs/Empty

# Check USB connection
lsusb | grep camera_name

# Verify camera permissions
ls -l /dev/video*

    💡 Tips & Best Practices¶

    ✅ DO: - Test in open space first - Start with slow speeds (0.1-0.2 m/s) - Monitor battery level regularly - Keep emergency stop accessible - Save successful configurations

    ❌ DON'T: - Run at maximum speed initially - Leave charging unattended - Block motor movement - Connect live power while debugging - Ignore error messages
