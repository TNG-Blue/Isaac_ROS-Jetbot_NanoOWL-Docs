    Calibration Stereo Tutorial

    Calibrate the Stereo Camera¶

    Calibrate the two IMX219 cameras of ros2_stereo, check the result against measurable acceptance criteria, and measure the disparity noise σ_d so that the per-pixel depth uncertainty the node publishes is true for your rig.

    Before you start

    • Time: about 1 hour
    • You need: the Jetson with both IMX219 cameras on CSI, a printed chessboard with 9 × 6 inner corners on a flat rigid board, a calliper, a textured flat target
    • You learn: stereo calibration (Zhang + joint refinement), rectification checks, σ_d characterisation, the per-pixel Kalman filter consistency test

    Recalibrate after any change

    Calibrate once per rig, and again after any change of lens, mount or flip_method. A calibration from another rig produces depth that looks plausible and is wrong.

    Why the numbers matter¶

    For a rectified pair with focal length f [px], baseline B [m] and disparity d [px] (Hartley & Zisserman §9.3, §12.1):

    Z = f·B / (d − d_off)              σ_Z = Z²·σ_d / (f·B)      (first order)

    On the Jetbot (f = 339.7 px at 480 px width, B = 0.06 m, so f·B = 20.38 px·m), one pixel of disparity error at 2 m is about 0.2 m of depth. Two things set that error: rectification quality (a row misalignment makes the matcher compare the wrong pixels) and the matcher noise σ_d. This tutorial controls the first and measures the second.

    1. Build and start uncalibrated¶

    ROS/build.sh -p ros2_stereo
source install/setup.bash
ros2 launch ros2_stereo jetbot_stereo.launch.py

    Without a calibration file the node starts with an explicit warning. Images are being captured, but depth is not to be trusted yet.

    2. Capture calibration pairs¶

    Measure one printed square with a calliper; you need its size in metres for step 3.

    Hold the board in view of both cameras and capture a pair for each pose:

    ros2 service call /stereo/stereo_node/capture_calibration_pair std_srvs/srv/Trigger

    Capture 25–40 poses:

    • distance 0.4–1 m;
    • tilt up to ±25° about both axes;
    • board centres spread over the whole image, including the corners.

    Cover the corners

    With boards only near the centre, lens distortion is extrapolated at the edges. On the synthetic test rig that raised the rectified row error at the image edge from 0.04 px to 0.35 px.

    Pairs are written to calibration_capture_dir (default /tmp/stereo_calibration).

    3. Run the calibration¶

    ros2 run ros2_stereo stereo_calibrate --images /tmp/stereo_calibration \
    --board 9x6 --square 0.025 --output ~/stereo_calibration.yaml

    Replace 0.025 with your measured square size in metres. The tool calibrates each camera (Zhang 2000), then refines both intrinsics and the extrinsics jointly (bundle adjustment). On the synthetic rig with 0.1 px corner noise, keeping the intrinsics fixed gave rectified row errors up to 0.65 px; the joint refinement stayed below 0.09 px over 40 draws (OpenCV 4.6).

    4. Accept or reject¶

    Accept the calibration only when all three hold:

    Criterion Threshold Why
    Stereo RMS reprojection error close to √2·σ_c, where the corner noise σ_c is typically 0.1–0.2 px a larger RMS means a bent board, bad detections or a moving camera
    Rectified row error ≤ 0.5 px; the tool exits with code 3 above it semi-global matching degrades beyond it (Hirschmüller & Gehrig 2009)
    Outlier views none listed (> 2 × median error) remove the listed images and re-run

    Calibrate at the capture size with the same flip_method used at run time. The node rescales the intrinsics to the working resolution exactly (f' = s·f, c' = s·(c + ½) − ½), so no second calibration is needed for another working size.

    5. Run with the calibration¶

    ros2 launch ros2_stereo jetbot_stereo.launch.py calibration_file:=$HOME/stereo_calibration.yaml
ros2 run rqt_image_view rqt_image_view /stereo/disparity/color
ros2 topic echo /diagnostics --field status[0].values

    Check that straight edges in left/image_rect are straight and that features lie on the same row in both rectified images.

    6. Measure σ_d¶

    The node ships with disparity_sigma: 0.3 px, a bound on the 0.278 px measured on a synthetic scene. VPI and SGBM matchers differ, and so does your scene texture, so measure it:

    1. Place a textured plane fronto-parallel at 1.0 m.
    2. Disable the temporal filter (temporal.enable: false in config/stereo_params.yaml, or ros2 param set /stereo/stereo_node temporal.enable false).

    3. Record disparity for 10 s:

      ros2 bag record -o sigma_d_1m /stereo/disparity --max-duration 10

    4. Over the valid pixels of each frame, fit a plane d = a·u + b·v + c and take the robust standard deviation of the residual, σ_d = 1.4826 · MAD. MAD is used because SGM sub-pixel errors are not Gaussian (pixel locking).

    5. Set disparity_sigma to that value.

    At 1 m the expected single-frame depth noise is then σ_Z = 1.0² · σ_d / 20.38 m, for example 14.7 mm with σ_d = 0.3 px.

    7. Check the estimator consistency¶

    Re-enable the temporal filter and record a static scene. Each pixel runs a scalar Kalman filter on disparity with a χ²₁ gate at γ = 6.635 (1 % rejection). When the noise model is right, the accepted normalised innovation squared averages

    E[NIS | NIS ≤ γ] = F₃(γ) / F₁(γ) = 0.925

    In /diagnostics, check:

    Value Expected
    temporal NIS mean ≈ 0.925
    temporal gated ≈ 1 %

    The node goes to WARN when the mean deviates by more than 25 % over at least 10 000 updates. The sampling standard deviation of the mean is about √(2/N) ≤ 1.4 %, so a 25 % deviation is a real model mismatch: re-measure σ_d before touching anything else. q₀ is the only tunable term, for image motion during rotation; set it from a recording and check it with these NIS values.

    Outputs you can now trust¶

    Topic Content
    /stereo/depth Z [m], NaN where invalid (REP 118)
    /stereo/depth/uncertainty σ_Z [m] per pixel
    /stereo/points point cloud in the left optical frame

    Consumers must treat NaN as unknown, never as free space.

    References¶

    • Z. Zhang, "A Flexible New Technique for Camera Calibration", IEEE TPAMI 22(11), 2000.
    • R. Hartley, A. Zisserman, Multiple View Geometry in Computer Vision, 2nd ed., 2004.
    • H. Hirschmüller, S. Gehrig, "Stereo Matching in the Presence of Sub-Pixel Calibration Errors", CVPR 2009.
    • D. Simon, Optimal State Estimation, Wiley 2006.
