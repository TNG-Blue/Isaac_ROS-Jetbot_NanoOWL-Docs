    CHANGELOG¶

    Source

    This page is rendered from .github/CHANGELOG.md, the authoritative description kept next to the code in .github/.

    All notable changes to Isaac_ROS-Jetbot_NanoOWL will be documented in this file.

    Documentation standardised in English October 9, 2026¶

    What's New¶

Details: Docs/CHANGELOG.md.
    • Remote UAV firmware documents, the ROS 2 node flowchart and the OpenMV API audit translated to English.

    Bug Fixes¶

    • Unmeasured performance figures, non-existent features and contact channels removed from the site, README.md and Server_OTA/README.md.
    • README.md quick start builds from the repository root with ROS/build.sh and links the published documentation.

    Documentation site rendered from the code October 9, 2026¶

    What's New¶

    • The MkDocs site covers every component: 39 pages are rendered at build time from the package READMEs and design records (source: front matter, hook Scripts/mkdocs_hooks/source_pages.py) and 14 pages are snapshots of the firmware and Android submodules (Scripts/mkdocs_hooks/snapshot_submodules.py). New sections: Simulation, Firmware, Deep Learning, MATLAB & Simulink, Mobile App, Examples & Utilities, MAVLink Relay Server, Control Design Standard. Details: Docs/CHANGELOG.md.
    • Material 9.7 features: link prefetch, instant previews, footnote tooltips, glossary tooltips.

    Bug Fixes¶

    • ROS 2 module pages described packages that do not exist; they now render the real packages.
    • Broken links in MATLAB/README.md and Utilities/DFRobot_I2C_Multiplexer/README.md.

    UAV 3-D map for the JetbotNanoOWL console October 9, 2026¶

    What's New¶

    • ros2_network_bridge 0.5.0 sends the planar LD19 scan as MAVLink OBSTACLE_DISTANCE (#330):

      • 360 one-degree sectors in BODY_FRD, in five messages per scan;
      • mount yaw and offset applied;
      • de-skewed to the scan stamp with the body twist;
      • decimated to fit the link budget, n = ⌈B_scan / (u_max C − B_streams)⌉.

      The console places each fan with the 6-DoF pose at its own timestamp and stacks the fans into a 3-D voxel map, so the UAV is mapped in 3-D rather than as a floor plan. * jetbot_console.launch.py gains three arguments: scan_topic, scan_mount_yaw_deg, and link_loss_action (default none; set rth for a UAV also flown from a GCS). * Tests: OBSTACLE_DISTANCE byte-exact against pymavlink, sector geometry, mount and no-return handling, de-skew, and budget decimation. The package now has 42 gtest cases.

    MAVLink relay: robot and console on different networks October 9, 2026¶

    What's New¶

    • Server_Relay/ (new; Go 1.21, standard library only) joins a robot and its consoles when they do not share a network. Both ends dial out over TLS, so any NAT is crossed, the carrier's CGNAT included:

      • per-robot, per-role tokens, stored only as SHA-256 hashes and compared in constant time;
      • frame-level forwarding;
      • observers can send nothing but a verified HEARTBEAT, so an observer credential can never command the robot.

      Tests cover TLS, the policy, back-pressure and timeouts (go test -race). Deployment: Dockerfile and README. CI: relay-server-ci.yml. * ros2_network_bridge 0.4.0: transport: relay (OpenSSL, CA or SPKI pin, token from a file, exponential back-off), with launch arguments in jetbot_console.launch.py. * JetbotNanoOWL connects as an observer through the same relay. It measures each fix's delay from its timestamp and carries the fix to the present before fusing it.

    ROS2 Network Bridge: ODOMETRY with covariances for the JetbotNanoOWL console October 9, 2026¶

    What's New¶

    • ros2_network_bridge 0.3.0 sends MAVLink ODOMETRY (#331): pose in LOCAL_NED and twist in BODY_FRD, with both 6×6 covariances mapped from the ROS conventions. The pose covariance goes through J = blockdiag(T, E⁻¹T); this is checked against central differences. An all-zero or non-finite covariance is sent as unknown, never as a perfect measurement.
    • jetbot_console.launch.py connects the Jetbot graph (/odometry) to the JetbotNanoOWL Android console. The console fuses ODOMETRY in its EKF and sends only a MAV_TYPE_LOG heartbeat, so it never acts as the GCS.
    • Details and the bandwidth budget: Source/ROS2_Network_Bridge/CHANGELOG.md.

    ROS2 Lidar AI Solution: NVIDIA code as submodules October 9, 2026¶

    What's New¶

    • Source/ROS2_Lidar_AI_Solution no longer carries copies of NVIDIA's code. NVIDIA-AI-IOT/ Lidar_AI_Solution is a git submodule at Lidar_AI_Solution/, next to CUDA-LidarAI/ (its nested CUDA-PointPillars is checked out at the upstream tip with --remote), built unmodified by the new standalone CMake project CUDA-LidarAI (lidar_ai_core, targets lidar_ai::*); the ROS 2 nodes link those targets. The libraries can be built and installed separately and the package built against them (-DUSE_INSTALLED_LIDAR_AI_CORE=ON).
    • The removed copy was stale and partly broken (empty source files, Git LFS pointers instead of libspconv, a missing upstream bounds check).
    • cuda_utilities: the duplicated ComputeCentroid is replaced by the GPU implementation, renamed ComputeCentroidDevice (device result, stream-ordered) plus ComputeCentroidHost, with intensity weighting and NaN/Inf rejection; pointcloud_preprocessor_node, isaac_ros_semantic_overlay_node and the CUDA-Utilities tests link again.
    • ros2_lidar_ai_solution 0.6.0; see Source/ROS2_Lidar_AI_Solution/CHANGELOG.md for the migration and the platform support of each component.

    Shell scripts: consistent interface and fixes October 9, 2026¶

    What's New¶

    Every repository shell script now has a usage header (purpose, options, environment, exit status), --help, strict mode (set -euo pipefail), quoted expansions, argument validation and a clean ShellCheck run; executable scripts carry the executable bit.

    • Scripts/shell/common.sh: no longer changes the caller's shell options or IFS, can be sourced twice, adds die and require_command; warnings go to stderr; honours NO_COLOR.
    • CMakePreBuild.sh: configures CUDA/CMakeLists.txt (it pointed at the repository root, which has none); build and install in CUDA/build, CUDA/install.
    • jetbot-nanoowl: a failing build-all step now stops the build instead of being reported as an unknown command; setup prints source commands (eval "$(jetbot-nanoowl setup)"); --config without a path and add-to-path without ~/.bashrc no longer crash.
    • ROS/: tag.sh selects the distribution non-interactively (--distro, $ROS_DISTRO, or the only one installed); install.sh installs ROS 2 Humble/Jazzy from the official ros2-apt-source with Ubuntu-release checks; build.sh builds the repository workspace (-p, -u, --rosdep, --test); run.sh lists workspace nodes and forwards Ctrl-C to nodes started in parallel.
    • Docker/scripts/docker_manager.sh 3.0.0 drives Docker/compose/docker-compose.yml (build, up, logs, exec, ...); the Dockerfiles it referenced no longer exist. ros2_build.sh builds any src/ workspace; its --symlink-install and --parallel-workers were passed to CMake because they came after --cmake-args.
    • Configs/run-setup.sh implements its steps (NVMe mount, nvidia default runtime, Docker data-root, swap, GUI, docker group, nvpmodel, ROS 2, NetworkManager) with --dry-run, --yes and --only. It parses .env instead of sourcing it: KEY=value# comment lines were executed as commands. .env comments moved to their own lines.
    • Scripts/install-firebase-sdk.sh 2.0.0: honours --jobs/BUILD_JOBS; no prompt in unattended runs (--reconfigure); deletes a /usr/local Abseil only with --remove-system-abseil.
    • Source/ROS2_Qt/configure_firebase.sh: validates input, hides the API key while typing, writes .env with mode 600; Source/ROS2_Qt/.env is git-ignored.
    • Server_OTA/scripts/build.sh builds static linux/amd64, linux/arm64 (Jetson) and linux/arm/7 binaries; run.sh starts the binary for the host or falls back to go run.
    • Scripts/dependencies/install_vpi3_x86_64.sh adds NVIDIA's signing key and picks the repository and Python binding matching the Ubuntu release.

    Breaking Changes¶

    • Docker/scripts/docker_manager.sh: services are the compose service names (docker_manager.sh list), e.g. ros2_stereo instead of stereo.
    • ROS/build.sh: ROS 1 (catkin) is no longer handled; the workspace is ROS 2 only.
    • ROS/run.sh: the sequential mode, which stopped each node after 10 s, was removed.
    • The ROS distribution selection moved from /tmp/selected_ros_version to ~/.cache/jetbot-nanoowl/ros_distro (ROS_SELECTION_FILE).

    Two-Jetson deployment: Docker, k3s, Helm October 8, 2026¶

    What's New¶

    • Every ROS 2 node is its own image (Docker/images.txt, one template that really builds the package) and its own Deployment in the ros2-jetson Helm chart.
    • Kubernetes/cluster/: k3s master + worker over Ethernet, image registry on the master.
    • The scheduler balances floating nodes over both Jetsons (requests, topology spread, GPU anti-affinity) and moves them within ≈ 35 s when the worker fails; hardware nodes stay pinned.
    • ROS 2 nodes communicate across the boards (host network, DDS bound to the cluster Ethernet, shared memory on a board); helm test checks it.
    • OTA server behind MetalLB at 192.168.10.200:8080 (firmware NET_OTA_SERVER_IP updated in JetOwl_FlightControl and JetOwl_Vision).
    • See Docker/CHANGELOG.md, Kubernetes/CHANGELOG.md, Helm/CHANGELOG.md.

    MATLAB Function blocks for Simulink and a real-time SLAM view October 2, 2026¶

    What's New¶

    • MATLAB/simulink/blocks/: Simulink models are assembled only from MATLAB Function blocks. Each block's code calls one .m file.
      • 18 ROS 2 sources plus a clock.
      • 7 processing blocks with cited formulas (ENU, ISA baro, scan → map, χ² ellipse, obstacles, SLAM NIS consistency, map area).
      • 2 real-time views (flight, SLAM) and a guarded flight/nav_command publisher.
    • jetowl_build_monitor_model builds the monitor model with fixed step and real-time pacing. jetowl_monitor_sil runs the same graph without Simulink.
    • SLAM view (/map, /slam/pose, /slam/path, /slam/debug, /scan): map and uncertainty, NIS consistency against exact χ² bounds, innovations, ICP quality and degeneracy, timing. Available in jetowl_ros2_viz (live / bag / demo) and as a Simulink sink.
    • See MATLAB/simulink/README.md and MATLAB/CHANGELOG.md.

    Isaac_ROS-Jetbot_NanoOWL 1.0.0 June 8, 2025¶

    Packages available as 1.0.0 Release tagged v1.0.0 on GitHub.

    What's New¶

    Initial release of Isaac_ROS-Jetbot_NanoOWL providing NVIDIA-accelerated object detection for autonomous robots including:

    • Core Features:
      • NanoOWL integration for real-time object detection on Jetson platforms
      • ROS 2 Humble support with optimized message passing
      • NVIDIA Isaac ROS compatibility for seamless integration
      • Hardware-accelerated inference using TensorRT
    • Robot Platform Support:
      • JetBot reference platform configuration
      • Custom robot integration examples
      • Sensor fusion capabilities
    • Development Tools:
      • Devcontainer setup for consistent development environment
      • Docker Compose orchestration for multi-container deployments
      • Automated build and deployment scripts
    • Documentation:
      • Comprehensive setup and usage guides
      • API reference documentation
      • Tutorial notebooks for getting started
      • Performance optimization guidelines

    Limitations¶

    This release has the following known limitations, with workarounds available in the troubleshooting section:

    • NanoOWL model inference limited to Jetson Orin and Xavier platforms
    • Maximum supported image resolution is 1920x1080 for real-time performance
    • Multi-camera support requires manual configuration
    • ROS 1 Noetic not supported (ROS 2 Humble only)

    Feature Requests & Issues Addressed¶

    This release addresses initial project setup and core functionality:

    • Initial project architecture and structure
    • Core object detection pipeline implementation
    • ROS 2 integration and message definitions
    • Devcontainer and Docker environment setup

    Guidelines for Future Releases¶

    Version Format¶

    Follow semantic versioning: MAJOR.MINOR.PATCH

    • MAJOR: Breaking changes, major new features, API redesign
    • MINOR: New features, backward compatible additions
    • PATCH: Bug fixes, security patches, documentation updates

    Release Entry Format¶

    ## Isaac_ROS-Jetbot_NanoOWL X.Y.Z Month Day, Year

Packages available as X.Y.Z Release tagged vX.Y.Z on GitHub.

### What's New

Updates including:

* `package_name`: Description of changes
* `component_name`: Feature additions or improvements
* New capabilities and enhancements

### Limitations

This release has the following known limitations:

* Known issue description with context
* Platform-specific limitations
* Temporary restrictions

### Feature Requests & Issues Addressed

This release contains fixes to address user feedback, including:

* [repository #123](link): Issue description
* [repository #456](link): Feature request implementation

    Content Guidelines¶

    What to Include:

    • User-facing changes and new features
    • API modifications and breaking changes
    • Bug fixes affecting functionality
    • Performance improvements
    • Security patches
    • Dependency updates that affect users
    • Known limitations and workarounds

    What to Exclude:

    • Internal code refactoring without user impact
    • Test-only changes
    • Documentation typo fixes (unless significant)
    • Build system changes (unless affecting users)

    Writing Style¶

    Follow NVIDIA Isaac ROS conventions:

    • Use clear, concise language
    • Start with package/component name in backticks when applicable
    • Focus on user impact and benefits
    • Include GitHub issue references: [repo #123](link)
    • Group related changes together
    • Use bullet points for readability

    Example Entry¶

    ## Isaac_ROS-Jetbot_NanoOWL 1.1.0 August 15, 2025

Packages available as 1.1.0 Release tagged v1.1.0 on GitHub.

### What's New

Updates including:

* `isaac_ros_nanoowl`: Add support for custom object classes
  * Enable runtime class configuration via ROS parameters
  * Improve inference performance by 15% on Jetson Orin
  * Add validation for custom class definitions
* `jetbot_bringup`: Enhance multi-camera synchronization
  * Support for stereo camera pairs
  * Automatic timestamp alignment
  * Configurable frame buffer size
* Documentation: Add advanced configuration guide
  * Camera calibration procedures
  * Performance tuning recommendations
  * Troubleshooting common issues

### Limitations

This release has the following known limitations:

* Custom object class training pipeline not yet integrated
* Stereo camera support limited to specific camera models
* Maximum 4 concurrent camera streams for real-time operation

### Feature Requests & Issues Addressed

This release contains fixes to address user feedback, including:

* [isaac_ros_jetbot_nanoowl #12](link): Add multi-camera support
* [isaac_ros_jetbot_nanoowl #34](link): Fix memory leak in continuous detection mode
* [isaac_ros_jetbot_nanoowl #56](link): Improve detection accuracy for small objects
