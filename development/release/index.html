    Release Process¶

    Guidelines for releasing new versions of Isaac ROS Jetbot NanoOWL.

    📋 Release Checklist¶

    Before releasing a new version:

    • All tests passing on main branch
    • CHANGELOG.md updated with release notes
    • Version numbers updated in all packages
    • Documentation updated for new features
    • Breaking changes clearly documented
    • Migration guide provided (for major releases)
    • Docker images built and tested
    • Security scan completed
    • Performance benchmarks reviewed

    🔢 Version Numbering¶

    We follow Semantic Versioning 2.0.0:

    Text Only
    MAJOR.MINOR.PATCH[-PRERELEASE][+BUILD]

    Examples: - 1.0.0 - Initial stable release - 1.1.0 - New feature (backward compatible) - 1.1.1 - Bug fix - 2.0.0 - Breaking change - 2.0.0-beta.1 - Pre-release - 2.0.0+20250126 - Build metadata

    Incrementing Rules¶

    MAJOR (x.0.0): - Breaking API changes - Incompatible system architecture changes - Major ROS2 version upgrades

    MINOR (1.x.0): - New features (backward compatible) - New ROS2 modules - Significant performance improvements - New hardware support

    PATCH (1.1.x): - Bug fixes - Documentation updates - Minor performance tweaks - Security patches

    🚀 Release Types¶

    Stable Release¶

    Full production-ready release.

    Process: 1. Create release branch from main 2. Run full test suite 3. Update version numbers 4. Generate changelog 5. Create Git tag 6. Build and push Docker images 7. Deploy documentation 8. Create GitHub release

    Beta Release¶

    Feature-complete but needs testing.

    Process: 1. Same as stable but with -beta.X suffix 2. Mark as "pre-release" on GitHub 3. Limited Docker image distribution 4. Announce to testing community

    Alpha Release¶

    Early preview for developers.

    Process: 1. Create from develop branch 2. Version: X.Y.Z-alpha.N 3. Internal testing only 4. Docker images tagged as alpha

    📝 Creating a Release¶

    Step 1: Prepare Release Branch¶

    Bash
    # Update main branch
git checkout main
git pull origin main

# Create release branch
git checkout -b release/v1.2.0

# Update version numbers
./scripts/update_version.sh 1.2.0

# Commit version updates
git add -A
git commit -m "chore(release): prepare v1.2.0"
git push origin release/v1.2.0

    Step 2: Update Changelog¶

    Edit CHANGELOG.md:

    Markdown
    ## [1.2.0] - 2025-02-07

### Added
- **Detection**: YOLOv9 model support (#123)
- **Navigation**: Dynamic obstacle avoidance (#145)
- **API**: REST API for remote control (#156)

### Changed
- **Performance**: 20% faster object detection (#134)
- **SLAM**: Improved loop closure accuracy (#142)

### Fixed
- **Camera**: Fixed IMX477 initialization issue (#138)
- **Motors**: Resolved encoder overflow bug (#150)

### Deprecated
- **API**: Old detection format (use Detection2DArray)

### Breaking Changes
- **Config**: Changed YAML structure for detection params
  - Migration: See [migration guide](docs/migration/v1.2.md)

### Security
- Updated dependencies with security patches

    Commit:

    Bash
    git add CHANGELOG.md
git commit -m "docs(changelog): add v1.2.0 release notes"

    Step 3: Run Full Test Suite¶

    Bash
    # Run all tests
colcon test

# Run integration tests
pytest tests/integration/

# Run performance benchmarks
pytest tests/performance/

# Security scan
snyk test

# Build Docker images
./scripts/build_docker.sh 1.2.0

    Step 4: Create Git Tag¶

    Bash
    # Merge to main
git checkout main
git merge --no-ff release/v1.2.0
git push origin main

# Create annotated tag
git tag -a v1.2.0 -m "Release version 1.2.0

Major changes:
- YOLOv9 support
- Dynamic obstacle avoidance
- REST API

See CHANGELOG.md for full details"

# Push tag
git push origin v1.2.0

    Step 5: Build Release Artifacts¶

    Bash
    # Build Docker images
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  --tag tngblue/jetbot-nanoowl:1.2.0 \
  --tag tngblue/jetbot-nanoowl:latest \
  --push \
  .

# Create source tarball
git archive --format=tar.gz --prefix=isaac-ros-jetbot-1.2.0/ v1.2.0 \
  > isaac-ros-jetbot-1.2.0.tar.gz

# Generate checksums
sha256sum isaac-ros-jetbot-1.2.0.tar.gz > checksums.txt

    Step 6: Create GitHub Release¶

    Bash
    # Using GitHub CLI
gh release create v1.2.0 \
  --title "Release v1.2.0" \
  --notes-file RELEASE_NOTES.md \
  isaac-ros-jetbot-1.2.0.tar.gz \
  checksums.txt

    Or manually on GitHub: 1. Go to Releases 2. Click "Draft a new release" 3. Select tag v1.2.0 4. Add title: "Release v1.2.0" 5. Paste changelog content 6. Upload artifacts 7. Publish release

    Step 7: Deploy Documentation¶

    Bash
    # Build and deploy docs
mkdocs build
mkdocs gh-deploy

# Or via GitHub Actions (automatic)

    Step 8: Announce Release¶

    Post announcement to: - [ ] GitHub Discussions - [ ] Project mailing list - [ ] Social media (Twitter, LinkedIn) - [ ] ROS Discourse - [ ] Project website

    Template:

    Markdown
    🎉 Isaac ROS Jetbot NanoOWL v1.2.0 Released!

We're excited to announce version 1.2.0 with major improvements:

✨ **New Features**
- YOLOv9 support for improved detection
- Dynamic obstacle avoidance
- REST API for remote control

⚡ **Performance**
- 20% faster object detection
- Improved SLAM accuracy

📚 **Documentation**
https://tng-blue.github.io/Isaac_ROS-Jetbot_NanoOWL/

🐳 **Docker**
```bash
docker pull tngblue/jetbot-nanoowl:1.2.0

    ⚠️ Breaking Changes See migration guide: https://...

    Full changelog: https://github.com/TNG-Blue/Isaac_ROS-Jetbot_NanoOWL/releases/tag/v1.2.0

    Text Only

## 🔄 Hotfix Process

For urgent bug fixes:

```bash
# Create hotfix branch from main
git checkout main
git checkout -b hotfix/v1.2.1

# Make fixes
git add -A
git commit -m "fix: critical detection bug"

# Update version to 1.2.1
./scripts/update_version.sh 1.2.1

# Update CHANGELOG
echo "## [1.2.1] - $(date +%Y-%m-%d)" >> CHANGELOG.md
echo "### Fixed" >> CHANGELOG.md
echo "- Critical detection bug causing crashes" >> CHANGELOG.md

# Merge and tag
git checkout main
git merge --no-ff hotfix/v1.2.1
git tag -a v1.2.1 -m "Hotfix: Critical detection bug"
git push origin main --tags

# Also merge back to develop
git checkout develop
git merge main
git push origin develop

    Monitor Release¶

    • Review download analytics

    Gather Feedback¶

    • Create feedback discussion thread
    • Survey users on new features
    • Monitor bug reports
    • Review performance metrics

    Plan Next Release¶

    • Review feature requests
    • Prioritize issues
    • Update project roadmap
    • Schedule next release date

    🎯 Release Schedule¶

    Regular Releases¶

    • Major: Every 12 months
    • Minor: Every 2-3 months
    • Patch: As needed (bug fixes)

    Release Timeline¶

    Text Only
    Month 1-2: Development
Month 3: Feature freeze
Week 1: Beta release
Week 2: Testing & bug fixes
Week 3: Release candidate
Week 4: Stable release

    🔒 Security Releases¶

    For security vulnerabilities:

    1. Do not disclose publicly until patched
    2. Create private fork for patch development
    3. Test thoroughly
    4. Release immediately once ready
    5. Publish security advisory
    6. Notify users directly if critical

    Security release version: 1.2.1-security.1

    2. isaac-ros-jetbot-X.Y.Z.tar.gz

    5. tngblue/jetbot-nanoowl:X.Y.Z

    6. tngblue/jetbot-nanoowl:latest

    7. Documentation:

    8. Hosted on GitHub Pages

    9. PDF export (for major releases)

    10. Checksums:

    11. SHA256 hashes for all artifacts
