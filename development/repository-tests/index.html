    Testing Framework¶

    Source

    This page is rendered from Tests/README.md, the authoritative description kept next to the code in Tests/.

    Overview¶

    This directory contains the automated testing framework for the Isaac_ROS-Jetbot_NanoOWL project. The framework uses pytest and is compatible with ROS2 Jazzy.

    Directory Structure¶

    Tests/
├── README.md           # This file
├── __init__.py         # Package initialization
├── conftest.py         # Shared pytest fixtures and configuration
├── unit/               # Unit tests for individual components
│   ├── __init__.py
│   └── test_example.py # Example unit test demonstrating structure
├── test_copyright.py   # Copyright header validation
├── test_flake8.py      # Code style validation
├── test_smoke.py       # Smoke tests for basic functionality
├── test_spoofing.py    # Security tests
└── test_threat_dashboard.py  # Threat dashboard tests

    Requirements¶

    Python Dependencies¶

    pip install pytest pytest-cov pytest-ros

    ROS2 Dependencies¶

    • ROS2 Jazzy (Jalisco)
    • colcon build tools
    • ament_python or ament_cmake for package building

    Running Tests¶

    Run All Tests¶

    pytest

    Run Specific Test Directory¶

    pytest Tests/unit/

    Run Specific Test File¶

    pytest Tests/unit/test_example.py

    Run Specific Test Function¶

    pytest Tests/unit/test_example.py::test_module_level_function

    Run with Coverage¶

    pytest --cov=Source --cov-report=html

    Run with Verbose Output¶

    pytest -v

    Run ROS-Marked Tests Only¶

    pytest -m ros

    Run Integration Tests¶

    pytest -m integration

    Writing Tests¶

    Test File Naming¶

    • Test files must start with test_ (e.g., test_motor_control.py)
    • Test files should be placed in appropriate subdirectories (unit/, integration/, etc.)

    Test Function Naming¶

    • Test functions must start with test_ (e.g., test_motor_speed())
    • Use descriptive names that indicate what is being tested

    Test Class Naming¶

    • Test classes must start with Test (e.g., TestMotorControl)
    • Group related tests in classes

    Example Unit Test¶

    import pytest


class TestMyComponent:
    """Tests for MyComponent."""

    def test_initialization(self):
        """Test component initialization."""
        component = MyComponent()
        assert component is not None

    @pytest.mark.ros
    def test_ros_node(self):
        """Test ROS2 node functionality."""
        # Tests requiring ROS2 runtime
        pass

    @pytest.fixture
    def sample_data(self):
        """Provide sample data for tests."""
        return {"key": "value"}

    def test_with_fixture(self, sample_data):
        """Test using fixture."""
        assert sample_data["key"] == "value"

    Parameterized Tests¶

    @pytest.mark.parametrize("input_value,expected", [
    (0, 0),
    (1, 1),
    (2, 4),
])
def test_square(input_value, expected):
    """Test square function."""
    assert input_value ** 2 == expected

    Test Markers¶

    The following pytest markers are available:

    • @pytest.mark.ros - Tests requiring ROS2 packages or runtime
    • @pytest.mark.integration - Longer-running or environment-dependent tests

    Fixtures¶

    Shared fixtures are defined in conftest.py. Common fixtures include:

    • ROS2 node initialization
    • Test data providers
    • Mock objects
    • Cleanup handlers

    CI/CD Integration¶

    Tests are automatically run in the CI/CD pipeline on:

    • Pull requests
    • Commits to main branches
    • Release tags

    Code Coverage¶

    Aim for:

    • Minimum 80% code coverage for new code
    • 100% coverage for critical components (safety, security)

    View coverage reports: 

    pytest --cov=Source --cov-report=html
open htmlcov/index.html

    ROS2 Jazzy Compatibility¶

    This testing framework is compatible with ROS2 Jazzy (Jalisco). Key considerations:

    • Use pytest-ros for ROS2-specific testing utilities
    • Initialize ROS2 context in fixtures when needed
    • Clean up ROS2 nodes properly in teardown
    • Use ROS2 launch testing for integration tests

    Best Practices¶

    1. Test Isolation: Each test should be independent
    2. Clear Assertions: Use descriptive assertion messages
    3. Fast Tests: Keep unit tests fast (< 1 second each)
    4. Mock External Dependencies: Use mocks for external services
    5. Test Edge Cases: Include boundary conditions and error cases
    6. Documentation: Document complex test scenarios
    7. Consistent Style: Follow project coding standards (PEP 8)

    Troubleshooting¶

    Tests Not Discovered¶

    • Ensure test files start with test_
    • Ensure test functions start with test_
    • Check pytest.ini configuration

    ROS2 Tests Failing¶

    • Verify ROS2 environment is sourced
    • Check ROS2 dependencies are installed
    • Ensure ROS2 nodes are properly initialized/cleaned up

    Import Errors¶

    • Verify package is installed or PYTHONPATH is set
    • Check for circular dependencies
    • Ensure init.py files exist
