    Deployment OTA

    Server OTA — API Reference¶

    Every route registered by setupRoutes() in Server_OTA/src/main.go, with the exact payloads produced by Server_OTA/src/handlers/handlers.go.

    Base URL in a local run: http://localhost:8080

    📋 Route Table¶

    Method Path Handler Purpose
    GET / HandleHome Renders the dashboard (web/templates/index.html)
    GET /api/stats HandleStats Storage and download counters
    GET /api/health HandleHealth Liveness / readiness probe
    GET /api/firmware/list HandleFirmwareList All firmware files with metadata
    GET /api/firmware/info?file= HandleFirmwareInfo Metadata for one file
    GET /download?file= HandleDownload Firmware binary download
    POST /upload HandleUpload Upload endpoint (placeholder, see below)
    GET /static/* http.FileServer CSS, JS, images from web/static
    GET /404 HandleNotFound 404 page

    All routes except /static/* pass through utils.WithRateLimit: at most 5 concurrent requests, others wait up to 5 s and then receive 503 Server busy as text/plain.

    📦 Response Envelope¶

    Every JSON route answers with models.APIResponse:

    {
  "data": { },
  "message": "human readable string",
  "success": true
}

    data is omitted on errors (omitempty), and success is false with the HTTP status carrying the reason.

    🔌 Endpoints¶

    GET /api/health¶

    Liveness probe. Used by the Docker HEALTHCHECK and by both App Engine manifests.

    curl -s http://localhost:8080/api/health

    {
  "data": { "status": "operational", "memory_mb": 24, "goroutines": 0, "timestamp": 0 },
  "message": "Server is healthy",
  "success": true
}
    Field Type Meaning
    status string Always operational while the handler is reachable
    memory_mb uint64 MemoryManager.GetMemoryStats().Alloc converted to MB
    goroutines int Currently always 0 — see Current gaps
    timestamp int64 Currently always 0 — GetUnixTime() is a stub

    Probe on status, not on payload

    Because two fields are placeholders, health checks should assert HTTP 200 and success == true, not the numeric values.

    GET /api/stats¶

    curl -s http://localhost:8080/api/stats

    {
  "data": { "total_files": 5, "total_size": 272105472, "downloads": 12, "server_version": "3.0.0" },
  "message": "Server statistics",
  "success": true
}
    Field Type Meaning
    total_files int Number of allowed files in data/firmware/, counted on this request
    total_size int64 Sum of their sizes in bytes
    downloads int32 Downloads served since process start (in-memory, reset on restart)
    server_version string Hard-coded "3.0.0" in the handler

    The handler calls ListFirmwareFiles() first, so the counters always reflect the same directory scan as /api/firmware/list.

    GET /api/firmware/list¶

    curl -s http://localhost:8080/api/firmware/list

    {
  "data": [
    {
      "size": 262144,
      "mod_time": "2026-09-14T08:31:07.482Z",
      "name": "stm32f407_motor_control_v183.bin",
      "version": "v183",
      "device_type": "STM32",
      "description": "Firmware for STM32"
    }
  ],
  "message": "Firmware list",
  "success": true
}
    Field Type Source
    size int64 os.FileInfo.Size()
    mod_time RFC 3339 os.FileInfo.ModTime()
    name string File name
    version string Parsed from the name after _v
    device_type string ESP32, ESP8266, Arduino, STM32 or Generic
    description string "Firmware for " + device_type

    Directories and files whose extension is not .bin, .hex, .elf, .img or .fw are skipped. Naming rules are in Firmware metadata.

    Errors: 500 with "Unable to list files" if data/firmware/ cannot be read (for example when it does not exist).

    GET /api/firmware/info?file=<name>¶

    curl -s "http://localhost:8080/api/firmware/info?file=stm32f407_motor_control_v183.bin"

    {
  "data": { "name": "stm32f407_motor_control_v183.bin", "size": 262144, "size_fmt": "256.0KB" },
  "message": "Firmware info",
  "success": true
}
    Status Condition message
    400 file query parameter missing File parameter required
    404 File not in data/firmware/ File not found

    size_fmt comes from utils.FormatFileSize: bytes below 1024 render as 512B, larger values as one decimal with no space (256.0KB, 1.5MB, 2.0GB).

    GET /download?file=<name>¶

    Streams the binary with http.ServeFile and increments the download counter.

    curl -OJ "http://localhost:8080/download?file=stm32f407_motor_control_v183.bin"

    Response headers

    Content-Disposition: attachment; filename=stm32f407_motor_control_v183.bin
Content-Type: application/octet-stream
    Status Condition message
    400 file missing File parameter required
    403 Extension not in the allow-list File type not allowed
    404 File does not exist File not found

    Write timeout bounds the transfer

    WriteTimeout is 30 s, so a download that cannot complete within that window is cut off. For large images, raise the timeout or place a proxy in front of the service.

    POST /upload¶

    curl -X POST -F "firmware=@stm32f407_motor_control_v183.bin" http://localhost:8080/upload

    { "message": "Upload endpoint placeholder", "success": true }

    Not implemented yet

    HandleUpload answers 200 without reading the multipart body — nothing is written to data/firmware/. A non-POST method returns 405 Method not allowed. Until the handler is implemented, stage firmware into data/firmware/ by another route (volume mount, scp, CI step); the UI's upload zone is subject to the same limitation.

    🤖 Device-Side Polling¶

    A minimal update check, using the fields the server actually provides:

    #!/usr/bin/env bash
set -euo pipefail

OTA_URL="http://ota-server.local:8080"
DEVICE="STM32"
CURRENT="v183"

latest=$(curl -fsS "${OTA_URL}/api/firmware/list" \
  | jq -r --arg dev "$DEVICE" '
      .data
      | map(select(.device_type == $dev))
      | sort_by(.mod_time)
      | last')

name=$(jq -r '.name'    <<<"$latest")
version=$(jq -r '.version' <<<"$latest")

if [[ "$version" != "$CURRENT" ]]; then
    curl -fsS -o "/tmp/${name}" "${OTA_URL}/download?file=${name}"
    echo "downloaded ${name} (${version})"
fi

    Selection is by mod_time rather than by comparing version strings, because extractVersion truncates at the first separator and cannot be ordered reliably — see the warning in Firmware metadata.
