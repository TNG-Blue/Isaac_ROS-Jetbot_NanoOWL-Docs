    Deployment OTA

    Server OTA — Architecture¶

    How the Go service is put together: packages, request pipeline, and the resource budget it runs under.

    📦 Packages¶

    Package File(s) Responsibility
    main src/main.go Resolves the working directory, creates data dirs, loads config, starts the memory manager, registers routes, runs http.Server
    config src/config/config.go Loads config/config.json once (sync.Once), falls back to built-in defaults and writes the file if it is missing; guarded by an RWMutex
    handlers src/handlers/handlers.go HTTP handlers and the route → handler map
    models src/models/models.go Config, FirmwareInfo, ServerStats, APIResponse, PageData, UploadResult, HealthStatus
    services src/services/firmware.go, logger.go, memory.go Firmware listing and metadata, logging, periodic GC
    utils src/utils/cache.go, format.go, middleware.go Template LRU cache, size/time formatting, rate limiting and JSON responses

    🔁 Request Pipeline¶

    graph TB
    Client["Device / Browser"] --> Mux["net/http DefaultServeMux"]
    Mux -->|"/static/*"| FS["http.FileServer<br/>web/static"]
    Mux -->|"all other routes"| RL["utils.WithRateLimit"]
    RL -->|"slot acquired"| H["handlers.*"]
    RL -->|"5 s timeout"| Busy["503 Server busy<br/>errorCount++"]
    H --> S["services.*<br/>data/firmware"]
    H --> R["utils.RespondSuccess / RespondError<br/>models.APIResponse"]
    S --> R
    R --> Client

    setupRoutes() registers the static file server under /static/, every entry of handlers.HandleAPI() (each already wrapped in WithRateLimit), and /404.

    Rate limiting¶

    var requestSemaphore = make(chan struct{}, 5)   // utils/middleware.go

    Each request tries to take a slot from a buffered channel of size 5. If no slot frees up within 5 seconds, the request is answered with 503 Server busy and the global error counter is incremented. SetMaxConcurrent(n) replaces the semaphore for deployments that can afford more parallelism — App Engine Flexible sets MAX_CONCURRENT_REQS: "10".

    Why a semaphore and not a token bucket

    The limit protects memory, not fairness: firmware transfers are large relative to the 256–512 MB instance sizes this service targets, so the bound that matters is "how many transfers may be in flight at once", which a counting semaphore expresses directly.

    ⏱️ Runtime Budget¶

    Setting Value Where
    ReadTimeout 10 s src/main.go
    WriteTimeout 30 s src/main.go
    IdleTimeout 60 s src/main.go
    MaxHeaderBytes 1 MB (1 << 20) src/main.go
    GC interval 30 s services/memory.go
    Memory cleanup threshold 80 % services/memory.go
    Template cache 4 templates, LRU eviction by last-use timestamp utils/cache.go

    services.OptimizeForEmbedded() runs before anything else, and MemoryManager (started in main, stopped via defer) reads runtime.MemStats on every tick and forces a collection when the threshold is crossed. WriteTimeout (30 s) is the practical ceiling on a single firmware download — size your images accordingly or put a proxy in front for very large transfers.

    🗂️ Firmware Metadata¶

    services.ListFirmwareFiles() reads data/firmware/, skips directories and disallowed extensions, and derives three fields from the file name. Naming matters:

    Field Rule Example
    version Text after the first _v, up to the next . or _; otherwise Unknown motor_v1.8.3.bin → v1 … see note below
    device_type Case-insensitive substring match: esp32, esp8266, arduino, stm32; otherwise Generic stm32f407_control.bin → STM32
    description "Firmware for " + device_type → Firmware for STM32

    Version parsing stops at the first separator

    extractVersion cuts at the first . or _ after _v, so fw_v1.8.3.bin yields v1, not v1.8.3. Use a separator-free version segment (fw_v183.bin) or treat the field as informational and keep the authoritative version inside the image header until the parser is extended.

    Listing also refreshes the shared counters (UpdateTotalSize, UpdateTotalFiles), which is why /api/stats is consistent with /api/firmware/list.

    📤 Response Envelope¶

    Every JSON endpoint answers with models.APIResponse:

    type APIResponse struct {
    Data    interface{} `json:"data,omitempty"`
    Message string      `json:"message"`
    Success bool        `json:"success"`
}

    RespondSuccess(w, data, message) sets success: true; RespondError(w, message, code) writes the status code, sets success: false (no data) and increments errorCount. JSON is encoded with SetEscapeHTML(false) so file names keep their literal characters.

    ⚠️ Current Gaps¶

    Documented because they affect what clients can rely on today:

    Area Behaviour in the code Consequence
    HandleUpload Returns RespondSuccess(w, nil, "Upload endpoint placeholder") without reading the multipart body Uploads must be staged into data/firmware/ by other means (scp, volume mount, CI)
    services.GetUnixTime() return int64(0) // TODO ServerStats.LastUpload stays 0, and HealthStatus.Timestamp is 0
    HandleHealth Goroutines is read from a local struct that is never populated goroutines is always 0; memory_mb is real (MemoryManager.GetMemoryStats)
    gracefulShutdown Defined in main.go but not wired to a signal handler The process exits without draining in-flight transfers

    The static Web Interface preview mirrors the JSON schema of these endpoints — field names and types — not these placeholder values, so it shows a populated dashboard.
