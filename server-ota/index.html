    Server OTA¶

    Professional OTA Server v3.0.0 — the Go service that distributes firmware to the Jetbot fleet: Jetson Orin Nano Super images, STM32 motor-control binaries, OpenMV vision firmware and the flight-control boards.

    Source: Server_OTA/

    Property Value Source
    Language / runtime Go (module server_ota), CI builds on Go 1.21 src/go.mod, .github/workflows/ota-server-ci.yml
    Listen address :8080 src/main.go
    Max upload size 50 MB (52428800 bytes) config/config.json
    Accepted extensions .bin, .hex, .elf, .img, .fw config/config.json, services/firmware.go
    Firmware storage data/firmware/ services/firmware.go
    Logs data/logs/ src/main.go
    Concurrency limit 5 in-flight requests, 5 s queue timeout → 503 utils/middleware.go
    Timeouts read 10 s · write 30 s · idle 60 s · header 1 MB src/main.go
    Memory management GC sweep every 30 s, cleanup above 80 % services/memory.go
    Template cache LRU, 4 entries utils/cache.go

    🧭 How It Fits the Fleet¶

    graph LR
    Dev["Developer / CI"] -->|upload firmware| OTA["Server OTA<br/>:8080"]
    OTA -->|"GET /api/firmware/list"| Jetson["Jetson Orin Nano Super"]
    OTA -->|"GET /download?file="| STM32["STM32 motor control"]
    OTA -->|"GET /download?file="| OpenMV["OpenMV RT1062"]
    Jetson -->|"GET /api/health"| OTA
    STM32 -->|"GET /api/health"| OTA

    A device polls /api/firmware/list, compares the version field against what it is running, and pulls the new image from /download?file=<name>. Version and device type are derived from the file name by the server — see Firmware metadata for the exact rules, which determine how you must name the files you upload.

    📁 Repository Layout¶

    Server_OTA/
├── src/                    # Go sources (module "server_ota")
│   ├── main.go             # entrypoint, routes, HTTP server
│   ├── config/             # JSON configuration loader
│   ├── handlers/           # HTTP handlers
│   ├── models/             # shared structs / API envelope
│   ├── services/           # firmware, logger, memory manager
│   └── utils/              # template cache, formatting, middleware
├── config/config.json      # runtime configuration
├── web/
│   ├── templates/          # index.html, 404.html
│   └── static/             # css, js, images
├── scripts/
│   ├── build.sh            # build the binary
│   ├── run.sh              # run the server
│   └── build_preview.sh    # static UI preview for these docs
├── app.yaml                # App Engine Standard
├── app-flexible.yaml       # App Engine Flexible
└── cloudbuild.yaml         # Cloud Build pipeline

    ▶️ Quick Start¶

    cd Server_OTA

./scripts/build.sh        # build bin/ota-server-3.0.0-linux (+ -rpi)
./scripts/run.sh          # serve http://localhost:8080

curl -s http://localhost:8080/api/health | jq

    The server creates data/firmware/, data/logs/ and web/static/* on startup, and writes a default config/config.json if none exists.

    Want to see the interface without running anything? Use the Web Interface preview.
