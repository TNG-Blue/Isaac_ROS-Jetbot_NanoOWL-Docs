    Features¶

    Isaac ROS Jetbot NanoOWL is a ROS 2 Humble platform for the NVIDIA Jetson Orin Nano Super: GPU perception, state estimation, closed-loop control, embedded firmware, a Gazebo simulation that runs the same driver code as the vehicle, and the tooling to deploy and update it. Every card below links to the page that documents that part in detail.

    Perception¶

    • Open-vocabulary object detection

      NanoOWL and YOLO decoders accelerated with TensorRT. With tracking enabled, detections are treated as a noisy measurement and pass through a recursive estimator whose prediction gates the next association.

      Object Detection

    • LiDAR SLAM

      LD19 and LPB40B drivers with CRC checks, Hampel outlier rejection and gyro de-skew, feeding an EKF with PL-ICP scan matching against a submap and a χ² innovation gate.

      SLAM & Navigation

    • Thermal night vision

      Bad-pixel repair, temporal low-pass filtering and CA-CFAR detection, followed by a constant-velocity Kalman tracker with NIS consistency monitoring.

      Night Vision

    • Stereo depth

      Rectified stereo matching and depth estimation for 3-D reconstruction and obstacle detection.

      Stereo Vision

    • CUDA vision library

      GPU kernels for pre- and post-processing tuned for sm_87, with CuPy/Numba bindings and benchmark results on the Orin Nano Super.

      CUDA Vision

    • RF spectrum monitoring

      Real-time wireless spectrum monitoring, signal analysis and interference detection.

      RF Spectrum

    Estimation and control¶

    Every path that moves hardware follows the same closed-loop chain, and each stage is derived, not tuned by feel (control-systems rule):

    flowchart LR
    S[Sensor] --> F[Filter]
    F --> E[Estimator]
    E --> C[Controller]
    C --> A[Actuator]
    A --> P[Plant]
    P -- measured state --> S

    A first-order low-pass \(H(s) = \dfrac{1}{\tau s + 1}\), \(\tau = \dfrac{1}{2\pi f_c}\), discretised with the backward-Euler rule \(s \approx (1 - z^{-1})/T_s\):

    \[ y[k] = y[k-1] + \alpha\,\bigl(x[k] - y[k-1]\bigr), \qquad \alpha = \frac{T_s}{\tau + T_s} \]

    Its phase lag \(\varphi(\omega) \approx -\arctan(\omega\tau)\) at the loop crossover is charged against the phase-margin budget.

    Kalman filter predict / update, with \(Q\) and \(R\) taken from measured noise densities:

    \[ \begin{aligned} \hat{x}_{k|k-1} &= F\,\hat{x}_{k-1|k-1} + B\,u_{k-1}, & P_{k|k-1} &= F P_{k-1|k-1} F^\top + Q \\ K_k &= P_{k|k-1} H^\top \bigl(H P_{k|k-1} H^\top + R\bigr)^{-1}, & \hat{x}_{k|k} &= \hat{x}_{k|k-1} + K_k\bigl(y_k - H\hat{x}_{k|k-1}\bigr) \end{aligned} \]

    Consistency is checked with the normalised innovation squared \(\nu_k^\top S_k^{-1} \nu_k \sim \chi^2_m\).

    PID with a filtered derivative on the measurement and back-calculation anti-windup:

    \[ u = K_p e + K_i \!\int e\,dt - \frac{K_d\, s}{1 + s\,T_d/N}\,y, \qquad \dot{I} = K_i e + \frac{1}{T_t}\bigl(u_\text{sat} - u\bigr) \]

    LQR, MPC, FOC and sliding-mode designs are used where the plant calls for them.

    References: K. J. Åström, T. Hägglund, Advanced PID Control; D. Simon, Optimal State Estimation; G. F. Franklin, J. D. Powell, M. Workman, Digital Control of Dynamic Systems.

    • Sensor fusion

      IMU, GNSS, encoder and odometry fusion with covariances carried through to the consumers.

      Sensor Fusion

    • Motion and flight control

      Cascaded controllers with saturation, rate limits and watchdog fail-safes; gains come with their margins.

      Control System

    • Coaxial X12 hexacopter simulation

      Gazebo Harmonic plugin at a 1 kHz lock-step with 12 BLDC motors, FOC ESC models, control allocation and gain synthesis with margin reports.

      Gazebo sources

    • MCU ⇄ Jetson sensor link

      IMU, GNSS and encoders stream over Ethernet/UDP with CRC-32 frames and a clock-sync Kalman filter. A virtual MCU sends the same frames in simulation, so every node downstream runs unchanged in SIL and on the vehicle.

      Microcontroller bridge

    Embedded firmware¶

    • Portenta H7 and JetOwl

      Dual-core STM32H747 firmware (Cortex-M7 control, Cortex-M4 I/O), FreeRTOS tasks, field-oriented motor control and micro-ROS.

      Microcontrollers

    • OpenMV vision

      On-camera blob, AprilTag and line detection with a documented serial protocol to the host.

      OpenMV RT1062 API audit

    • Long-range links

      LoRa and network bridges for telemetry and image transfer when Wi-Fi is not available.

      Network Bridge

    Deployment and operations¶

    • Containers

      Docker images for the Jetson and the host tools, orchestrated with Kubernetes and Helm charts.

      Docker · Kubernetes · Helm

    • Over-the-air updates

      A Go OTA server with firmware metadata, device detection and a web dashboard that is also published as a live preview with this site.

      Server OTA · Web interface

    • Monitoring

      Real-time CPU, memory and disk metrics, logging and fault detection, plus a Qt operator dashboard.

      Monitoring

    • Cloud integration

      Remote management and data analytics for robot fleets across locations.

      Cloud Integration
