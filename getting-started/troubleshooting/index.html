    Troubleshooting Guide¶

    Comprehensive solutions to common issues with Isaac ROS Jetbot NanoOWL.

    🔍 Quick Diagnostics¶

    Start with our automated diagnostic tool:

    Bash
    cd ~/ros2_ws/src/Isaac_ROS-Jetbot_NanoOWL
./scripts/health_check.sh

    This checks: - ✅ ROS2 environment - ✅ Hardware detection - ✅ GPU acceleration - ✅ Network configuration - ✅ Model files - ✅ Node status

    ⚠️ Installation Issues¶

    Problem: colcon build fails with memory error¶

    Symptoms:

    Text Only
    c++: fatal error: Killed signal terminated program cc1plus

    Solutions:

    Bash
    # Use only 1 parallel worker
colcon build --symlink-install --parallel-workers 1
    Bash
    # Create 4GB swap file
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make permanent
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Verify
free -h
    Bash
    # Build one package at a time
colcon build --packages-select jetbot_core
colcon build --packages-select jetbot_detection
# ... and so on

    Problem: CUDA not found during build¶

    Symptoms:

    Text Only
    CMake Error: Could not find CUDA
nvcc: command not found

    Solution:

    Bash
    # Check CUDA installation
ls /usr/local/cuda

# Add to PATH
echo 'export CUDA_HOME=/usr/local/cuda' >> ~/.bashrc
echo 'export PATH=$CUDA_HOME/bin:$PATH' >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=$CUDA_HOME/lib64:$LD_LIBRARY_PATH' >> ~/.bashrc

source ~/.bashrc

# Verify
nvcc --version

    Problem: ROS2 packages not found¶

    Symptoms:

    Text Only
    Package 'ros-humble-desktop' has no installation candidate

    Solution:

    Bash
    # Re-add ROS2 repository
sudo rm /etc/apt/sources.list.d/ros2.list
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
  http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | \
  sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

sudo apt update
sudo apt install ros-humble-desktop

    📹 Camera Issues¶

    Problem: Camera not detected¶

    Diagnostics:

    Bash
    # List video devices
ls -l /dev/video*

# Check kernel messages
dmesg | grep -i camera

# Test with GStreamer
gst-launch-1.0 v4l2src device=/dev/video0 ! xvimagesink

    Solutions:

    CSI Camera Not Detected
    1. Check physical connection:
    2. Lift black latch on CSI port
    3. Ensure cable contacts face PCB

    4. Press latch firmly closed

    5. Verify camera is enabled:

      Bash
      # Edit boot config
sudo nano /boot/config.txt

# Ensure line is present:
camera_auto_detect=1

# Reboot
sudo reboot

    6. Test with nvgstcapture:

      Bash
      nvgstcapture-1.0

    USB Camera Not Detected

    1. Check USB connection:

      Bash
      lsusb
# Should show camera device

    2. Verify permissions:

      Bash
      sudo usermod -aG video $USER
newgrp video

# Check device permissions
ls -l /dev/video0
# Should show: crw-rw---- 1 root video

    3. Try different USB port:

    4. USB 3.0 ports for high bandwidth
    5. Check power requirements

    Problem: Low frame rate / choppy video¶

    Solution:

    Bash
    # Reduce resolution
ros2 param set /camera_node image_width 640
ros2 param set /camera_node image_height 480

# Reduce framerate
ros2 param set /camera_node framerate 15.0

# Check actual FPS
ros2 topic hz /camera/image_raw

    🎯 Detection Issues¶

    Problem: Object detection not working¶

    Diagnostics:

    Bash
    # Check if model file exists
ls ~/ros2_ws/src/Isaac_ROS-Jetbot_NanoOWL/models/*.engine

# Check GPU usage
tegrastats

# View detection node logs
ros2 node list
ros2 node info /object_detection

    Solutions:

    Model file not found
    Bash
    # Download models
cd ~/ros2_ws/src/Isaac_ROS-Jetbot_NanoOWL
./scripts/download_models.sh

# Or manually download
wget https://github.com/TNG-Blue/models/releases/download/v1.0/yolov8n.engine
mv yolov8n.engine models/
    TensorRT engine incompatible
    Bash
    # Rebuild engine for your platform
cd ~/ros2_ws/src/Isaac_ROS-Jetbot_NanoOWL
python3 scripts/export_tensorrt.py \
  --weights models/yolov8n.pt \
  --device 0 \
  --include engine \
  --dynamic
    Low detection accuracy
    YAML
    # Edit config/detection_params.yaml
detection:
  confidence_threshold: 0.3  # Lower for more detections
  nms_threshold: 0.45        # Non-max suppression
  input_size: [640, 640]     # Higher resolution

    Problem: Detection too slow (<10 FPS)¶

    Solutions:

    1. Use smaller model:

      YAML
      # config/detection_params.yaml
model_path: "models/yolov8n.engine"  # Nano (fastest)
# vs yolov8s.engine (small)
# vs yolov8m.engine (medium)

    2. Reduce input resolution:

      YAML
      input_size: [416, 416]  # Instead of [640, 640]

    3. Enable power mode:

      Bash
      sudo nvpmodel -m 0  # Maximum performance
sudo jetson_clocks

    🗺️ Navigation Issues¶

    Problem: SLAM not building map¶

    Diagnostics:

    Bash
    # Check LIDAR data
ros2 topic echo /scan --once

# Check TF tree
ros2 run tf2_tools view_frames
evince frames.pdf

# Check SLAM node
ros2 node info /slam_toolbox

    Solutions:

    LIDAR not publishing
    Bash
    # Check LIDAR connection
ls /dev/ttyUSB*

# Set permissions
sudo chmod 666 /dev/ttyUSB0

# Or permanent fix
sudo usermod -aG dialout $USER
newgrp dialout

# Restart LIDAR node
ros2 launch rplidar_ros rplidar_a2_launch.py
    Robot moving too fast
    YAML
    # config/slam_params.yaml
minimum_travel_distance: 0.1  # Increase for slower mapping
minimum_travel_heading: 0.15
    Poor loop closure
    YAML
    # config/slam_params.yaml
loop_search_maximum_distance: 5.0  # Increase search radius
do_loop_closing: true
loop_match_minimum_chain_size: 10

    Problem: Robot not navigating to goal¶

    Diagnostics:

    Bash
    # Check navigation status
ros2 topic echo /navigate_to_pose/_action/status

# View costmaps
ros2 run rqt_image_view rqt_image_view /global_costmap/costmap
ros2 run rqt_image_view rqt_image_view /local_costmap/costmap

# Check planned path
ros2 topic echo /plan

    Solutions:

    Robot stuck / won't move

    1. Check footprint:

      YAML
      # config/nav_params.yaml
robot_radius: 0.2  # Increase if getting stuck

    2. Adjust costmap inflation:

      YAML
      inflation_layer:
  inflation_radius: 0.55
  cost_scaling_factor: 3.0

    3. Enable recovery behaviors:

      YAML
      enable_rotate_recovery: true
enable_backup_recovery: true

    Goal unreachable
    • Ensure goal is not in obstacle
    • Check if path exists in global costmap
    • Try setting intermediate waypoints

    🔌 Hardware Issues¶

    Problem: Motors not responding¶

    Diagnostics:

    Bash
    # Check motor controller communication
ros2 topic list | grep cmd_vel

# Echo velocity commands
ros2 topic echo /cmd_vel

# Test motor controller directly
ros2 run jetbot_control motor_test.py

    Solutions:

    I2C motor controller
    Bash
    # Check I2C devices
i2cdetect -y -r 1

# Should show address (typically 0x60)
# If not visible, check wiring

# Test I2C communication
i2cget -y 1 0x60 0x00
    Ethernet motor controller
    Bash
    # Check network connection
ping 192.168.1.103  # Portenta H7

# Check ROS2 communication
ros2 topic list | grep motor
ros2 topic echo /motor/status

    Problem: IMU data erratic¶

    Solution:

    Bash
    # Calibrate IMU
ros2 run jetbot_imu calibrate_imu.py

# Place robot on level surface
# Follow prompts for 6-axis calibration

# Verify after calibration
ros2 topic echo /imu/data

    Problem: GPS not acquiring satellites¶

    Solution:

    Bash
    # Ensure outdoor location
# Wait 2-5 minutes for cold start

# Check GPS status
cgps -s

# If no satellites after 5 minutes:
# - Check antenna connection
# - Verify power supply (5V)
# - Try different location (away from buildings)

    🌐 Network Issues¶

    Problem: ROS2 nodes can't communicate¶

    Diagnostics:

    Bash
    # Check ROS domain
echo $ROS_DOMAIN_ID

# Check multicast
ros2 multicast receive
# In another terminal:
ros2 multicast send

# Check firewall
sudo ufw status

    Solutions:

    Set ROS domain ID
    Bash
    echo 'export ROS_DOMAIN_ID=0' >> ~/.bashrc
source ~/.bashrc

# Verify
echo $ROS_DOMAIN_ID
    Configure firewall
    Bash
    # Allow ROS2 DDS ports
sudo ufw allow 7400:7500/udp
sudo ufw allow 7400:7500/tcp

# Or disable firewall (not recommended for production)
sudo ufw disable
    Use Cyclone DDS
    Bash
    # Install Cyclone DDS
sudo apt install ros-humble-rmw-cyclonedds-cpp

# Set as middleware
echo 'export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp' >> ~/.bashrc
source ~/.bashrc

    Problem: High latency on WiFi¶

    Solution:

    Bash
    # Use 5GHz band if available
sudo iwconfig wlan0 channel 36

# Reduce WiFi power saving
sudo iw dev wlan0 set power_save off

# Use Ethernet for critical data

    💻 Performance Issues¶

    Problem: System running slow¶

    Diagnostics:

    Bash
    # Check CPU usage
htop

# Check GPU usage
tegrastats

# Check disk I/O
iotop

# Check memory
free -h

    Solutions:

    High CPU usage
    Bash
    # Set power mode (Jetson)
sudo nvpmodel -m 0  # Maximum performance
sudo jetson_clocks

# Reduce node load
# - Lower camera framerate
# - Use smaller detection model
# - Disable unused sensors
    High memory usage
    Bash
    # Check memory per process
ps aux --sort=-%mem | head

# Add swap space (see above)
# Or close unused processes
    Thermal throttling
    Bash
    # Check temperature
tegrastats | grep temp

# If over 70°C:
# - Add active cooling (fan)
# - Improve chassis ventilation
# - Reduce power mode temporarily
sudo nvpmodel -m 2  # Lower power mode
